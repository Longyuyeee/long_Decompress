## 结论

项目没有偏离当前的核心产品目标。它已经从最初较宽泛的“跨平台解压工具”设想，收敛为以 Windows 桌面体验、
压缩/解压正确性、密码流程、资源管理器集成和可靠更新为中心的产品。这一变化与后续持续提出的 Windows 托盘、
右键菜单、一键解压、无控制台闪窗、应用内更新和真实安装验收要求一致，属于有依据的范围收敛。

当前没有发现需要阻止 v1.0.22 继续作为稳定基线的 P0 产品故障。核心归档路径、传统右键菜单和公开更新都有真实
安装环境证据。下一阶段不应继续用小版本号堆叠纯文档或发布治理变更，应优先偿还开发工具链安全债，并把已有的
HFSX 生成方案、桌面 E2E 和性能工具转化为可重复的持续证据。

## 后续开发计划

### 阶段 1：工具链安全迁移

1. 先迁移 Vite、Vitest、`@vitest/coverage-v8`、`@vitejs/plugin-vue` 和 vue-tsc，保持 Tauri 1、Tailwind 3、Pinia 2 不动。
2. 要求类型检查、184 项覆盖率测试、浏览器 E2E、Rust/Clippy、桌面构建和 NSIS 构建全部通过。
3. 迁移完成后重新执行完整 npm 审计；目标是消除当前 7 项开发链漏洞。

### 阶段 2：真实证据持续化

1. 为 HFSX 固定生成器增加可手动触发的 Windows/WSL 验收工作流和摘要产物。
2. 在固定交互式 Windows 主机可用后接入 self-hosted 桌面 E2E；在主机稳定前不得配置永久等待的必需检查。
3. 在同一固定机器累计至少 10 次性能样本，保存机器指纹、版本、逐次结果和统计区间。

### 阶段 3：架构收口与产品增量

1. 审计 `ParallelExtractor`，在“完整对齐生产语义”和“删除实验实现”之间作出明确选择。
2. 清理或归档仍把跨平台、通用 CLI、格式转换和损坏修复写成已承诺能力的旧说明。
3. 选择至少一项用户可感知的修复或增量后再规划 v1.0.23；纯文档和治理更新不单独升版。

## 明确不进入当前路线的事项

- 不采购或配置 Windows Authenticode/商业代码签名证书。
- 不发布依赖可信签名身份的 Windows 11 顶层右键菜单包；继续维护“显示更多选项”中的传统菜单。
- 不把跨平台桌面、绿色版、通用 CLI、格式转换或损坏修复作为下一个小版本的默认承诺。
- 不直接启用实验性并行解压，不降低事务、安全和错误分类标准换取表面性能。

## 下一版本进入条件

下一正式版本必须至少包含一项用户可感知改进，并通过现有 CI、候选安装生命周期、传统右键菜单四根/17 命令、
生产依赖审计和上一正式版到新版本的真实应用内更新。涉及归档语义、依赖主版本或系统集成时，必须增加对应的
专项回归证据。

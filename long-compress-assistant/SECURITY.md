# 安全性说明

## 密码处理安全性

### 当前实现

本项目在处理密码压缩/解压时采取了以下安全措施：

#### 1. **命令行参数传递（7z/RAR）**
- **使用方式**：`7z x -p<password>` 或 `rar a -hp<password>`
- **安全性分析**：
  - ❌ 密码会短暂出现在进程命令行参数中
  - ✅ 进程生命周期短（通常几秒到几分钟）
  - ✅ 这是 7z 和 RAR 命令行工具的**标准且唯一**支持方式
  - ⚠️ 本地管理员或有权限的进程可以通过 `ps` 或任务管理器查看

#### 2. **内存中传递（Rust 库）**
- **使用方式**：
  - `sevenz_rust` 库用于 7z 压缩
  - `zip` crate 用于 ZIP 加密
  - `aes-gcm` 用于 AES 加密（TAR.AES 系列）
- **安全性分析**：
  - ✅ 密码仅存在于进程内存中
  - ✅ 不会暴露到命令行参数
  - ✅ 更安全的方式

### 安全限制与风险

#### 已知风险
1. **进程列表暴露**：使用 7z/RAR CLI 时，密码会在进程列表中短暂可见
2. **内存转储**：如果系统崩溃生成内存转储，密码可能被提取
3. **日志记录**：确保不要将密码记录到日志文件中

#### 缓解措施
1. **最小化暴露时间**：
   - 使用非交互模式，进程快速完成
   - 不使用 shell 中间层，直接调用可执行文件
   
2. **优先使用内存传递**：
   - 7z 压缩使用 `sevenz_rust` 而非 CLI
   - ZIP 压缩使用 `zip` crate
   - TAR.AES 系列使用纯 Rust 实现
   
3. **不记录密码**：
   - 所有日志输出都过滤密码内容
   - UI 中密码输入框使用 `type="password"`

### 最佳实践建议

#### 对于用户
1. **使用密码本功能**：
   - 密码存储在 SQLite 数据库中（AES-256-GCM 加密）
   - 避免每次手动输入密码
   
2. **避免在不受信任的环境中使用**：
   - 多用户服务器
   - 共享计算机
   - 未加密的远程桌面会话

3. **使用强密码**：
   - 项目提供 5 种密码生成模式
   - 支持复杂密码（特殊字符、大小写混合）

#### 对于开发者
1. **永远不要**：
   - 在日志中记录密码
   - 将密码写入临时文件
   - 在错误消息中包含密码
   
2. **应该**：
   - 优先使用 Rust 库而非 CLI
   - 使用 `SecureString` 或 `Zeroize` trait 处理敏感数据
   - 在不再需要时立即清除内存中的密码

### 技术限制

#### 为什么不能完全避免命令行传递？

1. **7z CLI 限制**：
   - 不支持从环境变量读取密码
   - 不支持从 stdin 读取密码（仅在交互模式）
   - 唯一方式是 `-p<password>` 参数

2. **RAR CLI 限制**：
   - 同样只支持 `-p<password>` 或 `-hp<password>` 参数
   - 没有其他更安全的非交互式传递方式

3. **行业现状**：
   - WinRAR、7-Zip、PeaZip 等所有主流工具都使用相同方式
   - 这是压缩工具行业的标准做法

### 未来改进方向

1. **完全移除 CLI 依赖**：
   - 为 RAR 格式寻找纯 Rust 实现
   - 为所有格式提供原生 Rust 库支持

2. **内存保护**：
   - 使用 `zeroize` crate 自动清除密码
   - 使用 `secrecy` crate 包装敏感数据

3. **硬件安全模块（HSM）集成**：
   - 支持 Windows DPAPI
   - 支持 macOS Keychain
   - 支持 Linux Secret Service

### 合规性说明

- ✅ **GDPR**: 密码在本地处理，不传输到外部服务器
- ✅ **数据加密**: 密码本使用 AES-256-GCM 加密存储
- ⚠️ **审计日志**: 当前版本不记录密码使用审计日志（可作为企业版功能）

# v1.7.34 · 带结束标记的流式 LZMA ZIP 丢目录部分取回封板

日期：2026-10-29。

## 实现和用户行为

原 ZIP 本地条目恢复读入器新增未加密 method 14 的未知尺寸流边界识别。要求通用标志 bit 1 明确声明 EOS，读取 ZIP LZMA 的版本/属性长度前导及 5 字节属性，验证属性后以未知展开大小解码到实际结束标记。按实际展开量和 CRC 对照紧随其后的普通/ZIP64 描述符，可选签名有无均可；非零本地展开尺寸也必须吻合，不扫描正文中的签名猜测下一条。

LZMA 解码器会预读描述符与后续成员。通过公开的 `into_parts()` 取回未消费输入，以实际读取位置减去这些字节计算流边界，避免吞掉下一条。采用 64 KiB 输出缓冲，保留取消和现有展开上限；未知大小无法沿正常 ZIP 入口按文件大小缩小字典，因此新增恢复解码器的估算内存预算为 256 MiB，超出时在分配前停止该条目，不扩展普通完整包的原读取限制。

文件、空文件和明确 LZMA 目录接通，完整单包/数字切片可由非首卷进入；同包内原 Deflate/BZip2 方法继续接续。缺失/未声明 EOS、属性损坏、预算超界、截断、CRC/尺寸矛盾与未知边界处停止，只列出此前确认前缀。目录不因大小未知而跳过其压缩流；原总清单仍未知，缺中卷不跨缺口拼接。

用户沿原诊断、恢复、新包整体验证、结果/历史及失败重试入口操作。只确认到目录而无完整文件时继续禁用恢复并说明原因；结果始终标记部分取回。界面、单条展开、多选弹窗和等宽双栏保持，无新格式数量或密码流未知边界能力。正常带 EOS 和有可靠尺寸的无 EOS LZMA ZIP 读取路径保持。

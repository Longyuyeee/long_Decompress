# v1.3.9 之后的建议（原始建议，已衔接 1.4.0 计划）

2026-10-11：用户已确认 1.4.0 主线并追加六项 UI 要求，当前执行依据为 [v1.4.0 开发计划](V1.4.0_DEVELOPMENT_PLAN.md)。以下保留为原始建议，不代表额外全部纳入；若冲突以新计划为准，尤其快速打包已明确要求移除。

先依据新版本真实使用反馈排优先级，不以功能数量为目标。以下为建议，不是已完成或已批准的下一版清单。

1. **失败原因与下一步持续回归**：收集脱敏后的损坏、缺卷、密码错误、空间不足、被占用等真实任务，核对最终原因与可操作指引；不能把未知错误归为密码问题。用户源文件不上传。
2. **缩放与交互一致性**：补充不同 DPI、多屏切换、窗口最小尺寸、长中文文件名和多条同时展开的实际截图与操作；保持行内编辑、高度动画和手动配置优先。
3. **并行收益范围**：在可用的机械硬盘、SSD 和更多小文件/混合场景测端到端耗时、完整进程树资源与磁盘读写。未取得证据前保持默认关闭，不承诺倍数提速。
4. **历史和草稿可用性**：观察用户从旧历史补齐来源、批量纠正、跨页面返回及大库搜索的实际痛点，再确定是否需要更清楚的草稿状态或检索入口；保留原记录，不自动执行。
5. **冲突信息一致性**：评估其他格式能否可靠提供来源时间，以及元数据不变但内容变化的检测成本；无可靠信息时明确未知，不用暂存时间代替，不以全量哈希拖慢每次确认。

新功能、默认行为变化或支持范围调整需要先确认；完整多标签文件管理器、冷门格式扩展和 Windows N 支持不默认纳入。

## 用户目标与范围

让真实超过 4 GiB 的单文件在压缩、密码、数字/标准分卷、所选解压和转换之间可靠接续。已有 ZIP64 不是新增格式，不为凑版本重写既有实现；先固定真实输入和外部原包，再修复发现的具体缺陷。

- 阅读 ZIP 创建的 `large_file` 开关，以及标准 ZIP 读写器、ZIP64 扩展、跨卷偏移和数据描述符。
- 自有载荷逐块实际写入，记录全量流式 SHA-256；不使用改头小包、单纯预分配长度或空洞代替真实内容。
- 分别记录无密码、AES-256、ZipCrypto；数字卷、标准卷和最后小卷；原工具生成输入与产品生成输出的独立回解分别记账。
- 新增边界修复贯通浏览、检查、所选/完整提取、转换、失败任务接续及历史；保留默认行为。
- 单条行内展开、多选弹窗、左右等宽和小窗口滚动不变。仅对变化的流程作定向检查，已通过且未受影响的结果直接复用。

## 原包与首次复现

自有文件逐块实际写入 4,295,098,367 字节，全量 SHA-256 为 `b367b19cb8b5e3c7ca1c9ddf6d116d148fced70adc198ffaa3c5ddd4149a2ce6`；另有大文件后的中文说明、空文件和空目录。没有使用截长预分配或稀疏文件。[输入记录](evidence/zip64-1.5.15/source.json)与[四个原包](evidence/zip64-1.5.15/originals.json)由 7-Zip 26.04 原版生成，含普通/AES/ZipCrypto 及真实无 Seek 标准输出的 ZIP64 数据描述符。大载荷与原包留在忽略的 `test-results/zip64-1515`，生成脚本已保存，不向 Git 提交数 GiB 文件。

原生创建的无密码大包已读完三个文件并通过大小和 SHA-256 断言，但空目录断言失败：[首次红灯](evidence/zip64-1.5.15/empty-directory-red.txt)。共享输入收集器无条件跳过根目录，独立传入的空目录未产生归档条目；转换把空目录作为单独输入时也会丢失，不能删掉断言算完成。第二个[定向红灯](evidence/zip64-1.5.15/zip64-structure-red.txt)证明已损坏的 ZIP64 终目录仅返回无分类的英文错误，尚未作为确定结构损坏交给用户入口。

首次全量测试只编译不运行时带入了无关测试目标，后续限定 `--lib`。Debug 下 SHA-256 全量扫描过慢，未完成的首次扫描已停止；后续仅用命令行 `--config 'profile.test.package.sha2.opt-level=3'` 优化测试校验器，产品配置和运行时不改。首次数据描述符原包生成缺少 stdout 占位归档参数而失败，失败输出留存，修正调用后真实原工具生成成功；不把失败轮次记为通过。版本号此时仍为 1.5.14 的开发基线，最终桌面与发布身份后续分别记录。

明文单包、数字卷、标准卷的完整大小/哈希与空目录已通过，ZIP64 损坏终目录的定向红灯修正后通过。未完成的 Debug 密码编码阶段停止，继续只对测试中的 `miniz_oxide` 增加命令行优化；前三组已完成结果由 checkpoint 复用，产品代码和生产配置不改。追加流式描述符边界测试时发现 `data_start()` 返回可选值，修正测试 API 用法后接续编译，不把编译失败算通过。实际页面使用单独标识的优化运行程序，不据 Debug 测试耗时给出性能承诺。

后续显式采用 [大文件测试专用 profile](../scripts/zip64-1515-test-profile.toml)，对 ZIP、CRC 与密码相关测试依赖使用优化编译，避免 Debug 字节处理耗费时间；应用默认配置和生产 profile 不改。三组明文内容及相关六项回归保留，未完成的编码不计通过。AES 全内容已读完后，测试又以无密码接口读取加密末条目的偏移而失败；改为记录同一次正确密码读取的偏移，保持大小、完整哈希、目录和偏移断言。最后九组矩阵及真实流式描述符跨卷均通过，十组另由独立 7-Zip 全量回解核对。首次桌面命令缺少必填 `extract_only_newer`，修正调用后只接续未完成的所选提取，其前已返回的浏览和完整性结果继续保留。

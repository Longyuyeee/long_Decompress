# v1.5.40～v1.5.43 开发排期与格式补强阶段收尾

2026-10-21，基于已正式发布的 v1.5.39。用户要求调整后续版本排期，并明确格式补强何时可以阶段收尾。本文件为近期执行排期；用户随后选定的五个模块与格式主线回归见[v1.5.44～v1.5.59 分阶段路线](ARCHIVE_ROADMAP_1.5.44_TO_1.5.59.md)。v1.5.40 已完成功能封板，当前状态见[本版接续](NATIVE_SWM_CREATE_1.5.40.md)；v1.5.41 已完成[用途配置封板](PURPOSE_PRESETS_FREEZE_1.5.41.md)，v1.5.42 已完成[失败纠正封板](FAILURE_RECOVERY_FREEZE_1.5.42.md)，v1.5.43 已完成批处理与结果增强及显示封板，见[单版计划](ARCHIVE_ROADMAP_1.5.43.md)和[封板记录](BATCH_RESULTS_FREEZE_1.5.43.md)。近期排期在本版结束，后续按已批准五模块路线推进。

## 当前判断

最近二十版已覆盖更多格式方法、密码、分卷、转换、浏览提取与失败接续。最近九版中七版主要扩展 WIM/ESD 或 ZIP 编码方法，能力有所增加，但继续按单个算法排版，会让常用任务的易用性长期靠后。

后续顺序调整为：完成当前明确承诺的原生 SWM → 常用压缩配置易用性 → 解压失败纠正与实际问题 → 批处理和结果体验。性能沿受影响路径持续小步改进。严重阻断问题发现后优先修复，不等待对应主题版本。

版本号表示推进顺序，不承诺发布日期。相近的小改动优先放入同一功能版；若前一版已完整解决后一版某个问题，删除重复工作后再确定该版实际范围，不为版本数量重复开发。

### v1.5.41：复用现有能力

当前已有自定义预设、配置组、任务模板、智能分析和格式帮助。此版重点是第一次选择与后续复用更容易，实施前先核对这些入口的实际操作成本。用途名称必须说明对应参数；“较小体积”不是固定压缩率承诺，“加密分享”要说明接收方所需工具。算法、密码编码等高级参数保留在熟悉的位置，不增加必经向导、强制的全局/单独切换或新的任务弹窗。

### v1.5.42：以真实问题决定细项

当前已有失败分类、缺卷名称、原包/新包密码区分、批量纠正、补卷新任务和历史重做。根据用户实际操作或可复现样本选择剩余缺口，不预设这些功能全部需要重写。数据异常尚不能确定原因时，显示实际已知信息，不把所有异常都判为错密码；后续操作按当前支持能力提供。性能优化优先选择真实重复扫描、重复读取或操作等待，不预设收益比例。

### v1.5.43：保持既有结果和批量入口

当前已有打开结果位置、复制路径、产物清单、批量结果与生成校验清单。只调整实际难找、重复选择、状态不清或显示拥挤的地方；校验功能维持现有链路，暂不再连续扩展独立校验版本。界面调整应让左右信息分布合理，日志和结果可滚动，不以删减现有功能换取整齐。

## 格式补强可以在哪里收尾

全世界格式、专有变体和历史损坏包没有适合本项目承诺的穷尽终点，但产品的格式补强可以阶段完成。目标是在 v1.5.40 完成本轮约定范围后，转入兼容维护。

阶段完成以用户能完成的事为准：

1. 常用 ZIP/7Z/RAR，以及当前明确支持的其他格式，按已声明能力完成输入、配置、执行、结果和后续取回；RAR 创建仍遵循已有外部编码器条件，不要求每个格式拥有相同能力。
2. 原生密码、Long 自有 AES 包装、数字字节切片和原生多卷区分清楚；单文件与目录归档、只读与创建的范围明确，没有只换后缀或不可用选项。
3. 常见失败能够说明已知原因并接可用的纠正操作；可以保留已成功内容、补齐分卷或更换配置后继续，不承诺补造丢失数据。
4. 已知会阻断当前承诺范围内常用任务的问题得到处理，未支持能力在当前文档和界面就近说明；不以所有冷门研究完成或“没有任何 bug”作为阶段结束条件。

这些是产品范围边界，不新增全格式穷举任务。已有通过依据复用，只补改动影响的必要检查和宽/窄显示；不重复旧格式/密码矩阵、真实盘满或与本版无关的验证。

| 研究项 | 当前安排 |

## 持续保留的交互和发布原则

- 单条点击行内展开，多选在原弹窗修改；自然继承，编辑后自动形成单条配置。
- 左右等宽，窄窗滚动、日志和结果可访问；界面方便、美观，调整优先服务用户操作。
- 保留原件、原失败记录与已有成功结果，配置和恢复范围不被无关操作扩大。
- 功能版中合并同方向的小增强和相关实际修复；README 以软件特点为主，更新记录在末尾，中文 Release 说明实际用户收益与范围。
- 本排期最初只更新文档；后续功能开发与发布状态以各版接续和交接顶部为准。

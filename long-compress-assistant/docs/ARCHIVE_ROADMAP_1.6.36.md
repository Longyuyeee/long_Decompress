# v1.6.36 规划 · Deflate 非固实大文本开头预览

仅规划，尚未开发。接续完整图文预览，让大日志不必全部提取便能先确认内容；本阶段限定非固实 Deflate，普通包和密码包一起接通。

1. **先普通大文本**：为唯一普通非固实条目读取最多 1 MiB 开头。使用独立的部分读取入口，保留 UTF-8/UTF-16/常见编码识别和滚动；明确标出“仅开头、未检查后续内容”，提供提取全文入口。不得借用或放宽已有完整读取的流结束、CRC 与精确消费要求。
2. **接通密码和数字卷**：有序 AES → Deflate 载荷使用已有显式部分 AES 机制，手动密码/保险箱、内容与文件名加密、完整数字卷和非首卷保持。完整目录头仍须完成 AES 消费；手动错误不回退，不记整包密码成功，不能把部分内容称为密码或整包校验成功。
3. **控制实际开销**：实际输入、字典/参数、时间、取消和来源绑定沿用现有上限；不得因文件声明很大而分配全文缓冲。区分开头前损坏、短于声明和未检查尾部，遇到无法确认的组合给原提取入口。
4. **独立收尾一次**：原版工具样本由另一版本回解确认正文；补普通/密码大文本、精确边界、分卷、取消/来源及原宽窄窗口，完整读取只补受影响连续性，不重复旧矩阵。同步 README、Release、能力表和交接后发版。

下一阶段再拆 Deflate 固实大文本（前置依赖与所选开头合计受限），之后接续 Deflate64。继续更多格式/算法、密码/分卷与容错主线；ALZ 方法 3、历史 Bzip2/原工具图片和 EGG 加密固实维持有效外部原件条件，不为空取材单独发版。保留单条展开、多选弹窗、50/50 双栏、工具/主题与问号收纳，不增加首页配置区。

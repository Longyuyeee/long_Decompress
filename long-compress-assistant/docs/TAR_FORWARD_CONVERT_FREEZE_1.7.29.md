# v1.7.29 · TAR.LZO 前向链接内容转换封板

日期：2026-10-29。

## 用户行为与实现

完整 TAR.LZO 中“链接先出现、内容目标后出现”的直接引用，接入原“转换压缩包”入口。复用 v1.7.28 完整计划确认目标与来源版本，移除转换准备阶段的前向引用限制；原有暂存读取已能将链接物化为独立逻辑文件，无需增加一套写入器。普通头、GNU 长名称、局部 PAX、空文件及已证实的旧 GNU / PAX 1.0 稀疏逻辑内容可作为新包输入，完整数字卷可从非首卷进入。

私有解压目录恢复明确目录及各文件自身的日期后，既有 ZIP / ZIPX、7Z、TAR / TAR.GZ 创建器接续。按目标能力写入密码、分卷和时间，新包验证完成、来源重查通过后才提交，结果收据列出真实文件及大小；原转换任务的结果、历史与重试配置无需新增入口。原包保留，不写系统链接、不保留原 TAR 的物理硬链接关系，也不承诺目标保持稀疏空洞、全部权限或扩展元数据。

转换命令原有“完整结构、校验新包、保留原件”契约保持。读取或写入失败、校验失败、来源变更、取消及发布时目标冲突沿原事务回收私有目录和输出族；不能把临时新包当作完成结果。前向链接的嵌套物化仍明确提示先提取后打开，部分抢救不越过未确认前缀；任意链条、循环、符号链接及缺失/歧义目标不扩展。

## 本次检查

- 原生专项 5 项：7 组成功转换；读取后/发布前来源变化；发布时同名单文件/卷族及取消；损坏来源、缺卷、无链接普通包回退与单文件编码目标拒绝；注入的读取/写入错误与目标验证失败清理。首轮 4 项通过，一项反例误用稀疏逻辑长度构造截断位置，修正为实际编码正文内截断，仅补跑该项。模拟 I/O 错误不记作真实盘满测试。
- 成功目标：USTAR → ZIP；GNU → AES ZIP 标准分卷、AES ZIPX（XZ）和 TAR；PAX → ZipCrypto ZIP 数字卷、带文件名加密的固实 LZMA2 7Z 数字卷和 TAR.GZ。两组来源从完整数字卷的末卷读取。
- 每个新包先走原生校验再发布，原生取回核对精确目录树、文件内容和每个条目自己的编码日期；新包不包含原 `.tar.lzo` 包壳或私有暂存前缀。固定三组 GNU tar 1.35 原件 SHA 保持。
- 独立 Python TAR 解析从前向目标读取逻辑内容、从副本自身头读取日期；外部 7-Zip 26.04 对 7 份新包读回，与原生输出分别核对 108 个条目、87 个文件，包含空目录、中文/长名称、空文件和稀疏逻辑内容。副本与原目标为不同文件身份，结果收据大小与实际文件一致；数字输入独立拼回原件。
- 相关旧 2 项：原转换命令的保留原件/必须校验契约；尚未接通的前向嵌套提示与缓存清理。未重跑旧算法、密码或 UI 全矩阵。
- 当前 Shell DLL 已生成，八处版本身份通过。UI 源码未改，没有控制桌面；正式 Windows/前端构建、安装器及签名附件由本版 CI/Release 接续。

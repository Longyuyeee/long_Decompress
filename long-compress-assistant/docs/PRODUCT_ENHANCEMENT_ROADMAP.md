# Long解压产品增强路线

> 记录日期：2026-08-10  
> 对齐基线：v1.1.1 开发分支  
> 原则：新增能力必须复用现有归档识别、任务、事务、安全、日志、密码、配置组和真实桌面测试体系，不建立第二套旁路实现。

## 1. 产品判断

Long解压当前已经覆盖多格式压缩/解压、批量任务、密码保险箱、完整性检测、配置组、托盘、资源管理器菜单、事务提交、取消和公开更新。下一阶段不以继续堆叠格式为主，而以“安全可信、操作前可判断、归档内容可查看、重复工作可自动化”为主线。

参考同类产品后，值得吸收但必须结合现有能力重做的方向包括：

- NanaZip 的智能解压、解压后打开目录和 Mark-of-the-Web 传播；
- Bandizip 的归档测试、智能/高速压缩、归档浏览预览、压缩后校验和安全扫描；
- PeaZip 的图形任务导出脚本、任务复用和归档管理；
- WinRAR 的损坏归档诊断、恢复记录和修复体验；
- 7-Zip 的稳定格式引擎、文件管理器、命令行和自解压能力。

调研入口：

- <https://github.com/M2Team/NanaZip>
- <https://en.bandisoft.com/bandizip/help/>
- <https://peazip.github.io/index.html>
- <https://www.win-rar.com/open-rar-file.html?L=English>
- <https://www.7-zip.org/>

## 2. 融合约束

所有新能力都遵守以下边界：

1. 格式判断统一经过 `archive_format.rs` 和能力矩阵，不在前端复制扩展名清单。
2. 压缩与解压仍使用现有任务模型、类型隔离、进度、取消和实时日志，不创建不可观测的后台旁路。
3. 文件写入继续经过暂存、资源限制、冲突策略、事务提交和失败回滚；任何预览、修复或编辑都不能原地破坏原归档。
4. 密码统一使用现有密码保险箱和候选机制；日志、命令行和临时文件不得泄露密码。
5. 配置项优先进入现有全局设置与配置组；右键菜单只提供稳定高频入口，不复制完整高级设置。
6. 每项功能必须增加 Rust 真实样本回归、前端交互测试和必要的 Tauri 桌面闭环；只完成 Mock 或空样本不算完成。

## 3. 开发阶段

### P0：安全解压与安全压缩闭环

#### 3.1 Mark-of-the-Web 传播

目标：互联网来源归档解压后，输出文件继续保留 Windows `Zone.Identifier` 安全来源信息。

融合方式：

- 在现有解压事务开始时读取源归档的来源标记；
- 在暂存内容通过检查、准备提交时为普通文件写入同等级来源标记；
- 默认开启，在现有设置中心提供说明清晰的开关；
- 结果写入任务日志和诊断信息，不改变密码、冲突、取消及回滚语义；
- 验证普通文件、Office、脚本、可执行文件、目录、取消和回滚场景。

验收：带互联网来源标记的归档解压后，所有已提交文件保留来源标记；失败和取消不留下半提交 ADS。

#### 3.2 压缩后自动校验与源文件删除保护

目标：归档通过完整性检测后才进入“成功”状态；开启删除源文件时，必须校验成功后才能删除。

融合方式：

- 复用现有临时输出与原子发布机制；
- 复用 `test_archive_integrity`/引擎测试能力，但下沉为压缩发布流程的一部分；
- 设置中心和配置组增加“压缩完成后校验”，删除源文件时强制开启且不可绕过；
- 校验失败保持源文件不变，清理未发布输出，并在现有任务阶段与日志中显示失败原因；
- 分卷、密码 ZIP/7Z、AES 容器和取消分别建立真实回归。

验收：没有任何未经校验的归档能够触发源文件删除；校验失败不会覆盖既有目标。

### P1：归档浏览与诊断中心

#### 3.3 压缩包浏览中心

目标：不完整解压即可浏览目录、搜索、筛选并选择性解压。

融合方式：

- 第一阶段复用现有 `list_archive_contents`，扩展为结构化条目（路径、大小、压缩后大小、时间、CRC、加密状态）；
- 使用现有格式识别、密码保险箱、任务日志和解压事务；
- 浏览窗口提供目录树、列表、搜索、文件类型筛选和选择性解压；
- 图片预览仅把单个条目解到受限临时目录，关闭预览或退出应用时由 RAII 清理；
- 暂不直接编辑原归档，后续编辑必须通过“重建新归档 → 校验 → 原子替换”。

验收：ZIP、7Z、RAR、TAR 系列、密码归档和长路径均能浏览；预览不会绕过资源上限或留下临时文件。

#### 3.4 归档诊断与 ZIP 修复

目标：把已有内容列表、完整性测试、密码/损坏分类和 `repair_zip` 汇总为可理解的诊断流程。

融合方式：

- 诊断报告展示实际格式、加密/分卷状态、缺卷、CRC/截断、条目统计和可恢复性；
- ZIP 修复始终输出到新文件，完成后执行完整性校验，默认不覆盖原包；
- 支持复制诊断报告，任务日志保留关键证据但不记录密码；
- 其他格式在没有可靠修复能力时只提供诊断，不能宣称已修复。

验收：真实正常、损坏、截断、缺卷、错误密码归档均有稳定分类；修复失败不修改原文件。

### P1：智能压缩决策

#### 3.5 预计体积与智能模式

目标：让现有 `estimatedSize` 从占位状态成为可解释的压缩前分析能力。

融合方式：

- 使用受限抽样估算压缩率、预计输出体积和耗时，不完整读取超大文件；
- 识别视频、音频、图片和既有归档等低收益内容，建议“仅存储”或“快速”；
- 把智能结果映射到现有 `CompressionOptions`，用户仍可手动覆盖；
- 每个压缩组独立分析，结果进入现有详情面板和配置组，不改变任务分组模型；
- 记录预测值和实际结果，用固定机器性能工具评估误差，不作跨机器绝对承诺。

验收：分析可取消、内存有界；对典型文本、图片、视频、归档和混合目录给出稳定建议，并显示预测误差。

### P2：自动化与资源调度

#### 3.6 可执行任务模板

- 在现有配置组上增加源规则、目标规则、命名模板、包含/排除条件和校验策略；
- 支持从 GUI 导出可审计命令/任务文件，导入时先预览计划；
- 后续再增加监控文件夹和定时任务，默认不后台删除源文件；
- 所有自动任务进入现有任务中心并接受取消、冲突和更新阻断。

#### 3.7 自适应资源调度

- 复用现有并发任务设置和性能基线，增加磁盘空间预检、SSD/HDD/网络盘识别和小文件策略；
- 先优化任务级调度，实验性 `ParallelExtractor` 在完整对齐密码、事务、冲突、时间戳和取消前不得接入生产；
- 只有固定机器基线证明收益后才能改变默认并发参数。

## 4. 暂缓事项

- 无可信代码签名证书时，不继续投入 Windows 11 新式第一层菜单发布。
- 自解压 EXE 会扩大 SmartScreen 和安全交付问题，低于上述安全与浏览能力。
- 归档内直接编辑、通用修复、激进并行解压均须先证明事务安全，不做快速拼接。
- 不因竞品支持“更多格式”就扩大公开声明；仍以非空真实载荷闭环为准。

## 5. 推荐实施顺序

1. Mark-of-the-Web 传播。
2. 压缩后自动校验与删除源文件保护。
3. 压缩包浏览中心：结构化列表、搜索、筛选、选择性解压。
4. 预计体积和智能压缩模式。
5. 归档诊断与 ZIP 修复中心。
6. 图片预览、可执行任务模板、监控文件夹和自适应调度。

每个阶段独立 PR、独立审计和独立真实样本验收；不得把多个高风险文件语义变更混入同一版本。

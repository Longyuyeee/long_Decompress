# Long解压产品增强路线

> 记录日期：2026-08-10
>
> 对齐基线：v1.1.5
>
> 原则：新增能力必须复用现有归档识别、任务、事务、安全、日志、密码、配置组和真实桌面测试体系，不建立第二套旁路实现。

## 2026-08-15 主流程对齐补充

本轮没有继续扩充格式数量，而是收敛解压、压缩和密码主流程：密码候选只由后端状态机执行；批量任务接通有界并发和同输出目录互斥；真实字节事件驱动速度与 ETA；7Z 固实选项落到原生单块写入；分卷声明收敛为实际可创建的无密码 ZIP；非原生密码格式转 7Z 必须在面板和提交前两次明确告知。

性能策略保持原路线边界：并发能力上线但默认实际值仍为 1，历史配置自动迁移，不根据单台 NVMe 结果静默改为 4。用户可明确提高并发；在真实 HDD、网络盘和跨盘样本完成前，不做自动介质调度。速度/ETA 只覆盖能报告真实字节的路线，外部 CLI 与尚未接入字节回调的引擎列为后续可观测性工作，不显示估算吞吐冒充实测。

当前代码与真实样本门禁已通过，Draft PR #81 等待 Windows Release 可见桌面验收。验收未完成前不提升版本，不发布 Release。

## 1. 产品判断

Long解压当前已经覆盖多格式压缩/解压、批量任务、密码保险箱、完整性检测、配置组、托盘、资源管理器菜单、事务提交、取消和公开更新。下一阶段不以继续堆叠格式为主，而以“安全可信、操作前可判断、归档内容可查看、重复工作可自动化”为主线。

参考同类产品后，值得吸收但必须结合现有能力重做的方向包括：

- NanaZip 的智能解压、解压后打开目录和 Mark-of-the-Web 传播；
- Bandizip 的归档测试、智能/高速压缩、归档浏览预览、压缩后校验和安全扫描；
- PeaZip 的图形任务导出脚本、任务复用和归档管理；
- WinRAR 的损坏归档诊断、恢复记录和修复体验；
- 7-Zip 的稳定格式引擎、文件管理器、命令行和自解压能力。

调研入口：

- <https://github.com/M2Team/NanaZip>
- <https://en.bandisoft.com/bandizip/help/>
- <https://peazip.github.io/index.html>
- <https://www.win-rar.com/open-rar-file.html?L=English>
- <https://www.7-zip.org/>

## 2. 融合约束

所有新能力都遵守以下边界：

1. 格式判断统一经过 `archive_format.rs` 和能力矩阵，不在前端复制扩展名清单。
2. 压缩与解压仍使用现有任务模型、类型隔离、进度、取消和实时日志，不创建不可观测的后台旁路。
3. 文件写入继续经过暂存、资源限制、冲突策略、事务提交和失败回滚；任何预览、修复或编辑都不能原地破坏原归档。
4. 密码统一使用现有密码保险箱和候选机制；日志、命令行和临时文件不得泄露密码。
5. 配置项优先进入现有全局设置与配置组；右键菜单只提供稳定高频入口，不复制完整高级设置。
6. 每项功能必须增加 Rust 真实样本回归、前端交互测试和必要的 Tauri 桌面闭环；只完成 Mock 或空样本不算完成。

## 3. 开发阶段

### P0：安全解压与安全压缩闭环

#### 3.1 Mark-of-the-Web 传播

状态（2026-08-11）：实现与 Windows Release 桌面门禁均已完成，等待独立 PR 审核。

目标：互联网来源归档解压后，输出文件继续保留 Windows `Zone.Identifier` 安全来源信息。

融合方式：

- 在现有解压事务开始时读取源归档的来源标记；
- 在暂存内容通过检查、准备提交时为普通文件写入同等级来源标记；
- 默认开启，在现有设置中心提供说明清晰的开关；
- 结果写入任务日志和诊断信息，不改变密码、冲突、取消及回滚语义；
- 验证普通文件、Office、脚本、可执行文件、目录、取消和回滚场景。

验收：带互联网来源标记的归档解压后，所有已提交文件保留来源标记；失败和取消不留下半提交 ADS。

当前证据：已接入暂存提交事务和设置中心，Windows 真实 NTFS ADS 用例覆盖读取、传播、重命名提交、缺失/畸形/超限标记、取消清理及失败回滚。Windows Release Tauri + WebView2 门禁使用带 `ZoneId=3` 的真实 ZIP，在可见浏览中心解压普通文本、Office、PowerShell、EXE 和嵌套目录文件；默认开启时逐文件 ADS 与源标记一致且任务日志可追溯，随后从可见设置中心关闭开关并确认二次解压完全不创建 ADS。

#### 3.2 压缩后自动校验与源文件删除保护

状态（2026-08-11）：实现与 Windows Release 桌面门禁均已完成，等待独立 PR 审核。

目标：归档通过完整性检测后才进入“成功”状态；开启删除源文件时，必须校验成功后才能删除。

融合方式：

- 复用现有临时输出与原子发布机制；
- 复用 `test_archive_integrity`/引擎测试能力，但下沉为压缩发布流程的一部分；
- 设置中心和配置组增加“压缩完成后校验”，删除源文件时强制开启且不可绕过；
- 校验失败保持源文件不变，清理未发布输出，并在现有任务阶段与日志中显示失败原因；
- 分卷、密码 ZIP/7Z、AES 容器和取消分别建立真实回归。

验收：没有任何未经校验的归档能够触发源文件删除；校验失败不会覆盖既有目标。

当前证据：校验已置于唯一临时输出发布之前；删除源文件会在前后端强制开启校验。真实回归覆盖普通/密码 ZIP、密码 7Z、AES 外层认证与内层压缩流、标准多分卷、取消、既有目标保护和配置数据库升级。Windows Release Tauri + WebView2 门禁从可见压缩中心分别执行“校验并保留源文件”和“强制校验后删除源文件”：任务日志严格按校验开始、通过、完成排序，两个最终 ZIP 均经独立 7-Zip 完整性与内容复核；开启删除时，界面会把用户刚取消的校验重新勾选并锁定，提交任务保持 `verify_after=true`，且源文件只在归档发布成功后消失。

### P1：归档浏览与诊断中心

#### 3.3 压缩包浏览中心

状态（2026-08-11）：第一阶段实现与 Windows Release 桌面门禁均已完成，等待独立 PR 审核。

目标：不完整解压即可浏览目录、搜索、筛选并选择性解压。

融合方式：

- 第一阶段复用现有 `list_archive_contents`，扩展为结构化条目（路径、大小、压缩后大小、时间、CRC、加密状态）；
- 使用现有格式识别、密码保险箱、任务日志和解压事务；
- 浏览窗口提供目录树、列表、搜索、文件类型筛选和选择性解压；
- 图片预览优先使用进程内有界读取并以内存数据 URL 展示，不创建临时文件；不能证明有界读取的格式保持禁用；
- 暂不直接编辑原归档，后续编辑必须通过“重建新归档 → 校验 → 原子替换”。

验收：ZIP、7Z、RAR、TAR 系列、密码归档和长路径均能浏览；预览不会绕过资源上限或留下临时文件。

当前证据：已新增独立浏览中心与 `Ctrl+B` 导航，提供结构化条目、目录定位、搜索、类型筛选、精确多选和任务化选择性解压；ZIP/7Z/RAR 元数据由进程内引擎读取，未手填密码时复用密码保险箱候选，其他格式仅在无密码时使用非交互 7-Zip 元数据模式。精确选择在既有暂存事务内裁剪，不绕过路径安全、资源限制、冲突、Mark-of-the-Web、取消和回滚。真实矩阵覆盖中文长路径 ZIP、普通/加密头 7Z、错误密码、TAR/TAR.GZ/TAR.BZ2/TAR.XZ。Windows Release Tauri + WebView2 门禁进一步覆盖 7-Zip 生成的中文八层长路径 ZIP、密码与文件名加密 7Z、固定加密 RAR，以及搜索、精确单选、未选文件不落盘、RAR 输出哈希和页面无横向溢出；同时修复旧 ZIP 解压引擎无法读取 Unicode Path Extra Field 导致选择项被清空的问题，并禁止非空选择以零文件结果报成功。

图片预览首阶段（2026-08-10）已在 `agent/archive-image-preview` 实现：ZIP/TAR/TAR.GZ/TAR.BZ2/TAR.XZ/TAR.ZST 可精确读取单个条目，解压后上限 8 MiB，并以文件魔数确认 PNG/JPEG/GIF/WebP/BMP；TAR 流到目标条目的总扫描预算为 64 MiB，载荷必须与归档声明长度一致；单边超过 8192、总像素超过 1600 万、SVG/AVIF/ICO、扩展名伪装、截断和非规则条目均拒绝渲染。内容只以内存数据 URL 返回，不创建预览临时文件。由于 7Z 固实块与当前 RAR `read()` 无法证明严格有界，首阶段明确禁用这两类预览；元数据浏览和选择性解压能力不受影响。

#### 3.4 归档诊断与 ZIP 修复

目标：把已有内容列表、完整性测试、密码/损坏分类和 `repair_zip` 汇总为可理解的诊断流程。

状态（2026-08-10）：首阶段已在 `agent/archive-diagnostics-center` 实现。诊断被融合到文件完整性中心第三模式，输出实际格式、加密/分卷、缺卷、条目统计、完整性状态、问题说明和不含密码的证据。诊断与 ZIP 重建均可取消；原先不可靠的 7-Zip `r` 路线已删除。

融合方式：

- 诊断报告展示实际格式、加密/分卷状态、缺卷、CRC/截断、条目统计和可恢复性；
- ZIP 修复始终输出到新文件，完成后执行完整性校验，默认不覆盖原包；
- 支持复制诊断报告，任务日志保留关键证据但不记录密码；
- 其他格式在没有可靠修复能力时只提供诊断，不能宣称已修复。

验收：真实正常、损坏、截断、缺卷、错误密码归档均有稳定分类；修复失败不修改原文件。

当前证据：真实进程内样本覆盖健康 ZIP/7Z、ZIP CRC 损坏、ZIP 中央目录截断、ZIP/7Z/RAR 分卷缺口、加密 ZIP/7Z 缺少密码与错误密码、预取消和不支持安全密码验证的结构诊断。ZIP 修复只恢复可完整读取且路径安全的条目，写入同目录唯一临时文件，完成后再次完整校验并重命名到新的目标；原包哈希保持不变，截断、加密、零可恢复条目、取消和校验失败均不发布输出。正式合并前仍需使用固定 RAR 样本及 Windows 候选桌面执行一次可见诊断抽查。

### P1：智能压缩决策

#### 3.5 预计体积与智能模式

目标：让现有 `estimatedSize` 从占位状态成为可解释的压缩前分析能力。

状态（2026-08-11）：首阶段实现与 Windows Release 桌面门禁均已完成。后端最多扫描 100,000 个文件、抽取 16 个文件且总内容样本不超过 2 MiB；前端按单文件/压缩组独立分析，可取消、可重新分析、可采用建议。普通非分卷任务完成后会展示实际体积与预测误差。真实 Tauri + WebView2 门禁覆盖 24 文件、超过 8 MiB 的高可压缩目录，以及真实 PNG 与 MP4 类低收益组合；分别验证 7Z L7 固实建议、ZIP L1 快速建议、15 秒交互上限、采用建议后的现有配置更新和详情卡无横向溢出。

融合方式：

- 使用受限抽样估算压缩率、预计输出体积和耗时，不完整读取超大文件；
- 识别视频、音频、图片和既有归档等低收益内容，建议“仅存储”或“快速”；
- 把智能结果映射到现有 `CompressionOptions`，用户仍可手动覆盖；
- 每个压缩组独立分析，结果进入现有详情面板和配置组，不改变任务分组模型；
- 记录预测值和实际结果，用固定机器性能工具评估误差，不作跨机器绝对承诺。

验收：分析可取消、内存有界；对典型文本、图片、视频、归档和混合目录给出稳定建议，并显示预测误差。分卷归档的实际体积需要汇总多个卷，首阶段不显示误差，不能把单个卷大小当作总输出。

### P2：自动化与资源调度

#### 3.6 可执行任务模板

- 在现有配置组上增加源规则、目标规则、命名模板、包含/排除条件和校验策略；
- 支持从 GUI 导出可审计命令/任务文件，导入时先预览计划；
- 后续再增加监控文件夹和定时任务，默认不后台删除源文件；
- 所有自动任务进入现有任务中心并接受取消、冲突和更新阻断。

当前已完成：

- 复用压缩配置组建立 `long-decompress-task-template` v1，不新建第二套压缩参数模型；
- GUI 可导出模板、导入前结构化预览，并以预览内容的 SHA-256 绑定最终导入，文件被替换后必须重新预览；
- 模板文件最大 256 KiB，字段、变量、模式数量、格式能力、分卷和固实组合均由 Rust 严格验证；
- 固定密码、保险箱分类绑定、删除源文件、额外引擎参数和自动写入保险箱不导出；导入只创建配置组，自动应用关闭且不启动任务；
- 配置组与模板支持包含/排除 glob，排除规则优先，数据库 v4 迁移保留已有配置并为旧数据补空排除列表；
- GUI 可选择显式文件并生成待确认计划，Rust 重新读取最多 1000 个候选的真实元数据、去重并逐项说明接受/排除原因，不信任前端上报的大小和类型；
- 确认后只创建现有压缩中心的等待分组，密码清空、删除源文件关闭且显式清除自动启动标记。规则型模板首阶段不递归展开目录，避免把一次性草稿误当成监控任务；
- 文件夹规则只读预览已独立实现：只扫描用户当次选择的目录，最多 1000 个普通文件和 32 层，不跟随符号链接/Windows 重解析点；相隔 750 ms 的双元数据快照用于排除仍在变化的文件，并在 GUI 列出规则、稳定性和扫描截断原因；
- 只读预览不保存监控、不创建草稿、不启动任务。真实 Windows Release Tauri 门禁已覆盖模板导出/导入、显式文件草稿、目录只读预览、关闭预览后新增文件不触发任务，以及密码/删除源文件/额外参数不跨模板的安全边界；
- 持久监控生命周期已在独立分支实现：只有用户从预览明确保存后才授权目录，支持启动、暂停、停用和删除；启用/恢复时现有文件作为基线，不回填成草稿。根目录和候选均拒绝符号链接/Windows 重解析点，最多保存 20 项授权；
- 文件系统事件按 900 ms 固定窗口合并，随后复用既有 750 ms 有界稳定性扫描，并以规范路径、大小和修改时间跨事件去重；待确认批次写入数据库 v5，单目录最多保留 100 批。应用只将持久批次转换为现有压缩中心等待草稿，密码清空、删除源文件关闭且不会自动启动；真实 Windows Release Tauri 生命周期门禁已覆盖暂停、恢复基线、托盘后台、进程重启恢复、停用/重启用和删除后无残留监听器。

#### 3.7 自适应资源调度

- 复用现有并发任务设置和性能基线，增加磁盘空间预检、SSD/HDD/网络盘识别和小文件策略；
- 先优化任务级调度，实验性 `ParallelExtractor` 在完整对齐密码、事务、冲突、时间戳和取消前不得接入生产；
- 只有固定机器基线证明收益后才能改变默认并发参数。

第一阶段状态（2026-08-10）：`agent/resource-preflight` 已把结构化资源预检接入压缩和解压真实执行路径。后端统一探测目标卷与 128 MiB 安全预留；解压优先读取归档元数据的展开体积，压缩复用与当前格式/等级一致的智能分析结果，普通显式文件则使用保守体积估算。空间明确不足会在引擎启动前阻止，网络/移动/未知介质及未知体积采用可见警告并保留事务运行时保护。任务详情和日志可追溯预检结论。当前阶段没有启用旧 `TaskScheduler`、没有接入实验性并行解压，也没有改变默认并发。

Windows Release 桌面门禁（2026-08-10）已完成：资源管理器一键打包/一键解压走真实主流程，验证本机卷容量、文件系统、介质、普通文件保守估算、非空 ZIP 展开元数据、任务日志和两类可见卡片；可靠不足经正式 IPC 返回 blocked，且没有创建目标目录。卡片同时验证无横向溢出。门禁之后按顺序进入固定机器 SSD/HDD、单大文件/大量小文件和同盘/跨盘基线；只有证据证明稳定收益后，才设计与现有并发设置兼容的任务级策略。

固定机器 I/O 基线工具（2026-08-10）已进入独立分支：现有结构化性能脚本新增源端/目标端拓扑模式，复用正式 ZIP 单大文件和大量小文件路径，保证压缩、解压都按源端→目标端测量并执行真实内容校验。Windows 卷、物理磁盘、文件系统和 SSD/HDD 信息进入结果指纹，空间不足或磁盘身份不可证明时不会创建夹具，拓扑不一致的结果不能比较。当前开发机已先用 C→C 同卷 SSD 和 E→C 跨物理 SSD 单样本证明工具闭环，随后完成固定规模 10 样本正式矩阵；没有可证明 HDD，默认并发保持不变。

## 4. 暂缓事项

- 无可信代码签名证书时，不继续投入 Windows 11 新式第一层菜单发布。
- 自解压 EXE 会扩大 SmartScreen 和安全交付问题，低于上述安全与浏览能力。
- 归档内直接编辑、通用修复、激进并行解压均须先证明事务安全，不做快速拼接。
- 不因竞品支持“更多格式”就扩大公开声明；仍以非空真实载荷闭环为准。

## 5. 推荐实施顺序

1. Mark-of-the-Web 传播。
2. 压缩后自动校验与删除源文件保护。
3. 压缩包浏览中心：结构化列表、搜索、筛选、选择性解压。
4. 预计体积和智能压缩模式（首阶段与 Windows Release 桌面门禁均已完成）。
5. 归档诊断与 ZIP 修复中心（首阶段与 Windows Release 命令闭环均已完成）。
6. 图片受限预览（首阶段与 ZIP/TAR Windows Release 命令闭环均已完成）。
7. 可执行任务模板（导入审计、排除规则、待确认草稿、文件夹只读预览、持久监控生命周期和完整 Windows Release 生命周期门禁均已完成）。
8. 自适应资源调度第一阶段、Windows Release 桌面门禁和双 NVMe SSD 同卷/跨物理盘 10 样本基线已完成；下一步重复观察高波动 SSD 指标并补齐真实 HDD 合格样本，再以独立策略实验决定是否设计任务级调度，默认并发暂不调整。

每个阶段独立 PR、独立审计和独立真实样本验收；不得把多个高风险文件语义变更混入同一版本。

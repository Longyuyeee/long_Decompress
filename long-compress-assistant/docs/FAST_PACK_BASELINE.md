# 快速 ZIP 打包实现与初轮 A/B（2026-10-10）

## 行为

- 用户主动开启，默认关闭；旧配置缺少字段时关闭。仅普通/加密 ZIP 生效，分卷及其他格式在 UI 禁用且执行载荷不启用，不改变这些格式的既有策略。
- 每个至少 256 KiB 的文件，从头/中/尾各读取最多 32 KiB；复用现有压缩分析的读取及 Deflate 估算逻辑，以 level 1 测试样本，体积比例至少 98% 时该条目使用 Store，否则使用用户指定 Deflate 等级。小文件保持原策略。每文件采样内存不超过 96 KiB，采样后读指针回到零。
- 不依赖扩展名，不省略任何输入，AES 加密保持。真实执行日志报告直接存储的文件数。抽样不保证整文件最优压缩率，因此保留“包可能略大”的提示。

## 方法与环境

基于 `50b5698` 加本轮未提交改动，同一源码以 `LONG_NATIVE_ZIP_FAST_PACK=0/1` 对照；各 3 轮，固定 level 6，相同样本 manifest SHA-256，先关闭三轮再开启三轮，未清理缓存。测量包含采样、写包和关闭包，不包含界面、事务、资源预检与完整性验证耗时；落盘文件数、长度和 SHA-256 在计时后验证。

Windows 10.0.22621 x64；Ryzen 7 9700X / 16 逻辑处理器；内存 50,588,549,120 字节；Rust/Cargo 1.93.1；release 模式。根目录 `E:\ProjectSave\ClaudeProject\Long-Decompress\long-compress-assistant`。CPU 使用率、内存峰值、磁盘 I/O 计数未采集，不以此作为资源占用结论。

复跑（PowerShell，应用目录）：先设置 `$env:LONG_NATIVE_ZIP_FAST_PACK='0'`，运行 `node scripts/run-native-zip-baseline.mjs test-results/fast-pack/off.json`；再设置为 `1`，输出到 `on.json`。原始结果在本机 test-results，后续浏览器测试可能清理；本文保存主要结果与限制，样本构建脚本见 [原生基线](NATIVE_ZIP_BASELINE.md)。

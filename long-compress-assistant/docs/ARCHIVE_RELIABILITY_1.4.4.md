## 步骤 2：标准 ZIP 分卷创建（2026-10-13）

新增真正的 `.z01/…/.zip` 创建器，不只是修改数字切卷后缀。按磁盘重定位本地/中央目录偏移，处理 ZIP64、跨磁盘目录、AES 与 ZipCrypto 元数据；载荷分块读取，不把完整包放入内存。每卷范围 64 KiB 至小于 4 GiB；最多 65,536 个物理磁盘，过多时明确要求增大卷大小。请求分卷但不足一卷时输出普通 `.zip`。

普通压缩、转换/改密码/换卷、验证、事务发布和产物列表贯通；`.zip` 是标准卷组的主入口。历史执行配置、待处理草稿、配置组和可移植模板保留卷型。旧记录与旧配置仍使用原来的数字切卷，没有改变默认值。压缩强度 0 修正为真正仅存储；大文件创建按实际大小启用 ZIP64。

### 实际发现与修正

- 新控件挤压分卷标题成竖排，实际截图保留；卷型改为独立行，再查看默认/窄窗口截图。
- 创建之后旧校验器强制 `.001`，导致校验失败；改为与实际解压共用卷组读取层，没有关闭校验。新增直接校验标准卷的回归。
- 历史保存的白名单漏掉新字段，真实完成记录丢失卷型；补齐压缩/转换字段和有效值检查，再用桌面历史、原生配置组、模板导出/导入复核。
- 人工小 ZIP64 夹具最初对所有小/空文件错误使用 `large_file`，原包本身就不能通过独立 7-Zip；改为规范 ZIP64 尾记录，并要求独立检查先验证原包，再验证分卷，未删掉 ZIP64 场景。

## 步骤 3：密码与算法组合兼容（2026-10-13）

- 真实外部 PPMd ZIP 在原实现失败（不支持方法 98）。启用已经使用的 zip 8.6 的 `ppmd` 特性及锁定 ppmd-rust 1.4.0（CC0-1.0 或 MIT-0）；不是新增一种容器，也不改变创建默认方法。依据 [读取库文档](https://docs.rs/zip/8.6.0/zip/)，不把 ZIPX 扩展名等同于所有 WinZip 专有算法支持。
- 检查又发现加密 ZIPX 虽已识别为 ZIP，却被 Universal 路径仅匹配 `.zip` 的判断挡住。密码路径统一按 ZIP 别名/实际签名及逻辑卷组识别；ZIPX、JAR、改为 BIN 的加密 ZIP 回归通过，不改为明文命令行处理。
- 直接调用解压命令选择 RAR 中间卷没有规范化首卷，触发原生失败；后备 7-Zip 的 `-o` 被错误分成两个参数。命令入口现在复用共享卷组，先报缺卷，再定位实际首卷；后备输出参数合并为一个参数。真实 RAR4 新卷/旧 `.rar/.r00` 与 RAR5 固实卷从中间卷回解通过。
- 预检容量比率原来只按部分数字首卷聚合，标准 ZIP 的很小终卷会把正常大文件误判为异常膨胀。现在按共享卷组总量计算；数字 ZIP/ZIPX/TAR、7Z 和标准 ZIP 的边界回归仍保留真正过高比率失败断言，没有取消限制。

## 步骤 4：ZIP 完整条目救援（2026-10-13）

新增 `zip_recovery_reader.rs`：中央目录正常时沿用与实际解压相同的 zip 8.6/卷组读取能力；目录丢失时按本地头声明的可靠范围前进，支持普通 ZIP 和完整数字卷的目录重建。只将大小一致、完整读取且内容校验通过的条目写入新文件。损坏、不支持或不安全条目不发布；未知后续范围明确停止，不在压缩内容中搜索任意 PK 标记猜测边界。已能对目录仍可读的完整普通标准 ZIP 卷组恢复好的条目。

恢复器在发布前完整校验新包，保存到新的无覆盖路径；原包和卷组不改动。结果增加 `partial` 与 `directoryRebuilt`，显示恢复文件/目录、未恢复说明和目录丢失时原包总数未确认。部分恢复结果区使用警示色，顶部提示也改为警告，避免“新包完整”被误认为“原包已全部找回”。未恢复的 CRC 原因使用中文。密码包仍不支持重建；丢失目录且采用数据描述符的边界不猜测，缺卷需先补齐。标准磁盘卷丢失目录本身暂不承诺扫描重建；RAR 冗余恢复和候选格式不加入本版。

### 真实检查与首次失败

- 新增“目录全部丢失、坏一个条目”场景在旧实现失败；最初夹具调用了旧 zip 0.6 不存在的目录 API，纠正夹具后取得真实旧实现失败，再修复产品。原“截断最后 24 字节不可修复”测试截掉的是目录尾而不是文件内容，按新增需求改为完整条目可恢复；另保留真正截断首个载荷不得发布任何文件的检查。
- 启用 PPMd 后旧“未知算法”夹具仍把 Stored 数据伪标成 PPMd（98），不能再代表不支持算法。改为真正未知的方法 60000，原“不报损坏、不报可修复”断言严格保留。
- Rust 诊断/修复 24 项通过：坏 CRC、丢目录、数字小卷、普通标准卷、后续坏 ZIP64 字段、数据描述符、混合明文目录/密码文件、取消、已有目标和无完整文件均覆盖；事务发布 7 项通过。前端文件完整性/命令适配 2 文件 28 项、类型检查、隔离 Release 编译通过。
- `--zip-recovery-only` 真实 Windows WebView2 页面完成“别人发来的包目录丢失而且一个文件坏了—诊断—另存为取消—恢复到新包—查看未恢复原因—独立打开结果”的顺序。独立 7-Zip 原包生成、产物回解比对，确实只有两个完整中文文件，坏条目不存在，原包哈希不变。密码包丢目录不展示可修复，也不生成明文输出。96 MiB 真包在修复处理中实际取消，没有新包或临时文件；已有输出保持不变。
- 首次查看页面发现结果区已经写部分恢复，顶部仍用绿色成功提示，已纠正并重跑、查看默认/窄窗口；未仅以脚本成功判定 UI 完成。一次脚本取到了提示进入动画期间的空可见文本，改为等待原提示可见，保留严格“警告 + 部分恢复”断言。独立 ZIP 的原始名称为本地编码，夹具改用已知文件类型/大小定位破坏字节，不改原始名称；应用恢复后的中文文件内容及名称仍严格比较。

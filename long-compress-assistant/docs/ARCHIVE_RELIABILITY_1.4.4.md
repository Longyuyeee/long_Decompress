## 步骤 2：标准 ZIP 分卷创建（2026-10-13）

新增真正的 `.z01/…/.zip` 创建器，不只是修改数字切卷后缀。按磁盘重定位本地/中央目录偏移，处理 ZIP64、跨磁盘目录、AES 与 ZipCrypto 元数据；载荷分块读取，不把完整包放入内存。每卷范围 64 KiB 至小于 4 GiB；最多 65,536 个物理磁盘，过多时明确要求增大卷大小。请求分卷但不足一卷时输出普通 `.zip`。

普通压缩、转换/改密码/换卷、验证、事务发布和产物列表贯通；`.zip` 是标准卷组的主入口。历史执行配置、待处理草稿、配置组和可移植模板保留卷型。旧记录与旧配置仍使用原来的数字切卷，没有改变默认值。压缩强度 0 修正为真正仅存储；大文件创建按实际大小启用 ZIP64。

## 步骤 3：密码与算法组合兼容（2026-10-13）

- 真实外部 PPMd ZIP 在原实现失败（不支持方法 98）。启用已经使用的 zip 8.6 的 `ppmd` 特性及锁定 ppmd-rust 1.4.0（CC0-1.0 或 MIT-0）；不是新增一种容器，也不改变创建默认方法。依据 [读取库文档](https://docs.rs/zip/8.6.0/zip/)，不把 ZIPX 扩展名等同于所有 WinZip 专有算法支持。
- 检查又发现加密 ZIPX 虽已识别为 ZIP，却被 Universal 路径仅匹配 `.zip` 的判断挡住。密码路径统一按 ZIP 别名/实际签名及逻辑卷组识别；ZIPX、JAR、改为 BIN 的加密 ZIP 回归通过，不改为明文命令行处理。
- 直接调用解压命令选择 RAR 中间卷没有规范化首卷，触发原生失败；后备 7-Zip 的 `-o` 被错误分成两个参数。命令入口现在复用共享卷组，先报缺卷，再定位实际首卷；后备输出参数合并为一个参数。真实 RAR4 新卷/旧 `.rar/.r00` 与 RAR5 固实卷从中间卷回解通过。
- 预检容量比率原来只按部分数字首卷聚合，标准 ZIP 的很小终卷会把正常大文件误判为异常膨胀。现在按共享卷组总量计算；数字 ZIP/ZIPX/TAR、7Z 和标准 ZIP 的边界回归仍保留真正过高比率失败断言，没有取消限制。

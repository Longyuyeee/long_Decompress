# 历史保留与更早记录：场景审计

## 根因与范围

保存任务后曾执行 `DELETE ... LIMIT 500`，不是仅限制界面显示。旧代码连续保存 505 条失败记录、关闭重开数据库后仅剩 500 条，新测试先红，证明了实际数据删除。

按 1.3.5 后续计划拆分交付：本轮停止静默删除并提供稳定分页；全库筛选、全库统计和可配置保留策略仍未实现，不把“加载更多”说成完整历史搜索。

## 实现与策略

- 默认保留到用户明确删除/清空。没有新增自动清理或静默迁移旧记录；单条日志和字段原有上限不变，记录会持续占用本机磁盘。
- 删除保存后的清理 SQL，保存不再出现“写入已成功、旧记录整理失败”这一双步骤歧义；数据库本身的写入失败仍报告失败。
- 新增每页默认 100、最大 500 的读取接口，按 `completed_at DESC, id DESC` 游标取下一页。旧 `list_task_history` 保留最新最多 500 条兼容语义，不再充当历史保留上限。
- 同时刻完成用 ID 稳定排序，删除游标记录仍可继续翻页；新记录出现在游标之前时须刷新，不用偏移量导致重读。它不是事务快照：记录被修改或并发删除时以刷新结果为准。
- 界面显示当前加载数量，明示筛选/指标/趋势仅覆盖已加载数据；无匹配时仍可加载更早页。加载失败保留旧列表与游标，允许重试。
- 请求代次隔离刷新与旧分页；清空完成让在途结果失效，单条删除后过滤在途旧结果。不会重新执行历史任务。

## 验证

- 前端 60 文件、406 项通过，含分页重试、刷新竞态、清空竞态、删除竞态、清空失败及筛选无结果继续加载。
- Rust 库 406 项通过，12 项按原有条件忽略；严格 Clippy 通过。
- SQLite 505 条同时间戳记录，关闭/重开后完整保留；逐页无重复无遗漏，旧原始失败详情不变；插入新记录与删除游标记录后分页仍稳定，页大小有界。
- Windows 桌面历史门禁已通过：真实 ZIP 往返、损坏/完整 ZIP 队列、缺卷阻断与新草稿重试均正常；再通过真实保存接口写入 505 条合成历史、重启、搜索最早名称，第一页无结果后连续加载直至找到并查看原始失败详情。505 条为合成历史夹具，不冒充执行了 505 次解压。证据 `test-results/desktop-e2e/history-paging-result.json`；窄窗口无横向溢出通过，截图已复核。
- 桌面分页脚本首次因末页按钮消失而读到失效元素；改为断言界面实际加载数量每次增加至期望值，不修改产品或放宽分页数据要求。

## 接续边界

旧版已删除的数据无法恢复。降级后旧版保存逻辑可能再次清理 500 条之外记录，降级前应备份数据库。不承诺无限数据规模下的界面性能；已加载数据仍累积在内存中。下一轮应优先后端搜索/筛选、全库聚合与页面容量控制，然后设计可配置保留策略和持久待保存队列。

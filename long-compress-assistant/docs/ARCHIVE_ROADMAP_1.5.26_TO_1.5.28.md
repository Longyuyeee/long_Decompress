# 归档与使用体验升级路线 v1.5.26 至 v1.5.28

2026-10-20，接续已按范围完成的 [v1.5.23～v1.5.25](ARCHIVE_ROADMAP_1.5.23_TO_1.5.25.md)。v1.5.26 已按范围完成并封板，见[实施](ZPAQ_VOLUMES_1.5.26.md)与[封板](ZPAQ_VOLUMES_FREEZE_1.5.26.md)；v1.5.27 已完成并[封板](WIM_VOLUMES_FREEZE_1.5.27.md)；v1.5.28 已开始，见[实施](EXPLORER_CHECKSUMS_1.5.28.md)，尚未封板。

继续增加实际可用的格式、密码和分卷组合，并把创建、查看、提取、转换、失败处理和结果接通。每版独立收口；保留单条展开、多选弹窗、自然继承、左右等宽和窄窗滚动。

| --- | --- | --- |
| 1 · v1.5.26：ZPAQ 数字分卷 · 已完成 | 普通与密码大包可以指定大小拆分，从任意成员进入后续处理 | 原生密码、明确成员跨卷读取、创建、浏览/有界预览、检查、所选/整包、密码 ZIP 双向转换、补卷新任务和整组结果清单已接通，不先拼接完整临时包。通过七项不同 Rust、六项不同前端、四条公共原生与六条实际 UI 链；不含原生追加多部分、增量/历史或缺卷部分抢救。 |

## 代码依据与避免重复（开工前快照，ZPAQ/WIM 已由 v1.5.26/v1.5.27 接续）

- `compressionFormat.ts` / `compression_format.rs` 中 ZPAQ 和 WIM 的 `supportsSplit` 均为 false。ZPAQ 原生密码创建已经存在，v1.5.26 不是重新开发 ZPAQ 编码或密码算法。通用切卷阶段已经存在，但外部引擎读取的归组、临时源生命周期和失败链仍要接通。
- WIM 创建明确拒绝分卷和原生密码；后续需实现真实输入路由及相应用户链，不能只改前端列表。`.swm` 原生拆分继续单独评估。
- 资源管理器已有打包、解压、浏览和转换入口，`context_menu.rs` 尚无摘要计算/清单核对入口；v1.5.28 复用 v1.5.25，不重写哈希服务。

ALZ Obfuscated Deflate 方法 3、EGG 加密固实仍需可靠原厂正面原件和实现依据；ZPAQ 增量与历史恢复继续独立评估。没有正面依据时先写清可行性和边界，不把研究待办按版号自动标成完成。

每版只检查新增或受影响的真实链路，已通过的旧格式矩阵、基础密码/哈希算法及真实 VHD 盘满直接复用。完成后同步两份 README、中文 Release 和交接，走仓库必需 Windows package、普通受保护合入与正式发布。本轮 v1.5.26 与 v1.5.27 已完成，下一步按既定顺序推进 v1.5.28 资源管理器校验入口，不重复规划或提前宣称支持。

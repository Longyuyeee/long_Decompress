# 归档与使用体验升级路线 v1.5.26 至 v1.5.28

2026-10-20，接续已按范围完成的 [v1.5.23～v1.5.25](ARCHIVE_ROADMAP_1.5.23_TO_1.5.25.md)。以下均为计划，尚未开工；不能据此宣称已经支持。

继续增加实际可用的格式、密码和分卷组合，并把创建、查看、提取、转换、失败处理和结果接通。每版独立收口；保留单条展开、多选弹窗、自然继承、左右等宽和窄窗滚动。

| 顺序与版本 | 用户收益 | 实现范围与收口边界 |
| --- | --- | --- |
| 1 · v1.5.26：ZPAQ 数字分卷 | 已能创建密码 ZPAQ，但大包分享时不能按指定大小拆分，也不能从中间成员顺手打开 | 先确认普通与原生密码 ZPAQ 的数字切片读取可行性，再接创建、任意成员归组、浏览/有界预览、检查、所选/整包提取、密码 ZIP 互转和补卷新任务；结果带完整成员，沿 v1.5.25 生成整组清单。密码继续使用现有 ZPAQ 原生方式。数字切片不是 ZPAQ 原生多卷，也不包含增量更新/历史恢复；如需完整临时归档，明确空间、进度和取消，不能只开放格式开关。 |
| 2 · v1.5.27：WIM 数字分卷 | WIM 已有创建和读取，大镜像分享仍缺同样的拆卷与后续处理 | 先以独立 WIM 原件确认跨数字切片读取和内容/镜像选择语义，再贯通创建、任意成员浏览/预览、完整检查、提取、转换、缺卷原因、补齐后的新任务和结果清单。拟支持 `.wim.001` 数字切片，不称为 `.swm` 原生拆分镜像，不承诺系统部署兼容；普通 WIM 没有原生密码，沿既有明确替代流程，不伪造 WIM 密码能力。 |
| 3 · v1.5.28：资源管理器校验入口 | 用户拿到或准备分享一组文件，可以从 Windows 右键直接进入计算/核对，少找一遍文件 | 在现有经典右键菜单加入主动生成清单；对 `.sfv/.md5/.sha256` 提供核对入口。复用当前整组产物、相对路径、进度/停止/接续和逐项原因；单实例与多选传入不得丢文件或重复任务，打开入口不自动全文件重算。保持传统菜单、签名条件和现有新式菜单边界，不把菜单接入当作新格式。 |

## 代码依据与避免重复

- `compressionFormat.ts` / `compression_format.rs` 中 ZPAQ 和 WIM 的 `supportsSplit` 均为 false。ZPAQ 原生密码创建已经存在，v1.5.26 不是重新开发 ZPAQ 编码或密码算法。通用切卷阶段已经存在，但外部引擎读取的归组、临时源生命周期和失败链仍要接通。
- WIM 创建明确拒绝分卷和原生密码；后续需实现真实输入路由及相应用户链，不能只改前端列表。`.swm` 原生拆分继续单独评估。
- 资源管理器已有打包、解压、浏览和转换入口，`context_menu.rs` 尚无摘要计算/清单核对入口；v1.5.28 复用 v1.5.25，不重写哈希服务。

ALZ Obfuscated Deflate 方法 3、EGG 加密固实仍需可靠原厂正面原件和实现依据；ZPAQ 增量与历史恢复继续独立评估。没有正面依据时先写清可行性和边界，不把研究待办按版号自动标成完成。

每版只检查新增或受影响的真实链路，已通过的旧格式矩阵、基础密码/哈希算法及真实 VHD 盘满直接复用。完成后同步两份 README、中文 Release 和交接，走仓库必需 Windows package、普通受保护合入与正式发布。本轮仅写计划，未开始 v1.5.26 运行时代码。

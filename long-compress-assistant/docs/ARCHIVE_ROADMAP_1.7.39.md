# v1.7.39 规划 · ZIPX（XZ）多流与合法填充兼容

状态：仅规划。v1.7.38 仅支持单 XZ 流的未知边界恢复；当前正常 ZIPX 读取器也会拒绝流后的填充或后续流，本期先补正常读取，再接恢复，不增加格式数量。

可行性探测：真实 7-Zip 原件的 XZ 压缩流后接八字节零填充，或拼接另一个实际非空流，并修正 ZIP 累计 CRC、尺寸及目录；独立 7-Zip 对两份单成员结构控制均以退出码 0 读回完整内容。多流展开 3600000 字节，填充控制展开 200000 字节。见[证据](evidence/zip-xz-rescue-1.7.38/next-xz-probe.json)。这些是明确标记的派生控制，尚未实现本软件兼容，不代表所有 ZIPX 专有算法。

1. 先接通正常 ZIPX 浏览、校验、按需/完整解压中的普通 XZ 多流和合法零填充，仍验证目录精确展开量、所有流的块校验/索引/尾部、ZIP CRC 和压缩范围，拒绝任意尾随垃圾或未完整的后续流。
2. 再接未知尺寸丢目录恢复：按真实流结束与累计消费量/展开量/CRC，在准确位置优先匹配描述符；合法零填充只按四字节对齐连续确认，限制流数/填充量/内存，不扫描正文标记。
3. 覆盖两个非空流、空流组合、填充前后、普通/ZIP64、有/无签名、完整数字切片及来源日期。后流损坏或范围矛盾时不输出半个文件，只另存之前完整成员，原清单仍未知。零字节来源的外部工具差异继续如实记录。
4. 沿原暂存、新包验证、结果/历史、失败重试和取消入口，保留单条展开、多选弹窗及等宽双栏。只检查新增和受影响流程。

完成标准：声明范围内正常读取与恢复均能独立读回准确内容/日期，坏后流和非零垃圾仍被拒绝，原件不变。特殊滤镜/字典与密码未知边界先按独立来源另期确认；Zstandard 可跳过帧/外部字典、历史 method 20、跨缺口扫描、恢复记录、ALZ / EGG 和更宽日期/NTFS 亚秒等缺口保留。

# 特殊压缩导航纠偏审计

> 日期：2026-09-01  
> 基线：公开稳定版 `v1.1.17`，主线提交 `7df9bd4`  
> 目标：`v1.1.18`

## 1. 决策与原始需求对账

2026-08-26 的最初实施文档要求左侧导航不变，并在压缩中心内提供归档、图片、视频、PDF 四种模式。2026-09-01 产品负责人明确批准替换这一界面要求：压缩中心仅处理归档压缩；左侧新增一个“特殊压缩”入口，页面内再选择图片、视频或 PDF。

本次只改变入口和页面归属。最初需求中更关键的架构约束继续成立：四类工作负载仍归属统一 `compression` 顶层任务，复用任务状态、进度、取消、历史、容量预检、暂存、验证、原子发布和清理语义，不创建媒体旁路系统。

## 2. 实际代码基线

- `CompressionView.vue` 原先同时导入三个媒体工作区，并维护 `archive | image | video | pdf` 四模式状态。
- 三种媒体能力已经分别封装为 `ImageCompressionWorkspace.vue`、`VideoCompressionWorkspace.vue` 和 `PdfCompressionWorkspace.vue`，迁移页面容器无需搬动执行引擎。
- 路由和左侧导航原先只有 `/compress` / `Compress`，桌面及安装态媒体门禁也先进入压缩中心再切模式。

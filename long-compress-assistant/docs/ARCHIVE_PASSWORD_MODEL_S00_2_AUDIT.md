# S-00.2 归档密码领域模型收口审计（2026-08-27）

## 1. 开发目标

密码保险箱保存的是压缩文件的解压密码，不是网站账号凭据。本节点将活动界面和 Tauri CRUD 接口收敛到归档密码语义，同时保证旧版本已经写入的 `username`、`url`、`expires_at`、传统密码强度和自定义登录字段可继续读取，且用户编辑名称、密码或备注时不会破坏这些旧数据。

## 2. 实现边界

- WebView 的活动模型只包含：名称、密码正文、备注、标签、归档分类、收藏、创建/更新/最近调用时间、调用次数和按日本地使用历史；
- 新增、编辑接口只接受归档密码字段，不再接受网站账号、网址、过期时间、强度评分或自定义登录字段；
- Rust 在更新时先读取原条目，再只覆盖归档密码字段，生命周期统计和旧兼容字段由后端保留；
- 旧网站分类在响应边界归一为 `General / Work / Media / Documents / Other`，磁盘兼容枚举和导入导出格式暂不删除；
- 前端搜索只使用名称、备注和标签；隐藏的旧账号或网址不会继续影响搜索结果；
- 新增/编辑不再计算传统网站密码强度，统计仍以真实归档解锁调用、归档线索和使用趋势为准；
- 手动密码解压成功后的次数更新统一走 Rust 原子使用事件，不再通过“编辑整条密码记录”伪造统计字段。

传统密码审计、生成器和旧密码服务仍保留为未注册兼容代码，本节点没有把它们重新暴露给活动界面。后续清理只能在导入导出兼容矩阵完成后进行。

## 5. 需求对齐与下一步

本节点关闭了 S-00 审计中的“传统网站密码模型继续扩散”问题，没有改变密码自动尝试、密码复制、统计趋势或旧数据格式，也没有提前进入图片、视频、PDF 编码功能。

S-00 下一步为 S-00.3：删除或明确废弃 `task.ts` 的历史任务占位接口，并检查调用方是否全部使用真实历史 store。完成后继续统一格式支持等级和归档未参与构建的旧工程；S-00 全部通过前，媒体压缩 B-00 保持冻结。

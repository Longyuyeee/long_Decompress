# 归档浏览门禁夹具生命周期审计（2026-09-03）

## 结论

`archive-browser-only` 的临时 ZIP 丢失不是产品错误，而是门禁错误地复用了“一键解压输入”作为后续诊断/修复输入。真实桌面加载用户当前“解压后移入系统回收站”偏好后，一键解压会按产品语义回收该 ZIP，后续 `fileSha256` 因源文件不存在而报 `ENOENT`。

门禁现于真实压缩完成、尚未启动一键解压时复制一份独立 `roundtrip-payload-diagnostic-source.zip`。一键解压继续使用原始输出并尊重用户偏好；健康诊断、非破坏修复和可靠容量阻断只使用诊断副本。测试不点击偏好开关、不写回设置，也不要求用户关闭合法功能。

## 审计边界

- 产品压缩、解压、回收源包、诊断、修复和资源预检代码均未修改。
- 诊断副本先记录 SHA-256；修复后再次计算并要求完全一致，继续证明修复不会改写源归档。
- 媒体架构门禁锁定必须先 `copyFileSync(archivePath, diagnosticArchivePath)`，并从独立路径计算哈希，防止恢复对用户偏好的隐含依赖。
- Node 22.12 可移植 Zstandard frame 在同一完整门禁中真实到达后端能力驱动的右键菜单，不再只有独立 7-Zip 格式校验。

## 验证结果

- `npm.cmd run test:e2e:desktop:resource-preflight`：真实 Windows Tauri/WebView2 通过。
- 首轮完整归档浏览复验越过原 `ENOENT`，完成 Zstandard 能力菜单、180,000 条目 TAR 取消、长路径 ZIP、加密 7Z 和内部预览后，按设计因本机尚未准备固定加密 RAR 夹具而停止；未冒充通过。
- `npm.cmd run test:fixtures:archives`：五项固定外部夹具全部下载并按仓库清单验证。
- `npm.cmd run test:e2e:desktop:archive-browser`：在 Node 22.12.0 下完整通过；包含真实文件管理、Zstandard 能力来源、长路径 ZIP、加密 7Z、固定加密 RAR、选择性解压、文本预览、默认应用打开、非破坏修复与容量阻断。
- 媒体架构门禁已新增独立诊断副本的静态契约；该新增断言在用户要求暂停开发后未再单独复跑，接续时应首先补跑。

所有运行夹具、截图和结果位于被忽略的 `test-results/`，不提交机器路径或二进制。可移植证据为测试代码、固定夹具清单和本审计。

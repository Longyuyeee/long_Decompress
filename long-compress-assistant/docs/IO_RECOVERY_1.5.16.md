2026-10-19 从已正式发布的 v1.5.15（7be7a07）接续现行十目标的最后一项，分支 codex/v1.5.16-io-recovery。用户授权按版本推进至可发版，更新 README、Release 和开发文档，复用已通过且未受影响检查。

## 本版目标

- 处理中盘满、访问受阻、目标占用和源卷变化保留真正原因，不误入密码流程。
- 已有事务式输出、失败重建与历史是基础能力；只修具体缺口，不重新计算新增。
- 原记录保留，恢复空间/来源/占用条件后建立新任务。清楚说明未发布结果，回滚不完整仍先保留恢复目录。
- 单条展开、多选弹窗、自然配置继承、左右等宽及窄窗滚动保持。

## 开工审计与顺序

现有来源快照只覆盖归一后的一个入口文件，处理中其他分卷被替换或撤回不能从该快照识别。部分 7Z 读写错误转成字符串，公共盘满归一丢失原始细节；任务/历史还没有处理中 I/O 的明确分类及恢复指引。上述是待复现线索，不提前宣称已修复。

1. 固定定向复现，补真实卷组快照及 typed I/O 传播。
2. 接通错误到任务、历史、转换和用户恢复指引；保留发布阶段与回滚状态的优先级。
3. 对改动执行定向回归；本机做真实目标占用、处理中源卷撤回/替换、恢复来源后新任务及常用/窄窗实看。
4. 实际盘满限定独立小测试盘；已实现隔离 VHD 补充测试，但因 CI 工作流权限不足尚未执行。此项不计通过，不触碰个人盘符，不用注入异常冒充真实盘满。
5. 收口版本身份、README、中文 Release 与证据；必需候选构建通过后合入并正式发布。

以上是开工时的审计与计划；最终完成范围和未执行项见下方收口记录。ALZ 方法 3 未实现、EGG 加密固实未验证等边界保持。十目标完成后再按真实格式/方法、密码分卷和失败接续继续规划，不能把未完成组合抹掉。

本机真实 Windows 独占句柄已验证占用错误可保留；真实盘满计划使用单独手动 CI 路径和有标签、容量边界的 256 MiB VHD（未执行），不改本机盘符。测试中的压力文件逐块实际写入，只填自有虚拟盘。前端恢复入口沿用既有单条/批量结构。

## 最终实现与检查收口

typed I/O 从 ZIP/7Z、压缩、解压与冲突提交保留到 IPC、任务、诊断和历史；盘满、占用、权限、一般读写分别说明，保留实际路径与底层上下文。已确认的来源/发布/回滚原因优先，不让碰巧出现的密码文字覆盖它们。UnRAR 的不透明文件系统代码仅报一般读写，不凭代码猜盘满。

来源快照覆盖整个实际卷组，对成员存在性、大小、修改/创建时间及成员变化复核，包含处理中提前返回的失败路径。它是元数据快照，不能识别大小及时间等元数据完全相同的内容替换，也不增加每任务全包哈希。恢复条件后通过既有单条/批量纠正流程创建新任务，旧失败记录不改写。

真实目标占用检查又发现：冲突提交失败后旧暂存被留在 pending map，但界面已经转为失败新任务，无法继续该旧提交。本版增加确定 I/O 终止后的未发布暂存清理；清理失败保留路径警告和原原因，回滚不完整时仍保留恢复目录。红灯证据见 evidence/io-1.5.16/retained-staging-red.json；新增清理检查和原回滚检查通过，未把保留恢复文件的情形一并清除。

[检查清单](evidence/io-1.5.16/checks.json)统计 19 项不同 Rust（8 新增、11 相关既有）及六文件 157 项前端（86 + 53 + 18），重复运行的回滚项只计一次。相关测试发生过旧枚举断言失败，已改为检查原始 OS cause，修正记录单列；零匹配过滤器不计通过。前端类型/E2E 打包、Shell 版本 DLL 构建通过，版本统一 1.5.16；正常生产由必需候选构建提供，不为无变化再本地重打一包。

# v1.7.20 · TAR.LZO 所选链接内容提取封板

日期：2026-10-28。

## 实现与用户行为

完整 TAR.LZO 的所选提取先读取一次可确认的条目计划，再按来源顺序复制所选内容。复用已有 TAR.LZO 恢复解析及复制机制，接通普通头、局部 PAX linkpath 与 GNU L/K 的已确认前置普通、空、稀疏目标；原目标无需被选中。同源多份内容使用本次私有暂存中的已核对副本，不为每个别名重新解码整包，也不借用目标目录现有文件。所有输出均为独立文件。

选择使用归档原始条目名，输出采用已修复的安全名称；筛选只在计划阶段应用一次，避免修复名称后把已选条目过滤掉。所有请求路径均需存在，缺失选择不静默丢弃或扩大。目录联选、空目录、平铺、筛选和同名处理复用原发布事务；显示数据进度按所选逻辑字节，保留稀疏空洞和每份副本自己的修改时间。目录时间在子项全部提交后恢复，冲突等待阶段保留该计划与时间。普通选择不满足本期完整可确认范围时保留旧路线，所选链接不能降级为空文件。

暂停、取消、来源前后检查与暂存清理沿原任务控制；复制回调可返回 I/O 错误，磁盘空间和资源额度沿原检查。目录时间无法恢复使用原日志反馈。完整包之外仍引导补卷或部分取回，不把部分成功当完整成功。

原双栏菜单接通提取到另一栏和指定目录，提取后刷新对应目标栏；不新建常驻配置区域。短标记、悬停、来源详情与文本/图片预览保留，完整默认打开及嵌套物化继续提示先提取。历史重试和重启草稿保存 TAR.LZO 选择范围、目录方式和同名策略；原生历史持久化显式保留这些字段，避免重试整包解压。单条展开、多选弹窗及左右等宽布局保持。

## 原件与检查

复用 v1.7.17、v1.7.18 的真实 GNU/PAX 稀疏链接原件及 v1.7.19 两份图文原件。没有把构造样本当成新生产者支持。

- 新原生 10 项通过：四份原件的所选真实发布；原目标与多别名独立；目录联选、筛选、平铺和同名确认；暂停取消及受控错误 112；来源变化、尾部不完整和补卷；修复名称与不存在选择；普通文件回退；复制后来源变化与关闭时间保留；单别名 UI 原生收据；历史范围持久化。
- 相关旧原生 3 项通过：缺尾硬链接部分取回、冲突变化后保留暂存重新确认、显式目录时间在子项后恢复。
- Python 独立读取原 TAR 目标正文，核对 5 个实际目标目录的 20 个文件：完整 SHA、精确目录树、每份条目自己的时间、Windows 稀疏属性与实际分配，以及文件链接数为 1。对 GNU sparse 占位名称按生产者确认的目标身份取正文。
- 前端 10 项通过：本期菜单、别名精确选择、指定目录与目录联选，原列表与预览版本绑定；历史序列化、待执行重试和重启草稿保留范围与输出策略。
- 后台真实 Vue/CSS 原生值回放 3 组通过：1200×760 和 900×600 等宽双栏无横向溢出；单别名命令与实际提交收据对应、另一栏精确刷新及历史范围；文字预览与换行来源详情。六张截图逐张查看。首次冷启动页面超时，开发服务器就绪后重试同一未完成场景通过，没有重复执行已通过的原生/前端矩阵。
- 类型检查与 Vite 生产构建、Shell DLL 及八处版本身份通过。正式 NSIS、签名更新包和清单由对应提交 CI/Release 生成。

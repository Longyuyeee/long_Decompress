# v1.4.10 ZIP 兼容与选择性解压实施审计

## 范围与基线

2026-10-16，接续正式 v1.4.9 / `083082e`，分支 `codex/archive-compatibility-1-4-10`。用户批准从 [后续路线](ARCHIVE_FORMAT_AND_WORKFLOW_ROADMAP_2026-10-16.md)按顺序开发并在本版封板后发布。

本版聚焦选择性解压的密码/容量/读取一致性，以及加密 Zstandard、真实 ZIP64 密码与卷型的特定兼容缺口。SFX、LZIP、任意缺卷救援和新压缩方法创建留后续版本。

## 初始审计

- `CompressionService::extract` 在实际读取前按整个归档判断是否需要密码，手动及自动凭据验证也未带本次条目范围。
- 原生 ZIP 读取的密码预检查遍历全部条目；实际复制阶段另有文件筛选。仅选公开文件仍可能被未选加密条目挡住，需要实际复现。
- 转换当前完整落地临时内容后重新压缩，已有空间检查；读写优化属于 v1.4.15，不在本版扩展。
- 前端公开格式入口没有 LZIP/ZPAQ；内置 7-Zip 26.04 也无这两种处理器。不能只增加后缀。

## 步骤记录

1. 路线与接续入口已整理并推送 `a38e6a5`。
2. 两个真实读取回归在修改前均失败：只选公开说明报“需要输入密码”，只选甲方文件夹报“提供的密码不正确”。现共用 `ZipSelection`，密码判断、候选验证、容量与实际复制按同一原始路径范围；中文目录、文件筛选与选择交集、AES/ZipCrypto 以及选中后扁平化均检查。全包验证仍不得把单个条目密码当成整包凭据。
3. ZIP 普通、加密和数字/标准卷共用原生读取与选项，不再经不带选择范围的通用提取接口。目录浏览不为可直接读取的 ZIP 中央目录先尝试整包密码；预览、打开和嵌套包的自动凭据解析带所选条目。
4. 不支持的所选方法在密码尝试前明确说明；未选未知方法不会阻挡公开文件。初始测试误改 AES 外层方法，而实际方法来自 AES 扩展字段，按格式修正夹具，保留未知方法拒绝与原因断言。
5. 定向后端检查：选择相关 9 项（含 2 个原生 ZIP 用例）、原生 ZIP/并行 12 项、通用引擎 9 项、压缩服务 41 项通过，共 69 个不同用例。其中新增 10 项；不累计重复执行。与本次无关的显式性能、RAR 工具和系统回收站用例保持 ignored，不宣称已运行。七种方法的桌面回解和本版桌面用户链仍待执行。
6. 广一些的服务回归发现旧测试仍把 RAR/TAR 当作不可分卷，与 v1.4.3 已交付能力及未改动的格式表矛盾。拒绝夹具改为确实不支持所请求模式的 WIM/LZMA；不修改产品规则或移除拒绝断言。首次编译的内部调用参数、测试 Debug 派生遗漏均据编译错误补齐。

## 桌面兼容与页面复核

- 最终 Windows Release Tauri 程序完整用户链通过：独立 7-Zip 分别创建 AES/ZipCrypto 的公开文件、甲方密码、乙方不同密码混合包；从文件浏览器实际选择导入、搜索、勾选、公开文本预览、无密码提取、错误密码失败、改正密码继续、保险箱匹配及数字卷提取。未注入任务完成状态，原失败任务保留，未选文件没有发布，原包哈希不变。
- Zstandard ZIP 的 AES/ZipCrypto × 单包/数字卷/标准卷 **6 组**均由 `zip-rs 8.6` 夹具写入器生成，经独立 7-Zip 校验，再由实际应用完整解压，逐字节比较载荷。不是外部工具创建的加密 Zstandard 样本，也不是新增创建方法。
- 真实 **4,294,979,641 字节**文件（4 GiB + 12345）及其后的说明文件，经独立 7-Zip Copy ZIP 创建为 AES/ZipCrypto 各一组数字分卷；两组均独立全量校验、应用完整解压及大文件 SHA-256/尾随条目对照通过，不用小文件伪 ZIP64 头代替。最终程序再次执行两组检查。
- 统一 ZIP 读取时审计到原通用分卷路径还可读取旧 Shrink/Implode，原生依赖未打开相应功能。启用已有 `zip 8.6` 的 `legacy-zip`（新增锁定 `bitstream-io 4.9.0`、`core2 0.4.0`），接通 Shrink/Reduce/Implode。固定上游提交 `fd7c9b1ec5c06107ffbce435a30478d8ba19a41c` 的真实样本覆盖方法 **1/5/6**：Shrink/Implode 与独立 7-Zip 提取结果逐字节相同；Reduce factor 4 与上游单独公布的原始 `first.txt` 完全相同。7-Zip 26.04 对 Reduce 报不支持，本机旧 Bandizip 7.38 Beta 报 CRC 错误，均不算独立工具通过；不因此更换样本或放松内容断言。
- 最终程序对已有 7 方法 × 3 加密状态的 ZIP/ZIPX、数字卷与错密码拒绝重新执行，原有 RAR4/5、7Z 密码卷型定向路径也通过。此为受读取路由影响的兼容回归，不扩展 RAR4 恢复承诺。[方法结果](evidence/zip-selection-1.4.10/final/zip-codecs.json)及同目录兼容结果保留。

最终完整桌面结果包含 **13 组场景记录**及 **11 张截图**，见 [结果 JSON](evidence/zip-selection-1.4.10/final/zip-selection-1410-results.json)。最终测试程序 SHA-256 为 `7b178baac409d0f185a9bb6da7d02a94cd84f8ce5d49bf9fb129ce6a8c982fef`。早一轮、尚未修标题布局的结果只作 [历史快照](evidence/zip-selection-1.4.10/pre-ui-review/results.json)，不累计用例数量。

实际查看 1100×700、760×520 页面及滚动到页脚的画面。发现原“返回双栏文件浏览器”绝对定位按钮滚动后压住搜索框，改为标题操作区具名插槽，并复核窄窗口不遮挡搜索、可滚动到并命中解压按钮。前端本版相关 **20 项**通过（含新增标题插槽回归）；后端最新仍为 **69 个不同用例**。普通前端构建、测试 Release 编译、版本/Shell 资源身份检查通过。computer-use 抓图在本机高 DPI 下出现空白/局部画面，改用实际 WebView 全幅截图查看，不将不完整抓图当作页面通过证据。

### 实际失败与纠正

初次脚本误以为 Ctrl+B 直接进入压缩包页面，实际先进入双栏文件浏览器，按用户入口补上“打开压缩包”操作。另一次错误要求窄窗口页脚始终在视口内；原设计允许纵向滚动，改为真实滚动并检查按钮可达，没有改产品布局迎合该断言。真正发现的返回按钮遮挡另行修正并保留检查。

固定旧 ZIP 样本的首次 Node 网络下载发生 `ECONNRESET`，未记为应用失败。使用同一固定上游 URL 获取本地副本，脚本按 SHA-256 校验，可通过 `LONG_ZIP1410_LEGACY_FIXTURES` 指定缓存；内容与原始字节断言保持不变。

### 重现入口

先设置 `VITE_DESKTOP_E2E=1` 执行 `npm run build`，再 `cargo build --manifest-path src-tauri/Cargo.toml --release --features custom-protocol,desktop-e2e`。设置 `LONG_ZIP1410_REAL_ZIP64=1` 后执行 `node scripts/test-tauri-desktop.mjs --zip-selection-only`；该开关真实读取和写入大文件，非默认小夹具。`--password-compatibility-only` 执行已有方法回归。原始载荷及工具均在隔离测试目录，不改用户安装和个人记录。普通构建不启用这些测试入口。

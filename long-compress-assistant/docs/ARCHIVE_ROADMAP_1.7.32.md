# v1.7.32 规划 · ZIP / ZIPX UTC 修改时间写入

状态：已完成并封板；接续 v1.7.31 已编码 UTC 日期的读取与恢复。见[封板记录](ZIP_UTC_WRITE_FREEZE_1.7.32.md)及[发布说明](RELEASE_NOTES_1.7.32.md)。正式产物由本版 CI/Release 接续。

1. 在原生 ZIP / ZIPX 的共享源时间入口，对可明确表达的整数秒写入 Info-ZIP UT 修改时间，并让本地头与中央目录保持一致。保留既有 DOS 本地日期，供旧工具兼容；不改变内容压缩方法或密码校验使用的 DOS 字段。
2. 先沿 v1.7.31 可确认的 1970 至 2038 范围建立读写闭环，保存奇数秒、明确的非空/空目录日期；超界继续按原 DOS 策略并给出真实提示，不在有符号/无符号高位值间推断。UTC 扩展不编码亚秒。
3. 覆盖 ZIP / ZIPX、密码及标准/数字分卷的代表创建与转换流程，新包经验证后发布；用户沿原配置与结果入口操作。创建方法未变化时不重跑整套算法矩阵。

完成标准：声明范围内的实际新包经本软件及独立工具读回，内容、路径和 UTC 整数秒日期一致，原件保持；既有无 UT 包和旧工具兼容日期继续可用。界面、单条展开、多选弹窗及等宽双栏不变。

NTFS 亚秒/更宽日期范围、其他时间与权限元数据、重复读取成本继续分期。完成 UTC 读写闭环后，再按反馈推进算法/格式、密码/分卷和容错主线；ALZ / EGG 外部原件与原生密码/块分段等缺口仍保持未完成。

## 3. 视频代码边界核对

当前主分支存在且仅存在以下产品视频能力：

- `preflight_video_engine` 是唯一注册的 Tauri 视频命令；
- 后端 `validate_video_engine` 对 8 个资源先做普通文件、字节数和 SHA-256 校验，再直接以参数数组运行 `ffmpeg.exe` / `ffprobe.exe`；
- 固定能力为 FFmpeg 9.0.1、LGPL-only、`h264_mf`、内置 AAC、`hw_encoding=false` 和五个必需过滤器；
- 缺失资源和被改写的 ffmpeg 会在进程启动前拒绝；
- Tauri/NSIS 资源清单包含两套二进制、两份来源/配置文档和四份 FFmpeg/MinGW/GCC 法律文件，总展开 24,631,334 B。

当前明确不存在：

- 前端对 `preflight_video_engine` 的调用封装；
- ffprobe 输入分析模型、三档配置和流保留策略；
- `compress_video` 生产服务或命令；
- progress pipe、Windows Job Object、取消、暂存/发布事务和输出复验；
- 可用视频工作区。当前 UI 仍展示“节点 C”计划态，不创建任务。

因此 C-01.2.1 是“运行时准入”，不能对外表述为“视频压缩完成”或“v1.1.15 已支持视频压缩”。

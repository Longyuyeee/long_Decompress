# 后续归档升级路线 v1.5.17 至 v1.5.19

2026-10-19，从正式 v1.5.16 接续。v1.5.17、v1.5.18 已正式发布；v1.5.19 已功能封板，见[实施](CHECKSUM_DETAILS_1.5.19.md)和[封板](CHECKSUM_DETAILS_FREEZE_1.5.19.md)。三项目标按本文范围完成，后续[v1.5.20～v1.5.22](ARCHIVE_ROADMAP_1.5.20_TO_1.5.22.md)已规划，尚未实施。继续沿用户既定方向：扩展真实格式/方法、密码与分卷组合，解决从导入到结果的具体问题。上一轮十目标按调整范围完成，不等于 ALZ 方法 3、EGG 加密固实等原始缺口已经完成。

## 顺序与用户收益

| 版本 | 用户遇到的问题 | 开发范围 | 收口结果 |
| --- | --- | --- | --- |
| v1.5.17 | 某些 GZIP/BZIP2/XZ 文件含多个连续压缩流，用户需要确认最后一段也被完整读取 | 先用原工具生成多流原件，验证当前首流解码行为；统一普通流、TAR 包装流的浏览/预览、检查、整包/所选解压和转换。单个 TAR 数据流跨压缩流边界与多个完整 TAR 直接拼接须分开处理，不默认将任意拼接都解释为一个包 | 跨流的末尾文件内容正确，后段截断/校验失败不报全成功；数字分卷任意成员、补卷后新任务回归，常用/窄窗页面清楚 |
| v1.5.18 | 自有 AES 加密容器不能像已有普通 TAR/压缩流一样拆成可搬运的小卷 | 审计现有自有 .aes 容器；接通完整容器的数字分卷创建、卷组读取、密码、转换和结果入口。沿用既有加密格式，不设计新密码算法，不把自有容器称为通用 TAR 标准密码包 | 原工具/自有格式边界明确；正确密码与整组认证完成后才能发布，缺首中尾卷/错密/篡改分别提示，失败可修正后建立新任务 |
| v1.5.19 | 导入校验清单后只看到总失败提示，不知道哪一卷要补回或重新下载 | 在现有 SFV/MD5/SHA256 校验之上返回逐文件状态：匹配、缺失、内容不符、无法读取；展示明确路径，复制待补文件列表，按用户操作重查需要的项目并接续已有任务纠正入口 | 已匹配卷不无故重查，不能因只复查一项就把未检查项目当通过；缺失/占用/损坏原因清楚，不自动覆盖旧任务或后台重复全包哈希 |

## 当前接续

v1.5.17 已完成八组真实原件、多段共享解码、TAR 跨流末尾读取、普通流浏览/预览、数字卷任意成员预览归一、后段损坏提示及原任务纠正/密码 ZIP 转换。52 Rust、16 前端、25 原生程序记录、五条实际 UI 和十张实看页面完成，证据复用及程序身份见[本版记录](MULTISTREAM_1.5.17.md)。多个完整 TAR 直接拼接明确报不支持，不静默报全部完成。

v1.5.17 已正式发布，PR #212 合入，标签 6f41d9e，四附件和中文说明已核对。v1.5.18 已完成九种创建、整组认证读取、浏览/预览、所选/整包、转换、结果与补卷新任务；修复 TAR.AES 多源目录。22 Rust、805 前端单元、24 原生记录、五条 UI 与十张实看页面及独立回解通过，见[实施](AES_VOLUMES_1.5.18.md)与[封板](AES_VOLUMES_FREEZE_1.5.18.md)。v1.5.19 已完成逐文件原因、待补列表、按需复查及清单变化作废旧观察，原诊断和失败新任务接续通过。下一阶段见新路线，已有基础哈希不重复开发。

## 开工代码依据与避免重复

- v1.5.16 时，compression_format.rs 已允许 TAR、TAR.GZ/BZ2/XZ/ZST 等普通格式分卷；compression_service.rs 已有 generic_split 创建。is_tar_wrapped_archive 已移除数字后缀，native_extraction/tar.rs、archive_browser.rs、archive_preview.rs 已用 ZipInputReader 连续读数字卷。这些属于已有能力，v1.5.17 只补具体多流缺口及必要回归。
- 上述普通流/TAR 入口使用 GzDecoder、BzDecoder 和 XzDecoder 的常规构造；是否只读首流、是否导致末段遗漏，须先由真原件确认。Zstandard 的多帧行为分开回归，不能不经复现就全量重写解码器。后续原件可由已配置的原工具和独立回解核对，不用改头小包伪造格式支持。
- 自有 tar.aes、tar.gz.aes 等和单流 .aes 已有单文件密码读取，能力表在 v1.5.18 开工时不开放分卷，已由该版接通。开工先确认真实调用链；整组认证不能被逐卷解密或忽略失败代替。
- FileIntegrityView 已有批量哈希、清单导出和导入验证。v1.5.19 开工时，commands/file_integrity.rs 主要返回 valid/message，总结服务只有名称/布尔值。该版已补逐项原因与操作，不重新宣传新增哈希或新增校验入口。

## 延续与边界

每版开工核对当时主线，先锁定真实失败再修改；同一改动覆盖多个目标时可以合并调整版本。只做受影响的定向检查，复用已通过且未受影响证据，不重跑全格式矩阵。版本完成后更新两份 README、中文 Release 与开发交接。

单条行内展开、多选弹窗、自然配置继承、左右等宽与窄窗滚动保持。界面先说明用户下一步能做什么，原失败历史保留，修正条件后由用户启动新任务。不加入新的全局/单独模式选择，不新增大块常驻批量配置。

ALZ Obfuscated Deflate 方法 3 仍无可靠原厂正面样本/实现，EGG 加密固实仍未验证：留在研究待办，取得真实原包和可分发实现后再确定交付版本。v1.5.16 的隔离 VHD 真实盘满已在用户补充 workflow 授权后由隔离运行 39212555499 完成，最终收据在 v1.5.18 PR #213；注入 StorageFull 和实际 Windows 文件占用不能替代它。不因此触碰个人盘符或反复阻塞已完成的功能发布。

不新增云处理、备份调度或未授权的 ALZ/EGG/RAR 创建；默认开关与 Windows N 现有边界保持。本路线是可调整计划，v1.5.17～v1.5.19 已按范围收口，下一阶段仅规划；各版完成范围按对应证据与正式发布状态记录。

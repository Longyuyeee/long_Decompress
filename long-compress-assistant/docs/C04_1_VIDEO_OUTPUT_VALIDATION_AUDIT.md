# C-04.1 视频输出验证审计

日期：2026-08-28

范围：暂存输出身份、容器/流/时长/尺寸、完整帧扫描和截断拒绝

结论：**C-04.1 已完成；只验证由 C-03 暂存所有者持有的输出，尚未原子发布。**

## 1. 接续顺序纠偏

上一接续点写成先完成 C-03.3 命令/UI、再做 C-04。实际代码表明这会迫使公开命令返回未验证暂存文件，或让任务停在无法跨命令安全持有的中间态，违背最初“无效输出不得发布、任务和最终状态一致”的要求。因此安全顺序调整为：

1. C-03.1/C-03.2 完成参数、进度、Job Object 与内部暂存执行；
2. C-04.1/C-04.2 完成验证与同一事务内发布；
3. 再由 C-03.3 把完整管线一次性接入统一取消、事件和 UI。

这只是实现依赖调整，不改变 C-03/C-04 的原始验收范围。

## 2. 验证契约

| 原始要求 | 实际验证 | 状态 |
| --- | --- | --- |
| 普通、非零且未被替换的暂存文件 | `symlink_metadata` 拒绝目录/符号链接/零字节；编码完成时记录的字节数必须与验证时一致 | 通过 |
| MP4/H.264/AAC | 容器必须包含 `mp4`，恰好一个 H.264 视频流；输入有音频时恰好一个 AAC，输入无音频时不得新增音频 | 通过 |
| 尺寸与旋转 | 编码矩阵和可见尺寸均等于规划尺寸，旋转必须归一为 0° | 通过 |
| 明确的有损流策略 | 字幕、章节、附图必须为零；C-03 参数同时显式 `-map_metadata -1 -map_chapters -1` | 通过 |
| 可解释时长阈值 | `1%` 输入时长，最小 250 ms、最大 2,000 ms；超出即失败 | 通过 |
| 可解码性和截断拒绝 | 产品 ffprobe 对全部音视频流执行 `-count_frames`；视频最低为输入平均帧率×时长的 80%，AAC 最低为采样率/1024 推导帧数的 80% | 通过 |
| 验证失败不发布 | 服务只接受 `StagedVideoOutput`，本模块没有发布调用；对象 drop 自动清理 | 通过 |

## 3. 真实纠偏证据

首次截断测试把 `faststart` MP4 截掉一半后，容器元数据、1.2 秒声明时长和前 2 个视频帧仍能被读取，暴露“至少一帧即可”会误放行。实现随后增加完整音视频帧计数下限，同时锁定编码结束到验证之间的文件大小；同一真实截断样本现稳定拒绝且最终路径不存在。

真实产品输出还覆盖：

- VFR、90° 旋转、AAC、字幕输入：输出 MP4/H.264/AAC、360×640、0°，字幕/章节/附图为零，完整帧扫描通过；
- H.265 无音频输入：输出 H.264 且不凭空增加音频；
- 两种输出均保持暂存状态，验证后仍未发布。

## 历史体验配套：先全库查找，再补汇总与趋势

2026-10-10 接续：全库搜索、类型/终态/时间/失败类别筛选及绑定条件的前端分页已实现；当前统计/趋势仍仅针对已显示结果，已在界面说明并默认折叠。完整归档解压已支持恢复输出目录及子目录设置，接续优先展示执行前最终输出位置；压缩/媒体的配置恢复、全库聚合及摘要按需读取等继续分步推进。

1. 实际代码入口：`history_query_from_pool` 已支持关键词、类型、终态、时间、失败类别与游标，原无条件读取保持兼容。`HistoryView.vue` 的指标和趋势仍在已加载结果计算；后续全库统计须单独返回，不能把分页结果当全库。
2. 保持旧记录分类语义：缺失/未知结构化字段与已有标记解析一致；不要为检索便利批量改写原始错误。必要时增加只读派生字段或明确的索引迁移。
3. 查询游标与筛选条件绑定，换条件必须从第一页开始。文本输入适度延迟合并请求，旧响应不得覆盖新条件；错误时说明保留的是哪次查询结果。
4. 将全库汇总与查询匹配总数区分展示；趋势有明确日期边界，避免把加载页样本当作整体成功率。
5. 限制已加载页面累计内存，结合虚拟列表或页切换；用超过 500 条、同时间戳、旧版记录、多条件、无匹配、新记录插入与重启测试。当前时间字符串排序也应审计不同合法时区表示，必要时单独设计规范化索引，不能静默改原始时间。

6. 列表优先查询摘要，详情按需读取日志；限制页面累计缓存，避免仅减少 DOM 而继续累积全部日志。单条旧数据异常应有明确降级反馈，不让整页历史不可见。

## 可靠性配套：先持久待保存队列，再做保留策略

- 待保存历史以任务 ID 幂等持久化，落库确认后删除队列项；数据库失败、退出、重启和再失败都要验证。只恢复历史写入，不自动重新执行解压/压缩。
- 保留策略后续再做：让用户明确选择数量/时长策略并预览影响，再执行整理；默认不静默删历史，整理失败不能误报新任务完全未保存。旧版已删除的记录无法恢复。
- 配置快照只包含非敏感设置；历史落库、旧记录读取和诊断导出分别核对脱敏边界，不能因支持重试或导出而扩大明文密码持久化。

## 仍保留的约束

Windows N 暂不支持；真实 UI 选择器、所有媒体矩阵与卸载生命周期未因本版重新全验。每个实现步骤按代码核对→用户场景→测试→审计→推送推进，发布前明确实际覆盖范围。

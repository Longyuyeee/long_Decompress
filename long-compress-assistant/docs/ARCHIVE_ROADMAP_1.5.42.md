# v1.5.42：失败原因与调整后接续

2026-10-21 已完成功能封板，见[实际记录](FAILURE_RECOVERY_FREEZE_1.5.42.md)，接续 [近期排期](ARCHIVE_ROADMAP_1.5.40_TO_1.5.43.md) 与 v1.5.41。

检查现有操作发现三个实际缺口：转换失败/取消后清空密码，却能直接重试且不要求确认新包加密；全局任务栏的普通归档重试直接复用旧任务执行；当前压缩/转换失败主要显示原始错误，已有原因与指引集中在历史界面。另外，实时任务生成的“未分类/最后观测阶段”会遮住错误中已有的明确分类标记。

## 本版交付

1. 在原压缩与转换详情就近显示已有的失败分类、实际原因和下一步。未知原因保持未知，不把缺卷、占用、不支持方法或编码问题一律归为密码错误。
2. 转换调整生成待确认的新条目，保留原失败、原结果和来源关联；分别确认原包/新包密码，保留方法、卷型、输出位置与其他参数。已创建的待处理项可返回，不重复创建。
3. 普通压缩失败复用现有压缩草稿与配置区；任务栏解压重试返回原条展开纠正，不直接覆盖旧任务记录，也不自动执行。输出冲突建议新的压缩包名称，仍由用户确认启动。
4. 压缩和转换的已存在输出在预检分类，历史保存和筛选保持实际阶段；错误弹出提示简短，完整原因留在原任务。
5. 密码需求以布尔信息接入历史/草稿，历史不存密码。当前记录的未分类快照不再遮住明确标记；观测阶段仍与确认阶段区分。

保留单条展开、多选弹窗、自然继承、左右等宽与窄窗滚动，不新建失败中心。仅检查上述接续、代表性真实失败/成功结果与相关显示，已通过且未受影响的格式矩阵和盘满检查不重跑。

封板后同步 README、中文 Release、交接与当前排期，正常合入后发布。下一版仍为 v1.5.43 批处理和结果体验，随后进入五模块分阶段路线。

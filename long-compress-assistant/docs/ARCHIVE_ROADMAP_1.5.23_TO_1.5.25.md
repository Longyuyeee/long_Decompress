# 归档与使用体验升级路线 v1.5.23 至 v1.5.25

2026-10-20，接续 v1.5.20～v1.5.22 的三项计划。v1.5.23、v1.5.24 已正式发布；v1.5.25 已开工，见[实施记录](RESULT_CHECKSUMS_1.5.25.md)。各版独立收口，不作为旧版发布阻塞条件。

继续用户既定方向：增加实际可用的格式、密码及分卷组合，打通创建、查看、提取、转换、失败纠正与结果，持续修复真实流程问题。单条展开、多选弹窗、自然继承、左右等宽和窄窗滚动保持。

| 版本 | 用户问题与目标 | 计划范围与收口边界 |
| --- | --- | --- |
| v1.5.23（功能收口） | 已有 LZMA 单文件创建，仍不能拆成方便传输的数字分卷，普通流预览也未接统一入口 | 接通 `.lzma.001` 数字切卷和从任意成员浏览/有界预览、检查、提取、转换及补卷新任务；核对前后端能力表中的旧引擎依赖说明。已有 LZMA 编码器不重复开发，不把数字切片称为 LZMA 原生多卷。先用独立 LZMA-alone 原件确认真实路由及尾部损坏原因，再开放创建组合。 |
| v1.5.24（功能收口） | LZMA 归档目录/多文件和保留该编码的密码组合仍有缺口 | 在上版可靠 LZMA 流链路上增加 TAR.LZMA，再接 LZMA.AES/TAR.LZMA.AES（沿用既有 Long AES V2）；密码、数字卷、认证后浏览/预览、检查、所选/整包、转换与结果一并收口。明确单文件与 TAR 组合的用途，接收方需对应版本 Long解压；不宣传为通用 LZMA 原生密码标准。以独立 TAR/LZMA 完整回解及既有 AES 格式独立认证原件确认，若可行性证据改变范围先更新计划。 |
| v1.5.25 | 分享已经压好的一组分卷时，还要手动逐个选文件生成清单；跨目录同名文件导出只保留 basename，核对时容易找错 | 在现有完成结果/历史结果加入主动生成校验清单入口，卷组枚举全部实际产物；复用 v1.5.22 的进度、停止与未完成接续。按保存清单的基准目录写可核对的相对路径，处理子目录同名项，跨盘/不在基准目录内的来源给出明确调整方式；导出只用完整成功的摘要，不写入中断结果。生成后可直接在原校验入口核对，不自动全包重算，不重复开发现有基础哈希。 |

## 开工代码依据（历史状态，当前进度以上方为准）

- `native_compression/single_stream.rs::compress_lzma` 已通过 xz2 的 LZMA-alone 流原生创建；`CompressionRoute::Lzma` 已存在。不能把接入 LZMA 本身当作下一版新功能。
- `compressionFormat.ts` / `compression_format.rs` 对 lzma 仍标记不支持 split、依赖 7-Zip；`codec_stream::plain_format` 尚未包含 LZMA。v1.5.23 处理这些具体组合和路由缺口，逐条确认已有提取路径，不能只改能力表。
- 当前十五种 Long AES 内层不含 LZMA，格式列表中无 TAR.LZMA。v1.5.24 为拟新增组合，不能提前列入已支持格式。
- `FileIntegrityView.vue` 的摘要结果和 `export_checksum_file` 使用 fileName/file_name 导出，前端取 basename；不同目录下同名文件可能丢失层级。现有结果操作未提供生成摘要清单的完整入口，v1.5.25 连接这些用户步骤。

## 保留的待办与执行方式

ALZ Obfuscated Deflate 方法 3 与 EGG 加密固实仍需可靠原厂正面样本和实现依据；不按版号假定已解决，不为占位开放功能。ZPAQ 增量及历史恢复、WIM 原生分卷等仍单独评估，不混入本轮封板。RAR 创建/修复所需本机工具、Windows N 的既有边界保持。

每版仅检查新增或受影响的用户链；旧格式、已通过的真实 VHD 盘满及无关矩阵直接复用。实现完成后更新两份 README、中文 Release 与开发交接，按仓库必需 Windows package 完成普通受保护合入和正式发布。

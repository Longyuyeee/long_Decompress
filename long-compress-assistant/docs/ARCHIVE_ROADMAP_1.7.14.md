# v1.7.14 规划 · TAR.LZO PAX sparse 1.0 部分取回

状态：已完成并封板。接续 v1.7.13 的旧 GNU `S` 稀疏条目，恢复读取已支持局部 PAX sparse 1.0；正常完整读取保持既有能力。

1. 先取得 GNU tar 的 PAX sparse 1.0 生产者原件、官方 lzop 回解及独立逻辑内容依据，覆盖长名称、空洞、多段数据和大空洞。与构造损坏边界分开记录，不把自造异常样本当作兼容原件。
2. 首期只支持局部元数据明确声明的 1.0 布局，分别确认 PAX 记录、条目内文本稀疏图、图后填充、实际数据及条目末填充；物理大小、逻辑大小与有效路径不能互相替代。未知版本、冲突大小或不完整映射明确停止。
3. 复用已确认的流式逻辑 SHA、Windows 稀疏输出、修改时间、来源重查和取消清理；映射本身计入来源身份，不把稀疏图保存成用户文件，也不扫描缺口之后。
4. 原取回弹窗继续显示完整大小和包内数据，结果与历史仍明确为部分取回。只检查受影响的跨块/跨卷边界、选择范围、实际空洞输出、补卷重查与宽窄显示，复用旧 GNU 和时间矩阵，不新增常驻界面，不接管桌面。

完成情况：GNU 生产者原件、独立逻辑 SHA、跨块文本图与真实名称核对通过；新原生 8 项、相关旧回归 2 项、前端 4 项和后台 UI 3 组通过。4 份实际输出共 25 个文件的路径、逻辑内容、明确记录的修改时间及 Windows 稀疏分配完成独立核对。类型/Vite、Shell DLL 与版本身份通过，见 [实现与检查](TAR_PAX10_FREEZE_1.7.14.md)。

下一阶段 [v1.7.15 PAX sparse 0.1](ARCHIVE_ROADMAP_1.7.15.md)仅规划。0.0/0.1 的部分取回、链接救援、缺口后扫描及全部权限/所有者恢复不计入本期。ALZ/EGG 加密分卷外部原件与 LZOP 原生密码/块分段等继续独立研究，不将缺少依据的能力列为已完成。

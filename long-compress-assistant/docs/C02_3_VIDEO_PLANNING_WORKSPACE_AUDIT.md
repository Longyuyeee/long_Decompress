# C-02.3 视频探测与配置工作区审计

日期：2026-08-28

分支：`codex/video-c02-probe-model`

范围：把 C-02.1/C-02.2 后端事实和规划模型接入压缩中心，允许真实选择/拖入、批量与单项配置、估算和流变化展示；执行能力继续冻结。

## 结论

C-02.3 已完成。压缩中心的视频 Tab 不再是计划占位，而是可调用唯一后端 `plan_video_compression` 的真实探测与配置工作区。用户可添加多个候选，查看可见/编码尺寸、旋转、时长、VFR、编码、音轨/字幕/章节/封面、派生输出尺寸、目标码率和明确标为“预计输出 · 估算”的大小区间。

三档和最大分辨率使用同一 `VideoCompressionSettings` 模型；批量配置变化只重算跟随全局的条目，单项覆盖独立重算。每次异步规划携带递增 revision，旧请求晚返回时不能覆盖最新配置。

工作区的“开始视频压缩 · C-03”始终禁用，源码和架构门禁均禁止创建任务或调用视频编码。当前出现的 `canEncode` 只表示规划没有 HDR 等输入阻断，不能改变 UI 冻结状态。

## 边界与纠偏

- 视频草稿加入现有 `compression` store 的隔离集合，没有新增第二个 Pinia store，也不污染归档队列和图片草稿。
- 不使用浏览器 video 元数据作为媒体真相，所有事实和估算都来自后端规划报告。
- 不按文件扩展名宣称支持；未知扩展名也可送后端探测，损坏内容由 C-02.1 稳定拒绝。
- 不把后端稳定错误/策略代码原样作为主要产品说明；已对已知流变化提供中文解释，同时保留原始错误详情便于诊断。
- 不把“规划就绪”称作“可压缩”，不创建统一任务、历史或模拟进度。
- 全局/单项异步重规划增加 revision 防陈旧覆盖；删除条目后晚返回结果也无法复活草稿。

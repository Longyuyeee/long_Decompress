# B-05.2.2 图片资源与故障边界审计

审计日期：2026-08-28（Asia/Hong_Kong）

开发分支：`codex/archive-media-roadmap`

公开基线：`v1.1.14`；B-05 整体尚未完成，本节点不升版、不更新公开 Release。

## 1. 目标与真实测试边界

B-05.2.2 收口图片生产服务的五类边界：超大像素、Windows 中文长路径、目标冲突、磁盘空间耗尽和编码启动后的取消。专项命令先准备冻结真实图片，再生成一张可由 Pillow 完整解码的 10001×10000 PNG，随后直接调用生产 `image_compression_service`；结果由实际文件、错误类型和事务暂存目录共同判定。

磁盘满测试不会通过填满开发机磁盘制造破坏性环境。真实 JPEG 会完成生产解码、PNG 编码和 oxipng 内存优化，仅在生产最终暂存写入函数处注入标准 `std::io::ErrorKind::StorageFull`，从而安全验证同一错误传播与清理路径。该证据明确标为故障注入，不冒充物理磁盘耗尽。当前图片配置没有“删除源文件”选项，本节点只验证所有失败路径和成功长路径均不改变源文件；不把归档回收站能力冒充为图片功能。

## 3. 最终真实结果

核心命令：

```powershell
npm run test:image-boundaries:real
```

最终结构化证据位于 `test-results/b05-image-boundaries/result.json`：

- 96 MP 真实冻结 PNG：完整生产解码成功；
- 100.01 MP 有效 PNG：1,359,007 B，SHA-256 `a4ff6cfe2dbdf0a30efbd9f0565748d5c280943fa68a24ab7786231a5496d135`，被 100 MP 边界拒绝，无输出；
- 中文长路径：340 UTF-16 单元，真实 JPEG 发布成功，源文件不变；
- skip、rename、replace-if-smaller 和编码期目标竞态：全部符合安全策略，现有目标未被覆盖；
- StorageFull：输出不存在，事务暂存数 0；
- 编码启动后取消：输出不存在，事务暂存数 0；
- 最终专项生产运行耗时 2,432 ms，`differences=[]`。

超限夹具和结构化结果均在忽略的 `test-results` 中重新生成，不作为源码提交。

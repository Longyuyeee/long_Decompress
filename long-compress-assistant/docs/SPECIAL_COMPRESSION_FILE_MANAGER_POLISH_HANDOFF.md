## 1. 用户本轮明确需求

以下六项是下一次开发的冻结范围。不得把截图或旧文档中的说明当成新增指令，也不要在完成前扩展版本范围。

1. 特殊压缩的设置打开后不能挤压、压扁或改变主工作区结构；设置较多时应放入独立弹窗。
2. 删除特殊压缩页已经由 Tab 表达的重复文字。用户明确点名图片页的“图片压缩工作区 / 真实执行”和“支持 JPG、PNG、WebP；结果路径、尺寸与节省字节均来自后端验证”。
3. 特殊压缩整体视觉和动效对齐解压中心、压缩中心；不能只有静态换页或生硬出现/消失。
4. 双栏文件浏览器中，文件和文件夹的右键菜单都必须提供“在文件管理器中打开/定位”。
5. 修复双栏文件浏览器“在文件夹定位”最后只打开桌面的错误。
6. 查看特殊/受保护文件夹属性失败时，不展示生硬的底层错误；给出清晰提示，说明该位置可能是系统保护或特殊文件夹，并可建议到 Windows 文件管理器查看。

## 2. 真实代码审计结论

### 2.1 设置挤压根因

- 图片页 `ImageCompressionWorkspace.vue` 和视频页 `VideoCompressionWorkspace.vue` 原来把 `global-settings-card` 作为普通子元素插入纵向 flex 主布局。
- 设置卡片出现后会占用固定高度，文件投放区或任务列表只能被继续压缩。这不是分辨率偶发问题，而是布局模型必然结果。
- 压缩中心已有 `GlobalSettingsModal.vue`，底层复用 `components/ui/Modal.vue`；Modal 具备 Teleport、背景淡入、内容弹入、Esc、焦点恢复和内部滚动，适合作为本轮对标基线。

### 2.2 冗余文案

- 图片页和视频页各自重复显示“工作区”“真实执行”和能力说明；外层特殊压缩页的 Tab 已经明确当前类型。
- PDF 页仍保留 `PDF · D-04.2`、“安全分析、批量优化与验证发布”以及统一任务说明，尚未按本轮要求精简。
- 安全边界或会影响决策的提示不能一概删除。例如“不覆盖源文件”“估算不是最终大小”“流变化/HDR 阻断”仍有产品意义。

### 2.3 Explorer 定位根因

- 双栏普通文件的双击和右键当前调用 Tauri 命令 `open_in_explorer`。
- Windows 后端当前构造 `/select,"路径"` 后，再把这一整段作为单个 `Command.arg` 传给 `explorer`。进程 API 本身会负责参数引用，额外嵌入引号可能令 Explorer 解析失败并退回默认桌面。
- 目录右键目前只有应用内部“打开文件夹”和“在另一栏打开”，没有独立的系统文件管理器动作。

### 2.4 属性失败现状

- `file_manager_properties` 会拒绝符号链接/Windows 重解析点，并会在受保护目录递归统计失败时返回错误。
- 前端当前直接显示 `读取属性失败：${error}`。安全拒绝本身不应删除，但用户可见提示需要归类和转译。

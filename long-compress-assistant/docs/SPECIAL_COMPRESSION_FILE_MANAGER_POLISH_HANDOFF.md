# 特殊压缩与文件浏览器体验修正交接

> 最后更新：2026-09-02
> 当前公开基线：`v1.2.1`
> 开发分支：`codex/special-compression-file-manager-polish`
> 状态：六项体验修正及复审收尾已完成；进入 `v1.2.2` 候选准备，尚未打正式安装包、合并或发布

## 1. 本轮冻结需求与完成情况

1. 图片、视频批量设置已移入共享 Modal，打开、取消或保存都不再占用主工作区高度；取消不写回，保存后才应用。
2. 图片、视频、PDF 已删除由 Tab 重复表达的“工作区/真实执行/阶段号/统一任务”类标题和说明；不覆盖源文件、压缩率不保证、签名或有损风险等决策信息仍保留。
3. 特殊压缩 Tab 使用同步挂载的轻量淡入/位移动效，按钮具备 hover/press 反馈；`prefers-reduced-motion` 下关闭动效。没有采用会造成短暂无内容的 `mode="out-in"`。
4. 双栏文件浏览器的普通文件、压缩包和文件夹右键都提供独立系统动作。文件夹保留“在当前栏打开”，压缩包保留“浏览压缩包”，系统动作不会覆盖应用内动作。
5. Windows Explorer 参数改为文件使用两个进程参数 `["/select,", realPath]`，目录使用 `[realPath]`；不再手工把引号嵌进单个参数。绝对路径、存在性及文件/目录类型在启动前校验。
6. 属性读取失败不再显示底层拒绝或堆栈，统一提示该项目可能是系统保护或特殊文件夹，并建议到 Windows 文件管理器查看；后端对重解析点和受保护目录的安全拒绝保持不变。

完整预期—实际差异与测试证据见 [SPECIAL_COMPRESSION_FILE_MANAGER_POLISH_AUDIT.md](SPECIAL_COMPRESSION_FILE_MANAGER_POLISH_AUDIT.md)。

## 2. 真实代码边界

- 图片、视频、PDF 继续复用统一任务、取消、容量预检、验证、历史和原子发布；本轮没有复制或放宽后端压缩引擎。
- 双栏复制/移动仍默认不覆盖、拒绝重解析点写操作、目标暂存并做 BLAKE3 校验；跨卷移动仍是先校验目标再删源。
- Explorer 打开和属性查看只是只读便利功能。Explorer 可跟随系统解析特殊目录，但这不代表复制/移动/删除获得额外权限。
- 图片/视频单项设置继续位于各自内部任务列表；外层工作区为固定 flex 外壳，批量设置 Modal 和浏览器尺寸门禁已经证明不会改变外壳。

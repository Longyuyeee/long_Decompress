# v1.5.1 ZPAQ 创建闭环

## 范围与接续

2026-10-18 从已发布 v1.5.0 的主分支 `1c94e61` 接续，工作分支 `codex/v1.5.1-zpaq-create`。本版按批准路线完成新的日志式 ZPAQ 创建、原生密码、配置保存、历史再执行及转换输出；封板和发布前必须补真实桌面入口、常用及窄窗页面和官方工具独立回解。

创建沿用现有暂存、完整性校验和事务发布，不在原包上追加更新。密码通过标准输入传递，既不写命令行也不改成 7Z 容器。引擎使用两个线程、16 MiB 块，界面 1～9 级映射到上游 1～5 级；0 级后端请求使用去重存储。目录、中文和空文件与共享条目收集规则一致，关闭保持目录结构时保留同名文件的不同内容。

ZPAQ [作者文档](https://www.mattmahoney.net/dc/zpaqdoc.html)的多部分是按增量更新追加新段，不是固定容量分卷。本版不开放该入口，也不开放普通切片、增量备份或历史恢复；保留现有流式、日志式当前文件读取。新增范围不包含上述备份交互，后续版本仍按 ALZ、EGG 和外置卷 SFX 顺序。

## Windows 文件读写错误

上游 Windows 封装此前没有检查 `ReadFile`、`WriteFile`、定位和关闭的失败，部分上层调用也忽略返回字节数。适配器现对这些操作检查系统结果，短写直接失败，输出关闭前刷盘。检测到错误后，以 `LONG_ZPAQ_IO` 和系统错误码结束独立引擎进程，避免后台线程吞错、将读错当 EOF 或将未落盘文件计为完成。Rust 将此类错误显示为文件读写原因，不标成归档损坏或继续试密码。

故障控制只编译进 `build-zpaq-engine.ps1 -TestIO` 的专用测试程序，不进入随附生产程序。`node scripts/test-zpaq-io.mjs` 已通过创建、日志式提取、流式提取各六类故障，共 18 项；包括空间不足、真实部分写入后的短写、读取、定位、关闭和刷盘错误。生产程序在相同测试环境变量下正常读取，且不包含故障开关字符串。没有填满真实磁盘或改动用户原包；这是受控系统调用故障，不扩大为所有硬件掉电情形的证据。

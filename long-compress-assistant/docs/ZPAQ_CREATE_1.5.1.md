# v1.5.1 ZPAQ 创建闭环

## 范围与接续

2026-10-18 从已发布 v1.5.0 的主分支 `1c94e61` 接续，工作分支 `codex/v1.5.1-zpaq-create`。本版按批准路线完成新的日志式 ZPAQ 创建、原生密码、配置保存、历史再执行及转换输出；封板和发布前必须补真实桌面入口、常用及窄窗页面和官方工具独立回解。

创建沿用现有暂存、完整性校验和事务发布，不在原包上追加更新。密码通过标准输入传递，既不写命令行也不改成 7Z 容器。引擎使用两个线程、16 MiB 块，界面 1～9 级映射到上游 1～5 级；0 级后端请求使用去重存储。目录、中文和空文件与共享条目收集规则一致，关闭保持目录结构时保留同名文件的不同内容。

ZPAQ [作者文档](https://www.mattmahoney.net/dc/zpaqdoc.html)的多部分是按增量更新追加新段，不是固定容量分卷。本版不开放该入口，也不开放普通切片、增量备份或历史恢复；保留现有流式、日志式当前文件读取。新增范围不包含上述备份交互，后续版本仍按 ALZ、EGG 和外置卷 SFX 顺序。

## Windows 文件读写错误

上游 Windows 封装此前没有检查 `ReadFile`、`WriteFile`、定位和关闭的失败，部分上层调用也忽略返回字节数。适配器现对这些操作检查系统结果，短写直接失败，输出关闭前刷盘。检测到错误后，以 `LONG_ZPAQ_IO` 和系统错误码结束独立引擎进程，避免后台线程吞错、将读错当 EOF 或将未落盘文件计为完成。Rust 将此类错误显示为文件读写原因，不标成归档损坏或继续试密码。

故障控制只编译进 `build-zpaq-engine.ps1 -TestIO` 的专用测试程序，不进入随附生产程序。`node scripts/test-zpaq-io.mjs` 已通过创建、日志式提取、流式提取各六类故障，共 18 项；包括空间不足、真实部分写入后的短写、读取、定位、关闭和刷盘错误。生产程序在相同测试环境变量下正常读取，且不包含故障开关字符串。没有填满真实磁盘或改动用户原包；这是受控系统调用故障，不扩大为所有硬件掉电情形的证据。

## 当前验证

23 项不同 Rust 用例通过：十项 ZPAQ/模板及 I/O 分类、九项格式路由、单独显式运行的一项真实写入故障事务测试，以及三项子进程控制。故障事务测试覆盖空间不足、实际部分写入后的短写和刷盘失败，暂存清除、已有目标及源文件不变。前端九个文件共 128 项通过，包含配置界面、配置组管理、草稿和历史快照；生产前端与真实桌面 E2E 构建通过。

初轮前端发现设置页重复显示 ZPAQ，已移除只读时代的额外拼接，按当前格式能力生成一次，并明确列出随附引擎的创建能力。

## 真实用户流程与页面

`scripts/zpaq-151-gate.mjs` 使用真正的 Tauri 后端及页面按钮，文件选择器只替换为隔离测试路径，不注入执行成功。普通目录、中文密码目录分别由应用创建及回解，再用作者未经修改的 `zpaq64.exe` 独立回解；目录内三份已知载荷与空目录保持。另验证已有 ZPAQ 改密、AES ZIP 转为密码 ZPAQ、真实压缩中取消、配置保存后切换 ZIP 再应用回来，以及从成功历史再次生成草稿并启动。共七组流程完成，原包和源内容不变。

历史重做必须重新输入密码，只创建待确认草稿，原记录保持不变；新任务真实输出也经官方工具核对。取消用真实 16 MiB 随机源文件，在引擎已打开暂存输出后执行，并明确开启删除来源以验证失败/取消不会触发删除。

首轮页面实看发现保存配置弹窗在 760×520 下超过窗口高度，现已限制高度、内部滚动并更正预览配色；最终常用 1100×700 和窄窗 760×520 的创建、保存、应用、历史重做、转换和设置共 12 张页面已查看。长名称与 `.zpaq` 后缀分开，未支持的分卷保持禁用。历史说明初次取文本在内容尚未滚入可视区时为空，测试改为先滚动并等待真实渲染，没有放松断言或改变恢复规则。

末轮审计补上 `[zpaq-io]` 原因及原生 `std::io::Error` 链，浏览和诊断均优先认定 I/O，不被“已加密且提供密码”的通用兜底归成密码/损坏待定。具体路径、程序 SHA、载荷和页面记录见[桌面证据](evidence/zpaq-create-1.5.1/results.json)，低层故障矩阵见[故障证据](evidence/zpaq-create-1.5.1/io-faults.json)。

## 末检追加的暂停修正

首轮冻结 `f0e5106` 后的审计发现，ZPAQ 异步引擎只接了取消通道，界面暂停会挡住后续提交，却不能停止正在编码的子进程。真实心跳子进程证明旧通道在暂停期间仍从 7 字节增长到 16 字节；原断言失败，故撤回首轮封板，未合入或发布候选 `235ea65`。其 Windows package `39081172773` 虽通过，也不能作为修正后的候选证据。

新增归档专用异步通道，复用现有 Windows 子进程暂停/恢复机制；只将 ZPAQ 读取和创建接入该通道，其余媒体/RAR 提示输入保持原行为。相同心跳断言现在通过，恢复后继续写入，取消会结束并回收子进程；真实 ZPAQ 场景还覆盖编码中暂停、恢复和暂停中取消。没有删去失败用例或放宽断言。

最终七组桌面流程 UTC `2026-10-18T00:16:14.227Z` 通过，E2E 程序 ProductVersion 1.5.1、33497600 字节、SHA256 `5fc167fbefd909a465fd25de07f135245ec1e0f94266862059ef77fb9717b0dc`。一次快速菜单脚本操作后实际目标仍为 ZIP，见[保留的失败页面](evidence/zpaq-create-1.5.1/selection-before-state-wait.png)；脚本现先等待菜单动画和实际选中值，再输入其他参数，没有改产品默认值或放松分卷禁用断言。后续相同用户流程完整通过。最终证据覆盖原 JSON 和固定创建产物，首轮未修暂停的安装包不能混用。

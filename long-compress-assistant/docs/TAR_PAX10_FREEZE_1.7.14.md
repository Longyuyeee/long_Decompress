# v1.7.14 · PAX sparse 1.0 部分取回封板记录

日期：2026-10-28。

## 已完成

TAR.LZO 恢复读取支持局部 PAX `GNU.sparse.major=1/minor=0`。专用 `GNU.sparse.name` 是真实名称，普通 `path`/头内名称可能是 GNU 生成的 `GNUSparseFile` 占位路径，不把占位目录作为用户资料。普通 PAX、全局继承及完整 TAR 读取器保留原规则；全局 sparse、未知版本/属性、缺失属性、叠加 GNU 长名称及非普通文件明确停止。

条目内文本图按 512 B 读取，核对十进制段数、偏移和长度，分别确认图后零填充、实际数据和条目末填充。最多 65,536 段、8 MiB 图，复用总映射和 512 GiB 逻辑量边界；不逐字节触发外层进度。物理大小含图，storedBytes 只含实际数据，逻辑大小包含空洞；有效 PAX size 若与头内物理大小冲突则停止。范围核对与旧 GNU 共用，图计入来源 revision。

扫描与取回复用流式逻辑 SHA、Windows 稀疏写入、文件/目录时间、来源重查和取消清理。确认图、数据及填充均落在已校验连续前缀后才提交完整条目；不跳过缺卷或损坏。原件保留，独立结果和原历史仍标为部分取回。

界面只补充问号帮助的支持范围；原筛选、目录联选、大小提示、折叠结果及历史沿用。单条展开、多选弹窗、等宽双栏和主题未改动，没有新增常驻配置区。

格式依据：[GNU tar 稀疏格式说明](https://www.gnu.org/software/tar/manual/tar.html#PAX-1)。本版不修改完整读取器和已验证的 Windows 稀疏写入实现。

## 原件与检查

`tests/fixtures/archives/tar-pax10-1714/` 为 GNU tar 1.35 `--format=pax --sparse --sparse-version=1.0 --hole-detection=raw` 原件，官方固定 SHA lzop 压缩并完整回解一致。源文件/GNU/Python 的逻辑 SHA 一致；真实路径由源文件和 GNU 读取确认。这一 Python 版本对部分名称暴露占位 path，因此只作为逻辑内容依据，没有把它当作名称 oracle。原件和工具 SHA、物理位置、图与逻辑清单见 manifest。异常边界构造与生产者兼容依据分开。

- 新原生 8 项全部通过：完整原件浏览/完整性/健康诊断；坏尾、坏校验和缺结束标记的实际取回及所选子集；PAX/跨块图/数据边界与异常范围；局部版本、属性、类型、物理大小及名称冲突；相同源大小/时间/逻辑内容但不同图的 revision；缺中卷和补卷重查；非整块数据的独立两层填充；扫描/空洞复制取消与真实写入失败。仅将一项测试标题改为准确的“扫描取消”，测试主体不变，没有重跑成功项。
- 相关旧原生 2 项通过：旧 GNU 完整原件的浏览/完整性/诊断；不支持元数据停止与复制取消清理。未重跑完整旧格式矩阵。
- 前端 4 项通过：真实长名称、逻辑/包内大小和零数据；所选文件/目录的折叠结果与逻辑字节历史；旧稀疏列表和历史兼容。新选择测试最初取消父目录导致子项同步取消，改为“取消所列”后选择目标，只续跑这一失败项。
- 独立 Python 核对 4 份实际输出、25 个逻辑文件的 SHA、精确树、明确记录的修改时间及 Windows 稀疏分配。64 MiB 文件包内 512 B、实际分配 64 KiB；全零 1 MiB 文件包内和实际分配均为 0；跨块图样本逻辑 16 MiB、包内 393,216 B，实际分配 6 MiB。原件 SHA 未变。
- 后台真实 Vue/CSS 回放本次原生报告和结果，3 组通过：零数据筛选，宽窄结果及大小详情，所选子集与原部分历史。1100×700、760×520 无横向溢出，底部按钮可见，详情可滚动；6 张截图逐张查看。IPC 明确为原生值回放，未接管桌面。
- 类型/Vite、版本 Shell DLL 与 8 个版本来源身份通过。正式 Windows 安装包和更新清单由对应提交 CI/Release 生成；未重跑默认应用、更新及其他格式的未受影响矩阵。

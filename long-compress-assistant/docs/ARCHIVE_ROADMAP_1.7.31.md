# v1.7.31 · ZIP / ZIPX 的 UTC 修改时间读取与恢复

状态：已完成功能开发并封板；接续 v1.7.30 前向链接嵌套流程。

目前原生 ZIP 的文件、并行工作项与目录日期主要采用 DOS 本地两秒日期。下一阶段先读取外部包已经编码的 UTC 修改时间，让用户跨时区取回资料时尽量保持原时间，并保留已编码的奇数秒；创建侧写入扩展另行分期。

1. 先支持经完整确认的 Info-ZIP Extended Timestamp（0x5455）修改时间，统一日期解析规则；没有可用扩展时保持既有 DOS 本地日期。缺失、冲突、重复或不可表达属性须明确处理，不凭空生成时间、不让可忽略的扩展错误覆盖内容读取结果。
2. 浏览、顺序/并行提取、精确所选文件和提交后目录日期共用规则。沿既有转换暂存输入传递已恢复的时间，目标格式按自身能力写入；本期不承诺 ZIP 创建器已经写入 UTC 扩展。
3. 以外部生产者原件核对明确 UTC 值、奇数秒、DOS 回退和目录时间；密码及完整标准/数字分卷只取代表流程，不重跑未改创建器的整套方法矩阵。不修改用户电脑的时区或默认应用设置。

完成标准：声明范围内，包内已编码的 UTC 修改时间在浏览和实际取回结果一致，原件保持、内容不变，原界面和交互不变。UTC 扩展写入、NTFS 亚秒/其他元数据、重复扫描成本继续分期；ALZ / EGG 外部原件、原生密码/块分段及其他算法/格式和容错缺口继续列为未完成。

参考：[Info-ZIP 扩展字段说明](https://libzip.org/specifications/extrafld.txt)；现有依赖解析器 `src-tauri/vendor/zip/src/extra_fields/extended_timestamp.rs` 和原生 ZIP 日期入口。具体字段冲突优先级与可表达范围在开发前按原件确认。

实际口径：中央目录唯一 UT 修改字段、长度 5、低三位标志，确认范围为 Unix 秒 0..2147483647（1970-01-01 至 2038-01-19 03:14:07 UTC）。其他值、重复/缺失/可选字段内的无效值使用原 DOS 本地日期，不从仅本地头或高位符号歧义推断。完整额外字段容器截断仍报错。浏览、顺序/并行、目录、较新判断/冲突提示，以及密码回退和资料对比日期读数接入共享规则。

见[封板记录](ZIP_UTC_READ_FREEZE_1.7.31.md)。下一阶段 [v1.7.32 UTC 日期写入](ARCHIVE_ROADMAP_1.7.32.md)仅规划。

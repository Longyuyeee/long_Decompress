# v1.7.10 · GNU/PAX 混合名称取回封板记录

日期：2026-10-27。

## 已完成

恢复读取允许一条 GNU `L` 与一条局部 PAX `x` 以两种顺序连续出现；各控制头仍按自身物理大小读取、确认完整内容与填充后再提交状态。文件使用有效 PAX 大小，名称只作用一次；后续普通文件不继承上一条名称。原有全局 PAX 状态保留，未知属性、重复记录、孤立元数据、链接/稀疏和缺口仍明确停止。

正常读取与恢复共享 `check_mixed_path`：局部 PAX 不提供 path 或其字节与 GNU 名称完全一致时接通，局部路径冲突和混合记录中的空路径删除停止。没有把某个解析器的隐式优先级当作用户文件名。正常读取捕获并确认 GNU 名称记录，声明内多余零填充规范为单个 NUL；原包不修改，恢复继续使用原始物理位置及内容 SHA。

不新增功能页，复用原诊断、筛选、目录联选、独立结果与部分历史，保留单条展开、多选弹窗、左右等宽、包内外一致双栏和主题。未修改正常创建算法或依赖版本。

## 独立依据

五份组合样本在 `tests/fixtures/archives/tar-mixed-1710/`：以此前自编资料的 GNU tar 1.35 原件为基础，由 Python tarfile 插入局部 PAX 记录，官方 lzop 压缩。不是应用写入器生成，也不冒称第三方混合原包。原始 TAR/LZOP SHA、每个路径/类型/大小/文件 SHA 和控制记录位置均写入 manifest。

覆盖 `L→x`、`x→L`、带全局状态的交替布局、PAX 覆盖非零普通头大小，以及声明 1024 字节、名称后全部为零的 GNU 控制记录。每份完整样本均由官方 lzop 完整回解，GNU tar 与 Python 对清单、类型和逐文件内容一致；后来增加的样本独立验证，已通过的组合样本按固定 SHA 复用。

冲突路径另作探针，不作为支持样本：`L→x` 中 GNU/Python 名称有分歧；`x→L` 中两者虽一致，旧 tar-rs 的 GNU 优先路径也与之不同。因此本版对所有局部路径冲突统一明确停止，没有只把恢复端接通。探针记录在证据目录，锁定 tar 0.4.46 的读取实现可对照 [上游源码](https://github.com/composefs/tar-rs/blob/0.4.46/src/entry.rs)。

# 两个归档中心的条目展开 UI 回归审计

## 对比方法与实际问题

- 用户要求以 v1.3.6 的规整布局和展开动效为参照修复，不是回退后续功能。
- 对比 `v1.3.6`（`6cca1de`）与本轮修改前 `d371228` 的真实源码；另建隔离工作树运行旧版前端。同一组中文文件、1280/920/760 窗口截图对照，实际查看截图，不仅检查代码。旧版使用当前已安装前端依赖与浏览器，并非重跑旧安装包；开发服务器单独缓存、允许读取共享依赖，未更改旧版产品组件。
- 解压中心删除了旧版高度过渡钩子，但留下从 0 高度到自然高度的 CSS，实际无法稳定插值；上下箭头也变成了省略号。
- 压缩中心已恢复完整行内参数，沿用旧版用于简短全局摘要的半宽列。920 宽度下参数卡片约百像素，标题/密码挤压、按钮省略；参数网格 `align-items: end` 使同一行卡片上下错位。
- 旧版也有窄窗口任务行裁切，不能直接恢复旧版固定最小列宽。保留后续行内编辑、多条展开、预计输出路径与风险提示、手动设置优先等功能。

## 修正

1. 两个中心共享物理高度动画：350ms 平滑展开/收起，不缩放文字和输入控件；完成后释放高度，不留下固定高度裁切。中途反向切换承接当前高度，系统/应用“减少动画”设置可关闭动效。
2. 解压入口恢复旋转上下箭头及“展开/收起”名称。
3. 按实际详情容器宽度（以 rem 适配字体缩放）切换两栏/上下布局，不只看窗口宽度。宽窗口保留配置、执行两栏；不足时配置完整呈现，日志区下置。宽布局内部可滚动，窄布局由任务列表滚动，不用横向隐藏掩盖列溢出。
4. 压缩参数卡片等高对齐；标题允许正常换行，功能按钮按可用宽度排布且显示文字，不再硬塞三列后省略。

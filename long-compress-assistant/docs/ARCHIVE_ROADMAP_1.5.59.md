# v1.5.59 ZIP Bzip2 跨流程兼容（待开发）

2026-10-22。五模块按 v1.5.58 的完成边界收尾后，正式回到格式、算法、密码、卷型与容错兼容主线。本文仅规划，未开始本版运行时开发。

## 先解决一个实际断点

项目已能创建、浏览与提取 Bzip2 ZIP，但 `zip_edit.rs` 与 `source_comparison.rs` 仍明确限制原方法为 Store/Deflate。用户拿到或自己生成 Bzip2 ZIP 后，不能沿同一流程编辑资料或比较内容。本版以这一种方法打通读取、密码、取材及结果，不再增加阅读器或其他大模块的扩展阶段。

## 推进顺序与完成范围

1. **独立普通 Bzip2 ZIP。** 先复核现有方法 12 解码与写出路线、条目边界和 CRC；扩展编辑目录与实际读取、文件夹/ZIP 对比与所选内容核对。复用已有编解码器，不只解除方法白名单。
2. **密码与完整卷组。** 沿现有 AES/ZipCrypto、编码及完整数字/标准卷读取路径接入可适用的比较、精确取回与补充取材；保持来源版本。编辑原件的卷型边界单独保留，不把分卷取材等同于原生分卷回写。
3. **另存与流程接续。** 编辑后的独立新 ZIP 继续原修改清单、冲突复核、密码与结果。原条目方法和必要元数据只有实际能保持时才保留；需要改写为其他方法时明确说明，不能悄悄声称无损。草稿、历史、失败纠正、资料库/工作流适用入口按同一范围贯通。
4. **异常可处理。** 分清未知方法、错误密码/编码、缺卷、截断及内容损坏。失败保留来源与既有结果，不把未读完整条目标成可用；能够沿原救援流程处理的提供原入口。

只检查本版新增方法及受影响路径的真实内容、独立回解和必要宽窄显示，保留 v1.5.34 创建与既有读取依据，不重复旧全格式矩阵、盘满、媒体压缩或个人安装。

## 之后的主线

- 按同样粒度处理 ZIP LZMA、Zstandard、PPMd 在新旧流程中的实际兼容缺口，每版选择有限的方法与密码/卷型组合，不把全部算法塞进一个小版本。
- 继续评估 ALZ Obfuscated Deflate（方法 3）、EGG 加密固实、ZPAQ 原生多部分/损坏事务取回等未完成项。须先有真实正向来源和可独立确认的内容，不能用改方法标记或未验证组合冒充新增支持；据可行性再写具体实施版本。
- 每种新增支持都延伸到适用的创建/转换、浏览、预览/阅读、提取、编辑/对比/索引/工作流与统一结果。性能随真实重复读取和等待逐版改进，不重新无限扩展大模块。

原单条展开、多选弹窗、自然继承、压缩/解压 50/50 与窄窗滚动保持。对具体方法、密码及卷型的支持只按当版真实交付说明。

# 已提交解压结果的清理告警

## 代码审计与修复

基线 `master@78738b1`。原需求是准确表达任务最终结果，而不是把所有后续异常都算作解压失败。

- 已确认普通解压提交后的清理失败只记警告，但 `resolve_pending_extraction` 在成功提交之后执行 `pending.staging.cleanup()?`，可能把已落盘的成功结果误报为失败。
- 两条成功提交路径统一使用 `cleanup_after_commit`，仅返回可选警告，继续既有完成流程。日志说明“输出已提交”“无需重新解压”，包含临时目录和系统错误详情。
- 未提交的失败、回滚错误和待处理冲突仍沿用原错误路径；没有把这些故障降级为警告。取消、覆盖策略、源文件清理选项未变更。
- 清理失败时不把对象标记为已清理，仍保留原有 Drop 重试；警告表示当次尝试失败，不保证进程退出后目录一定残留。
- 版本 1.3.2、schema 8 不变，历史旧记录不回写。

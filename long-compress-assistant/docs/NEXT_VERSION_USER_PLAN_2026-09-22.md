## 本轮交付：历史“看不见”后的可用操作

用户：“上个月的任务怎么没了？不要让我重新解压，我只想看原来的结果。”

- 保持默认最近 30 天，不为了测试通过改成默认全部时间。
- 有已加载记录但筛选无结果时，解释记录可能被筛选隐藏，提供一键重置关键词、类型、状态、失败类别、时间范围。
- 明确只展示已加载记录，最多 500 条，不承诺读取了整个历史库；没有记录时不显示无效按钮。
- 中英文文案同步；按钮不发后端命令，不修改历史，不启动解压。
- 测试固定 `Date.now` 并在每例后恢复；原 9 条断言保留。新增过期记录找回、30 天精确边界（边界保留、早 1 ms 排除、全部时间可见）。新增找回场景先在无按钮旧实现失败，修复后通过。
- 新场景最初把应用初始化命令误算为重置动作；核对后改为比较点击前后的完整调用列表，验证按钮不产生任何额外命令，而非忽略写入命令。
- 正式 `npm run test:unit` 58 文件 **377/377**、类型检查/生产构建、diff 检查通过。属于组件和模拟命令验证，未执行真实桌面验收，不改写上轮文件选择器阻塞记录。

## 后续能力，按用户价值排序（尚未承诺版本）

1. **失败后下一步可操作**：确认的损坏/缺卷/占用分别给出对应动作，衔接现有完整性诊断、重新选择来源、新输出目录；未知原因必须保持未知。不能把所有失败都引向试密码或重跑。
2. **完整历史检索**：后端分页/查询与前端加载更多配套，解决超过 500 条后找不到旧任务；验收需含跨页筛选、不重复、不遗漏、明确计数。不能只把本地筛选按钮改名为“全部记录”。
3. **重启后保留未保存结果**：设计最小持久待保存队列，落库成功再清理；模拟数据库写入失败与进程重启，禁止为保记录而自动重跑压缩。先定义恢复状态与去重规则再实施。
4. **从历史重建任务更可信**：版本化保存非敏感配置快照，显示“哪些恢复了、哪些需重新确认”；不持久化明文密码，不把缺失参数猜成原配置。

这些是本项目代码审计后的建议，不是已经交付的功能，也不是外部竞品研究结论。

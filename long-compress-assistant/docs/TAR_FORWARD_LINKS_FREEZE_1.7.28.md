# v1.7.28 · TAR.LZO 前向链接兼容提取封板

日期：2026-10-29。

## 实现与用户行为

完整 TAR.LZO 的目标解析由“只能引用此前已确认内容”扩展为“完整读取结束后确认唯一直接内容目标”。浏览和完整提取共用目标身份解析器，目标在链接前后均可，不能引用另一条链接、目录、重复歧义或缺失目标。普通、空文件、GNU 长名称、局部 PAX 和本版原件中的旧 GNU / PAX 1.0 稀疏内容可沿原入口取回。副本是独立文件，使用各自编码修改时间，原目标无需选中。

浏览完成外层尾部与内容校验后才发布最终逻辑大小；前向预览完整确认后按原身份重放目标，两遍共用原 64 MiB 扫描预算。普通/后向预览的短路径与原图片/文本限制保持。正常与精确所选提取复用已有计划、物理顺序解码、已选副本和暂存事务，没有为每条链接重复解码原包；目录、筛选、平铺、冲突确认、来源版本和取消接通。

专用前缀抢救仍在首个未确认条目停止，不从缺卷/损坏尾部推断前向完整内容；完整检查和诊断沿完整计划确认，避免正常可取回的前向包被误判只能抢救。前向链接的转换与嵌套物化明确留待后续，当前提示先正常提取后压缩/打开；原有后向链接流程保持。

## 原件与检查

- 原件由 GNU tar 1.35 对真实 Linux 硬链接执行创建、删除原内容条目、拼接另一份 GNU 创建的内容归档得到，没有手写/改写原件头。普通、GNU、PAX 三组固定 SHA，各含混合前/后向引用；GNU/PAX 的后置内容另包含稀疏写入。GNU 普通单遍解压会因前向目标未出现失败，故独立生产者基准分两次按目标内容、剩余条目顺序提取，核对 inode 与 SHA；修改时间另按独立 TAR 头核对，副本和目标编码日期不同。
- GNU PAX 稀疏条目的删除曾触发生产者工具失败，最终配方先删除普通内容记录，再拼接由官方稀疏写入器生成的目标；未把工具失败后的文件当原件。最终三组配方与基准全部完成。
- 新原生 6 项通过：三组真实原件及数字卷的浏览、文本/图片/稀疏前缀预览、完整检查与诊断；完整/所选提取、内容及自身日期；目录、筛选、平铺、时间关闭、独立关系和冲突接续；缺尾、缺卷、来源变化与取消；缺失/重复/链条/循环/目录/带正文目标拒绝；转换和嵌套未接通提示及暂存清理。初轮一处断言错误地要求仅选择单份普通内容也应减少数据量，校正后仅重跑受影响项，其余通过项保留。
- 相关旧 4 项通过：浏览与完整提取对未确认目标的拒绝、预览累计预算和大图片限制、原前缀抢救停止边界。旧用例移除了本版已支持的完整前向引用反例；未重跑无关矩阵。
- 独立核对 3 组原件的 44 个编码条目：官方 LZOP 1.03 解出字节与固定 GNU TAR 一致，Python TAR 解析核对逻辑内容及各自日期，再核对 9 份原生完整/所选输出的精确目录树、101 个条目、83 个文件 SHA/日期及原件保持；数字读取源独立拼回比较。没有用项目读回结果代替外部原件基准。
- Shell DLL、八处版本身份与差异空白通过。UI 源码未改，没有控制桌面，也未重复前端或已通过的无关检查；正式 Windows/前端构建、安装器及签名附件由本版 CI/Release 接续。

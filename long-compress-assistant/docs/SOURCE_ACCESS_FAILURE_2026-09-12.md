# 源文件检查失败：实现与接续

## 需求对齐与纠偏

沿用原规划的“失败时给出实际原因和阶段”，不新增功能中心。基线为 `master@faea49f`，版本仍为 1.3.2，数据库 schema 仍为 8。

实际代码入口曾用 `is_file()` 将目录和元数据访问异常统一转换为文件不存在；后续快照复查则直接返回未分类 I/O 错误。本轮用统一元数据检查代替入口布尔判断，保留系统错误正文。

- `source-missing`：系统返回 NotFound，说明源文件不存在或已移动，建议重新选择。
- `source-unavailable`：权限或其他元数据检查异常，显示“源文件无法检查”，保留系统详情，不推测为磁盘损坏或密码错误。
- `source-invalid`：源路径存在但不是普通文件，提示选择压缩包文件。
- 入口与密码检测后的复查记录 Pre-checking；引擎返回后的复查记录 Extracting。历史保存、筛选、详情、诊断导出均识别类别；前端不会再次进入密码重试。
- 元数据可读不等于文件内容一定可读；本轮不宣称覆盖引擎读取载荷时的所有 I/O 故障。旧无标记记录继续保持未分类，不回写猜测。
- 不改变现有暂存对象的生命周期、冲突策略和发布顺序。复查失败提前返回仍由暂存对象 Drop 清理，不能提交未经确认的结果。

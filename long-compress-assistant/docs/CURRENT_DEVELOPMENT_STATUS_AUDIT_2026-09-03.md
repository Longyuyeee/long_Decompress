### 2. 压缩任务详情密度

组任务与单文件任务均启用紧凑智能分析、紧凑压缩设置和紧凑存储预检。760 px 断点不再把核心参数强制改为单列；全部业务设置、左右双栏、有界高度和配置/日志独立滚动均保留。

已通过聚焦组件 10/10、类型检查、Chromium 响应式回归、带测试桥前端构建、Rust Release 构建，以及真实 Windows Tauri/WebView2 的 920×620、760×520 压缩/解压详情门禁。完整记录见 [COMPRESSION_TASK_DETAIL_DENSITY_AUDIT_2026-09-03.md](COMPRESSION_TASK_DETAIL_DENSITY_AUDIT_2026-09-03.md)。

### 3. Node 20/22/24 桌面门禁兼容

桌面脚本不再顶层依赖 Node 22.12.0 不提供的 `zstdCompressSync`。小型 Zstandard 能力夹具改为脚本内生成标准单段 raw-block frame，不改变产品归档引擎。

默认 Node 22.12.0 已通过真实响应式桌面门禁；34 字节 frame 被产品随包 7-Zip 26.02 正确识别并完整校验。完整记录见 [DESKTOP_E2E_NODE_COMPAT_AUDIT_2026-09-03.md](DESKTOP_E2E_NODE_COMPAT_AUDIT_2026-09-03.md)。

### 4. 归档浏览门禁夹具生命周期

审计确认 `archive-browser-only` 曾把一键解压输入继续用于后续诊断和修复。当用户合法启用“解压后移入系统回收站”时，测试临时 ZIP 会被回收，后续读取报 `ENOENT`；这不是产品解压错误。

门禁现于解压前复制独立诊断源，后续健康诊断、非破坏修复和容量阻断使用该副本，不读取或修改用户偏好。Node 22.12.0 下完整真实归档浏览门禁已经通过，覆盖 Zstandard 能力菜单、180,000 条目 TAR 取消、长路径 ZIP、加密 7Z、固定加密 RAR、选择性解压、预览、默认应用打开和非破坏修复。完整记录见 [ARCHIVE_BROWSER_FIXTURE_LIFECYCLE_AUDIT_2026-09-03.md](ARCHIVE_BROWSER_FIXTURE_LIFECYCLE_AUDIT_2026-09-03.md)。

## 偏离审计

当前没有偏离最初路线：本轮都在修复前序审计明确列出的压缩详情密度，以及保证既有真实桌面验收可复现。没有扩展产品功能、改变压缩/解压事务、削弱资源预检，也没有擅自升版或发布。

两个过程中发现的偏差均已按实际原因纠正：

1. 测试脚本使用超出已声明 Node 范围的顶层 API，已改为可移植夹具。
2. 归档浏览门禁错误假设用户关闭源包回收，已改为独立诊断夹具，不修改用户选择。

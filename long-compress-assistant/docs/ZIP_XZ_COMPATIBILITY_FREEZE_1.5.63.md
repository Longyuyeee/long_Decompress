# v1.5.63 ZIPX（XZ）跨流程兼容封板记录

2026-10-22。实施见[路线](ARCHIVE_ROADMAP_1.5.63.md)，用户说明见[Release](RELEASE_NOTES_1.5.63.md)。

## 实际范围（功能已封板，进入发布）

- ZIP 方法 95 的独立普通/AES/ZipCrypto ZIP/ZIPX 接入原编辑与资料对比。ZIPX 浏览入口可直接整理，默认后缀、保存对话框、标题、按钮和任务格式准确；方法 95 的 `.zip` 来源也默认建议 `.zipx`，仍允许明确另存 `.zip`。
- 非空普通保留条目复制原压缩数据，密码条目按原方法重编码；空 XZ 条目沿既有 ZIPX 创建规则仅存储，内容、元数据与密码设置保留。新增/替换及所选组包明确 Deflate/Store。原件、已有输出与原失败保留，不冒称全部元数据无损。
- 文件夹↔ZIP/ZIPX、归档↔归档的实际内容核对、精确取回、所选取材、完整数字卷与标准 `.zxNN/.zipx`、明确密码编码及原草稿/历史共用原流程，不做原生分卷回写。
- 保留原单 XZ 流解码器、校验和资源行为，新增实际大小、完整结束和载荷消耗检查；额外尾部（包括填充或后续流）拒绝，空读取不初始化。不是独立 `.xz` 或全部 ZIPX 方法的扩展，无新依赖或资源限制。
- 原单条展开、多选弹窗、自然继承、压缩/解压左右等宽、窄窗滚动和 schema 18 保持。只补入口、正确名称和支持提示。

## 新增与受影响检查

九项不同 Rust 已完成：普通原字节/方法/备注/时间/权限及新增；AES/ZipCrypto、明确 CP936、保留/去密码/换密码与空文件；错误/缺密码和已有输出保留；实际内容核对；数字卷取材的精确范围、来源变化/缺卷与编辑边界；CRC/大小/截断拒绝；真实 Python/liblzma XZ 流原字节另存、空 XZ 规范另存及独立 7-Zip 回解；尾部/头校验/截断、额外数据/后续流、伪造匹配 CRC 的前缀大小拒绝；流式空读取与 `.zip` 别名输出。

首次测试编码器引用了产品未启用的 XZ 编码特性，改为独立 Python/liblzma 生成样本，没有为测试增加产品功能或依赖。首次八项通过；独立回解指出填充与空 XZ 的 ZIP 互通差异，收紧尾部检查并把空条目规范为 Store，只接续这一正向项与受影响的尾部反例，其余成功项保留。真实内容是实际 XZ 编码，不用修改标记的 Store 数据当支持证明。

六项前端命名/默认后缀/任务身份/恢复检查通过，八处版本身份/Shell DLL 通过。最后补 ZIPX 提示文案后仅更新最终类型/Vite 与桌面资源构建，不重跑六项无关逻辑检查。原生 `custom-protocol,desktop-e2e` 构建完成，最终桌面 SHA-256：`68a2a0b8d65832e2df7d23d6dd69e2cc9bc718f2e91bbab287b23af37e9378a5`。四条真实桌面组合、18 条宽窄显示、6 图实看首轮通过，见[原始记录](evidence/zip-xz-compatibility-1.5.63/desktop-progress.json)与[检查收据](evidence/zip-xz-compatibility-1.5.63/checks.json)。这是检查程序身份，不当作正式安装包身份。

1. 独立 Python/liblzma 生成真实方法 95 的 ZIPX，直接在浏览器单条右键改名/移动，默认 `.zipx` 名称正确，再添加文件另存；7-Zip 回解、原 XZ 方法与新增 Deflate 正确。
2. AES ZIPX 错密码失败不产输出，修改清单保留；纠正密码并设置新 AES 密码后另存成功，原失败保留，独立回解内容和 XZ 方法正确。
3. AES 数字 `.zipx.001` 卷组从非首成员读取，缺密码核对未完成，补密码后内容相同；弹窗只取所选文件。正常退出/重启恢复精确范围且密码为空，补密码取回及历史再取回均只产所选内容。
4. ZipCrypto 原生标准 `.zxNN/.zipx` 从非首成员读取，归档↔归档内容核对、缺卷拒绝/补齐、所选引用组包完成；按明确 Deflate/去密码输出独立 ZIP，7-Zip 回解仅含所选内容，全部原件和原卷组 SHA-256 保持。

桌面全部对应上述最终程序，没有因脚本问题重复完成组合；已通过的原生/前端逻辑保留，只接续有实际变更影响的检查。

复用 v1.4.18 既有 ZIPX 创建/转换与原标准卷互通依据，不重跑旧全格式/密码/算法/媒体矩阵、真实盘满或个人安装。候选、正常合入、标签和正式附件收据在本版 PR 接续，不为回填再提交打包。

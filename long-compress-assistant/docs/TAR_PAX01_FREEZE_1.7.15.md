# v1.7.15 · PAX sparse 0.1 部分取回封板记录

日期：2026-10-28。

## 已完成

TAR.LZO 恢复读取支持局部 PAX sparse 0.1：以 `GNU.sparse.map` 识别元数据逗号图，核对 `GNU.sparse.size`、`numblocks` 和 `name`。该布局没有 1.0 的 major/minor 声明与条目内文本图；两套属性混合时停止，不猜正文起点。全局 sparse、未知属性、缺失/重复属性、非普通文件和叠加 GNU 长名称仍停止。

图按声明段数逐对读取严格十进制值，核对范围、顺序、逻辑大小及存储总量。保留每文件 65,536 段、总映射和 512 GiB 逻辑量边界，局部 PAX 继续使用已有 1 MiB 元数据上限。头内物理大小直接表示存储数据量；PAX plain size 与之冲突则停止，不能用逻辑大小代替。没有 1.0 的正文图，数据 offset 位于真实文件头之后。

复用已验证的有界 Layout、包含空洞的流式 SHA、Windows 稀疏输出、文件/目录时间、来源重查与取消清理。元数据及其填充、真实头、数据和条目填充都完整并落在外层已校验连续前缀时，才提交可取回条目。真实名称取自专用属性，不展示 GNU 占位目录；取回另存，历史继续标为部分取回，不跨缺口扫描。

界面只在原问号帮助补充 0.1 支持。原筛选、目录联选、完整/包内大小、折叠结果与原历史保持；单条展开、多选弹窗、等宽双栏和主题不变。没有修改正常完整读取器、稀疏写入或时间恢复实现。

格式依据：[GNU tar PAX 0.0/0.1 说明](https://www.gnu.org/s/tar/manual/html_node/PAX-0.html)。

## 原件与检查

原件见 `tests/fixtures/archives/tar-pax01-1715/`：从固定 SHA 的 v1.7.14 项目自编源文件中取材，GNU tar 1.35 以 `--sparse-version=0.1` 生产新布局，官方固定 SHA lzop 压缩并完整回解一致。十个条目覆盖中文长名称、目录、少/多段、全零、大空洞及后续普通文件。源文件、GNU、Python 逻辑 SHA 一致；GNU/源路径确认真实名称，Python 只作独立内容依据。96 数据段样本的局部元数据为 1,433 B，明确跨多个块；manifest 保存物理边界、映射、逻辑清单和来源/工具 SHA。异常构造单独记录，不冒称其他生产者兼容证据。

- 新原生 7 项全部通过：完整原件浏览/完整性/健康诊断；坏尾、坏校验与缺结束标记的实际取回和子集；元数据载荷/填充、真实头和数据截断；逗号图/段数/范围/版本/类型/大小冲突；相同源大小/时间及逻辑内容但不同图的 revision；缺中卷与补卷重查；小数据填充、零段文件和元数据扫描取消。首轮编译发现重复测试助手，去重后七项运行通过，未重复成功项。
- 相关旧原生 2 项通过：PAX 1.0 完整原件及版本/类型/物理大小规则。旧 GNU、时间、默认应用、更新和其他格式的未受影响矩阵继续复用。
- 前端 2 项通过：真实名称、逻辑/包内大小与零数据；所选稀疏文件/目录的原折叠结果及逻辑字节历史。
- 独立 Python 核对 4 份实际输出、25 个文件的逻辑 SHA、精确树、明确修改时间及 Windows 稀疏分配。64 MiB 样本包内 512 B、实际分配 64 KiB；1 MiB 全零文件包内及实际分配均为 0；16 MiB 多段样本包内 393,216 B、实际分配 6 MiB。原件 SHA 未变。
- 后台真实 Vue/CSS 回放本版原生报告和结果，3 组通过：零数据筛选、宽窄结果及两种大小、所选子集与原部分历史。1100×700、760×520 无横向溢出，底部按钮可见，详情可滚动；六张截图逐张查看。IPC 明确为回放，没有接管桌面。
- 类型/Vite、版本 Shell DLL 与 8 个版本来源身份通过。正式 Windows 安装器和更新清单以对应提交的 CI/Release 为准。

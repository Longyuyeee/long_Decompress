# 历史错误检索与诊断报告（2026-09-12）

## 需求与方案

接续 PR #125 和当前升级规划。实际历史模型只有 `errorMessage` 与日志，未存独立错误类别/阶段；上一轮提供了稳定的 `archive-inspection` 标记。

本轮采用兼容的读取层解析：只有已保存标记能提供类别，只有检测标记/检测失败前缀能证明检测阶段。未标记旧记录显示“未分类、阶段未知”，缺失原因显示“原记录未保存具体失败原因”。不根据“数据错误”猜测文件损坏，不修改旧数据库。这是结构化错误全面落库前的可交付步骤，不能声称所有引擎已产生结构化错误。

## 完成内容

- `src/utils/taskFailure.ts` 提供共享错误描述：类别、阶段、依据及原始消息；未知新标记向后兼容为未分类。
- 历史搜索包含错误正文和类别名称，新增失败类别筛选；与原类型、状态、日期条件组合。
- 详情展示最终原因及已知类别/阶段；成功和取消记录不按失败解析。
- 用户选择路径后通过既有 `write_text_file` 命令导出 JSON 报告，不新增后端文件写入接口。已核对该命令注册且支持 `.json`。
- 报告包含选中任务的保存路径、时间、格式、字节指标、错误和日志，带 schemaVersion、导出时应用版本与时间。应用版本不冒充原任务执行版本；日志保留上限及旧信息缺失明确说明。
- 保存对话框取消不写文件；写入失败显示错误且允许重试。导出期间固定选中记录快照，不因用户随后切换选择而串任务。

## 验收及边界

- 类型检查和生产前端构建通过；历史视图、错误描述、任务 store 定向 25/25 通过。
- 回归覆盖已知/未知/缺失分类、成功记录排除、正文搜索、旧失败筛选、选中任务导出、取消不写入、写入失败反馈与重试按钮恢复。
- 本轮不重跑用户源归档、不迁移历史数据库、不改变解压执行和密码逻辑；UI/IPC 接线由组件测试验证，不冒充正式安装版手工操作。
- 版本保持 1.3.2。下一步仍是所有引擎一致输出类别和真实阶段、历史任务配置重建，以及退出应用后的未保存记录恢复。

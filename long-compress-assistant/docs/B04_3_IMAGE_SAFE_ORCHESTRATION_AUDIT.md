# B-04.3 图片安全批量编排审计

审计日期：2026-08-28（Asia/Hong_Kong）

开发分支：`codex/archive-media-roadmap`

公开基线：`v1.1.14`；本节点不升版、不生成 Release、不启用图片执行按钮。

## 1. 开发目标与边界

B-04.3 将前端同源设置准确映射为后端图片请求，在后端真实文件系统上生成确定目标路径，并建立逐图唯一 task id、顺序批量执行、按终态文件数计算的进度和统一取消。目标规划不得绕过 B-03 的暂存、验证和原子发布事务。

本节点不把图片子任务写入统一 task store，不写完成/失败/取消历史，也不展示真实结果图；这些分别属于 B-04.4 和 B-04.5，因此“开始图片压缩”按钮继续禁用。

## 2. 预期、实际与修正

| 检查项 | 预期 | 开发前实际 | 本节点修正与实际结果 |
| --- | --- | --- | --- |
| 命令契约 | 前端能调用目标规划和单图压缩命令 | `src` 中没有 `compress_image_file` 调用 | `useTauriCommands` 新增强类型规划与压缩封装，载荷保持 camelCase 契约 |
| 确定目标 | 默认生成与源文件不同的稳定名称 | 没有目标路径生成逻辑 | 后端按真实源文件名生成 `<stem>.compressed.<ext>`，默认输出到源目录或明确输出目录 |
| rename | 现有文件和同批预留路径都不能被覆盖 | 后端只会因目标存在而失败 | 后端逐项查找 `<stem>.compressed (n).<ext>`；真实磁盘占用和同批预留共同参与判定 |
| skip | 冲突时明确跳过且不改动现有字节 | 没有 skip 映射 | 返回结构化 `skipped` 计划；真实现有文件逐字节保持不变 |
| replace-if-smaller | 候选必须小于源文件，不得借策略覆盖既有目标 | 只有服务层 `onlyIfSmaller`，目标存在仍安全失败 | 前端只将该策略映射为 `onlyIfSmaller=true`；若目标已存在，规划仍显式失败关闭，不降低 B-03 禁止覆盖边界 |
| 批内隔离 | 每张图使用唯一 task id，目标不能互撞 | 没有批量执行器 | 执行前验证 task id 全部唯一；已规划目标作为 `reservedDestinations` 传给后端 |
| 真实进度 | 仅按已完成/跳过/失败/取消文件数更新 | 草稿进度恒为 0 | 每个文件进入终态后计算 `settled / total`，不从离散阶段伪造编码百分比 |
| 统一取消 | 取消当前后端子任务，未启动项不再编码 | 没有图片批量取消 | 批量执行器调用既有 `cancel_compression` 边界；活动项和未启动项均返回 cancelled |
| 规划期竞态 | 规划尚未返回时取消，不得随后启动编码 | 第一轮实现只在循环开始检查取消 | 聚焦测试暴露该窄窗口后，在规划返回/异常处再次检查取消；实际 `compress` 调用次数为 0 |

## 3. 真实测试证据

固定真实文件来自 `test-results/media-fixture-audit/fixtures/images`，并与冻结清单字节数核对：

- `exif-orientation.jpg`：15,788 B；前端实际映射为 WebP、320 × 180 限制、rename、`onlyIfSmaller=false`；
- `transparent.png`：1,546 B；skip 计划不会触发编码；
- `photo.webp`：用于活动任务取消和规划期取消；
- Rust 在真实临时目录创建既有目标与重命名冲突，确认 skip 保留原字节、rename 越过磁盘占用和批内预留、replace-if-smaller 对既有目标失败关闭；
- Rust 使用规划得到的目标实际压缩透明 PNG，重新读取输出并核对格式与真实文件字节数。

预期进度为两项批量 `[50, 100]`，实际为 `[50, 100]`；取消三项批量时，实际只向活动 task id 发送一次取消，三项终态均为 cancelled。规划期取消的第一轮实际行为存在潜在启动窗口，修正后真实测试确认没有调用编码命令。

## 5. 审计结论与下一接续点

B-04.3 已完成。规划由后端真实文件系统权威决定，批量编排只报告真实文件终态，取消不会在规划结束后误启动编码，现有文件和 B-03 发布事务均未被绕过。

下一步严格进入 **B-04.4 队列与历史**：把图片子任务接入统一 task store，以 `taskType=compression`、`workloadKind=image` 和后端输入/输出事实写入完成、失败、取消历史，并验证跨重启读取。在 B-04.4 完成前仍不得启用按钮或用预计值填充结果与历史。

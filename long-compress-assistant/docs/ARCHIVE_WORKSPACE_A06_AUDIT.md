# A-06 正式安装态综合矩阵审计

日期：2026-08-26

分支：`codex/archive-media-roadmap`

公开基线：`v1.1.13`
安装态候选：仅用于覆盖安装验证的 `1.1.14`，本步骤提交不升版、不发布

## 1. 开发目标与结论

A-06 的目标不是再次证明开发版能运行，而是验证同一份正式候选二进制经过 NSIS 覆盖安装后，仍能完成归档浏览、安全打开、选择性解压、卸载与基线恢复。最终矩阵全部通过，大节点 A 的产品能力与安装边界已收口；下一步可独立执行 `v1.1.14` 发布准备，不在本节点提前引入图片、视频或 PDF 压缩。

## 2. 预期—初始实际—修正

| 项目 | 预期 | 初始实际 | 修正与最终实际 |
| --- | --- | --- | --- |
| 候选身份 | 安装后的 EXE 必须等于本次候选构建 | 同版本覆盖安装可能沿用旧文件，无法证明测试对象 | 安装脚本增加候选 EXE SHA-256 对账；用临时候选身份覆盖安装，最终字节一致 |
| 正式运行边界 | 安装版不得带桌面 E2E 测试桥 | 旧门禁只验证开发 Release | 安装后直接由 tauri-driver 启动，确认测试桥不存在 |
| 预览后继续操作 | Esc 关闭预览，后续右键不被遮罩拦截 | 真实运行中 Esc 未关闭文本预览，后续步骤超时 | 统一弹层 Esc 优先级并补单测；正式安装态复验通过 |
| 解压完成判定 | 完成后才允许切换归档 | 首个文件出现时任务可能仍在事务收尾；短时 Toast 也可能被轮询错过 | 门禁同时等待预期磁盘内容与操作按钮恢复，消除提前切换与瞬时提示竞态 |
| RAR 密码语义 | 正确密码输出固定内容；错误密码不应被误判为“目录不可读” | 固定 RAR 只加密正文，错误密码仍可合法读取目录 | 安装态验证正确密码与固定 SHA-256；错误密码无明文发布继续由既有真实 Release 专项门禁负责 |
| 损坏包提示 | 等到可读的中文错误正文 | Toast 容器先出现、正文稍后更新，脚本偶发读到空串 | 等待正文匹配“损坏/结构/格式”后记录，最终显示“压缩包结构损坏或内容不完整” |

## 4. 分层验收边界

- A-06 安装态覆盖用户可见的工作区、格式、嵌套、安全和安装生命周期。
- 路径穿越、错误 RAR 密码不发布明文、超大预览预算、磁盘容量保护、事务回滚等底层安全项由 A-03/A-04/A-05.2 及全格式真实桌面门禁继续承担，不用脆弱 UI 假设重复模拟。
- Windows 11 顶层原生菜单仍受签名身份限制；无证书环境按既定范围验证经典菜单，不把“更多选项”限制伪装成已解决。

## 5. 本步骤验证

- `npm.cmd run test:unit -- --run src/views/__tests__/ArchiveBrowserView.test.ts`：40 个测试文件、234 项全部通过。
- `npm.cmd run tauri build`：临时 `1.1.14` 正式 NSIS 候选构建成功；因未配置签名证书，按设计跳过 Windows 11 identity package。
- `npm.cmd run test:installed-release -- ... -RunArchiveWorkspaceMatrix`：安装、工作区矩阵、卸载及 `v1.1.13` 恢复全部通过。

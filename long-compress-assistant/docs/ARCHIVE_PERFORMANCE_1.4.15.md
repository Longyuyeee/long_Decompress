# v1.4.15 大包及海量文件流程优化实施审计

## 当前状态（2026-10-17）

用户批准[十二版本路线](ARCHIVE_ROADMAP_1.4.15_TO_1.5.5.md)入文档并恢复开发。本版从 `458b14b` 接续，分支 `codex/v1.4.15-archive-performance`；公开仍为 v1.4.13，v1.4.14 候选未发布。本版尚未升版、封板或发布，不修改用户安装目录、个人任务与历史。

## 本版范围与步骤

1. 对照用户流程和实际代码，建立可复跑的海量小文件/大文件测量，记录耗时、内存、重复读取和取消；先保留基线。
2. 优先优化任务内可可靠复用的 ZIP 元数据、选择范围和密码检查，不能以减少校验、忽略混合密码或复用过期源文件换速度。
3. 分别检查 TAR 完整暂存成本与 RAR 进度扫描；只实施确有收益且可验证的项，未完成部分如实列明。
4. 每步定向回归、真实内容对比、审计和推送；UI 若改变，实际查看常用/窄窗口页面。最后完成真实应用链及本版封板发布流程。

## 阶段二：ZIP 任务内复用加密索引

### 实施与审计

- 在既有 `ZipSelection` 扫描中保留所选加密条目索引。提取前只对这些条目做密码预检，不重复打开所选明文文件、初始化其解码器或定位数据。
- 完整密码尝试使用同一索引，避免再次读取所有明文条目的元数据；只有确实读取加密文件时才分配内容校验缓冲。
- 预检增加取消检查，保留全部所选加密条目的检查、实际提取时完整 CRC/内容校验、混合密码范围和 UTF-8/本机编码短头碰撞兼容。没有跨任务缓存、没有复用旧源文件、没有 UI 或默认并行设置改动。
- 对照 `f2a22b2` 的原函数，原明文预检只初始化解码器并不读取完整内容；去掉它不等于去掉内容校验。完整性仍在真实提取和密码验证的完整读取中检查。

## 阶段七：TAR.LZ4 / TAR.BR 有界流式创建

### 实施与审计

- 先收集与原 TAR 路径相同的条目，再创建目标；原 TAR 写入器接入 2×64 KiB 有界通道与 64 KiB 写缓冲，消费者继续使用原 LZ4/Brotli 拉取编码 API。没有完整 TAR 磁盘副本，也不把整个 TAR 放入内存。LZIP 与其字典上限保持不变。
- 源文件读取与既有条目/时间戳规则复用；保留编码结束、flush、sync、数字分卷及服务后续校验/发布。LZ4 保持内容校验和，流式帧不再提前写入未知的内容大小；单文件 LZ4 仍提供大小。
- 出错先关闭接收端再等待生产线程，避免队列满时无法结束；生产源文件错误不能被编码器的正常 EOF 掩盖。取消仍返回原有取消类型，磁盘满/编码结束错误保留真实原因。进度以实际源字节更新，预留编码结束和后续阶段，不提前宣布任务成功。

### 定向回归与独立回解

- Release 编解码/桥接 **12 个用例**及原 TAR **4 个用例**通过；另有两个显式 ignored 的测量/产物导出入口，不算功能用例。新增覆盖有界写入、源文件消失、消费者磁盘满不死锁、取消退出、编码结束写出失败。没有放宽原断言。
- 首轮固定 GNU LZIP 回归失败：Git 中原文件为 LF 58 字节，Windows 检出后为 CRLF 59 字节。给该固定载荷添加 `-text` 检出规则，并恢复为 Git 原始字节（SHA256 `0de8963d45a6bea509b9594357dc9e1bf03238bc658de21ca81085b378ac4579`），之后通过；不是修改预期迁就程序输出。导出工具首次编译的返回类型错误已修正，失败运行不计成功。
- 真实流式产物经独立 Python `lz4.frame` 4.4.5、Node Brotli 解码，完整 TAR 字节与原生 TAR 参考逐字节相同；Windows bsdtar 再提取核对中文目录、全部三个文件内容及空目录。报告见[独立回解](evidence/archive-performance-1.4.15/tar-independent.json)，脚本 `verify-tar-stream-outputs.mjs`；Python 依赖仅放在本次忽略的测试目录，没有改项目/全局依赖。

## 阶段八：RAR 预检查不再阻塞异步工作线程

- 实际代码确认 RAR 解压前统计在异步函数内逐条同步读取/skip，原来没有任务控制检查。现将同一原生 SDK 扫描移至 `spawn_blocking`，打开、读条目和 skip 前后调用现有暂停/取消入口；仍完整统计文件数/展开字节，保留溢出、资源限制与磁盘空间判断，没有省略预检换取速度。
- 检查 SDK 调用返回后再处理其错误，用户已取消时保留 `Cancelled` 类型，不误报密码或损坏；未取消时仍保留原 SDK 原因。线程异常另行明确报告。

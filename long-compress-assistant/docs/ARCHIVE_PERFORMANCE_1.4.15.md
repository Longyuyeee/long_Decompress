# v1.4.15 大包及海量文件流程优化实施审计

## 当前状态（2026-10-17）

用户批准[十二版本路线](ARCHIVE_ROADMAP_1.4.15_TO_1.5.5.md)入文档并恢复开发。本版从 `458b14b` 接续，分支 `codex/v1.4.15-archive-performance`；公开仍为 v1.4.13，v1.4.14 候选未发布。本版尚未升版、封板或发布，不修改用户安装目录、个人任务与历史。

## 本版范围与步骤

1. 对照用户流程和实际代码，建立可复跑的海量小文件/大文件测量，记录耗时、内存、重复读取和取消；先保留基线。
2. 优先优化任务内可可靠复用的 ZIP 元数据、选择范围和密码检查，不能以减少校验、忽略混合密码或复用过期源文件换速度。
3. 分别检查 TAR 完整暂存成本与 RAR 进度扫描；只实施确有收益且可验证的项，未完成部分如实列明。
4. 每步定向回归、真实内容对比、审计和推送；UI 若改变，实际查看常用/窄窗口页面。最后完成真实应用链及本版封板发布流程。

## 阶段一：路线与代码核对

- 已拉取远端；基线与 origin 一致，开始时工作区干净。新版本独立分支继承 v1.4.14，不往 PR #168 添加性能改动。
- 已写入十二版本目标，并在开发交接、产品路线和旧暂停记录中标明恢复状态。
- `zip_selection.rs` 已统一所选范围与总大小；`native_extraction/zip.rs` 仍另行逐条打开条目做密码预检，然后实际提取再次打开。需要测量解码器初始化、元数据查找与密码验证成本，不把静态重复直接当作实测瓶颈。
- `zip_password.rs` 的非 ASCII 双编码碰撞兼容依赖完整内容校验，优化不能绕过；未选的密码条目不应影响所选范围。
- `codec_stream.rs` 的 TAR 组合创建先写完整 TAR 暂存文件再压缩，属于待测 I/O 候选，不宣称已优化。
- 本阶段仅维护文档，没有功能或 UI 修改，没有新增性能结果，也不重复旧版本已完成检查。

- RAR 进度扫描、TAR 暂存的实测与取舍。

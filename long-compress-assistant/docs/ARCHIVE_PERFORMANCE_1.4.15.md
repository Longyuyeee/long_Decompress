## 当前状态（2026-10-17）

用户批准[十二版本路线](ARCHIVE_ROADMAP_1.4.15_TO_1.5.5.md)入文档并恢复开发。本版从 `458b14b` 接续，分支 `codex/v1.4.15-archive-performance`；公开仍为 v1.4.13，v1.4.14 候选未发布。本版尚未升版、封板或发布，不修改用户安装目录、个人任务与历史。

## 本版范围与步骤

1. 对照用户流程和实际代码，建立可复跑的海量小文件/大文件测量，记录耗时、内存、重复读取和取消；先保留基线。
2. 优先优化任务内可可靠复用的 ZIP 元数据、选择范围和密码检查，不能以减少校验、忽略混合密码或复用过期源文件换速度。
3. 分别检查 TAR 完整暂存成本与 RAR 进度扫描；只实施确有收益且可验证的项，未完成部分如实列明。
4. 每步定向回归、真实内容对比、审计和推送；UI 若改变，实际查看常用/窄窗口页面。最后完成真实应用链及本版封板发布流程。

## 阶段二：ZIP 任务内复用加密索引

### 实施与审计

- 在既有 `ZipSelection` 扫描中保留所选加密条目索引。提取前只对这些条目做密码预检，不重复打开所选明文文件、初始化其解码器或定位数据。
- 完整密码尝试使用同一索引，避免再次读取所有明文条目的元数据；只有确实读取加密文件时才分配内容校验缓冲。
- 预检增加取消检查，保留全部所选加密条目的检查、实际提取时完整 CRC/内容校验、混合密码范围和 UTF-8/本机编码短头碰撞兼容。没有跨任务缓存、没有复用旧源文件、没有 UI 或默认并行设置改动。
- 对照 `f2a22b2` 的原函数，原明文预检只初始化解码器并不读取完整内容；去掉它不等于去掉内容校验。完整性仍在真实提取和密码验证的完整读取中检查。

### 已通过

- Release 定向用例：提取 12、所选范围 8、通用引擎 9、密码编码 6、原生 ZIP 行为 3，共 **38 个不同用例**。基准与外部真实样本入口的 `ignored` 不计入这个数。
- 新增覆盖：所选加密索引准确、明文预检零新增定位/读取、预检取消、后续不同密码在写出文件前失败。既有受影响检查覆盖未选密码、Zstandard 密码数字/标准卷、损坏不误判密码、编码碰撞、过滤/时间戳及缓冲释放。
- `node --check scripts/measure-zip-preflight.mjs`、`git diff --check` 通过。Rust 仅出现已有 sevenz-rust 的 SeedRead/生命周期警告，未修改无关依赖。

### 同进程 A/B 实测

Windows 10.0.22621、Ryzen 7 9700X（16 逻辑线程）、Rust 1.93.1、Release。原实现保留在 `#[cfg(test)]`，与生产新实现使用同一磁盘文件、同一程序，交替顺序，一轮预热后各测五轮。每次新建归档对象并重新选择；计时只覆盖选择扫描之后的密码预检，不包含解压、UI、事务提交或物理磁盘吞吐。

| 场景 | 原预检中位数 | 新预检中位数 | 逻辑定位次数 | 加密数据读取 |
| --- | --- | --- | --- | --- |
| 5000 个明文文件 | 5.3554 ms | 0.0005 ms | 5000 → 0 | 两者均 0 |
| 5000 明文 + 最后一个 ZipCrypto 文件 | 3.5065 ms | 0.0179 ms | 5001 → 1 | 两者均 63 字节、2 次读取 |

这些结果证明去掉了重复初始化/定位，不代表整体解压有相同比例提速。未测峰值内存或物理 I/O，不据此宣传收益。完整原始观察、机器、源码 SHA256 和测量时的 dirty 状态见[证据 JSON](evidence/archive-performance-1.4.15/preflight.json)。测量期间四个源码/脚本哈希不变；`dirty=true` 是尚未提交的本阶段代码，不冒称已经发布的提交。

复跑：`node scripts/measure-zip-preflight.mjs`。优化前端到端原生引擎三轮基线已在干净的 `f2a22b2` 上完成：32 MiB 大文件、1000 个 4 KiB 小文件及真实混合媒体；所有输出均核对 SHA256。优化后继续用相同输入测量，不能用预检数字代替整条引擎结果。

# v1.6.8 ALZ Bzip2 有界读取

接续 v1.6.5 完整性修复，减少较大旧 ALZ 的整条内存占用并移除单条 256 MiB 压缩输入限制。原计划要求先取得历史原工具大包；本轮 4.99.0.1 实际执行发现旧命令不支持，未取得该原件。为交付可验证的实现增量，范围调整为受控真实压缩流边界和独立完整回解，不冒充原工具互通，详见[来源收据](evidence/alz-bounded-1.6.8/sources.json)。

1. **已完成：有界输入**。32 KiB 读取、最多 4 MiB 当前压缩块窗口，消费后丢弃整字节，保留跨块位对齐与连续密码状态。候选探测预算按实际块计算，不再按整条声明大小购买工作量；输出大小、CRC、EOS、尾随和 I/O 原因沿用。
2. **已完成：越过旧限制**。自有确定性载荷经 Python/libbzip2 编码后明确重封 ALZ，352 个实际块、282,956,568 字节压缩数据；旧 helper 失败，新 helper 校验成功，Bandizip 独立回解与预定 SHA-256 相符。普通/密码/原生组小样同样为受控回归。
3. **应用接续**。原双栏浏览、所选/整包提取、转换和暂停/取消/继续按本版实际桌面记录收口；现有 ALZ 有界文本/图片预览仍未开放，不把双击默认打开误记为已支持预览。当前原有 UI 与交互保持。
4. **发布**。只检查改动影响的解码边界、密码终止分类、应用流程和必要显示；README、版本身份、Release 与交接同步，最终状态见[封板记录](ALZ_BOUNDED_FREEZE_1.6.8.md)，走正常受保护 PR/标签发布。

下一阶段 [v1.6.9 ALZ 包内预览](ARCHIVE_ROADMAP_1.6.9.md)仅规划。历史大 Bzip2 原件、方法 3、EGG 加密固实继续独立保留来源缺口，不重复旧 48 项方法 2 / 20 次拒绝请求，不外推全组合或增加空格式名。

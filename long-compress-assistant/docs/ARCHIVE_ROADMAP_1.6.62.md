# v1.6.62 · LZOP 单文件创建

已完成功能封板。已确认固定 MIT 编码库接口；本版按固定模式、标准分块容器与现有流程推进，不暴露无效的等级、密码或创建分卷选项。目录与旧名称读取阶段完成后，继续格式与算法主线，让用户在原压缩中心直接生成可以交给其他工具读取的 `.lzo`。

1. 先确认现有 LZO 编码器的接口、内存与许可范围，生成符合 LZOP 容器的单文件输出，由官方 lzop 完整回解并逐字节/SHA256 核对。首阶段只承诺已验证方法，不把 LZO 算法裸流当作 LZOP。
2. 在原单条展开和多选弹窗配置中接入格式、输出名称、分析、进度、取消、结果位置与历史。LZOP 不提供原生密码，不让用户填写无效选项；多文件和文件夹仍明确使用合适的归档格式。
3. 接通其他归档到单成员 LZOP 的转换，仅在来源确实满足单文件范围时提供；多文件来源给出可操作提示，不能悄悄丢文件。完整输出验证、冲突和失败暂存沿用现有流程。
4. 覆盖空文件、不可压缩/大块数据、中文与长文件名及取消/输出失败，只补新路线和受影响检查。TAR.LZO 创建、多成员创建、数字切卷创建随后分期评估，不能因读取支持便宣称创建支持。

保留双栏等宽、原有操作、主题和快捷键，不增加常驻说明。ALZ/EGG 的有效外部原件缺口继续保留；取得真实失败包时可按用户影响调整优先级，不以合成样本填补兼容证据。

完成记录：原生创建/校验、实际采样、单条展开/批量弹窗、原包密码转入和多文件拒绝、结果/历史、图文取回及取消贯通。新输出通过官方完整回解 SHA256；实际界面发现的新目录问题已修正，只续跑受影响项，详见 [封板记录](LZOP_CREATE_FREEZE_1.6.62.md)。下一阶段 [v1.6.63 TAR.LZO](ARCHIVE_ROADMAP_1.6.63.md)仅规划。

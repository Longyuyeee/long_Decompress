# 解压运行态界面与跨盘事务审计（2026-09-03）

## 范围与基线

- 基线：公开 `v1.2.5`，`master@e4f79d2`；开发分支 `codex/decompression-runtime-ux`。
- 本轮修复解压运行态信息架构、速度显示、跨盘根目录提交、密码尝试日志和无边框窗口交互；发布阻断闭环后已进入 `v1.2.6` 候选。
- 冻结原则：进度数字缓动只属于显示层，任务存储和后端真实进度不伪造；源压缩包回收失败不得推翻已经提交成功的解压结果；密码明文不得进入日志。

## 六项需求逐条对齐

1. **低高度侧栏不再挤压**：窗口高度不超过 640 px 时，品牌区缩至 56 px，导航保持 40 px 点击高度，仅隐藏次要快捷键和版本行。真实 Tauri 窗口在 920×620 与原生最小尺寸 760×520 下，导航均为 `clientHeight=scrollHeight=354`，8 个目的地全部在可视区域内。
2. **左下任务摘要重构**：环形进度、任务数、任务名、阶段、速度和当前文件均为单行省略；展开/最小化按钮固定在卡片右上角，不再占用文案流。真实活动任务截图中摘要约 77 px 高，`clientWidth=scrollWidth=189`。
3. **未展开任务补足信息**：运行态行新增阶段、当前文件、速度、缓动百分比及连续进度条；完成/失败任务不再保留容易误导的瞬时速度。
4. **展开详情消除结构性换行**：配置/执行栏在真实 920×620 Tauri 窗口中实测为 247/331 px，详情、配置、执行和存储预检的横向溢出均为 0；长路径与日志均单行省略并通过 `title` 保留全文。原“目标存储预检”大卡改为 36–38 px 的“存储预检 / 状态 / 可用空间”摘要。
5. **速度和进度显示纠偏**：后端至少取得 250 ms 非终态观察窗口才发布吞吐，终态单样本不再计算天文速度；任务进入完成/失败/取消时清除速度和 ETA。显示层新增 360–900 ms ease-out 数字过渡，20.22→33.55 会经过中间值，权威任务进度保持原值。
6. **跨盘与密码流程**：Windows 盘符根目录没有父目录，旧逻辑会把 `H:\` 的暂存目录错误退回进程目录，最终跨卷 `rename` 触发 `os error 17`；现改为在所选盘根目录创建同卷暂存。内置 254 项字典仍逐项真实验证，但永久日志只保留 1/2/3、每 25 项和末项，实时候选继续由进度事件展示。

## 真实桌面追加发现与纠偏

- **失败态密码控件横向溢出**：真实加密 RAR 失败后展开详情，左侧 247 px 配置栏最初出现 `scrollWidth=357`，保险箱和重试按钮会被裁掉。密码输入现独占一行，操作按钮位于第二行；修复后真实窗口为 `scrollWidth=clientWidth=237`，没有越界子元素，输入和两个按钮均可见可达。
- **高 DPI 缩放速度减半**：在系统 200% 缩放下，旧代码再次用 `scaleFactor` 除以已经是 CSS 像素的 `PointerEvent.screenX/screenY` 差值，拖动 80×50 只会缩放 40×25。现在只把原生物理窗口位置/大小换算为逻辑像素，指针差值保持不变；真实 Tauri 窗口复验得到精确 -80×-50。
- **标题栏拖动边界**：真实页面 32 px 标题栏的 `mousedown` 已确认调用一次 `appWindow.startDragging()`，窗口边缘缩放已在原生窗口实测。远程 WebView 输入不能进入 Windows 的系统移动循环，因此没有把“物理拖动改变坐标”伪写为通过；该系统级动作仍由现有组件单测保护，并应在发布候选人工门禁中再拖动一次。

## 发布阻断闭环追加审计（2026-09-03）

- 标准 `npm run test:e2e:desktop:responsive-layout` 已在正式 Release Tauri/WebView2 会话通过。真实 920×620 首轮发现解压配置栏仅 247 px，修正容器断点后，920×620 与 760×520 的解压/压缩详情均通过双栏宽度、有界高度、独立日志滚动和横向溢出门禁。
- 参考 `Long_MarkDownReader` 的原生窗口方案后确认其为 Tauri 2；本项目 Tauri 1 的 drag-region 属性在真实输入下没有产生窗口位移，因此没有照抄后宣称成功。最终标题栏和八方向缩放统一使用 Windows `WM_NCLBUTTONDOWN` 系统循环，真实系统输入测得标题栏移动 `48×28`、缩放 `40×30`，释放后继续移动不会改变尺寸。
- `npm run test:e2e:desktop:volume-root` 使用映射到隔离临时目录的 Windows 逻辑卷根。它完整调用产品 `extract_file` IPC；输出内容逐字节一致，源 ZIP 保留，根目录 `.long-extract-*` 暂存为 0。该映射位于与工作区不同的底层卷，旧的“回退工作目录”逻辑会真实触发跨卷失败。
- 桌面门禁现在只默认启动精确的 Cargo 应用二进制，不再静默回退到过期的 `Long解压.exe`；EdgeDriver 可从 Selenium 缓存发现，并在会话创建不兼容时逐候选回退。
- 三项阻断均已闭环，版本身份已提升到 `1.2.6`。后续发布状态以 [RELEASE_AUDIT_1.2.6.md](RELEASE_AUDIT_1.2.6.md) 为唯一依据。

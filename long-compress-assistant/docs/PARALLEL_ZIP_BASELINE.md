# 受限 ZIP 并行解压与 A/B（2026-10-10）

## 实现范围

- 按用户确认新增设置，默认关闭，旧设置缺字段/重置均关闭；新启动任务读取开关。每个符合条件的任务最多 2 个工作线程，所有原生 ZIP 任务（含顺序回退）共用最多 min(逻辑处理器数, 4) 个工作名额，避免任务数乘以线程数。等待名额和复制循环均检查取消/暂停。
- 限普通非加密 Store/Deflate ZIP、保留目录结构、至少两个 ≥256 KiB 文件。选择性/过滤解压、跳过损坏、仅更新文件、符号链接、重复/歧义路径、空目录条目、已有输出目标等使用原顺序路径。无额外工作名额时顺序执行。不调用旧的独立 ParallelExtractor 实验模块。
- 并行工作先写原有暂存目录，后续发布/冲突/回滚仍走原事务；已开始写入后的 CRC、写入错误直接返回，不再尝试顺序解压掩盖失败。每个并行工作线程有 256 KiB 复制缓冲，不把这个静态上界等同于进程内存峰值（还含 ZIP 元数据等）。
- 加密回退专项发现 ZIP 的元数据读取原先仍调用需密码的 by_index；改为 by_index_raw 读取头信息，数据仍用 by_index_decrypt，真实 AES 回退逐字节验证通过。

## 既有三场景回归 A/B

使用 `scripts/run-native-zip-baseline.mjs`，应用目录为输入/输出根目录，先关闭 3 轮再开启 3 轮；不清缓存，压缩等级 6，快速打包关闭。以下为最终实现后的观测，18 次均校验落盘文件数、长度与 SHA-256。

| 场景 | 关闭中位数 / 范围 ms | 开启中位数 / 范围 ms |
| --- | --- | --- |
| 单个 32 MiB 随机文件（顺序回退） | 40.49 / 38.64–48.61 | 42.22 / 40.78–42.49 |
| 1000 × 4 KiB 小文件（顺序回退） | 194.77 / 183.66–216.82 | 196.23 / 194.18–226.37 |
| 35 项混合媒体/文本 | 10.03 / 8.59–10.88 | 7.00 / 6.94–8.88 |

早期实现对小文件回退也逐目标查询文件系统，观测到 206.18→239.13 ms 的退化。已改为先用归档元数据判定小文件集合，再检查并行候选目标；表中为修正后重测，不删除或掩盖首次负面结果。单大文件/小文件不宣称提速；混合与多大文件仅是本机暖缓存样本，不外推机械硬盘或全部场景。

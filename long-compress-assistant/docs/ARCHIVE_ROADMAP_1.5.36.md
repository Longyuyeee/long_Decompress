# 下一版：v1.5.36 ZPAQ 增量更新与历史接续

2026-10-21，接续v1.5.35。本版开始实施：先核对随附适配器真实追加、内容比较和保留语义，再接普通/密码、数字卷、配置与结果，最后封板发布。

## 用户要解决的问题

持续整理项目资料时，希望往已有备份里添加新文件、更新同名内容，并保留之前的版本。首版采用“基于已有ZPAQ另存更新包”：保留旧快照，只压缩新增或变化内容，成功后生成新的结果。需要复制已有归档，不承诺减少全部磁盘读写或固定压缩率；界面应提前说明空间和耗时。

## 依据与实施顺序

现有zpaq_engine.rs只提供创建和所选快照读取：create明确拒绝现存暂存目标，使用-long-create；v1.5.30已具备历史快照选择。标准引擎的日志结构有增量能力，不等于当前适配器已开放更新。不能移除现有创建保护后直接向用户原件追加。

1. **先确认真实增量语义。** 用独立官方工具制作普通/原生密码、多事务和有删除历史的原件，验证随附适配器在副本上追加的方法。核对未改、增加、同名修改、同大小/同时间内容变化、空文件/目录、中文路径，以及旧/新快照的完整独立回解；先明确元数据比较与内容比较的区别。未变化时提示用户，不虚构新增快照或节省量。
2. **接通“添加与更新”，保留未选旧内容。** 用户选已有ZPAQ及本次文件/文件夹，确认归档内路径映射和输出新位置；已有路径同名更新、未选旧条目保留，不提供删除同步。原件和旧卷组保持；复制旧归档的空间与过程显示为真实阶段。失败或中断不把半成品当作完成结果。
3. **密码与卷组接续。** 普通和原生密码使用原密码继续更新，不同时做改密；数字卷作为现有来源读取，完整复制到工作文件后追加，再按用户选择输出单包或数字卷，缺卷先补齐。原生追加多部分、跨卷原地修改及损坏事务抢救继续独立研究。
4. **接现有工作流和结果。** 待处理/草稿、任务进度/暂停取消、失败纠正、历史重做和统一结果保留更新来源、输入与输出；密码仍需重新填写。完成后能打开新包、选择新旧快照、预览/检查/所选及完整提取、继续内容转换。保持单条展开、多选弹窗、自然继承、50/50与窄窗滚动。
5. **按新增影响收尾。** 只检查本版更新链；已通过的旧格式/密码矩阵与真实盘满不重跑，最后更新README、中文Release和范围记录，通过正常受保护合入与签名发布。

ZIP LZMA写入仍是单独研究（当前zip库编码分支明确不支持）；WIM固实/ESD、SWM创建/部署、ALZ方法3及EGG加密固实保留原长期方向，不计入本版。删除同步、定时备份和直接覆盖原归档也不列为首版增量更新的完成条件。

# D-04.2 PDF 统一任务与桌面闭环审计

审计日期：2026-08-31

开发基线：`master` / `f6004b0`

开发分支：`codex/pdf-d04-2-task-ui`

## 1. 节点结论

D-04.2 已将 D-04.1 的单一安全命令接入现有统一任务、取消、历史和桌面工作区，没有建立 PDF 专用旁路任务系统。真实 Windows Tauri 门禁已完成表单 PDF 的分析、显式有损确认、显式保留较大结果、转换、结构验证、原子发布、终态历史和系统默认 PDF 阅读器打开；输入哈希保持不变，结构化 expected/actual 差异为 0。

D-04 总节点仍未关闭。下一接续点严格为 D-04.3：补齐原始路线要求的完整内容/结构/大页数与大图片矩阵、批量失败/取消和正式安装态闭环。D-04.3 关闭前版本保持 `1.1.16`，不得打包发布 `1.1.17`。

## 2. 原始需求与实际代码对齐

| 原始需求 | 实际代码 | 判断 |
| --- | --- | --- |
| 媒体继续属于统一 `compression` 任务 | `usePdfOptimizationBatch` 创建 `type= compression`、`workloadKind=pdf` 任务，终态由既有 task store 持久化 | 对齐 |
| PDF 只有真实阶段，不显示伪进度/ETA | 页面消费后端 `Transforming`、`Validating`、`Publishing`；成功后才置 100%，不显示估算 ETA | 对齐 |
| 最终历史只记录实测事实 | 输入/输出字节取 `PublishedPdfOutput`，页数取验证后的 `outputFacts`；失败/取消不生成指标 | 对齐 |
| 默认新文件、批量冲突安全 | 每项调用后端规划器，批内保留目标集合，顺序执行，不覆盖现有目标 | 对齐 |
| 变大默认拒绝，用户可明确保留 | 开关默认关闭并显示空间警告；锁定配置前必须由用户主动开启，后端仍执行完整结构验证 | 对齐 |
| 签名默认只分析、加密不得伪装支持 | 签名继续阻断；审计实际执行能力后，正确密码的加密 PDF 也新增 `PDF_ENCRYPTED_EXECUTION_UNSUPPORTED` 阻断 | 纠偏完成 |
| 安装版完成批量、失败、历史和默认阅读器 | 本节点真实隔离 Release 已完成单项成功/历史/默认阅读器；完整批量、失败/取消和正式 NSIS 留给 D-04.3 | 尚未全部关闭，不提前宣称完成 |

## 3. 实现事实

- 新增前端 PDF 执行类型和 `usePdfOptimizationBatch`：顺序批处理、批内目标保留、共享取消、失败/取消分类、历史持久化等待和发布事实落任务。
- PDF 工作区新增输出目录、批量开始/取消、每项结果、显式保留较大输出及默认阅读器打开；配置仍为页面内草稿，不持久化密码或风险选择。
- `open_pdf_output_with_default_application` 只接受绝对路径、非符号链接普通文件和 `.pdf` 扩展名，然后复用已有系统默认应用打开服务。
- 任务阶段类型增加 `Transforming`，没有增加 PDF 专用状态仓库；历史 schema 已有 `pdf` 与 `pageCount`，无需数据库迁移。
- 合同升级到 D-04.2，并将统一任务、顺序批量、终态历史、实测指标和默认阅读器纳入静态/负向门禁。

## 4. 真实桌面证据

隔离 Release 使用 `VITE_DESKTOP_E2E=1` 前端与 `custom-protocol,desktop-e2e` 后端，使用正式打包 qpdf 和现场生成的 10 类 PDF 夹具。D-04.2 聚焦门禁结果：

- `form.pdf`：1 页、8,589 B、2 个表单字段与建议输出名称均符合预期；
- 兼容图片模式必须先显式确认；“保留较大结果”默认关闭并由测试真实点击启用；
- 最终历史为 `completed / pdf / pageCount=1`，实测输出大于 0，历史写入前最终文件已经存在；
- `signed.pdf` 和密码已验证的 `encrypted.pdf` 均不可锁定执行；错误密码字段会清空且密码不留在 DOM；
- 默认阅读器按钮真实调用系统默认应用并返回成功；三个源文件 SHA-256 均未变化；
- 1100×720 与 760×560 两种真实窗口尺寸主区域和 PDF 工作区横向溢出均为 0；
- `test-results/desktop-e2e/pdf-workspace-result.json` 的 4 组 expected/actual 差异为 0。该目录含本机路径与截图，按仓库证据策略保持忽略；可重复入口为 `npm.cmd run test:e2e:desktop:pdf-workspace`。

## 5. 回归审计与纠偏

第一次桌面门禁在创建会话前失败：脚本选中了 2026-08-30 遗留的旧 Release 二进制，`DevToolsActivePort` 未产生。按桌面测试规范重建 E2E 前端及 Release 后，旧 D-02.2 门禁通过；随后将同一门禁升级为 D-04.2 执行/历史/默认阅读器证据并再次通过。没有把首次基础设施失败删去或冒充首次全绿。

第一次全量 Rust 回归还复现了交接审计已登记的加密 7Z 错误密码非确定性：底层可能返回 `Data Error`、`Decompression failed` 或 `corrupted input data`，旧分类只识别最后一种，因此偶发误报 `damaged`。修正仅限“已确认加密且已提供密码”的模糊解码失败，仍明确提示“密码错误或密文损坏”；未加密 `Data Error` 继续分类为损坏。新增定向测试后，真实加密 7Z 连续 10 次通过，第二次全量 Rust 通过。

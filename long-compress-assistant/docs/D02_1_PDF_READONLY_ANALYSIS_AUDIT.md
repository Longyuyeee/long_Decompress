# D-02.1 PDF 输入候选与只读结构化分析审计

审计日期：2026-08-31

节点状态：**完成；PDF 产品 UI 与转换执行继续冻结。**

## 1. 开发目标与范围

D-02 要求用户在执行前看到页数、输入大小、加密、签名、表单和附件等真实事实。本小步只关闭其第一个可独立验收单元：建立 PDF 输入候选/分析结果类型，并让产品后端通过正式 qpdf 12.4.0 运行时执行只读结构分析。

本步不实现两模式表单、输出路径、转换、临时文件、发布、历史或源文件处理，也没有解除 `enableProductUi=false`。因此不能把本提交描述为“PDF 压缩可用”。

## 2. 需求—代码对账

| 原始要求 | 实际实现 | 审计结论 |
| --- | --- | --- |
| 返回真实输入事实 | `services/pdf_analysis.rs` 返回字节数、页数、加密、密码状态、签名字段、普通表单字段、附件、书签数量、警告和阻断原因 | 完成 |
| 使用正式产品运行时 | Tauri 命令先执行既有 qpdf 十文件身份/能力预检，再调用 `resources/pdf-engine/qpdf.exe` | 完成 |
| 禁止原始参数 | qpdf 参数由后端固定构造，仅允许布尔探测和裁剪后的 JSON v2 分析键 | 完成 |
| 密码不得进入日志、历史或参数 | 加密 PDF 密码通过固定参数 `--password-file=-` 写入子进程 stdin；请求类型不派生 `Debug`，错误只返回稳定分类 | 完成 |
| 签名默认只分析 | 检出 `/Sig` 字段后返回 `PDF_ANALYSIS_SIGNED_DOCUMENT_ANALYSIS_ONLY` 阻断原因 | 完成 |
| 加密文件需正确密码 | 无密码返回不完整事实和 `required`；错误密码返回 `PDF_ANALYSIS_INVALID_PASSWORD`；正确密码才返回完整结构 | 完成 |
| 源文件只读 | 分析路径没有任何输出参数；真实门禁比较运行前后 SHA-256 | 完成 |
| UI 不得提前开放 | `CompressionView.vue` 未改，`enableProductUi` 继续为 `false` | 完成 |

## 3. 安全与资源边界

- qpdf 子进程最长 30 秒，JSON stdout 上限 32 MiB，超限和超时使用稳定错误分类。
- 输入缺失、目录、空文件在启动 qpdf 前拒绝。
- JSON 只请求 `pages`、`acroform`、`attachments`、`outlines`，不读取流数据。
- 无密码时不会猜测加密文档内部是否有签名、表单或附件，对应字段返回 `null`，避免把“未知”伪装成“没有”。
- 签名字段和普通交互表单字段分别统计，签名本身不被误报为普通表单。
- 本步不接受执行参数，也不产生输出 PDF，D-03 的取消、空间预检、验证和原子发布边界没有被提前复制或绕开。

## 4. 真实测试：预期—实际—差异

真实入口：`npm run test:pdf-d02-analysis:real`

该入口先生成既有 10 类合成真实 PDF，再由产品 Rust 分析函数调用仓库正式 qpdf 运行时。结构化证据写入 `test-results/d02-pdf-analysis/result.json`，其中每项同时保存 `expected`、`actual` 和 `differences`。

| 场景 | 预期 | 实际 | 差异/修正 |
| --- | --- | --- | --- |
| 文本、扫描、混合、透明、注释 | 页数、字节数及普通风险事实与样本合同一致 | 全部一致 | 0；无需修正 |
| 表单 | 识别 `archive_name`、`preserve_metadata`，不误报签名 | 完全一致 | 0；无需修正 |
| 书签 | 两页且书签数量可读 | 完全一致 | 0；无需修正 |
| 附件 | 识别 `d01-evidence.txt` | 完全一致 | 0；无需修正 |
| 数字签名 | 识别 `FixtureSignature`，返回只分析阻断 | 完全一致 | 0；无需修正 |
| 加密且无密码 | 只确认加密/需密码，内部事实为未知且阻断规划 | 完全一致 | 0；无需修正 |
| 加密且正确密码 | 返回一页完整事实，密码状态为 `accepted` | 完全一致 | 0；无需修正 |
| 加密且错误密码 | 稳定返回 `PDF_ANALYSIS_INVALID_PASSWORD`，不包含测试密码 | 完全一致 | 0；无需修正 |
| 所有源文件 | 分析前后 SHA-256 不变 | 全部未变化 | 0；无需修正 |

最终结构化比较共 12 组，剩余差异为 0。单元门禁另外覆盖参数数组不含密码、签名/普通表单分离、附件/嵌套书签解析和空文件启动前拒绝。

开发过程中发现 D-01 基线脚本曾使用 `--password=<value>`，不能直接复制到产品路径；qpdf 12.4.0 的实际帮助与 stdin 实测证明 `--password-file=-` 可用，因此产品实现改用 stdin。该差异在进入产品代码前已纠正，并由错误密码真实路径和参数数组负向测试锁定。

阶段回归首次运行媒体架构门禁时，实际结果仍按旧 D-01 合同拒绝任何预检外命令，与 D-02.1“允许且只允许只读分析”的预期不一致；门禁已改为精确要求一个预检命令、一个分析命令，并继续禁止转换/发布命令。第二次运行又发现负向单测中的字符串 `--password=` 被宽泛文本扫描误报，随后收紧为检查生产参数构造。修正后架构门禁检查 17 个媒体生产文件并通过。这两次失败均保留为需求—实际差异，没有通过删除安全检查规避。

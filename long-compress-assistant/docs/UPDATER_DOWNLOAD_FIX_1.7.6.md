# v1.7.6 · 更新重复下载与进度修正

状态：功能封板完成，接续正式合并与发布。日期 2026-10-27，分支 `codex/updater-single-download-fix`。

## 原因与修改

项目锁定的 Tauri 1.8.3 更新器 `UpdateBuilder::check()` 每次发现新版本都会新增 `once_global(EVENT_INSTALL_UPDATE)` 监听；前端调用的旧 JS `checkUpdate()` 使用这条通道。自动检查后再手动检查、或稍后再次检查，会积累多个等待安装入口，一次安装事件可触发多份下载。原进度事件 `chunkLength` 确实是单个数据块长度；前端相加本身没有把累计值当增量，但未区分并行下载。原生源码依据为本地锁定依赖的 `src/updater/mod.rs` 检查/安装和 `src/updater/core.rs` 数据流实现。

新增原生 `check_app_update` / `install_app_update`：检查使用 `skip_events()`，只保存最新响应，不注册遗留的安装监听；安装核对版本后消费一次响应。原生操作锁同时覆盖检查和安装，不能通过重复 IPC 绕过。下载仍调用 Tauri 原来的 `download_and_install()`，保留原生数据块事件、下载后签名核对及 Windows 安装交接。

前端改为上述接口，保留现有更新状态、稍后提醒、跳过版本与进度组件。安装开始重置计数；失效监听通过 generation 忽略回调，重复安装不改变当前状态。若接收量超出声明 Content-Length，保留真实接收字节，清空本次不可信总大小并使用不确定进度，后续块不再恢复这个错误分母；不强行显示 100%。

# v1.7.34 规划 · 带结束标记的流式 LZMA ZIP 丢目录部分取回

状态：已完成并封板；接续 v1.7.33 流式 BZip2 ZIP。见[封板记录](ZIP_LZMA_RESCUE_FREEZE_1.7.34.md)及[发布说明](RELEASE_NOTES_1.7.34.md)，正式附件由本版 CI/Release 接续。

现有未知尺寸边界识别将覆盖 Deflate 与 BZip2，下一阶段处理 ZIP method 14 的 LZMA 流，优先使用独立生产者可实际生成的带结束标记来源。

1. 核对独立生产者真实流式 ZIP32 / ZIP64 原件，确认 ZIP LZMA 属性前导、通用标志中的结束标记约定和数据描述符。只在属性合法、解码器明确结束、消费字节数、展开量与 CRC 均可确认时接续下一条；无结束标记而又没有可靠本地尺寸的来源停止。
2. 首期处理未加密单包及完整数字切片的已确认连续前缀，覆盖普通/空文件、目录与混合方法；矛盾尺寸、损坏、截断和不支持的未知边界不扫描跳过。原包总数仍未知，不把部分取回描述为完整修复。
3. 沿原诊断、独立新包、完整内容校验、结果入口、部分历史和失败重试流程，不新增常驻配置或页面。保留单条展开、多选弹窗、等宽双栏以及现有取消和资源上限，只检查新增及受影响流程。

完成标准：声明范围内的真实原件与最终新包内容经独立工具比对，原件保持，正常 LZMA ZIP、Deflate/BZip2 部分取回保持。具体是否可支持目录与各类描述符，先以真实生产者样本确认再封板。

密码流未知边界、其他流式方法、跨缺口扫描、恢复记录修复、ALZ / EGG 外部原件与原生密码/块分段继续独立分期。UTC 更宽范围、NTFS 亚秒及其他元数据、重复读取成本仍是后续候选。

本期已确认声明范围内的文件、空文件和目录可取回；未知尺寸 LZMA 恢复的估算解码内存预算为 256 MiB。下一阶段 [v1.7.35 ZIP 部分取回结果保留修改时间](ARCHIVE_ROADMAP_1.7.35.md)仅规划。

## 用户可用范围

| 输出 | 方法 | 密码 | 分卷 |
| --- | --- | --- | --- |
| ZIP 默认 | Deflate；强度 0 沿用 Store | 无密码 / AES-256 / ZipCrypto，沿用既有密码编码选项 | 不分卷 / `.zip.001` 数字卷 / `.z01/…/.zip` 标准卷 |
| ZIP 可选 | Zstandard；强度 0 为最低压缩强度，仍使用 Zstandard | 同上 | 同上 |
| ZIPX | XZ；空文件使用 Store，保留密码设置 | 同上 | 不分卷 / `.zipx.001` 数字卷 |

ZIPX 标准分卷创建本版不开放，界面只提供数字卷，后端也明确拒绝该组合；需要标准分卷时可以选择 ZIP。原型 `.z01/.zipx` 虽能由本机读取，但独立 7-Zip 不接受；改为 WinZip 文档所述 `.zx01/.zipx` 后也未通过该工具的完整读取，不能宣称已完成互通。命名参考 [WinZip 官方分卷说明](https://kb.winzip.com/help/CS/help_split_zip_info.htm)。后续应取得独立可交换样本，再单独扩展。

不新增其他 ZIPX 专有方法，不承诺任意文件都更小、更快；没有新增大于 4 GiB 的实物测试或吞吐提升结论。已有读取、救援及其他格式能力沿用各版证据。

## 流程与界面

- 单条任务继续点击行内展开，多选仍在原弹窗内修改；详情左右各占 50%，两列各自可滚动。
- 方法选择紧跟目标格式；ZIPX 显示 XZ，兼容说明收在问号帮助。密码、密码编码、分卷选项继续按所选格式显示。
- 单条、分组、批量配置、批量转换、改密/重新分卷接入新方法；ZIPX 数字卷可作为后续转换来源。
- 配置组、任务模板导入导出、快速预设、待处理草稿及历史再次执行保留方法。旧配置缺少方法时仍按原有 ZIP 默认行为执行；只展开有效配置不会自动转为独立配置。
- 智能分析按所选方法抽样，改变方法后提示旧估计已过期；运行中的分析记录开始时的设置，避免把旧结果标成新方法的估计。

## 实现与发现的问题

普通 ZIP 与密码 ZIP 共用现有新版 ZIP 写入器，通过类型化 `zip_method` 选择 Deflate / Zstandard；ZIPX 由明确输出类型使用 XZ。目录、密码编码、进度、取消、分卷暂存、产物发布及已有解压器继续复用。

真实完整流程发现 XZ 空文件输出的索引校验失败：独立 7-Zip 对空文件报 Data Error，小文本则正常。现改为空文件 Store，实际数据文件继续使用 XZ；目录与空文件均保留，AES / ZipCrypto 不降级。检查覆盖所有文件内容，补上最初仅核对主体载荷未发现空文件错误的遗漏。原始诊断见保留的本版证据。

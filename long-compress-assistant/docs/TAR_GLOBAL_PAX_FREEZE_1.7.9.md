# v1.7.9 · 全局 PAX 一致读取封板记录

日期：2026-10-27。

## 实现

`tar_pax` 提供共享、按归档独立的全局状态和长度驱动的属性解析。全局字段持续继承，局部只作用于下一条，空值删除对应覆盖。`g`/`x`/GNU `L`/`K` 控制记录保留各自物理大小；普通条目使用最终 `size`，元数据不进入用户清单。完整读取通过有界流适配到有效局部 PAX，文件数据持续流式读取，不暂存整份 TAR；旧 GNU 稀疏的扩展块按原结构透传。

正常浏览、图文预览、解压、提取预检和完整验证接入同一读取层；转换沿现有“完整提取→重建→验证”的引擎。TAR.LZO 部分取回复用共享解析与状态，但继续只接受已经完整校验的普通文件/目录。全局 1 MiB、正常局部 8 MiB、恢复局部 1 MiB，状态总量有界；未知全局属性、换行值、重复普通属性和不确定布局停止。现有稀疏局部重复块对保持，恢复仍不支持链接/稀疏/缺口后扫描或 GNU 与局部 PAX 混合叠加。

TAR 依赖从 0.4.44 提升至 0.4.46，采用上游普通条目 PAX size 始终覆盖文件头、覆盖不套用到中间控制记录的修正。Cargo 同时重新选择部分 Windows 依赖引用；没有提升其他包版本。共享逻辑条目保留带符号和小数的 PAX mtime，完整浏览与请求保留时间的提取使用同一时间；不宣称恢复结果保存了全部原始时间元数据。

## 独立依据与明确分歧

`tests/fixtures/archives/tar-pax-179/manifest.json` 固定原始 TAR / TAR.LZO SHA、每条路径/大小/时间及文件 SHA。两个自编资料原件分别由 GNU tar 1.35、Python tarfile 制作，用已固定 SHA 的官方 lzop 压缩；官方完整回解、GNU 清单/逐文件内容、Python 清单/内容一致。应用自己的写入器不参与原件制作。

另有一个明确构造的状态边界样本：Python TarInfo 生成物理头，原始自编文件内容与哈希固定，覆盖全局 path/size、非零头覆盖、局部覆盖、连续全局更新、空值删除、状态恢复及负小数时间。它不是第三方损坏原包，也不作为 GNU/Python 工具一致原件：GNU tar 1.35 对后续全局状态和空数值删除产生差异，Python 3.12 对全局 size 与中间局部头也有差异。首次尝试用 GNU 读取该构造样本失败后，准备脚本已明确分开两类依据，没有改变应用解析去迁就工具错误。

全局逐字段持续生效的定义见 [IBM pax 格式说明](https://www.ibm.com/docs/en/SSLTBW_2.5.0/pdf/bpxa500_v2r5.pdf)；[Go 官方历史格式测试说明](https://go.googlesource.com/go/+/go1.12.17/src/archive/tar/writer_test.go)也明确记录 GNU/BSD 的全局状态及空值删除分歧。TAR 依赖边界修正见 [上游说明](https://github.com/composefs/tar-rs/security/advisories/GHSA-3pv8-6f4r-ffg2)。本版声明的是支持范围内的共享解释，不宣称所有工具对所有 PAX 变体完全一致。

## 定向结果与复用

- 新原生 6 项：原件/构造样本的正常浏览、文本预览、完整提取、密码 ZIP 重建与逐文件核对、健康诊断；9 份坏尾/坏校验/缺结束标记的部分取回；控制记录头/内容/填充截断；未知属性、坏记录及换行值；缺中卷、更换来源与取消；按最终路径选择提取及预检。
- 首轮新增 5 项全部通过。随后只补跑新增换行分歧用例所在项与新增所选提取项，未重复成功的完整流程。
- 受影响旧回归 8 项通过：旧 GNU 和 PAX 0.0/0.1/1.0 稀疏原件、共享浏览/预览与格式识别、GNU 长名称恢复、剩余未知类型停止和取消清理。旧未知类型表的 `g` 改为仍未支持的 `V`，全局记录已由新检查覆盖。
- 独立 Python 核对 6 份完整输出和 9 份恢复输出：完整路径、所有父目录/空目录及文件 SHA 一致，无元数据伪文件。构造样本依据显式原始哈希，未冒称独立工具一致解码。
- 原生真实报告和结果值回放到后台 Vue/CSS，2 组界面流程通过：名称与目录、筛选、原取回结果和部分历史；1100×700、760×520 无横向溢出，确认按钮在视口内。三张截图已逐张查看。IPC 是明确回放，不冒充真实桌面命令。
- 类型/Vite、Shell DLL 和 v1.7.9 的 8 个版本来源及标签身份通过；正式 Windows 产物由对应提交 CI/Release 生成。原生内容测试后仅提升发布版本身份，并纠正 mtime 错误信息误称“稀疏布局”的文字；不因此重跑内容矩阵。

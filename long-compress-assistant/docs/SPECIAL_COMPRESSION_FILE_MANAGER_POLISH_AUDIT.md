# 特殊压缩与文件浏览器体验修正审计

> 审计日期：2026-09-02  
> 基线版本：`v1.2.1`  
> 分支：`codex/special-compression-file-manager-polish`

## 1. 需求对齐

本轮只关闭用户明确提出的六项体验问题：特殊压缩设置不挤压、删除重复文案、对齐中心页动效、文件和文件夹统一系统打开、修复 Explorer 回落桌面、特殊目录属性失败友好提示。没有改动压缩算法、安全事务边界或公开版本身份。

## 2. 预期—首次实际—修正—最终实际

| 场景 | 预期 | 首次实际 | 修正 | 最终实际 |
| --- | --- | --- | --- | --- |
| 图片/视频批量设置 | 设置独立滚动，主外壳不变 | 设置卡插入纵向 flex，必然压缩投放区/任务区 | 共享 Modal；草稿、取消、保存语义 | 三档视口打开前后外壳宽高差 0，页面滚动高度差 0 |
| 特殊压缩文案 | Tab 已表达类型，不重复标题 | 图片/视频/PDF 均有工作区、阶段或执行说明 | 删除重复标题和证明性说明，保留风险信息 | 单元合同锁定点名文案不再出现 |
| Tab/按钮动效 | 对齐中心页且立即可操作 | Tab 静态切换；首版 `out-in` 在离场期间内容暂不可用 | 同步挂载新工作区并执行 200 ms 入场关键帧；按钮 hover/press；reduced-motion 关闭 | 聚焦 40/40 与 Chromium 2/2 通过，无交互空档 |
| 文件/目录右键 | 两类对象均能调用系统文件管理器 | 文件夹只有应用内打开；压缩包只有内部浏览 | 新增独立系统动作，保留原应用动作 | 文件夹、压缩包、普通文件三组前端合同均传递精确路径 |
| Explorer 定位 | 中文/空格路径打开正确目录或选中正确文件 | 单个参数手工嵌入引号，Explorer 可能回落桌面 | `/select,` 与路径分开交给进程 API 引用；目录直接传路径 | 真实 Tauri 调用后，COM 观察到精确目录和精确选中项 |
| 特殊目录属性 | 安全拒绝时给稳定提示 | 原始 `读取属性失败：<backend>` 暴露给用户 | 前端归一化成系统保护/特殊文件夹提示 | 单元合同证明不泄漏拒绝码和内部详情；安全拒绝仍保留 |

## 3. 测试审计

### 3.1 首轮失败未被掩盖

- 文件浏览器新增合同首次为 6 通过、4 失败：三类系统动作不存在，属性错误仍为原始失败。
- 加入 `mode="out-in"` 后，聚焦回归出现 10 项失败：切 Tab 后工作区在离场计时器结束前为空。没有延长等待掩盖，改为同步挂载入场动画后恢复 40/40。
- 首次桌面门禁因未指定 EdgeDriver 直接停止；第二次使用系统 Edge 152 驱动，但 WebView2 实际为 151，出现明确版本不匹配。改用本机匹配 WebView2 151 的驱动后才进入产品门禁并通过。

### 3.2 最终结果

| 门禁 | 最终实际 |
| --- | --- |
| 类型检查 | 通过 |
| 前端全量 | 48 文件，280/280 |
| Explorer Rust 合同 | 5/5 |
| Rust Clippy | 全目标、E2E 特性、零告警 |
| Chromium 特殊压缩 | 2/2；三档视口几何差 0 |
| E2E 前端构建 | 通过 |
| Rust 隔离 Release | 通过 |
| Windows Tauri/WebView2 | 精确目录打开、精确文件选中、真实复制/移动/属性全部通过 |

真实 Explorer 夹具为测试临时根下的 `中文 空格目录/定位 文件.txt`。门禁通过或失败都会只关闭位于该测试根目录下的 Explorer 窗口，不关闭用户已有其他窗口。机器截图和临时数据位于被忽略的 `test-results`，不提交仓库。

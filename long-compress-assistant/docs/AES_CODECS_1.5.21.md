# v1.5.21 Long AES 内层扩展

2026-10-20，从已正式发布 v1.5.20 `beece33` 接续既定路线。正在开发，未封板。

目标是接通 LZ4/Brotli/LZIP 及对应 TAR 的六种 `.aes` 格式：密码、数字分卷、任意卷浏览/有界预览、完整检查、所选/整包解压、转换、结果与失败新任务。复用现有 AES V2、KDF 与认证，不改默认开关或设计新密码算法；接收方需 Long解压，不称为原生格式密码标准。

开工缺口：AesCompressionKind、格式能力/路由、AuthenticatedInner 内层名单、解压分派、完整性验证与转换格式列表均只覆盖旧组合。普通 LZ4/Brotli 的内部预览也未接通；普通 LZIP 进入共享完整性入口仍落到 Zstandard 分派，需一并修正并固定回归。

保留单条展开、多选弹窗、自然继承、左右等宽和窄窗滚动。先使用独立 cryptography 与 LZ4/Brotli/GNU lzip 原件证实，再定向检查和实际用户流程；不重跑已通过的 AES 基础算法、VHD 或无关全格式矩阵。v1.5.22 校验进度仍仅规划。


## 实施进度

- 六种能力、前后端格式/密码名单、压缩/解压/验证路由及转换列表已接通；`.tlz.aes` 别名与历史格式归一同步。内层完成后复用原 AES V2 包装，再沿已有事务数字切卷路径发布。
- 普通 LZ4/Brotli 与新 AES 内层共享有界文本/图片预览，普通 LZIP 公共完整性分派改为真实 LZIP；浏览预算与预览读取预算保持，认证后的临时空间要求保持。
- LZ4.AES 强度显示为快速模式；内层实际编码也用于压缩抽样。新单文件转换有明确提示，目录和多文件使用 TAR 组合，原交互与布局不变。
- 独立 CPython cryptography 49.0.0、lz4.frame 4.4.5、Brotli 1.2.0、GNU lzip 1.24.1 生成六个非空 AES V2 原件，包含中文、图标、空文件和空目录，SHA256/工具身份在样本 manifest。没有修改加密算法或 KDF 默认。
- 首轮六个前端缺口红灯，修正后 83 项通过；新增继承组件后该文件 34 项通过（与前轮有重叠，最终不同前端为 89 项）。类型/普通生产及 Shell 版本构建通过；Rust 与真实桌面接续中，不把待执行项计通过。

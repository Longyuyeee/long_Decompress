# v1.7.5 规划 · TAR.LZO 完整条目部分取回

状态：功能封板完成（2026-10-27），接续正式合并与发布。接续 v1.7.4 普通 LZOP 完整成员部分取回，继续真实失败包、缺卷和目录资料兼容主线。

## 用户目标

TAR.LZO 通常只有一个外层 LZOP 成员。它的尾部缺失时，已通过外层数据块校验、且内部 TAR 条目完整的文件仍可能取回。本期先确认这条证据链，再沿原救援弹窗选择文件；不能直接套用“完整外层成员”的判断，也不能仅凭 TAR 头校验宣称文件内容完好。

## 推进顺序

1. 确认 LZOP 已完整解码并通过校验的数据块前缀，以及 TAR 条目头、声明长度、数据和填充的边界。缺中间卷仍在首个间断处停止，不拼接后面的卷。
2. 首期覆盖普通文件、目录、空文件和 UTF-8 PAX 路径。只把所有所需字节均已落在通过校验的前缀内的完整条目列为可取回；遇到不支持的 TAR 特性或未确认的元数据状态时停止并说明原因。
3. 复用原部分取回二级界面、所选范围、独立结果目录、重新检查来源、取消清理和历史标签；保持单条展开、多选弹窗与等宽布局。目录只围绕已确认条目建立，长路径与重名沿既有规则处理。
4. 用官方 lzop 与独立 TAR 工具的完整原件作为内容依据，派生尾部截断和缺卷样本。检查头/数据/填充跨块跨卷、空目录、PAX、损坏后无半文件、取消及补齐后正常解压；不重复旧格式与安装检查。

## 边界

本期不宣称支持 TAR 全部稀疏、硬链接和符号链接变体；这些单独评估，遇到未知状态不继续猜条目。无内容校验的外层数据不列为已确认文件，不从任意字节搜索 TAR 头，不新增原生密码或修复缺失数据。正常解压、浏览和全量转换仍要求完整来源，部分结果始终明确标识。

完成后继续分期推进更多算法、格式、分卷和真实损坏包兼容；ALZ / EGG 外部原件缺口保留，不能用自造样本替代。

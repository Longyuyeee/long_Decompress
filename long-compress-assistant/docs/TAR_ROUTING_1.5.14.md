# v1.5.14 TAR 收口与真实格式路由

本轮继续交付原十版路线的第八个目标（TAR 特殊布局），不是宣称第九个 ZIP64 大边界已完成。v1.5.13 原包、实现和封板证据保留，见[TAR 稀疏审计](TAR_SPARSE_1.5.13.md)。发布前追加审计发现真实格式与 TAR 后缀冲突会被新预检查/完整性入口错误路由，必须先修复。

## 真实复现与版本决策

由 ZIP 库实际写出的有效 ZIP，仅将文件名保存为 `.tar`、`.tar.gz` 或 `.tar.xz`，内容不改。魔数检测正确返回 ZIP，但 `tar_compatibility::integrity_route` 仅按名称选择 TAR，抢占原 ZIP 检查/预检查。两个新增定向测试在未经修复的 1.5.13 源码均失败，见[红灯](evidence/tar-routing-1.5.14/red.txt)。浏览/预览中更早已有相似的后缀优先分支，同步纠正，不能只让单个检查测试通过。

v1.5.13 候选已通过必需构建并经 PR #207 受保护合入，但发现问题后取消正式构建 `39153731610`（cancelled），GitHub 无该版本 Release。原标签 `c601fe96d564d9be06e662ce94dfd65b886a26a5` 保留，不移动或重用；原候选记录不能冒充正式包。修复和同一 TAR 交付统一升至 **v1.5.14**，随后 ZIP64 大边界为 v1.5.15、过程 I/O 为 v1.5.16。十个目标不增加、不删减，只调整编号，不将撤回版本计为一次新增能力交付。

## 收口条件

TAR 路由只接受检测到的 TAR，或与真实外层压缩格式匹配的 TAR 复合后缀；已知 ZIP/7Z/RAR/自有加密容器不能被名称抢占。浏览、文本预览、检查、诊断、预检查、提取与转换按同一原则；原二十 GNU/PAX 稀疏原件及所有故障/控制保持原字节。新增真实 ZIP 误后缀场景，同时复核常用/窄窗实际页面。

完成真实桌面与定向回归、普通生产、八处版本身份、受保护候选和正式资产后才重新宣布封板发布。普通倍率/逻辑磁盘限制、原有默认设置、个人安装与数据保持。Windows 普通填零输出及 Linux 元数据/未知稀疏布局边界不扩张；ALZ 方法 3 与 EGG 加密固实未完成状态继续保留。

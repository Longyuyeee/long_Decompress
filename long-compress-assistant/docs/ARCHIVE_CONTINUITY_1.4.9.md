## 批准范围与基线（2026-10-15）

用户批准按审计建议继续到下一次封板。基线为正式 v1.4.8 / `1d4eea2`，工作分支 `codex/archive-continuity-1-4-9`。本轮聚焦三个可交付改进，不把所有格式组合承诺为已支持，也不新增任意缺卷救援。

1. **RAR 管道密码兼容。** 实际 RAR/UnRAR `consio.cpp:getwstr` 对重定向输入调用 `CharToWide`，Windows 实现使用 `CP_ACP`，不是 OEM。修正恢复命令的编码选择，保留不能表示字符的明确错误，不通过静默替换或额外暴露密码绕过限制。复核普通、内容密码和文件名密码分卷的相关路径。
2. **批量检查修复工作区接续。** 切页保留列表、结果及各自配置；关闭软件后提供恢复/丢弃入口，不自动开始检查、修复或解压。落盘不保存密码，恢复后加密结果需重新填写结果密码；不得把旧密码状态伪装成已验证，也不得重复入队。来源/结果失效允许明确处理。
3. **大文件校验取消。** RAR 内容校验通过 UnRAR 数据回调检查取消，不必等待整个条目完成；不将取消包装成损坏或密码错误。只优化实际检查路径，不承诺未经对比的吞吐提升，不伪造字节进度。

保持单条行内展开、多选弹窗与独立配置。UI 修改查看真实 Release Tauri 页面，覆盖常用/窄窗口和字号缩放；用户链检查围绕切页、重启恢复、补密码、重新检查、修复及入队。复用不受影响的 v1.4.8 格式证据，不重复无关全量矩阵。RAR4 恢复、无法由工具 ANSI 字符集表达的密码以及 ZIP 任意缺卷仍为后续范围。

## 实施与审计

第一步完成：恢复命令的密码输入使用 Windows ANSI 代码页，与 RAR 管道读取一致；无法表示的字符仍明确报错。新增固定 CP1252（é/€）、CP936（中文）、UTF-8 及不可表示字符检查，避免只在本机 ANSI/OEM 相同的环境误判全部兼容。

`cargo test --manifest-path src-tauri/Cargo.toml --lib services::rar_recovery::tests -- --include-ignored` 实际 **7 项通过**，包含真实 Rar.exe 恢复记录修复、恢复卷创建/首中末卷补齐、普通/内容密码/中文文件名密码。工具仍使用隔离的 RAR 7.23；这不代表已验证另一台 ANSI/OEM 不同机器，也不扩大 RAR4 或任意 Unicode 管道密码承诺。原有 sevenz-rust 两项警告未在本轮修改。

后端共同编译时一并完成第三步：vendor/unrar 新增同步借用取消标志的 `test_with_cancel`，数据/换卷回调检查取消并解除栈指针；普通读取/解压接口不变。检查、修复后校验、补建恢复卷前校验均使用它。初次编译遗漏两处内部 Skip 调用的新参数，按编译错误补齐，没有放松断言。

同一命令最新实际 **8 项通过**（覆盖此前 7 项，不累计成 15 项）。新增真实 128 MiB 单文件 RAR，在条目读取期间发出取消，处理报错返回且随后重新全量校验成功；取消单条目耗时上界 2 秒。这是取消响应证据，不是压缩/解压吞吐提升基准。

第二步代码及定向检查完成：工作区移入 Pinia，切页保留内存状态，重启提供恢复/丢弃入口；保存列表、报告及恢复产物位置，两个密码字段均不落盘。旧报告恢复后须重新检查才能据此修复；加密恢复结果单独补密码，入队先检查整组产物仍存在，缺失结果可重新检查修复。批量检查独立于页面生命周期继续处理，不因切页清空或取消。

前端 `ArchiveRecoveryBatch`、`FileIntegrityView` 和既有 `pendingDrafts` 三文件最新 **22 项通过**，类型检查通过。新增覆盖切页、重启草稿、密码不落盘/补填、失效结果、多次入队、加载失败不清空原工作与无效草稿丢弃。最终审计发现完整诊断入口也必须限制旧报告，据此同步关闭绕过入口，相关断言通过。

## 接续边界

正式公开版仍为 v1.4.8。本次按“推进到封板”交付，不自动合并、推标签或创建正式 Release。普通 NSIS 由 PR 的必需 Windows package 收口，结果/运行链接记录在 PR 正文，不为文档回写反复构建同一源码。

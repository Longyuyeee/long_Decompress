# v1.7.9 · 全局 PAX 与完整 TAR 流程一致性

状态：开发完成，按本次定向结果封板。接续 v1.7.8 的 GNU 长名称部分取回，普通文件/目录的全局 PAX 与正常读取、部分取回使用共享状态规则。正式 Windows 产物以对应提交的 CI/Release 为准。

## 用户目标

含常见全局 PAX 元数据的 TAR / TAR.LZO，正常浏览、解压、转换、诊断和部分取回对文件名与大小的理解一致。元数据不显示成用户文件；遇到无法支持的布局，保留此前已确认的资料并说明停止位置。

## 已完成

1. 两份 GNU tar / Python tarfile 制作、官方 lzop 压缩的原件完成独立清单和逐文件内容核对。连续全局更新/空值删除另用明确构造的 POSIX 状态边界样本，记录工具分歧，不称为工具一致原件。
2. 新增有界共享 PAX 状态和完整读取适配层；全局按字段持续继承，局部覆盖仅作用于下一条，空值删除对应覆盖，归档之间重置。控制记录使用自身物理大小，不作为文件显示。TAR 依赖升至 0.4.46，修正非零文件头大小覆盖及中间控制记录边界。
3. 浏览、图文预览、所选解压、预检、验证及转换使用同一正常读取层；TAR.LZO 部分取回使用同一属性解析/状态规则。完整读取保留 PAX 修改时间，包括负时间和小数；不宣称部分取回已经保存全部时间元数据。
4. 完整与部分结果核对名称、目录和 SHA；缺卷、记录截断、来源替换、取消及明确停止接通原诊断、取回弹窗、结果和历史。没有新增页面。

保留单条展开、多选弹窗、左右等宽、原双栏结构和恢复二级弹窗。仍不承诺链接/稀疏部分取回或缺口后扫描。按用户要求使用后台测试和截图，不接管桌面。

未知全局属性、换行属性值、重复普通属性和过大的元数据明确停止。已有普通完整 GNU/PAX 稀疏读取保持；GNU 长名称与局部 PAX 叠加的部分取回仍不支持，接续 [v1.7.10](ARCHIVE_ROADMAP_1.7.10.md)，仅规划。见 [实现与检查](TAR_GLOBAL_PAX_FREEZE_1.7.9.md)和 [Release](RELEASE_NOTES_1.7.9.md)。

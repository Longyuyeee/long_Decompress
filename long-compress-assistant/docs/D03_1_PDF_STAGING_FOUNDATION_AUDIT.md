# D-03.1 PDF 内部暂存执行基础审计

审计日期：2026-08-31

节点状态：**完成**

执行边界：**内部固定参数转换到同目录受控暂存；不注册产品命令、不校验候选语义、不发布最终文件、不创建任务或历史**

## 1. 目标与需求对齐

D-03.1 只建立 PDF 执行事务的第一层：后端在执行前重新读取真实 PDF 事实，复用共享存储预检，以固定 qpdf 参数数组运行两种已审计模式，并把候选写入目标目录旁的隐藏暂存文件。源文件在转换前后必须保持 SHA-256 一致；取消、超时、进程失败或返回对象被丢弃时，暂存文件由所有权守卫清理。

本节点刻意不越过 D-03 的后续边界：没有 Tauri 产品命令和 UI 执行入口，没有 `qpdf --check`/页树/表单/附件等候选语义校验，没有输出锁与原子发布，也没有任务、历史或“完成”状态。数字签名继续阻断。加密 PDF 虽可用 stdin 密码完成只读分析，但在无法证明“不把凭据放入命令行且保持原加密”的执行方案前继续阻断。

## 2. 真实代码实现

- `src-tauri/src/services/pdf_transform.rs` 定义两种模式、稳定错误码、固定参数数组和内部 `transform_pdf_to_staging` API。
- 执行前调用既有 `analyze_pdf_input`，拒绝分析不完整、数字签名、加密及未确认的图片有损模式。
- 调用共享 `preflight_operation_resources`，按输入字节两倍作不可靠保守估算；明确不足时不启动 qpdf。
- 使用 `staged_output_path(..., "pdf-transform")` 在最终目标同目录生成暂存，`PdfStagedOutput::Drop` 调用统一清理；最终目标在本节点始终不存在。
- qpdf 的 stdin/stdout 关闭，stderr 最多读取 1 MiB；轮询取消，600 秒超时，终止后等待子进程退出。只有退出码成功、暂存为非链接普通非空文件且源 SHA-256 未变化才返回所有权守卫。
- `config/pdf-optimization-contract.json` 和媒体架构门禁固定 `internal-library-only`、验证/发布关闭、加密执行关闭、共享容量预检和源哈希边界。

## 3. 预期—实际—差异—修正

| 项目 | 预期 | 首次实际 | 修正/最终实际 |
| --- | --- | --- | --- |
| Rust 所有权 | 返回暂存守卫且 Drop 自动清理 | 从实现了 Drop 的结构体更新语法移动字段，编译失败；测试报错类型又缺少 `Debug` | 改为先创建可变守卫再写入字节数，并派生 `Debug`；定向单测 2/2 通过 |

其余门禁：PDF 契约、17 文件媒体架构、严格 Clippy、前端 46 文件 267/267、生产构建、D-02.1 真实 12 组回归均通过。仓库既有 Rust 文件整体不满足当前 rustfmt 的全仓格式输出，本节点使用文件级 `rustfmt --check` 验证新增服务，并撤销了误触发的非本节点格式漂移。

## 4. 节点审计与接续点

D-03.1 已满足“真实代码、真实 qpdf、真实 PDF、差异修正、文档审计”的关闭条件。它只证明候选暂存执行和回滚所有权成立，不证明候选可安全发布。

下一唯一接续点为 **D-03.2 候选验证与失败矩阵**：对暂存候选执行 qpdf `--check` 并读取页树，逐项比较页数、加密状态、表单、附件、注释和书签策略；补损坏输入、进程中取消、超时/失败、磁盘不足、目标竞争与更大输出默认拒绝的真实预期—实际证据。D-03.2 仍不得开放 UI 最终完成或写历史；验证与原子发布、输出锁、统一任务/历史应在后续安全编排节点完成。

当前产品版本保持 `1.1.16`。只有 D-01 至 D-04、正式安装版、公开更新与 Release 门禁全部关闭，才允许打包并发布 `v1.1.17`；因此本节点不修改版本号、Release notes 或 GitHub Release。

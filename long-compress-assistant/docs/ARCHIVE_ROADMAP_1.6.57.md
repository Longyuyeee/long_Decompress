# v1.6.57 规划 · LZOP 单文件读取与转换

已完成功能封板，见[开发记录](LZOP_READ_CONVERT_FREEZE_1.6.57.md)。下一阶段 [v1.6.58 TAR.LZO](ARCHIVE_ROADMAP_1.6.58.md)仅规划。架构 BCJ 阶段由 v1.6.56 收尾，接下来回到新增格式和真实失败包兼容主线。先让用户直接打开常见 Linux 备份中的 `.lzo` 文件，查看内容、提取或转换；不继续用过滤器选项数量代替格式覆盖。

1. 先核实现有随包能力和可复用的 LZO 解码器、来源/许可及实际 Windows 兼容性。以官方 lzop 生成的非空原件为依据，区分 LZOP 容器和裸 LZO 数据；不凭后缀直接解码。
2. 本版先做普通单文件的只读闭环：识别、浏览、文本/图片预览、完整检查、提取，以及转成 ZIP/7Z。处理未压缩块、LZO1X 常见方法、多块、头/块校验、空文件、截断及损坏；具体支持范围以原件证据为准。只显示实际可确认的大小和状态。
3. 沿原双栏文件浏览器、解压中心、工具中心和结果入口接入，历史与失败纠正保留来源。密码不是 LZOP 原生能力，不伪造密码或恢复承诺；遇到不支持的参数说明原因和可行下一步。
4. 原单条展开、多选弹窗、自然继承、左右等宽、主题与快捷键保持；必要说明放圆形问号，不增加铺满页面的介绍。只检查新增与受影响路径，补独立原件、实际桌面及宽窄显示。

后续分期：先评估 TAR.LZO 的目录/多文件读取及转换，再评估数字切卷；每期按完整用户流程交付，不把识别后缀当作完成。创建能力、原生密码和缺卷救援不在本期。ALZ/EGG 缺有效外部原件等兼容条目继续保留，拿到原件后按影响优先处理。

参考：[lzop 官方说明](https://www.lzop.org/)、[libarchive LZOP 读取实现](https://github.com/libarchive/libarchive/blob/master/libarchive/archive_read_support_filter_lzop.c)。参考不代表当前应用已支持，具体实现和许可在开发时确认。

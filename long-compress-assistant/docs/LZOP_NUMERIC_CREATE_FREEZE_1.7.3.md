# v1.7.3 · LZOP / TAR.LZO 数字分卷记录

状态：功能封板完成，接续正式合并与发布；版本身份 1.7.3，分支 `codex/lzop-numeric-create-173`，日期 2026-10-27。最终源码、标签及安装附件以 GitHub 为准。

## 实现和交互

开放两种格式既有的数字切卷能力，不再清除继承的分卷设置。复用通用流程：先暂存标准流，按大小切片，完整校验后整组发布；失败、取消或已有目标冲突时不发布半组，不改原来源。未新建编码器、重复切卷服务或增加依赖。

原单条展开的分卷卡片、转换大小输入接通，多选可保留原值、关闭或统一大小；仅改选中任务，不改全局。LZOP / TAR.LZO 混合选择可以只改大小而保留格式，强制数字卷型。实际小窗截图发现“保持各自设置”时仍显示无关算法和恢复选项，最终收起这些控件，仅保留有效配置。额外说明收进问号，左右等宽、主题、双栏包内外共用结构保留。

修正新的数字输入在 Vue 中转换为 number 后，批量补丁却需要字符串的问题；补丁显式规范化为字符串。来源密码仍只读取原包，不误认为 LZOP 新包具有密码。

- 9 组原生/桌面新分卷先核对编号、每卷长度、合并流 SHA，再由独立工具逐文件读取。6 个不同的标准流经过官方 Windows lzop 全流检查、官方 Linux lzop 名称与内容回解；TAR.LZO 再由 Windows bsdtar 还原目录。相同标准流仅切片大小不同或产物/工具身份相同的成功回执直接复用。见 [独立回执](evidence/lzop-numeric-create-1.7.3/official.json)。工具及下载包身份沿用已核对的官方原件，不安装新运行时、不放入发布包。

## 保留边界与下一步

数字切片不是 LZOP 原生多卷或原生块分段；外部软件需先合并完整流。无新增格式数、原生密码或缺卷救援；普通 LZOP 不表达空目录，TAR.LZO 保留目录。没有总成员/总卷数字段，不保证发现“完整成员及后续内容整体丢失”；老 Windows lzop 的 ANSI 中文名称限制保留。ALZ / EGG 外部原件缺口未关闭。

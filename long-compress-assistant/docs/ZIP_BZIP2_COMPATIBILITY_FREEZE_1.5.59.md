# v1.5.59 ZIP Bzip2 跨流程兼容封板记录

2026-10-22。实施见 [路线](ARCHIVE_ROADMAP_1.5.59.md)，用户说明见 [Release](RELEASE_NOTES_1.5.59.md)。

## 交付范围（功能已封板，进入发布）

- 独立 Store/Deflate/Bzip2 ZIP 可沿原编辑清单添加、替换、重命名、目录整理和另存。普通原条目直接复制原压缩数据；密码条目重新按原方法和明确密码方案写出，保留原支持的时间、权限与备注。新增/替换仍选 Deflate/Store。
- 资料对比的文件夹↔ZIP、ZIP↔ZIP 纳入方法 12。复用实际内容 SHA-256、AES/ZipCrypto、明确密码编码、完整数字/标准卷及任意成员归组、精确取回和补充组包。组包按明确所选方法重新编码独立 ZIP，来源引用沿草稿/历史/失败接续。
- 编辑核对真实读取大小，原 CRC/解码器错误仍阻断另存；ZIP 大小异常在内容核对中标记本项未完成，其他已完成结论保留。未知方法保留具体条目和方法说明；缺卷、密码与编码使用原入口纠正。
- 编辑显示原包方法及保留/新增方法的差别。原单条展开、多选弹窗、自然继承、50/50、窄窗滚动与 schema 18 保持。

原包不覆盖。分卷可作为读取、比较、取材来源，仍不提供原生分卷编辑或损坏包修复；不宣称所有元数据无损或全部外部工具兼容。其他方法保持原能力，不把本版方法白名单扩展当成所有 ZIP 的支持。

## 新增与受影响检查

七项不同 Rust 检查通过（`cargo test --lib bzip21559`）：原方法/原压缩字节、备注/时间/权限保留及新增内容；AES/ZipCrypto 和明确 CP936 读取、保留/去密码/新密码写出；错误/缺密码与已有输出保留；真实内容对比；数字卷取材的精确范围、来源变化/缺卷及编辑卷型边界；真实 CRC、目录大小及截断流拒绝；未知方法区分。使用真实 Bzip2 流，不以篡改方法标记冒充正向来源。

类型/Vite、八处版本身份、Shell DLL 和原生 `custom-protocol,desktop-e2e` 构建通过。前端仅新增方法说明及支持提示，不为静态文案新增重复单测。四条真实桌面组合流程通过，18 条宽窄布局、6 张代表图实看，见[原始记录](evidence/zip-bzip2-compatibility-1.5.59/desktop-progress.json)。原生桌面程序 SHA-256：`10f38470fe297b75b1070a868853df5578ae568fdd6cc49552eb232ede45f432`（`custom-protocol,desktop-e2e` 构建，不当作正式安装包身份）。

1. 独立 7-Zip 生成的真实 Bzip2 源：单项右键整理、改名/移动、添加 Deflate 内容、原清单另存，独立 7-Zip 回解并确认内容与 Bzip2 方法。
2. AES Bzip2 原包：错误密码失败不生成输出，纠正后设新 AES 密码，保留 Bzip2；实际回解及原失败记录保留。
3. AES Bzip2 数字卷：从非首卷读取、缺密码结论未完成、填密码后实际内容相同；多选弹窗仅取回一个内部文件。正常关闭/同资料重启，草稿范围保留而密码为空，补密码执行与历史再取回均只产目标文件。
4. ZipCrypto Bzip2 标准卷：从非首卷读取，ZIP↔ZIP 实际内容相同；移走中间卷后拒绝完整清单，补回后按所选引用组包。明确去密码、按 Deflate 生成独立 ZIP，独立回解仅所选内容；全部原独立包/卷组 SHA-256 保持。

首次桌面尝试没有完整通过项，原浏览器默认多选导致脚本应先明确单项；后续下拉等待补齐。均只改操作脚本，原运行时/交互没有改动；已完成的普通编辑流程保留，只接续后面未完成项。源码和图对应同一原生程序，之后仅整理文档与记录。

v1.5.34 的创建、浏览、提取、转换和其他既有解码能力按原依据复用；本版不重跑旧全格式/密码/算法/媒体矩阵、真实盘满或个人安装。

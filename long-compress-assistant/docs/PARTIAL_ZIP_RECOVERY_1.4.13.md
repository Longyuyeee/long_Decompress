# v1.4.13 缺卷 ZIP 部分抢救

日期：2026-10-16。基线为 v1.4.12 发布后文档提交 `9856d50`，分支 `codex/partial-zip-recovery-1-4-13`。用户批准按缺卷救援、密码包、恢复结果的顺序推进到可发版；本轮不自动合入或正式发布。

## 用户目标与范围

收到标准 ZIP 分卷但缺少其中某卷时，能够先救出其他卷中的完整文件，清楚了解未恢复项，并沿用现有结果入口继续解压。先覆盖目录完整可读的 `.z01/…/.zip`，不要求用户移动或修改原卷；原件保留，新结果单独保存。

- 缺首卷或中间卷时，从仍可读取的完整目录定位条目；只有文件头与压缩内容完整落在连续现有卷中的条目才进入救援。
- 普通 ZIP、AES、ZipCrypto 复用既有密码读取与内容核对；错误密码与缺卷分别提示。混合包的明文条目不能证明密码正确。
- 复用已有部分恢复结果、未恢复说明、打开位置、批量配置和恢复结果入队，改善缺卷场景的说明与显示。
- 终卷或目录所在卷缺失、目录不完整、未知边界及数字切卷长度无法确定时保留明确的补卷指导；不承诺任意缺卷恢复。
- RAR4 是次要候选，须有可用真实旧包；不作为本版 ZIP 主线的发布阻塞。ZIP 输出方法增强仍留 v1.4.14。

## 实施顺序

1. 接入仅供救援的标准 ZIP 缺卷读取视图，保持正常浏览/解压要求完整卷组的行为。
2. 打通诊断、原密码、逐项完整文件救援，保留每个未恢复文件及原因。
3. 在已有页面接入恢复结果与后续操作；单条展开、多选弹窗、窄窗口可滚动和等宽详情保持。
4. 定向核对新用户链和真实常用/窄窗口显示，旧 ZIP/LZIP/SFX/RAR/媒体及安装生命周期检查直接复用。
5. 记录结果与边界，统一版本、README 与中文 Release；最终候选安装包成功即可达到可发版，不为状态回填重复打包。

## 当前进展

- 开发起点：诊断及修复入口均遇缺卷直接退出，标准读取器也要求卷组完整。
- 标准卷读取器增加仅供救援的模式，将目录中的磁盘相对位置映射到现有卷；每个条目的文件头、名称与压缩内容必须位于连续现有卷中。不猜缺卷长度，正常解压仍拒绝缺卷。
- 诊断、密码与修复已接入；新包保留成功恢复的文件名清单。单项与批量结果采用同一按需展开的列表，部分恢复用提示色区分。

## 实际桌面与独立回解

实际程序版本 1.4.13，SHA-256 `96ae090322fb3d9f6bc43aaba1f984a6010008d29a7559288ae7de11b3c884f4`。普通/AES/ZipCrypto 三种外部 ZIP 原包经标准分盘并由独立 7-Zip 完整读取，再分别移除首卷和中卷。六组实际原生命令各恢复预期三个文件，包括缺卷后的文件及跨两个连续现有卷的文件；恢复新包经独立 7-Zip 校验、解压与源载荷哈希比较。密码缺省和错误密码均未产生结果，终卷缺失明确拒绝救援。18 个现存输入卷与原完整卷组哈希一致。

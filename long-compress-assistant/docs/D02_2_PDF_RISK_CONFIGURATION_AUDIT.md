# D-02.2 PDF 两模式配置与执行前风险界面审计

审计日期：2026-08-31

节点状态：**完成**

执行边界：**只读分析 + 页面内配置草稿；不转换、不生成输出、不创建任务、不写历史**

## 1. 目标与需求对齐

D-02.2 消费 D-02.1 的真实 qpdf 结构化报告，在压缩中心开放 PDF 配置工作区。界面必须展示页数、输入字节、加密/密码、数字签名、表单、附件和书签事实；提供“无损整理”和“兼容图片优化”两种模式；对有损图片优化进行显式确认，对数字签名文档保持仅分析阻断。默认只建议新文件，禁止覆盖源文件，也不得承诺输出一定更小。

本节点没有引入 PDF 转换或发布命令。“锁定配置”只修改当前 Vue 页面中的草稿状态，没有接入 `useTaskStore`、`useCompressionStore`、任务历史或持久化层。D-03 执行仍明确冻结。

## 2. 真实代码实现

- `PdfCompressionWorkspace.vue` 通过产品 `analyze_pdf_input` 命令读取真实 PDF 事实；加密文件只有在正确密码分析完成后才进入配置状态，密码在成功或失败后均从输入框清空。
- `pdfOptimizationWorkspace.ts` 集中定义两模式语义、默认 `.organized.pdf` / `.optimized.pdf` 新文件路径、签名阻断、有损确认和“不保证变小”规则。
- `CompressionView.vue` 将原 PDF 占位区域替换为真实 D-02.2 工作区，但没有新增任何执行按钮或后端转换入口。
- `pdf-optimization-contract.json` 升级为 D-02.2，并由契约门禁固定 `executionEnabled=false`、`createsTasks=false`、页面内草稿、新文件输出、有损确认和签名阻断。
- 媒体架构门禁要求 PDF 工作区存在，并继续禁止任何 `optimize/compress/execute/publish_pdf` 命令。

# v1.5.17 多段压缩流完整读取

2026-10-19，从已正式发布 v1.5.16（41e4eb7）接续后续三版路线第一项，分支 codex/v1.5.17-multistream。用户授权按版本推进至可发版，更新两份 README、中文 Release 和开发路线，复用未受影响的检查。

## 开工审计与目标

普通 GZIP/BZIP2/XZ、TAR 包装流、TAR 计划/浏览/预览/检查入口使用单段解码构造；先用真实多流原件确认首段后遗漏或尾部错误漏检，不能仅凭源码宣称修复。Zstandard 当前已默认读多帧，只做必要控制回归。普通数字分卷创建与读取是既有能力，不重复宣传新增。

先生成独立 CPython/系统 libzstd 压缩流与 GNU tar 原件，记录工具、参数与内容哈希；固定真实失败，再统一连续读取。单个 TAR 跨压缩流边界与多个完整 TAR 拼接分开处理，后者不默默漏掉后面的包却报全成功。普通流浏览/有界预览与末尾所选、转换、后段损坏和补卷新任务接通。保留单条展开、多选弹窗、自然继承、左右等宽和窄窗滚动。

本版开工时尚未封板或发布。后续 v1.5.18 自有 AES 容器分卷、v1.5.19 逐文件校验原因未开始；本版只回归已有单包 AES 的内层读取，不提前开放容器分卷。ALZ 方法 3、EGG 加密固实和真实 VHD 盘满补测待办保持。

## 首轮真实复现

八组 CPython gzip/bz2/lzma 与系统 libzstd 多段原件，TAR 内层由 GNU tar 1.35 生成。独立 7-Zip 26.04 已对八组压缩流完整回解并匹配哈希。首轮确认 GZIP 浏览大小仅 31 字节而实际 44168；后段截断被原校验误作成功，跨段 GZIP/BZIP2/XZ TAR 读取失败，两个完整 TAR 拼接被接受却忽略后段。

首轮八个测试红灯已保存。Zstandard 的浏览/预览/检查已通过到提取准备环节，其红灯来自新增共享解码工厂尚未支持 zst，不能据此宣称旧 Zstandard 多帧有缺陷；另一个工厂原始哈希红灯也是新接口覆盖。其余真实失败按上段具体原因处理，不把红灯个数当新增缺陷数。

## 实现接续

GZIP/BZIP2/XZ 使用共享多段读取，Zstandard 保留多帧读取；TAR 计划、浏览、预览、提取和验证及已有 AES 单包内层验证接入同一路径。TAR 结束后的非零内容明确报不支持，不将多个完整 TAR 静默当单包处理。压缩流数据失败保留具体原因，嵌套 std::io::Error 的真实 OS 原因仍可分类，不误作损坏或错密。

普通流增加原生浏览和现有查看器的有界预览。小文件扫描得到准确总量；浏览超过 8 MiB 时显示大小未知，不再为了列出一个大文件而读完整包。文本最多显示 1 MiB、读取预算 64 MiB，图片最多 8 MiB，超出引导先提取后打开。已有普通格式数字卷创建与读取保持；数值卷的压缩体积按整组统计，GZIP/BZIP2 别名名称保持。

该阶段定向检查汇总 51 项不同 Rust（13 新增、38 相关既有）及 16 项 FileIntegrityView 前端通过。早期六项通过后，只复核受改动影响的路径；四个未受影响新检查复用。相关 TAR 回归一项曾发现诊断具体原因被笼统覆盖，现补 TAR 上下文并单独重跑通过；20 个已通过同模块检查没有重复。诊断显示移除内部标记，报告/导出保留原内容。版本与 Shell DLL 接续为 1.5.17，最终桌面/发布结果另记，尚不计通过。

## 实际桌面发现的中卷预览缺口

首轮程序 e1898beaa8764f58e9a8bb4bbae3c58b69643f74a1a83ee9cebd27c0aea1f0b5 已完成八原件全提取/完整性、八后段损坏清理、八数字卷任意成员读取，均按完整内容哈希核对。UI 实看发现，从 .002 浏览到目录后点末尾文本却把源卷当普通 XZ，不能预览。原因是预览 API 只在检测魔数时归一，后续格式判断仍用用户点选的非首卷路径。

现图片/文本预览都先在后台归一到完整卷组；新增首/中/尾成员检查以及既有密码 ZIP 编码/数字卷预览回归通过。累计 52 项不同 Rust（14 新增、38 相关既有）。只重做受影响预览，24 条提取/错误/卷组入口结果按旧程序身份复用；图片预览归一属于受影响路径，会在新程序补单包与末卷实际读取。最终 UI 与发布状态继续记录，尚不提前计通过。

脚本早期还修正了 Vec 选项不能传 null、已打开归档时应点浏览器自己的打开按钮两处测试问题。它们没有修改产品功能，已完成的 native 结果没有重跑；中卷预览失败则是实际产品缺陷，红灯页面另存。

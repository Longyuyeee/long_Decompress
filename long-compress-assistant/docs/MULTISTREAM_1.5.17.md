# v1.5.17 多段压缩流完整读取

2026-10-19，从已正式发布 v1.5.16（41e4eb7）接续后续三版路线第一项，分支 codex/v1.5.17-multistream。用户授权按版本推进至可发版，更新两份 README、中文 Release 和开发路线，复用未受影响的检查。

## 开工审计与目标

普通 GZIP/BZIP2/XZ、TAR 包装流、TAR 计划/浏览/预览/检查入口使用单段解码构造；先用真实多流原件确认首段后遗漏或尾部错误漏检，不能仅凭源码宣称修复。Zstandard 当前已默认读多帧，只做必要控制回归。普通数字分卷创建与读取是既有能力，不重复宣传新增。

先生成独立 CPython/系统 libzstd 压缩流与 GNU tar 原件，记录工具、参数与内容哈希；固定真实失败，再统一连续读取。单个 TAR 跨压缩流边界与多个完整 TAR 拼接分开处理，后者不默默漏掉后面的包却报全成功。普通流浏览/有界预览与末尾所选、转换、后段损坏和补卷新任务接通。保留单条展开、多选弹窗、自然继承、左右等宽和窄窗滚动。

本版开工时尚未封板或发布。后续 v1.5.18 自有 AES 容器分卷、v1.5.19 逐文件校验原因未开始；本版只回归已有单包 AES 的内层读取，不提前开放容器分卷。ALZ 方法 3、EGG 加密固实和真实 VHD 盘满补测待办保持。

## 首轮真实复现

八组 CPython gzip/bz2/lzma 与系统 libzstd 多段原件，TAR 内层由 GNU tar 1.35 生成。独立 7-Zip 26.04 已对八组压缩流完整回解并匹配哈希。首轮确认 GZIP 浏览大小仅 31 字节而实际 44168；后段截断被原校验误作成功，跨段 GZIP/BZIP2/XZ TAR 读取失败，两个完整 TAR 拼接被接受却忽略后段。

首轮八个测试红灯已保存。Zstandard 的浏览/预览/检查已通过到提取准备环节，其红灯来自新增共享解码工厂尚未支持 zst，不能据此宣称旧 Zstandard 多帧有缺陷；另一个工厂原始哈希红灯也是新接口覆盖。其余真实失败按上段具体原因处理，不把红灯个数当新增缺陷数。

# v1.5.3 EGG 基础读取

从 v1.5.2 发布后主线 `9efeb92` 接续，功能和真实桌面已封板，统一 v1.5.3，接续受保护 PR 与发布。按批准路线补充 EGG 只读，不新增 EGG 创建，也不改变现有压缩默认项。

## 范围和接入依据

评估 [unegg](https://github.com/alkegi/unegg) 0.2.1，固定提交 `9929009ca4d010e8cd88bb796f7a1868162026d4`，MIT；测试目录另标 CC0。原厂格式组合参考 [Bandizip EGG 说明](https://en.bandisoft.com/bandizip/help/how-to-open-alz-and-egg-files/)。许可证保留到随附引擎，商业原工具只用于独立验证，不随产品分发。

本版以真实原包验证 Store、Deflate、Bzip2、LZMA、基础 ZipCrypto、UTF-8 名称与原生 `.volN.egg` 为范围。AZO、固实、AES/LEA 留在 v1.5.4；必须明确说明不支持，不能退回通用密码遍历。算法、密码和卷型分别验证，不能从单一成功包外推所有组合。

## 顺序

1. 核对原始载荷、分卷链接、索引与解码错误。修正上游截断流、名称有损转换和卷链检查，再提供隔离进程及固定资源身份。
2. 接识别、任意成员归组、浏览/所选解压、完整性、转换和任务历史；结构失败先于密码，完整载荷/大小/CRC 后才认可密码。
3. 真实桌面走导入、密码纠正、缺卷补回、重试、结果检查；实际暂停/取消，查看常用及窄窗 UI。每步审计并推送。
4. 达到范围后冻结功能、统一版本、受保护 PR、必需构建与中文 Release，回下载验证安装器和更新资产，再回填交接。

## 初审发现

上游 Deflate 在没有 StreamEnd 时可结束；默认文件名解码替换无效字节并去掉部分路径字符；多卷只寻找 next ID，未核实反向链接。必须定向修复，不通过改名原包、缩减载荷断言或注入成功规避。

## 基础实现审计

隔离 `long-egg` 已接统一浏览/所选解压/密码确认/检查/转换路由，严格识别原生双向 ID、缺首/中/末卷、循环和混卷，复用事务暂存与真实子进程控制。普通格式不会退到 7-Zip 假装支持 EGG。最终认定密码前验证所选实际加密内容的全部数据块大小/CRC；结构和未实现方法先于密码。

十三组上游原包和四组原版 ALZip 新包均有独立 Bandizip 载荷核对。真实原工具证明 EGG 的 UTF-8 文件名和密码字节不是同一回事：本机原工具使用 CP936 中文密码；新增 EGG 密码专用标签，默认 UTF-8，明确 CP936 可读原包，名字仍按原始标记读取。沿用已有可持久化来源编码字段，贯通任务、重试、历史、转换和诊断；密码本不保存到历史。不可表示字符及 CP932 别名拒绝有损替换。

八项新后端集成、三项辅助进程边界测试及十个前端文件 138 项检查通过，类型/构建通过；真实桌面矩阵进行中，暂不记为封板。256 MiB 控制包由原 ALZip 生成，准确来源保留在忽略目录与后续桌面证据。首次桌面构建命令的 npm 参数转发失败，已改为直接调用 Tauri CLI；失败构建不算验证通过。

末轮发现历史保存已知 `unsupported` 标记时仍归为 unknown，已贯通保存、筛选和重试指引，不将未知方法误说成密码错误或损坏。新增回归先复现分类筛选丢失，修正 SQL 和分类白名单后验证。Deflate 提前结束和 Deflate/Bzip2 尾部余量明确拒绝；LZMA 解码器对额外输入可能返回 Ok，但产生额外/变化内容，必须按产品实际完整大小和 CRC 条件拒绝，而不能把底层返回 Ok 当成通过。新回归直接使用相同输出上限和最终内容条件，不只判断底层返回码。CRC 不认证来源，也不提供损坏修复。

## 最终封板证据

76 项不同 Rust 检查（EGG 8、历史分类 1、诊断 32、既有 ALZ 8、卷组 9、ZIP 密码 14、helper 4）、十个前端文件 140 项、类型/构建与普通生产构建通过。最终真实桌面 `2026-10-18T03:00:58.341Z` 完成，ProductVersion 1.5.3；26 个场景、26 张 1100×700/760×520 页面和横向布局记录见[桌面收据](evidence/egg-basic-1.5.3/results.json)。全部图片已逐一查看，来源编码、问号说明、自然滚动、左右参数和弹窗边界正常。

十七组真原包独立载荷覆盖 Store/Deflate/Bzip2/LZMA、ZipCrypto、原生卷与 UTF-8 名称；CP936 中文密码由本机原版 ALZip 和独立 Bandizip 证明。算法和密码组合以固定包为限，不从单一方法外推所有方法/代码页。复杂 AZO/固实/AES/LEA 原包只用作明确拒绝，不算已支持。实际文件浏览器双击中卷、选择提取、中文密码纠正、历史恢复编码而重新输入密码、补原卷后新任务、多成员去重、转换 ZIP 独立回解、诊断与三类批量/设置页面完成；原失败记录保留。

256 MiB 原 ALZip 控制包证明真实 helper 暂停无 CPU 进展、恢复及暂停中取消；开启完成后删除时，取消仍保留源包且不发布/残留暂存。运行时实际 helper 与最终库存哈希核对，测试不是注入成功。第一轮 E2E v1.5.2 的结果不作为最终程序身份；最终 v1.5.3 E2E 是测试程序，不是安装器。无个人安装、设置或历史改动。

## 明确边界和复跑

不创建 EGG、不提供 AZO/固实/AES/LEA、全局/文件名加密、损坏修复或缺卷部分救援；仅支持版本 256，最多 1000 原生卷、250000 条目、16 MiB 单个元数据字段、512 GiB 声明展开总量、256 MiB 单个 LZMA 压缩输入。纯加密空文件没有完整密码载荷可确认，明确拒绝，不用短头伪证密码。CRC 不能认证来源或保证检测所有修改。

复跑先执行 `scripts/build-egg-engine.ps1` 和固定原包库存脚本，再运行 `cargo test --lib egg_` 与上述定向回归、`cargo test --manifest-path tools/egg-engine/Cargo.toml`、前端十文件检查。桌面用 `VITE_DESKTOP_E2E=1` 构建前端，直接调用 `node node_modules/@tauri-apps/cli/tauri.js build --config src-tauri/tauri.e2e.conf.json --features desktop-e2e --bundles none`；指定实际 `Long解压.exe` 的 `TAURI_APP_BINARY` 后执行 `node scripts/test-tauri-desktop.mjs --egg-153-only`。`egg-engine.lock.json` 固定源码、引擎与全部随附许可，安装包内复验用 `scripts/inspect-egg-153-installer.mjs`。

新机器的控制包可用同一原 ALZip 生成器与 `prepare-egg-153-control.mjs` 新建公开随机载荷，保留那次身份，不冒充本次完全相同原字节。本次控制包身份随桌面收据，原始商业工具不分发。发布后按已批准路线进入 v1.5.4 复杂 EGG，再做 v1.5.5 外置卷 SFX；尚有两个版本，不重复规划。

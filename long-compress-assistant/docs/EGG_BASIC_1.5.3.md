# v1.5.3 EGG 基础读取

从 v1.5.2 发布后主线 `9efeb92` 接续，当前实施中，尚未封板或发布。按批准路线补充 EGG 只读，不新增 EGG 创建，也不改变现有压缩默认项。

## 范围和接入依据

评估 [unegg](https://github.com/alkegi/unegg) 0.2.1，固定提交 `9929009ca4d010e8cd88bb796f7a1868162026d4`，MIT；测试目录另标 CC0。原厂格式组合参考 [Bandizip EGG 说明](https://en.bandisoft.com/bandizip/help/how-to-open-alz-and-egg-files/)。许可证保留到随附引擎，商业原工具只用于独立验证，不随产品分发。

本版以真实原包验证 Store、Deflate、Bzip2、LZMA、基础 ZipCrypto、UTF-8 名称与原生 `.volN.egg` 为范围。AZO、固实、AES/LEA 留在 v1.5.4；必须明确说明不支持，不能退回通用密码遍历。算法、密码和卷型分别验证，不能从单一成功包外推所有组合。

## 顺序

1. 核对原始载荷、分卷链接、索引与解码错误。修正上游截断流、名称有损转换和卷链检查，再提供隔离进程及固定资源身份。
2. 接识别、任意成员归组、浏览/所选解压、完整性、转换和任务历史；结构失败先于密码，完整载荷/大小/CRC 后才认可密码。
3. 真实桌面走导入、密码纠正、缺卷补回、重试、结果检查；实际暂停/取消，查看常用及窄窗 UI。每步审计并推送。
4. 达到范围后冻结功能、统一版本、受保护 PR、必需构建与中文 Release，回下载验证安装器和更新资产，再回填交接。

## 初审发现

上游 Deflate 在没有 StreamEnd 时可结束；默认文件名解码替换无效字节并去掉部分路径字符；多卷只寻找 next ID，未核实反向链接。必须定向修复，不通过改名原包、缩减载荷断言或注入成功规避。

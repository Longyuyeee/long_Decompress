# v1.5.24 TAR.LZMA 与 Long AES 组合

2026-10-20，从正式 v1.5.23 `42de107` 接续[既定路线](ARCHIVE_ROADMAP_1.5.23_TO_1.5.25.md)。本版正在实施，尚未封板或发布。

## 用户目标和范围

为目录和多个文件提供 TAR.LZMA，并为保留 LZMA 编码的分享需求增加 LZMA.AES / TAR.LZMA.AES。接通创建、密码、数字分卷、任意成员浏览与预览、完整检查、所选/整包解压、转换、失败纠正及结果入口。复用已有 LZMA-alone、TAR、Long AES V2 和任务事务，不设计新的加密格式。

单文件 LZMA.AES 与多文件 TAR.LZMA.AES 分别说明用途；Long AES 包需接收方使用支持本组合的 Long解压，不称为通用 LZMA 原生密码标准。保留普通 LZMA 的既有行为，不默默把用户选择转换成其他格式。

单条点击展开、多选弹窗、自然继承、左右等宽、窄窗滚动保持；新功能在原有入口增加，长说明不挤占配置和执行日志。

## 开工确认与执行顺序

1. 当前 TAR.LZMA 不在前后端能力表或路由；LZMA-alone 已可创建和读取，不重复开发编码器。
2. 现有 Long AES 的十五种内层名单不含 LZMA，需同时补全认证后内层识别、创建、查看、检查和提取分派，不能只开放格式选项。
3. 先用独立 Python TAR/LZMA 与 cryptography 认证原件确认真实内容，再接通普通 TAR.LZMA 和两种加密组合；数字切卷沿已有发布事务执行。
4. 只检查新增或受影响链路，并实看常用/窄窗页面；旧格式、已通过的 AES 基础算法与真实 VHD 盘满不重跑。
5. 完成后同步两份 README、中文 Release、格式等级及开发交接，走必需 Windows package、普通受保护合入和正式发布。

v1.5.25 结果生成相对路径校验清单仍仅规划，不混入本版；ALZ 方法 3 与 EGG 加密固实研究边界保持。

# v1.7.18 · GNU 长链接目标内容取回封板记录

日期：2026-10-28。

## 实现与范围

TAR.LZO 部分取回分别保存 GNU `K` 长链接目标和 `L` 自身长名称，独立核对物理大小、载荷、NUL 结束符及零填充。完整元数据只作用于下一个对应条目一次，K 必须对应硬链接；K 与局部 PAX linkpath 同时存在时必须一致。重复、孤立、冲突、非链接附带目标或记录不完整均停止，不把元数据当作用户文件。

目标继续只绑定归档中前面已确认的内容文件，使用原始路径和目标身份，独立于 Windows 输出名称修复。复用 v1.7.17 的来源 revision、按来源顺序复制、稀疏写入、逻辑 SHA、修改时间和暂存发布。原目标无需选中，所有输出均为独立文件，不创建系统链接，也不从输出目录已有文件取内容。

界面仅更新原圆形问号中的支持范围。短来源提示、完整来源的折叠详情、逻辑大小与部分历史均沿用；单条展开、多选弹窗、等宽双栏和压缩包作为特殊文件夹的结构保留。

依据：[GNU tar 文件头说明](https://www.gnu.org/software/tar/manual/tar.html#Standard)中的 GNUTYPE_LONGLINK / GNUTYPE_LONGNAME，以及本版真实生产者原件。支持结论以已核对的子集为准。

## 原件与检查

`tests/fixtures/archives/tar-gnu-longlink-1718/` 来自 GNU tar 1.35 `--format=gnu --sparse` 和项目自编文件、真实 Linux 硬链接。15 个条目含 6 个硬链接，覆盖单独 K、K+L、自身/目标长名称、空文件及旧 GNU S 稀疏目标。GNU 完整提取与源目录的名称、SHA 和 inode 关系逐项一致；Python 独立读取目标内容，官方固定 SHA lzop 完整回解与 TAR 原件一致。故障样本在此基础上另行构造。

- 新原生 7 项首轮通过：完整 GNU 原件及目标绑定；坏尾、显式 CRC 故障与缺结束标记的实际取回；K/L 两种顺序及一致 PAX 目标；孤立/重复/冲突/无效记录；载荷、填充、硬链接头边界和元数据期间取消；名称修复相同而目标身份不同的来源重查；缺中卷及补卷重查。
- 相关旧原生 3 项通过：普通头/PAX 生产者、未确认/链条/歧义目标停止，以及完整旧 GNU 稀疏目录/预览/检查。移除旧测试中“K 一律不支持”的过时断言，正向与异常记录由本版覆盖。其他已通过且未受影响的矩阵复用。
- 前端 2 项通过，核对长来源、内容大小、空文件和仅选链接的历史/折叠结果。类型检查、Vite 生产构建、Shell DLL 与八个版本来源一致性通过。
- 独立 Python 核对 4 份实际输出、43 个文件的精确路径、逻辑 SHA、明确修改时间、Windows 稀疏属性/分配量；所有文件 st_nlink 为 1。仅选链接及空目录得到 6 个文件、1 个明确目录、33,954,438 逻辑字节，没有带出原目标或缓存文件。
- 后台真实 Vue/CSS 回放原生报告及结果，3 组通过。1100×700 和 760×520 无横向溢出、底部按钮可见，长名称/来源在原详情内换行与滚动。六张截图逐张查看；IPC 明确为原生值回放，未操作用户桌面。

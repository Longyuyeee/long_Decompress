# v1.4.7 RAR 恢复与右键入口实施记录

日期：2026-10-15。基线：正式 v1.4.6 / `d7c9daf`；分支：`codex/rar-recovery-1-4-7`。用户要求按既有方向推进到可发版，保持单条展开、多选弹窗，不重复无关矩阵。本轮功能与定向检查已完成，最终普通安装包由分支 PR 的 `Windows package` 构建；本记录不表示已正式发布。

## 已实现

- RAR 诊断按真实格式分派，改名为 `.rar` 的 ZIP 仍按 ZIP 检查；同组 RAR 新旧数据卷和 `.rev` 按完整名称关联，避免把相近名称混在一起。
- 使用本机 Rar.exe 在独立副本中执行恢复记录修复或恢复卷重建。RAR 仅输出损坏卷的替换文件，因此会把替换卷与完好卷副本用统一文件名组成新卷组，再用 UnRAR 逐条读取测试。
- 结果另存到新的 `<名称>.repaired` 目录，拒绝覆盖已有结果；取消或失败清理临时副本。恢复卷不足或校验失败不发布不完整卷组；结构重建标为部分恢复。
- 密码与加密方式保持。修复命令使用重定向 stdin，按本机 OEM 编码写入一次密码并关闭管道；不会改用命令参数传递修复密码。需要读取密码的恢复卷补卷中，无法表示的字符或换行会明确提示；恢复记录修复可在不读取加密文件名的情况下处理密文，结果仍须用正确密码原生验证。
- RAR 恢复保护可选 3/5/10%，默认关闭。单条、多选弹窗、转换、配置组/便携模板、草稿及历史快照保留比例；既有配置省略该项时沿用关闭。修正 RAR 文件名加密快照和模板被旧的“仅 7Z”条件丢弃的问题。
- Windows 经典/原生菜单增加 `--repair-archive`，RAR 分卷及 `.rev` 直接进入检查页面，多项可切换。恢复卷只提供检查修复，不作为普通压缩包导入。新菜单及旧格式遗漏的卸载项一并清理。
- 修复结果可沿用原失败任务或本次修改的输出目录、子目录、密码创建新待处理任务，原失败记录保留；由用户开始解压。恢复保护默认折叠，沿用现有双栏和窄窗口布局。

## 真实发现与修正

1. 测试夹具中的创建参数 `-p-` 被 RAR 当作密码，改为明确不设置创建密码；生成带加密文件名的 `.rev` 夹具则需要提供其原密码。
2. RAR 修复加密文件名归档后可生成有效结果但返回 11；最终以候选结果的原生内容校验为依据。恢复卷重建遇到密码验证失败则明确要求填写或修改密码。
3. RAR 重定向输入使用 OEM 编码。本机 CP936 的中文密码以 UTF-8 输入会被拒绝，改为 OEM 输入后，重建首卷与原始字节完全一致。
4. 分卷的恢复记录修复只生成损坏卷，直接把其当成全组会失败；现组合完好副本再校验。
5. 新菜单检查发现安装器缺少 LZ4/Brotli 等 8 个旧关联清理项，已按实际注册列表补齐，相关检查随后通过。
6. 同目录的 `same.rar` 和 `same.part1.rar` 可属于两个不同归档，现按命名方式隔离，发布前还确认多卷结果的首文件确实属于分卷。
7. 实际失败任务仍把受损加密 RAR 的预检失败显示为确定的错误密码；现使用 `ambiguous-data` 分类并给出核对/修复方向，最后桌面检查已通过该断言。
8. 首次桌面脚本指向上版遗留的 `Long解压.exe`，二进制版本检查及时拒绝，改为本次 Cargo 生成的英文程序名；另一轮在自动诊断期间填写被禁用的密码框，脚本改为等待恢复可输入。均为夹具定位/等待问题，未绕过产品行为；最终两条用户链完整通过。

## 本轮边界

新增恢复实测以 RAR5 为依据，不将未实测 RAR4 恢复升级为完整支持。需要本机 Rar.exe、至少一个仍保留的数据卷，并有足够可用恢复数据；只有 `.rev` 而没有数据卷的组暂不给出修复入口。RAR 内容校验在当前条目读取结束后响应取消，复制和外部修复可以中途取消；取消后不会发布结果。

本轮不创建 `.rev`，不新增标准 ZIP 分卷丢目录、未知数据描述符或新格式。普通 RAR 解压及已有 ZIP 救援保持既有能力。完整用户说明见 [Release 正文](RELEASE_NOTES_1.4.7.md)。

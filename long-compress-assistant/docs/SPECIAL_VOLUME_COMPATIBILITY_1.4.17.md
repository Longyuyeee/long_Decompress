# v1.4.17 特殊分卷兼容

## 当前进度

2026-10-17 从 `85d3fed`（v1.4.16 发布后主线）接续，分支 `codex/v1.4.17-special-volumes`。本版尚未封板；正式版仍为 v1.4.16。按用户要求，本轮以完成当前版本并发布为目标，只有必须确认的操作或范围选择才暂停。

## 实际代码审计

1. `split_archive_detector.rs` 对 `.haozipNN.zip` 有独立分组逻辑，通过终卷 EOCD 确认卷数；`StandardZipReader` 将磁盘相对偏移映射为可寻址 ZIP 视图，不拼接载荷副本。已有真实 ZipCrypto 论坛卷和 v1.4.11 证据继续复用。
2. 前端 `archiveSource.ts`、`compressionFormat.ts` 的论坛卷规则仅限 ZIP。7Z 原生数字卷入口使用 `.7z.NNN`，读取端通过 `NumericVolumeReader` 跨卷。不能在未见好压真实产物前，将 ZIP 的磁盘目录规则或普通数字卷规则直接套到 7Z 论坛卷。
3. 解压执行在读取及密码检测前重新检查卷组，缺卷时保留具体名称。特殊卷实现还必须贯通浏览、检查、转换、失败后补卷重试和独立输出目录；只增加后缀不算兼容完成。

## 原工具核对

本机使用已有便携版好压 `6.6.0.11316`，没有运行安装器或更改文件关联、右键菜单、缩放、个人 Long解压设置。GUI 的 SHA256 为 `3f1fcb803594528eee34ed72f29739c1fd2a3bf2b2ccbd521b15d1198654c659`。

- 经典模式 ZIP 的密码页提供两次密码、显示密码；“加密文件名”禁用并标注仅支持 7Z。密码页及算法页未见 ZIP AES 选择，因此当前不能承诺已取得好压 GUI AES ZIP 论坛原卷。
- 7Z 模式可同时选择“生成论坛专用分卷”、固实压缩、内容密码，以及可选“加密文件名”。当前先准备内容密码、不加密文件名的真实样本。
- 自有输入由现有 `prepare-haozip-forum-fixture.mjs` 准备：说明文件 124 字节、非重复二进制 163,871 字节及空目录。预期哈希与 v1.4.11 的确定输入一致，不包含个人数据。
- 本机临时输入清单位于 `test-results/haozip-forum-manual-DVoGlB/fixture-inputs.json`。它只是输入清单，不是归档生成或验收成功证据；换电脑应在真实原卷固定后使用仓库样本。

点击生成后，好压弹出“所选的分卷大小为 65,536 字节，确定用指定大小进行分卷压缩吗”。电脑操作技能要求接受第三方确认提示前询问用户，已请求确认。该提示尚未接受，输出目录仍空，不能记成真实样本生成成功。

## 封板前剩余工作

1. 确认上述测试容量提示及本版好压 AES ZIP 的能力边界。若原工具不能生成，不改名普通卷代替，不将没有证据的组合算作完成。
2. 固定好压 GUI 生成的 7Z 论坛内容密码、文件名密码原卷，记录生成选项、卷名/字节/哈希及独立工具完整回解的载荷哈希。
3. 依据真实字节和命名补齐分组、跨卷读取和错误分类；验证从每一成员导入、乱序去重、错误密码后纠正、缺首/中/末卷及补回继续。
4. 按真实入口完成浏览/解压/检查/转换，核对内容和空目录，查看常用及窄窗口页面，保持原始卷与原失败记录不变。
5. 相关回归及普通生产构建通过后审计封板、统一版本、README 和中文 Release，经受保护主线 PR 与必需 Windows package 后发布安装包及更新资产。未受影响的旧格式、媒体和安装流程证据按范围复用，不重跑无关矩阵。

# v1.5.9 加密 RAR 最终原因与补卷接续

从 `53035eb` 接续[十版路线](ARCHIVE_ROADMAP_1.5.6_TO_1.5.15.md)。本版保留原生引擎真实请求的下一卷、密码已被前面内容证明的状态以及后续校验失败上下文，贯通浏览、密码候选、检查、诊断、提取、转换和最终历史。不新增 RAR 创建或卷修复能力，不按文件名推定加密头隐藏的尾卷数量。

## 固定原包与复现

[原包清单](../tests/fixtures/archives/rar-159/manifest.json)包含十二组真实 WinRAR 6.24/RAR 7.23 输出：RAR4 旧/新卷名、普通卷/SFX，RAR5 普通卷/SFX；每类都有原组和同名、同密码、不同内容的另一原组。7-Zip 26.04 独立回解核对完整内容，第一条非空加密文件先通过 CRC，再进入跨卷载荷。原大文件首条 SFX 继续回归，不能仅靠小条目掩盖密码预检中缺卷。

v1.5.8 的四种文件名密码 SFX 缺尾在正确密码下显示 `文件损坏: RAR password verification failed: EOpen@Process (Could not open next volume)`，不带具体名称。代码中 `UCM_CHANGEVOLUMEW` 已得到名称，但同步操作返回 `UnrarError` 时丢弃；诊断又按错误文本是否包含“密码”判断错密。先以未改实现运行缺尾回归，再修正原生上下文和明确分类。输入 EXE 只作为数据读取。

修改前的缺尾测试已真实运行并失败：六类原组分别通过浏览、检查和预检重现名称/分类缺失，见[原始红灯日志](evidence/rar-final-causes-1.5.9/red-tests.txt)。最初测试编译阶段补齐了测试模块导入；不把编译错误计作产品复现。原包成员、已知产出及错误断言保持。

## 封板条件

原卷、中卷导入和完整内容正例；原卷缺首/中/尾、换入另一原组、真实截断及错误/正确密码；前面密码已证明时不重新引导无限试密；原生取消和事务清理不退化。真实页面保留最终名称与原因，补回原卷创建新任务并保留旧失败，浏览、所选提取、检查和转换核对最终产物。常用/窄窗页面必须实看，不注入成功、不放宽断言。

## 实施审计

范围和真实红灯原包先提交 `14c5b8f`。本地 UnRAR Rust 包装保留 Unicode 卷名，区分请求未打开的 ASK 和已经找到的 NOTIFY；只有失败返回时确认不存在的 ASK 才标为缺卷。检查文件状态在原生同步操作返回后进行，不放入 C 回调，按失败时快照保存，事后补回不会改写旧错误。打开和读头回调在栈数据失效前清除；未修改 C++ 解码器。新增的公开错误上下文字段是本地 API 修改，已写入包装说明和随包 SOURCE。

RAR 浏览、预检、密码候选、完整性、提取及只读诊断复用明确分类。打开时的加密头标志本身不证明密码；成功读出加密头或完整校验非空加密条目后，才保留“前段密码已通过”的上下文。后续 CRC/密钥失败用 `rar-later-data`，不等于整个归档密码正确，也不排除后续条目另设密码。未知或不可读卷不猜损坏，取消优先，明确类别不盲目回退 CLI。诊断不再按文本含“密码”判错密，混卷不提供含糊修复；历史后端允许持久化新类别，前端给出核对原组的指导。

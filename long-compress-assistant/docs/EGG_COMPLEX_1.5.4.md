# v1.5.4 复杂 EGG 读取

从已发布 v1.5.3 的发布后主线 `4304d43` 接续。按批准路线补 AZO、固实、AES-128/256、LEA-128/256 的只读闭环，不新增 EGG 创建、全局/文件名加密或损坏修复。每种方法、密码及原生卷组合按真实原包分别确认，未验证组合不外推。

## 代码与范围审计

当前隔离 helper 已接统一浏览、密码、所选/整包提取、检查、转换和重试；复杂方法仍明确拒绝。保留的上游 `extract.rs` 未编译，不能通过直接启用来宣称完成：固实路径聚合全部压缩输入，AES/LEA 构造器固定 UTF-8 密码，短验证器不是完整密码证据。

新增 AZO 候选为 [libazo 0.1.1](https://github.com/alkegi/libazo)，已取得发布源码与 MIT 许可。其入口会读入整段压缩数据，结束标记后未检查剩余输入；接入前改为逐 AZO 块有界读取，核对结束、长度、CRC 与读写错误。算法参考[上游格式说明](https://github.com/alkegi/docs/blob/master/egg.md)及[原厂组合说明](https://en.bandisoft.com/bandizip/help/how-to-open-alz-and-egg-files/)。

## 实施顺序

1. 固定来源和真实原包/独立载荷，修正解码边界、密码字节及固实输入/输出划分；保持原生卷双向链接和事务发布。
2. 接复杂读取和所选范围：固实选中文件仍需解码其共享流，依赖块需要的密码和失败原因必须显示，不能因条目自身无数据块而漏判。
3. 真实桌面验证错密码纠正、中文编码、所选提取、缺卷补回、检查/转换和实际暂停取消；有变化的常用/窄窗页面必须查看。
4. 完成定向审计后封板、统一版本、受保护合入、正式发布及四资产回下载核对，再回填两份 README、收据和交接。未完成验证前不写成已发布。

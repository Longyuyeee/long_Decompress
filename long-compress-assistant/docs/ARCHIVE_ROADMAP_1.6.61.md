# v1.6.61 规划 · LZOP 成员路径与名称兼容

已完成功能封板，见[记录](LZOP_PATHS_NAMES_FREEZE_1.6.61.md)。下一阶段 [v1.6.62 单文件创建](ARCHIVE_ROADMAP_1.6.62.md)仅规划。在多成员文件读取后，继续处理收到资料时容易遇到的目录还原和旧名称编码问题；保持格式/算法与实际兼容主线。

1. 用官方 `-P` 多文件原件确认带路径成员的实际行为，分别记录名称/路径标志、官方逐文件回解及内容 SHA256。与目前 `-N` 式仅还原文件名的行为区分，不把简单拼接或头部改写当成官方原件。
2. 接通原双栏的成员目录、筛选、图文预览、文件夹按需取回、完整提取及 ZIP/7Z 转换；复用已有保留路径配置，扁平取回保持稳定重名处理和来源历史。
3. 明确处理 UTF-8/Latin-1 与旧 Windows/DOS 名称。未标明具体代码页时不猜测为某一中文编码；需要用户选择时放进原压缩包选项二级区域，预览/取回/转换采用同一份选择。无法确认的名称继续提供稳定成员名取回。
4. 覆盖重名/大小写、路径相交、空目录可确认程度、非首数字卷、坏尾/取消和来源变化；只检查新增及受影响流程。原生块分段标记、LZOP 创建/密码和缺卷内容救援继续分别评估，不并入此承诺。

保持单条展开、多选弹窗、自然继承、左右等宽、主题和快捷键，减少说明占用主要区域。ALZ/EGG 有效外部原件缺口继续保留；取得真实原件后按用户影响推进，不以合成样本替代兼容证据。

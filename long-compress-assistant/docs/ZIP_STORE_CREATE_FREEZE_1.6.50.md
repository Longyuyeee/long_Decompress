# v1.6.50 · ZIP 明确仅存储与低收益建议

## 已完成

按[本版路线](ARCHIVE_ROADMAP_1.6.50.md)，在原 ZIP 方法字段加入「仅存储（Store）」，用于快速打包已经压缩的数据。默认继续 Deflate，旧 Deflate + 强度 0 仍为 Store；Bzip2、PPMd、LZMA、Zstandard 的旧强度 0 继续按各自原映射执行，ZIPX 继续 XZ。没有增加格式数、外部引擎或依赖。

单条/全局/转换/配置组原位置提供选择；明确选 Store 后收起不适用的强度，切回恢复原值。多选明确指定 ZIP Store 时收起强度且不提交该字段；保持混合格式时仍可分别配置。预设、配置组/便携模板、待处理草稿、历史与工作流保留方法。原单条行内展开、编辑后自动独立、多选弹窗、左右等宽、主题/工具/快捷键保持，不增加页面或常驻说明区。

输出真正的 ZIP Stored（方法 0），密码继续支持 AES256 / ZipCrypto，数字卷和标准 .z01/…/.zip 分卷沿原路径；源包读取和目标算法独立。进度、日志、结果/提取入口、取消与冲突保留。原分析改用真实 ZIP writer 抽样，包括 Deflate、Store、Zstandard、Bzip2、PPMd、LZMA；仅存储的预计数据比例至少 1，耗时不受保留强度影响，扩展名不会虚构 Store 的压缩收益。

所选 ZIP 压缩方法对至少 4 KiB 内容样本的收益不足 2% 时，在原结果内给出可选的仅存储建议。只凭 jpg 等扩展名不触发；小样本不触发。明确采用才只修改当前任务的方法，保留强度、密码、加密方式、卷型和分卷，不改全局或自动执行。旧 Deflate 0 和已选 Store 不重复给建议，方法变化使原结果失效。必要说明收进问号。

## 转换选择修复

审计发现原 normalizeConversionSettings 在更新后又无条件写回旧 zipMethod，且 sevenZipMethod 的适用格式条件误写为 ZIP。现只在目标对应格式保留本次新方法，其他格式继续保存原值，修复单条、默认配置及多选中选方法后被还原的问题，涵盖 ZIP Store 与既有 ZIP/7Z 方法。通过真实转换 UI 选择和执行核对历史，避免仅从后端直接调用得到通过。

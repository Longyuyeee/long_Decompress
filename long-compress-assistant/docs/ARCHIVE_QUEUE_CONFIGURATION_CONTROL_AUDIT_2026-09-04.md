# 归档队列、配置来源与停止语义审计（2026-09-04）

## 本轮目标与真实根因

本轮按用户提出的四项问题审查真实前后端代码，没有把界面现象直接当作原因：

1. **显示顺序与执行顺序不一致**：`AeroTable` 已按中文数字自然顺序显示，但 `DecompressView` 仍按任务创建顺序启动，因此界面第一项不一定先运行。
2. **并发设置看似失效**：`maxConcurrentTasks` 确实传入 `runArchiveTasks`；不同输出资源会按上限并行，但同一输出目录会被安全资源键串行化，默认“同目录”时容易被误认为设置无效。
3. **全局与单独配置来源不清**：压缩中心内部用 `settings === undefined` 表示跟随全局，但界面没有明确切换；解压任务只保存配置快照，没有记录来源。
4. **停止与暂停混淆**：列表发出了单项停止事件，但解压父视图没有接线；全局停止又逐项等待后端清理，后续任务不能及时收到停止信号。后端只有取消令牌，没有统一的可恢复暂停协议。

## 已完成修改

- 新增共享自然排序工具，解压列表显示和启动队列使用同一比较器；名称相同再以任务 ID 稳定排序。
- 排队任务可在前端直接结束，不再错误调用尚不存在的后端进程；已被停止的排队任务取得并发槽后会被跳过。
- 解压单项停止事件已经接到任务仓库；解压与压缩的全局停止均并行发出停止请求，解压全局停止同时结束等待任务。
- 等待状态由暂停符号改为时钟；操作文案明确为“停止全部”和“停止此任务”。
- 解压任务新增显式 `global / individual` 配置来源；压缩组和单文件任务新增同样的显式切换。切回全局会清除单项覆盖，切到单独会复制当前全局值作为可编辑快照。
- 设置中心新增默认压缩格式、默认压缩等级、解压默认同名文件夹；这些字段进入现有本地与后端设置持久化。新压缩草稿从持久化默认值开始。
- 智能解压目录判断继续保留：它根据每个压缩包的真实根条目数决定同名文件夹；显式操作全局同名文件夹开关时仍会覆盖所有跟随全局的待处理任务。

## 并发边界

并发上限不是“无条件同时写入同一个文件夹”。当前事务先写独立 staging，再提交到最终目录；同一最终目录仍可能发生同名冲突、覆盖/改名策略竞争，因此现阶段继续串行提交是正确的安全边界。不同输出目录的任务会按设置并行。

若后续要求同一目录也并行，必须先在后端实现目录级提交仲裁或按最终子目录计算更细资源键，并用同名冲突真实样本验证；不能仅删除前端资源锁。

## 尚未完成与下一接续点

### P0：真正的运行中暂停 / 恢复

当前不能只增加 `paused` 状态：ZIP/7Z/RAR 原生路径、7-Zip/WinRAR 外部进程以及事务提交都只共享取消令牌，没有统一暂停条件和恢复边界。下一步需先设计后端任务控制器：

1. 区分 `cancelled`、`pause_requested`、`paused`、`resume_requested`；
2. 原生循环在安全块边界等待，外部进程必须采用可证明安全的 Windows 进程暂停方案；
3. 暂停期间保留 staging、资源锁和进度快照，不写历史终态；
4. 恢复后继续同一任务，停止后清理 staging 并释放槽位，队列接续下一项；
5. 为 ZIP、7Z、RAR/CLI、密码尝试、提交阶段分别建立真实暂停/恢复/停止矩阵。

在上述协议完成前，界面只提供真实可用的停止，不冒充暂停。

## 版本结论

本轮队列顺序、并发解释、配置来源和真实停止链路已经收口，桌面 archive-flow 门禁通过；但用户要求的运行中暂停 / 恢复尚未实现。因此本轮提交和推送代码与交接文档，不提升版本、不修改 README 稳定版本、不创建 tag 或 Release。当前仍以公开 `v1.2.7` 为稳定基线。

# v1.5.5 外置卷 SFX 与旧自解压

从 v1.5.4 发布后主线 `479dcab` 接续，完成十二版路线最后一版。目标是原工具真实生成的 EXE 首卷加外置数据卷，以及旧 RAR4 SFX 的只读归组、密码、浏览、所选/整包提取、检查、转换和缺卷补回。输入 EXE 始终作为数据读取，不执行；不创建 SFX，不承诺任意自解压程序。

## 开工审计

`sfx_archive.rs` 检查 MZ 内真实归档头；RAR 头部与 CRC、7Z 相对偏移及普通单 EXE 在 v1.4.11 已接通。当前 RAR 卷组正则仅接受 `.rar/.rNN`，EXE 首卷不在组内；7Z SFX 相对读取仅打开单个文件。不能通过更改后缀或直接取消拒绝逻辑补齐。RAR 诊断的 SFX 分支目前只记录一个文件，需同步检查真实外置卷，保持缺卷原因先于密码。参考 [RARLAB 原厂格式说明](https://www.rarlab.com/technote.htm)。

## 实施与封板顺序

1. 原版 RAR 6.24/7.23 与 7-Zip 生成真实普通/内容密码/文件名密码 SFX，固定原名、原始字节及独立载荷，确认实际外置卷命名。旧 RAR4 单 EXE 与已发布能力分别记账。
2. 统一任意成员归组、相对读取、缺首/中/末卷及头部损坏原因；错误密码、混卷和损坏不一概归为密码错误。未知组合保持明确边界。
3. 按真实用户顺序验证浏览、所选提取、密码纠正、缺卷补回新任务、历史和转换；实际暂停/取消与输出清理必须有效。UI 如有修改，查看常用/窄窗页面。
4. 定向审计、提交推送，满足条件后固定封板提交，受保护合入、统一版本、发布四资产及中文说明，回下载核对并回填 README/交接。全部十二版交付后再按格式、密码/分卷互通和流程容错规划后续版本。

## 实施审计

十五组原包经独立 7-Zip 固定文件名、字节数和 SHA256：RAR4 单 EXE、RAR4 旧式 `.exe/.r00…`、RAR4/5 新式 `.part1.exe/.part2.rar…`，各含普通、内容密码、文件名密码；7-Zip 24.09 的独立 GUI 模块与 `.7z.001…` 三类组合。RAR4 是原 RAR 6.24 生成的旧格式，不冒称全部古早模块兼容。7Z 独立模块只接受实测原始模块哈希，数据卷不包含 EXE，可独立打开；任意 EXE 不凭同名伴随文件识别为启动模块。来源、许可与固定原字节见 `tests/fixtures/archives/sfx-155`。

共享卷组现在包含真实 RAR EXE 首卷，任意成员回到同一来源，浏览/密码/解压/诊断/检查共用；可见卷头核对 CRC、原生卷标记及 RAR5 卷内序号。明确的缺中卷、可见缺尾卷和卷头损坏先于密码。加密卷头隐藏最终卷数时不猜，解锁后的完整原生读取继续验证；缺首卷提示同名原始 EXE 的可能性，不让用户改名其他分卷。自解压诊断不开放修复。

两项真实使用问题由原包回归复现后修正：加密空文件不能证明 RAR 密码，候选需验证非空加密内容；RAR4 文件名加密 SFX 的 CLI 文本可能同时含 Headers Error 和 Wrong password，密码需求改由原生 RAR 元数据判断，不在预检阶段拒绝正确密码。完整性检查也走原生 RAR/7Z，避免把 EXE 的 PE 资源当作归档内容校验成功。

256 MiB 真实 RAR5 SFX 控制包用于块内暂停/恢复/取消。UnRAR 会预分配文件长度，测试观察与独立原载荷一致的已写内容，不能以逻辑长度冒充处理进度；原载荷须在启动提取前读取，避免测试准备 I/O 抢占真实暂停窗口。首轮取消后共享锁残留，短暂重试未解决，撤回该假设修改。固定 `unrar_sys 0.5.8` 原发布源码和 MSVC `/EHsc` 后，同一原生控制场景通过：内容先实际写入 62390272 字节，暂停不增长，恢复增长，暂停中取消，源卷保留且无发布/暂存结果。新增原生取消后立即删除输出的单元回归通过。源码 commit、许可及修改说明随仓库保留，解码算法不变；这只是控制场景重验，尚不替代最终完整桌面门禁。

真实桌面双击 `.r02` 又复现了入口遗漏：文件管理器只判断归档后缀，未包括共享分卷候选，因而没有打开归档页面。R02/001 两项回归先失败后修正，同时接右键“解压到另一栏”；仍由后端核实组内文件，不把候选当作完整归档。缺首卷的 EXE 备选提示在实际页面验证中继续核对。

末轮截图实看发现，成功纠正密码后旧浏览错误提示短暂残留；现在只清除该浏览请求自己的错误，不清除别的任务错误。SFX 诊断正常时还曾显示实际不支持的创建恢复卷按钮，原生报告新增明确 `sfx_readonly` 状态，普通 RAR 功能不变，中卷入口也不靠扩展名猜能力。三项界面回归先失败再修正；同步保留 ZIP 编码结论的明确文字，不降低旧断言。

首次完整桌面链通过后审看截图，发现错密码场景的输出目录未创建，实际被目录检查拦截；该结果撤回，不算密码流程证据。重验先准备真实可用输出目录，要求错误任务的最终原因包含密码且不含目录/系统找不到文件，再纠正密码并逐文件核对，保留旧错误记录。浏览的表头仅切换当前目录文件，不清除子目录选择；测试按实际勾选状态操作并核对最终仅有说明文件，不修改产品选择逻辑。

最终定向 Rust 94 项不同测试通过（另 7 项需要专用外部条件的旧测试为 ignored，不计成功），十文件 214 项前端及类型检查通过。UTC `2026-10-18T06:05:41.835Z` 完整桌面链通过 24 场景与 18 张常用/窄窗截图，十五组原包完整内容及独立转换回解核对。错误密码任务确认是 RAR 内容预检失败，不是目录不存在，正确密码创建新任务后成功，旧失败不变。最后控制场景先实际写入 20971520 字节，再暂停/恢复/暂停中取消，无发布或暂存残留。见[桌面收据](evidence/sfx-volumes-1.5.5/results.json)。

版本统一至 v1.5.5；最终普通生产构建、候选和正式发布按[封板记录](SFX_VOLUMES_FREEZE_1.5.5.md)分别记账，E2E 程序不作为安装包。个人安装、设置和历史未改；商业原工具只生成测试原包，不随应用分发。旧生成 Shell DLL 由同版新资源替换，旧文件可从 Git 恢复。

## 换机复跑与接续

v1.5.5 已于 UTC `2026-10-18T06:47:55Z` [正式发布](https://github.com/Longyuyeee/long_Decompress/releases/tag/v1.5.5)。PR #191 受保护合入，标签 `739e5e5` 与最终候选 `b0918a0` 同树；候选 `39103656875`、主线 `39104385580`、正式构建 `39104426802` 均成功，四资产/中文说明和包内主程序/引擎核对完成。准确体积、哈希及检查边界见[封板记录](SFX_VOLUMES_FREEZE_1.5.5.md)、[候选](evidence/sfx-volumes-1.5.5/candidate.json)与[正式收据](evidence/sfx-volumes-1.5.5/release.json)。原十二版已全部交付，下一轮按后续十版路线先修 RAR 实际字节进度。

首候选 Windows package 成功，但包检查脚本按 UTF-8 读取了 7-Zip 默认控制台编码的中文主程序名，未找到成员，检查失败。明确 `-sccUTF-8` 后按真实中文名称核对，不改产品文件名、不忽略主程序检查；候选重新构建和收据以最终记录为准，功能冻结不变。

十五组固定原包、清单、独立载荷和许可均在 `tests/fixtures/archives/sfx-155`，包含原 EXE 字节。测试只读取 EXE。核对原包可运行 `node scripts/create-sfx-155-fixtures.mjs`，但需要清单中的 RAR 6.24、RAR 7.23、7-Zip 24.09 原生产工具和随附独立 7-Zip；该脚本保留已有原包，不能在没有工具时用改名或新文件替代旧证据。常规内容/归组回归见 `sfx_archive::tests`，不依赖执行生产工具。

大控制包未入 Git，准确九卷、源载荷哈希和生产器身份已在桌面收据 `control` 字段保留。本机 `test-results/sfx-155-control/manifest.json` 对应 256 MiB 源载荷 `1a04258f4db4d37deb6804f922cdb9740756353babd645b4c23ec77b7d058279`。新机先按 EGG 控制包准备脚本生成自己的载荷，再运行 `node scripts/prepare-sfx-155-control.mjs`；重生成须使用新身份，不冒称本轮相同字节。原源载荷/原卷如需完全复跑，应按收据传递并逐项核对。

桌面复跑顺序：设置 `VITE_DESKTOP_E2E=1` 后运行 Tauri `build --features desktop-e2e --bundles none`，完成后将 `TAURI_APP_BINARY` 指向实际生成的 `src-tauri/target/release/Long解压.exe`，运行 `node scripts/test-tauri-desktop.mjs --sfx-155-only`。普通生产构建须单独、不带 E2E 环境变量执行；两类构建不能并发覆盖同一 `dist`。控制测试用 25 ms 检查真实内容增长，避免 Selenium 默认 500 ms 轮询错过缓存中的 Store 提取；不减慢产品或把预分配当进展。

RAR 当前界面进度仍有预分配长度估算，未宣传为已精确统计实际解码字节，接续 [v1.5.6 至 v1.5.15 十版路线](ARCHIVE_ROADMAP_1.5.6_TO_1.5.15.md)优先处理。此路线延续格式、密码/分卷与容错方向，不新增备份调度，不恢复快速打包。

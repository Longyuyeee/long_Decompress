# 原生 ZIP 引擎性能基线

## 为什么另建基线

旧 `archive_performance_regression.rs` 的解压段是测试代码自行读 ZIP、写文件，不经过产品原生 ZIP 引擎。本基准直接调用 `native_compression::zip::compress` 和 `native_extraction::zip::extract_with_optional_window`；桌面入口 `extract` 也委托同一个实现，继续传入真实窗口。

仅在基准中不发送窗口事件。解析、密码预检、目录与过滤规则、缓冲池、文件读写、时间戳和取消检查仍执行。不包含任务调度、密码保险箱候选搜索、暂存事务发布、源删除、完整性验证阶段及前端刷新；不能称作完整应用耗时，也不能与旧测试解压时间直接计算提速。

## 重跑方式

在 `long-compress-assistant` 下运行：

```powershell
node scripts/run-native-zip-baseline.mjs
```

默认每类 3 轮，输出到 `test-results/native-zip-baseline/result.json`。可传入自选结果文件路径，避免其他测试清理 test-results 后丢失原始数据：

```powershell
node scripts/run-native-zip-baseline.mjs C:/benchmarks/native-zip-before.json
```

可选环境变量：`LONG_NATIVE_ZIP_ITERATIONS`（1–20，默认 3）、`LONG_NATIVE_ZIP_MIB`（16–2048，默认 32）、`LONG_NATIVE_ZIP_FILES`（100–50000，默认 1000）、`LONG_NATIVE_ZIP_ROOT`（已存在目录，默认应用仓库目录）。实际字节数和文件数以报告为准。样本只创建在选定根目录下的独立临时目录，运行结束由临时目录对象回收，不扫描或修改个人文件。

## 样本与参数

- 大文件：32 MiB 确定性伪随机数据。
- 小文件：1000 个 4 KiB 中文文件名文件，内容由固定种子生成。
- 混合媒体：生成真实编码的 PNG、JPEG，复制仓库自带 H.265 MP4，加 32 个可压缩文本文件。不是给随机数据改媒体扩展名；它是小规模合成混合样本，不等同于真实大照片库。
- 固定普通 ZIP / Deflate level 6，无密码、不分卷、扁平路径。Rust 默认 level 为 0，引擎会截到 1；正式基准显式写 6，不把默认值误认为用户常用等级。
- 各次使用新目录，固定 large→small→mixed_media 顺序，不清空系统缓存。生成样本和校验不计入引擎计时；解压读的是刚写完的归档，因此不能推断冷盘吞吐。

## 结果和可信范围

- 每次结束后检查输出文件总数、逐文件长度、逐文件 SHA-256；样本摘要包含文件名、长度和内容 SHA-256，跨轮不同则拒绝生成成功报告。
- 报告保存每轮毫秒值、中位数/最小值/最大值、样本清单摘要、包体积、机器/工具链、提交和开始/结束时工作区是否有改动。
- CPU 占用、峰值内存、I/O 计数和 UI 延迟未采集，字段明确为 null，不填入推测数据。
- 本轮为开发中观测，不是 A/B 对照或发布阈值。后续比较须固定提交、样本摘要、参数、硬件和环境，并记录波动；混合样本随编码器版本变化时应建立新基线。
- 相同实现的正常回归包括过滤、中文嵌套路径、时间戳、预先取消及无效归档；旧 ZIP 密码预检和格式兼容测试继续保留。

九组样本全部通过数量、长度和 SHA-256 校验。新增 2 项真实引擎回归通过；既有 ZIP 模块 5 项时间戳、格式兼容、混合加密密码预检回归通过。脚本语法检查和差异检查通过。没有测量前端或安装包，不声称所有应用流程通过。

初次基准以异步测试直接调用同步引擎，触发嵌套 runtime 错误；已改为同步测试入口，与产品阻塞工作线程的执行条件相符。没有删除缓冲池等待、取消检查或其他产品行为来让测试通过。

源修改时间仍需独立补齐：冲突后端当前不提供归档原始时间，而默认不保留时间戳时，暂存文件时间是本次写入时间。此处保持“未知”，不把它冒充归档时间。本轮只建立测量工具，不修改冲突元数据语义。

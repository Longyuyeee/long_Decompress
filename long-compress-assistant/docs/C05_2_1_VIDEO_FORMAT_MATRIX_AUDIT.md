# C-05.2.1 视频格式、分辨率与三预设真实矩阵审计

日期：2026-08-29
分支：`codex/video-c02-probe-model`

## 结论

**C-05.2.1 已完成，C-05 尚未关闭。** 可重复矩阵已用 5 种真实输入容器、4 个分辨率层级和全部 3 档预设，完成 7 次唯一产品压缩管线执行。每份输出均由产品内置 ffprobe 独立复核容器、编码、尺寸、时长、流、可解码帧和实际字节；结果差异为 0。

本子步是覆盖集，不是 5×4×3 的 60 项笛卡尔积：5 个输入样本共同覆盖 MP4/H.264、MOV/MPEG-4、AVI/MPEG-4、WMV/WMV2 和 WebM/VP9，分辨率覆盖 480p、720p、1080p、4K；4K WebM 再分别执行清晰、均衡、小体积，从而锁定三档输出策略。10 分钟与大文件明确保留给 C-05.2.2，不能据此宣称整个 C-05.2 已完成。

## 需求纠偏与许可证边界

- 小体积预设的上限是 854×480，但 3840×2160 输入按原始“保持宽高比、偶数尺寸”要求计算后应为 852×480。首次矩阵用 854×480 作为预期而失败；已纠正验收清单，没有修改产品去制造拉伸输出。
- 产品随附的 LGPL FFmpeg 9.0.1 只包含产品所需解码器、`h264_mf`、AAC 和 MP4 muxer，无法自行生成 MOV/AVI/WMV/WebM 全部测试输入。矩阵因此使用固定 URL 与 SHA-256 的 Gyan GPL full build 9.0.1，仅在忽略目录 `test-results/c05-fixture-tool` 生成合成输入。
- GPL 工具不得进入 `src-tauri/resources`、安装包或生产调用路径。架构门禁固定 `productIntegrationAllowed: false`、工具哈希、测试目录和产品 ffprobe/私有产品管线边界。

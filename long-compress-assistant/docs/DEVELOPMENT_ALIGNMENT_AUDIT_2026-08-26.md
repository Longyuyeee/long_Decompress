## 3. 已发现的偏移与风险

### P1：密码保险箱保护语义与实际存储不一致（S-00.1 已解决）

`README.md` 仍声明移除主密码后“继续使用安装实例密钥保护本机数据”，但 `EncryptedPasswordService` 的新增、更新和文件保存路径会把 `PasswordEntryDb` 直接序列化到 `passwords/*.json`；Windows 权限收紧函数当前也是空实现。

用户取消手工锁定和主密码输入的决定应继续保留，但“无感使用”不能被描述成“已经加密保护”。S-00 必须二选一并完成迁移验证：

1. 优先方案：使用 Windows 当前用户级保护（例如 DPAPI）保护密码正文，启动时无须用户输入主密码；
2. 降级方案：明确更名为本地解压密码本，删除安装实例密钥保护的公开声明和未生效的加密外观。

S-00.1 已采用优先方案落地：Windows 当前用户 DPAPI 保护随机安装密钥，密码正文使用 AES-256-GCM，WebView 不再接触安装密钥；旧数据迁移、篡改拒绝、真实应用重启和加密 7Z 密码命中均已通过。证据见 [PASSWORD_VAULT_PROTECTION_S00_1_AUDIT.md](PASSWORD_VAULT_PROTECTION_S00_1_AUDIT.md)。

### P1：B-00 只有方向，没有可执行门禁

路线图已经提出 `workloadKind`、版本化指标、第三方引擎许可与发布事务复用，但此前没有独立的 B-00 工作项和验收目标。若直接实现图片压缩页面，会把模型迁移、任务取消、历史兼容、依赖来源和安装包体积留到最后处理。

本次已在主路线图补充 B-00。B-00 只允许模型、迁移、依赖清单、事务边界和测试夹具设计，不允许接入图片、视频或 PDF 编码引擎。

### P2：传统密码管理器模型残留

前端 `src/stores/password.ts` 仍包含 `username`、`url`、传统网站密码强度、过期与通用健康分析字段。当前用户界面已经切换到归档密码调用、归档线索和使用趋势语义，因此这些字段属于兼容债务，不应继续成为新统计或新 API 的基础。

S-00 应定义归档密码的最小领域模型；旧字段只用于读取和迁移，不在新界面、新统计或媒体功能中扩散。

### P2：文档与仓库卫生

- `DEVELOPMENT_HANDOFF.md` 是按时间追加的历史记录，旧段落中的“当前版本”只代表当时状态；接手必须以文件顶部和本审计为准。
- HFSX 的历史记录同时出现“非空验证通过”和“只能生成空镜像”的旧结论。公开兼容性应以后续真实固定样本和发布审计为准，后续整理时增加明确的支持等级表。
- `src/stores/task.ts` 保留未实现的 `fetchTasks` 占位接口；历史任务已经由独立 store 实现，应删除或明确废弃。
- `src-tauri/TranslateSoftware` 是未进入 Tauri `bundle.resources` 的旧工程，应在确认无构建引用后移入归档或删除，避免被误认为产品组成。

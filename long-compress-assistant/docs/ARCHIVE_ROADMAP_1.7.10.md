# v1.7.10 · GNU/PAX 混合名称记录的完整条目取回

状态：开发完成，按本次定向结果封板。接续全局 PAX 的完整流程一致性，继续格式兼容与实际失败包容错主线。支持 GNU `L`→PAX `x` 和 `x`→`L` 两种顺序；接受局部 PAX 未指定路径或路径与 GNU 名称完全一致的普通文件/目录。冲突和混合记录中的空路径删除明确停止，不猜名称优先级。正式产物以对应提交 CI/Release 为准。

1. 五份独立工具组合样本完成 GNU tar/Python 清单与逐文件内容核对：两种顺序、交替布局、非零文件头大小覆盖和 GNU 名称声明内零填充。样本由自编 GNU 原件和 Python 元数据组合，不冒称第三方混合原包。
2. 正常读取和恢复共用冲突名称判断。GNU 与局部 PAX 各只保留一条，不放宽重复、孤立、截断或未知布局。控制记录按自身物理大小完整读取，名称元数据不进入清单，用完清空。
3. GNU 名称声明内多余零填充在正常读取侧规范为单个结束标记，恢复仍按原物理位置复制。普通文件/目录、目录联选、独立结果、部分历史及来源替换后重查接通原入口。
4. 新原生 6 项、相关旧回归 3 项、23 份真实输出路径/目录/SHA 和后台界面 2 组通过。GNU 名称规范化后只接续受影响的完整读取项，新增零填充样本也完成正常流程；其余成功项复用。宽窄截图逐张查看，没有接管桌面或重跑全格式矩阵。

本期仍不承诺链接、稀疏文件部分取回、缺口后扫描或完整保留恢复文件全部元数据。LZOP 原生密码/原生块分段以及 ALZ/EGG 有效外部原件缺口继续独立分期；收到用户真实失败包时按影响插入修复。

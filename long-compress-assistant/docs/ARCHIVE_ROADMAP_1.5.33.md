# 下一版：v1.5.33 WIM LZMS 非固实创建

2026-10-20，接续 v1.5.32。已按下列非固实内容归档范围完成，见[实施](WIM_LZMS_1.5.33.md)与[封板](WIM_LZMS_FREEZE_1.5.33.md)；下方保留原顺序。下一版仅规划[ZIP BZip2创建](ARCHIVE_ROADMAP_1.5.34.md)。

## 用户要解决的问题

Store、XPRESS和LZX已覆盖存储、快速及体积优先，接下来补充LZMS这一已有读取能力的方法，让需要进一步尝试压缩体积的用户可以完成创建、转换和后续提取。方法说明应写清更耗时、旧工具兼容性较少和实际效果取决于内容，不默认替换现有选择，不把固实/ESD和非固实WIM混为一谈。

## 依据与顺序

1. 固定wimlib1.14.5对应源码内的doc/man1/wimcapture.1明确支持`--compress=LZMS`，不自动启用固实；32KiB是其支持的非固实块大小。产品已有LZMS读取依据，但本版新建仍需先确认真实标志、资源表、独立解码完整摘要与空目录。先用小块和受限线程实测耗时/内存、暂停/取消/失败，不直接套用默认64MiB固实设置，也不承诺特定压缩率。达不到普通内容归档条件时保留研究状态，不发布空选项。
2. 仅在现有WIM方法选择加入LZMS，旧任务Store和现有XPRESS/LZX均不改。接入单条展开、多选弹窗、自然继承、配置组/模板、预设、草稿、历史和转换；无效强度保持停用，解释放在就近帮助。
3. 只核对新增LZMS影响链：文件/目录与密码原包转换、数字切卷、任意成员浏览/有界预览/检查、所选及完整提取、转新密码ZIP、缺卷补回新任务和统一结果，完成源数据不丢失。旧算法/密码矩阵和真实盘满不重跑。
4. 保持50/50、窄窗滚动和原交互，检查真实显示后更新README、中文Release与交接，按独立版本收口。

不承诺WIM密码、固实/ESD创建、原生SWM创建、系统部署或完整Windows权限元数据。ZPAQ增量/原生追加多部分/损坏事务抢救、ALZ方法3及EGG加密固实继续单独研究，有可靠正面依据再排入功能版本。

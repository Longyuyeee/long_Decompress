# v1.7.21 · TAR.LZO 整包提取与链接内容检查封板

日期：2026-10-28。

## 实现与用户行为

正常整包解压接通 v1.7.20 的完整条目计划。无局部选择时把已确认的全部普通、目录、空、稀疏及硬链接内容纳入原暂存发布；普通头、局部 PAX linkpath 与 GNU L/K 使用相同的原始目标身份。链接副本输出独立文件，不创建系统链接，不借用目标目录的旧文件。同源副本按来源顺序处理，避免逐个重新解码整包。保留各自修改时间，目录时间在子项提交后恢复。

整包中的硬链接只在完整、内容已校验且目标身份可确认时走该计划。普通整包不含硬链接时保留旧 TAR 提取入口，局部选择沿原行为；目录布局、平铺、筛选、同名等待/跳过/改名/覆盖、暂停取消、空间检查和来源前后重查复用原机制。未知/歧义/前向目标、链条、带正文硬链接及符号链接不扩展。

公共完整性检查和原生 TAR.LZO 验证使用同一份完整确认扫描，不写输出文件。发现旧回退验证只读取条目正文，可能跳过未确认链接或符号链接却报告完整成功；本期为 TAR.LZO 回退增加普通内容类型要求，无法确认的链接不再通过。诊断回退同步使用该规则，其他格式的原通用验证规则不变。普通无内容校验 LZOP/TAR.LZO 沿原兼容入口处理，不把它冒充本期确认的链接内容。

完整读取期间重查来源版本；原件变化、坏 TAR 结束块、外层校验失败、额外数据/成员及缺卷都不能作为整包结果提交。所选提取、文本/图片预览、原任务结果和历史保留。界面无新增常驻区域，继续使用单条展开、多选弹窗及等宽双栏。

## 原件与检查

复用 v1.7.17、v1.7.18 的 GNU/PAX 稀疏链接原件及 v1.7.19 的两份图文原件，未新增或宣称额外生产者支持。

- 新原生 7 项通过：四份原件整包真实发布；公共完整性、原生验证和诊断一致；七类未确认/特殊链接不能健康通过；坏尾/校验/拼接成员和数字缺卷补齐；完整范围筛选、平铺、四种同名策略及各自时间；取消/受控错误 112/来源变化；普通及无校验回退和局部选择保持。首轮 4 项通过、3 项失败；修正回退类型检查与来源变化提示后，只重跑失败的 3 项。
- 相关旧原生 3 项通过：所选 GNU/PAX/稀疏副本真实发布、原暂停继续及未选特殊条目回退、旧 TAR.LZO 图文/诊断/所选流程。一条旧测试过滤名称未命中，纠正为实际测试名后执行，不计作已通过检查。
- Python 独立读取原 TAR，核对 5 个实际目标目录（四份整包和一份数字分卷补齐）共 52 个文件：完整 SHA、精确目录树、每份文件与显式目录的时间、Windows 稀疏属性及实际分配、链接数为 1。GNU sparse 占位名按原件条目序号与 PAX 真实名称对应，不把 Python 的显示占位路径当输出路径。
- 前端 3 项通过：普通/数字来源整包命令使用空局部选择并保留完整历史，健康 TAR.LZO 不误显示部分取回入口。
- 后台真实 Vue/CSS 原生值回放 3 组通过：整包任务、结果及完整历史；真实完整诊断报告；包内与实际完整结果目录的双栏显示。1200×760 与 900×600 无横向溢出，任务详情及浏览器两栏等宽；六张最终截图逐张查看。资源预检使用实测文件系统值的 IPC 桩，其余处理结果来自原生实际收据；没有接管用户桌面。
- 类型检查与 Vite 生产构建、Shell DLL 和八处版本身份通过。正式安装器和自动更新附件由对应提交 CI/Release 接续，未重跑无关格式矩阵。

# v1.5.64 ZPAQ 原生多部分只读与快照接续（已完成封板）

2026-10-22。接续 v1.5.63；已有创建方法的 ZIP 工作区断点补齐后，回到用户确定的格式、密码、分卷与容错主线。已完成完整原生组读取闭环及定向桌面收尾，见[封板记录](ZPAQ_NATIVE_MULTIPART_FREEZE_1.5.64.md)。

## 用户目标与正向依据

现有 ZPAQ 支持数字切片和另存增量更新，仍不支持原厂按事务追加生成的原生多部分归档。用户应能确认整组来源，读取当前/旧快照并取回需要的文件，而不是把后续部分当成独立包误读。

[官方 ZPAQ 文档](https://mattmahoney.net/dc/zpaqdoc.html)说明多部分以数字顺序共同构成归档，每次更新可新增一个部分；原生密码沿整组同一密钥流读取。这提供可由官方工具真实生成、独立回解的依据，不用普通数字切片代替原生多部分证明。

## 分阶段实施与封板范围

1. 用独立官方工具生成普通/密码、至少三个真实事务和有增删变化的原件，记录各部分、各快照和所选文件身份；先核对已有跨成员读取器、盐/偏移、事务边界和快照逻辑的实际缺口。
2. 先接完整组的只读导入、浏览和快照选择。通过明确的整组确认处理成员名歧义，独立同名系列不自动混入；可从任意成员定位并确认该组。来源身份与变化判断覆盖整组，不静默读成最新快照或只读首部分。
3. 接原有文本/图片预览、完整检查、所选/整包取回及转换。密码仅在会话使用；草稿/历史保存来源组、快照和精确范围，恢复后补密码。缺成员/次序异常/来源变化清楚提示，补齐后新任务接续，原件、已有输出和旧失败保留。
4. 沿原单条展开、多选弹窗、自然继承、左右等宽、进度/结果和窄窗滚动收尾。只检查新增及受影响的普通/密码真实组合、独立回解和必要显示，不重跑旧全格式矩阵、盘满或个人安装。

本版先解决完整原生组的读取闭环，不同时塞入原地追加、原生多部分创建/更新或损坏事务抢救。之后将另存多部分更新与不完整事务救援分别规划；ALZ 方法 3、EGG 加密固实等缺口继续保留，按真实可行原件推进，不用其他格式版本替代它们的交付。

普通/密码三事务原件和全部快照独立回解、五项不同 Rust、八项不同前端、最终构建与版本身份通过。七条真实桌面流程、24 条宽窄布局和十图实看完成；密码原生组的快照格式前置识别与浏览器精确历史范围已补齐。候选、正常合入/标签和正式附件收据在本版 PR 接续。下一版 [v1.5.65 原生多部分另存增量更新](ARCHIVE_ROADMAP_1.5.65.md) 仅规划未开发。

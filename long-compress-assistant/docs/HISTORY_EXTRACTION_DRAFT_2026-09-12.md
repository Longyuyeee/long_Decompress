# 从历史创建完整解压草稿（2026-09-12）

## 实际代码与需求对齐

基线为 PR #126 后的 `master@44117e5`。历史仅保存来源、输出、结果和日志，没有密码、条目筛选及完整执行配置；因此不能把历史重建称为原样重试。

本轮提供明确的“创建完整解压草稿”，只针对归档解压历史；压缩和特殊压缩历史不展示入口。用户确认当前来源并重新选择输出目录，草稿进入既有解压队列，不自动运行。后续压缩任务重建应先保存可复用参数，不能拿归档解压逻辑套用。

## 实现

- 历史详情内可修改来源或重新选择文件，处理源文件已移动/重新下载的情况。
- 复用后端 `detect_split_archive`：完整分卷组归一到首卷，缺卷列出原因并阻止创建；再用 `get_file_info` 检查当前来源为非空文件。
- 输出目录必须由本次对话框选择，不把旧任务最终输出路径误当新任务父目录。
- 新任务使用新 ID、pending 状态、individual 配置；完整解压到同名子目录、保留源文件、清空密码和筛选条件。执行仍经过原资源预检、密码、冲突及事务流程。
- 原历史不变；草稿日志写入关联历史 ID，后续终态保存时沿既有日志机制保留来源。
- 重复点击不重复创建；关闭面板或切换记录期间返回的检查不会创建旧任务。
- 界面明确旧记录缺少内容指纹，当前文件存在/非空不代表与原任务使用的内容相同。当前冲突策略及密码保险箱设置仍影响实际执行。

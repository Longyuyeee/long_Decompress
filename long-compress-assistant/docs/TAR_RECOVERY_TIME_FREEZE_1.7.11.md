# v1.7.11 · TAR.LZO 取回文件修改时间封板记录

日期：2026-10-27。

## 已完成

检查完整普通文件时记录有效 mtime：普通头八进制与 GNU 有符号 base-256、局部/全局 PAX 的继承、覆盖及空值删除均接通。PAX 十进制转为带符号整数秒和非负纳秒；负数小数整体取负，不经过 f64。没有修改正常浏览/解压的时间实现、原名称/大小规则或依赖。

复制后核对 SHA、刷新输出、检查取消，再通过原输出句柄设置时间并回读确认；原文件和独立结果发布流程保留。时间缺失、当前不能精确表达、目标时间范围/精度不足或设置失败时在对应文件记录提示，不把内容成功变为失败。目录不应用时间。纯 LZOP 成员仍不承诺时间恢复。

结果仍使用原二级弹窗，文件与时间列表默认收起；展开显示原时间（UTC）及逐文件提示。原历史详情仅保存时间保留/未完整保留数量，前后端均校验数量和，旧记录不要求新字段。没有新增常驻配置区或页面，单条展开、多选弹窗、双栏及主题保持。

## 样本与独立依据

`tests/fixtures/archives/tar-time-1711/` 两份自编资料的 Python tarfile GNU/PAX 生产者原件，由固定 SHA 的官方 lzop 压缩、完整回解核对。GNU/Python 对清单和逐文件内容一致。普通时间、正小数与负整数由 GNU 完整时间清单核对；负数小数的精确值使用 Decimal 和 Python 读取值，语义与 [Go parsePAXTime](https://go.dev/src/archive/tar/strconv.go)一致。

首轮独立探针发现 GNU tar 1.35 对 `-1.123456700` 显示为秒 -1、纳秒 123456700，Python/Go 数值语义为秒 -2、纳秒 876543300。该分歧保留在 manifest，没有冒称所有工具时间一致。应用沿用此前正常读取的整体负数语义。全局/局部删除另复用 v1.7.9 的固定 SHA 显式 POSIX 状态边界样本；它本来就不属于 GNU/Python 一致原件，本版未重新生成或冒称第三方原包。

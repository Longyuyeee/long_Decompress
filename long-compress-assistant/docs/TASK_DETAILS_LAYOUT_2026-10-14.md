# 等宽任务详情的结构与显示整理

接续滚动与 `50% / 50%` 列宽修复。用户进一步要求结构合理、美观，避免把原来的大卡片直接挤进半列；本轮保留单条展开、多选弹窗及已有配置、结果、密码信息和滚动操作。

## 实际调整

- **左侧配置**：名称、密码始终占整行；格式与强度只在列宽足够时并排。移除核心字段外的重复卡片边框，保留控件本身的边框与留白。窄列分析按钮放到标题下方，配置组按钮和分卷、目录、附加选项仍在原页面。
- **右侧摘要**：两个中心复用 `TaskExecutionOverview.vue`，合并阶段、百分比、速度、体积等原有信息。进度条与实际百分比一致，窄列数据自然换行；当前文件最多显示两行，悬停可查看完整路径。解压的候选密码与尝试次数保留，长密码通过悬停查看完整内容。
- **日志阅读**：保留至少 `12rem` 的日志高度，统一背景、边框、文字大小和行距。日志标题在右侧滚动时保持可见；日志内部继续独立滚动。右侧到边界后允许继续滚动任务列表，避免短窗口下内容被挡在页脚下面却无法继续带入视野。
- **适应窗口**：双列仍各占一半；原有窄窗口上下布局保留，两侧详情高度统一按窗口调整。解压目录按钮在窄配置列中换到下一行，不挤压路径标签。

首次查看发现设置组件的 `.compact` 样式覆盖了父视图的单列规则，本轮在设置组件内部补上同一配置列宽条件。没有靠缩小所有文字或修改交互来塞入内容。

## 追加：小窗口与放大后的任务行（2026-10-14）

用户追问小窗口是否变形。复查上一轮真实桌面截图发现遗漏：详情区可滚动，但解压任务行仍将状态、执行阶段和百分比挤在三列，`920×620 + 125%` 时阶段文字与百分比重叠。旧检查只看详情区溢出，没有检查任务行文字相交，因此上面的 16 场景记录不能作为任务行无重叠的依据。

现已将任务行状态和百分比放在第一行，执行阶段、文件与进度条放在第二行，行高按内容展开。长文本可省略并通过悬停查看完整信息，暂停状态仍保留百分比；操作按钮、单条展开和多选弹窗不变。详情区宽度足够时保持左右各半，窄时上下排列，内容通过纵向滚动访问。

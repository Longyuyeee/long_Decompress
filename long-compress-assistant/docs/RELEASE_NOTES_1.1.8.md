# Long解压 v1.1.8

v1.1.8 是针对 Windows Defender 启发式隔离的安全热修复。我们在真实 Windows 11 环境确认，v1.1.7 的未签名主程序会在加载旧设置时重复写入用户级 `Run` 启动项，触发 `Behavior:Win32/Persistence.A!ml`，随后被机器学习规则隔离并表现为程序退出、EXE 消失。

## 修复与收敛

- 暂停未签名 Windows 构建中的开机自启动能力，设置中心不再提供该入口。
- 删除主程序中的 `set_auto_start`、`check_auto_start` 及 Windows `Run` 键读写实现。
- 旧配置中的 `autoStart` 在加载时迁移为关闭，迁移只更新应用设置，不触碰注册表。
- NSIS 安装与更新阶段一次性清理 `Long解压`、`LongDecompress` 和旧品牌遗留启动值。
- 安装迁移不删除 `%APPDATA%` 中的密码保险箱、任务历史、安装密钥或其他用户数据。
- 修复解压服务误查空 SQLite 密码表的问题；加密归档现在直接读取密码保险箱实际使用的文件库，按收藏、使用频率和最近使用顺序优先尝试，命中后同步更新使用统计。
- 密码保险箱无法读取时，实时日志会显示明确原因，不再把读取故障误报成“密码本为空”。
- 历史任务详情改用完全不透明的模态表面，遮罩不再透过抽屉内容；列表状态、完成时间与箭头重新分配固定空间，“已完成”在紧凑窗口中保持单行药丸形态。
- 修复密码已被自动解压命中、当天使用趋势仍为 0：再次进入保险箱及打开统计时会同步文件型保险箱的最新数据，每日记录与趋势统一按用户本地自然日聚合；复制密码也通过同一原子操作同步更新次数、最后使用时间和每日历史。
- 左侧栏底部新增版本角标，直接读取当前安装包的原生应用版本；紧凑侧栏下自动收敛为仅显示版本号，不使用容易与安装包失配的硬编码文本。

## 发布门禁

- 前端 35 个测试文件、204 项测试和生产构建通过；Rust 241 项通过、1 项固定机基准按设计忽略，Clippy 以 warnings 视为错误通过。
- 浏览器端 32 项通过、13 项按项目配置跳过；真实 Windows Tauri 历史任务 ZIP 回环及重启恢复门禁通过。
- NSIS 覆盖安装到真实 `E:\Long\Long解压` 目录成功，版本注册为 1.1.8；旧设置迁移为关闭，三个历史 `Run` 值为空，用户数据库体积保持不变。
- 对 Release 主程序和 NSIS 安装包执行 Microsoft Defender 自定义扫描，均无新增检测；安装态持续运行 120 秒后进程与 EXE 仍存在，保护历史新增检测为 0。
- 文件型密码保险箱与真实加密归档回归通过：保险箱密码可在启用通用字典前直接命中，并正确累计使用次数；同时用当前 Windows 用户的实际保险箱完成只读解锁与条目可见性验证。
- 历史任务真实 ZIP 回环门禁新增 760×520 紧凑窗口断言：详情背景 alpha 为 1，详情和页面横向溢出均不超过 1px，状态及完成时间均不换行。
- 新增真实保险箱使用门禁：隔离保险箱初始统计为 0，使用其中密码自动解开真实加密 7Z 后，验证当天趋势末点和 7 天合计均变为 1。
- GitHub Release 继续要求安装包、更新压缩包、更新签名和 `latest.json` 四项资产全部可用后才完成发布。

## 兼容性说明

- 历史任务、密码保险箱统计、ZIP/AES ZIP/TAR 系列真实进度、归档浏览及右键菜单能力保持不变。
- 项目仍没有商业 Windows Authenticode 代码签名证书。开机自启动将在取得可信签名并通过多引擎验证后重新评估，不以要求用户关闭 Defender 或添加目录白名单作为解决方案。

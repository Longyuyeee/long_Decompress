# v1.7.8 · TAR.LZO GNU 长名称取回封板记录

日期：2026-10-27。

## 本版完成与范围拆分

原扩展元数据计划拆为 GNU 长名称和全局 PAX 两个版本。本版完成 GNU `L` 长文件名/长目录的部分取回；[v1.7.9](ARCHIVE_ROADMAP_1.7.9.md)单独处理全局 PAX 与完整浏览、解压、转换、诊断和恢复的一致性，尚未开发。全局元数据会持续改变后续名称与大小，不能只在恢复侧跳过全局头就宣称完成。

`tar_lzo_recovery` 现在在名称记录头、内容和填充均完整且经过外层 LZOP 内容校验后，才将名称应用于下一条普通文件或目录；应用后立即清空。记录本身不进入用户清单。沿用已有名称编码选择，UTF-8 和显式 CP936 已覆盖；所有路径继续经过原路径检查和重名分配。

名称记录限制为 1 MiB，要求非空、存在 NUL 结束标记且标记后没有其他非零内容。孤立名称记录、重复记录、GNU/PAX 混合叠加、链接、稀疏、全局 PAX 和其他未知布局明确停止，不扫描缺口之后。已支持的局部 PAX 保持原流程。普通完整读取与转换入口未修改，不把损坏来源降级为整包成功。

复用原恢复弹窗、目录联选、单独结果和部分历史。列表改为文件名优先、父目录次要，完整路径保留在 title 提示中，避免长父目录遮住 readme.txt 等真正文件名。单条展开、多选弹窗、左右等宽和原双栏结构保持。

## 独立内容依据

- 原件：`tests/fixtures/archives/tar-lzo-gnu-178/complete.tar.lzo`，自编测试文件，GNU tar 1.35 `--format=gnu` 创建，固定来源的官方 lzop Linux 二进制压缩。
- 原件 SHA-256：`6f1a65a8736b11281616e0666c69f5a75d36b43762250bd0d2114bfd58ba1c99`。
- 完整 TAR SHA-256：`3d538fc3f69eb2736c9d19366016b51861d02268218cf84740ea23481795b74b`。
- lzop 二进制及发行包 SHA 沿用已记录来源，并在准备脚本中核对。无新增运行依赖，应用自己的写入器没有参与原件创建。
- 官方 lzop 完整回解、GNU tar 清单与逐文件内容、Python tarfile 三者一致。原件含 9 个逻辑条目、5 个 GNU 长名称控制记录，覆盖 UTF-8 长目录、空目录、同名叶文件的不同目录、长文件名及名称后的普通文件。
- 坏尾、坏校验和缺中卷保留前 8 条（6 个文件、2 个显式目录）；缺失外层结束标记时 9 条内容均可确认，但仍标记部分取回。独立 Python 核对三份实际恢复目录的完整相对路径、所有父目录和文件 SHA，全量一致。

GNU `L` 描述下一条文件的依据见 [GNU tar 格式说明](https://www.gnu.org/software/tar/manual/tar.html)。不将自编坏尾样本当作第三方损坏原包；坏尾与边界样本均由已核对原件或原始 TAR 字节明确派生。

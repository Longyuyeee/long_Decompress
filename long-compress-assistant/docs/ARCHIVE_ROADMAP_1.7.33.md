# v1.7.33 规划 · 流式 BZip2 ZIP 丢目录部分取回

状态：仅规划；接续 v1.7.32 UTC 读写闭环，回到算法兼容与容错取回主线，本轮不提前实现。

现有丢目录扫描只能为未加密、尺寸未知的 Deflate 流确认结束边界。下一阶段先支持同类 BZip2 ZIP：原中央目录损坏或丢失时，尽量取回仍能完整确认的文件，用户继续使用原部分恢复入口。

1. 先核对独立生产者生成的真实流式 BZip2 ZIP，确认本地尺寸、流结束和普通/ZIP64 数据描述符的实际组合。按解码器消费量、展开量及 CRC 确认边界，再匹配描述符，不扫描正文中的签名猜测下一个文件。
2. 首期限定未加密来源及完整普通包/完整数字切片的已确认前缀；普通、空文件、目录和后续完整成员按原恢复清单接续。错 CRC、截断、矛盾尺寸、未知加密边界或缺口停止，原件保持。
3. 沿既有暂存、新包验证、结果/部分历史和失败重试流程，明确区分已取回、未确认和原总数未知。保留取消与当前资源限制，不新增常驻配置或页面，界面和既有交互保持。

完成标准：声明范围内的真实来源可取回完整 BZip2 成员，内容经独立工具比对，正常包流程及旧 Deflate 抢救保持；损坏尾部和不支持边界不当作成功。仅运行本次新增及受影响检查。

密码流的未知边界、其他流式方法、缺口后扫描、恢复记录修复与 ALZ / EGG 外部原件/原生密码/块分段继续另行安排。NTFS 亚秒/更宽日期范围与重复读取成本继续保留为独立候选。

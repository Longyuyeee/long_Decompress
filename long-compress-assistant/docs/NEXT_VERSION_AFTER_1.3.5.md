# 1.3.5 之后：历史可找回与结果不丢失

失败后的基本指引已完成，不继续堆积同类文案作为版本主体。下一版优先解决“为什么较早的记录消失了”。以下尚未实现，不保证恢复已经删除的数据。

## 1. 历史保留与查询（下一主线）

代码核对：`commands/task_history.rs` 保存后执行 SQL 删除最新 500 条之外的记录，查询也上限 500；`stores/history.ts` 一次加载 500，页面在内存筛选。因此只加“加载更多”无法找回后端已删除记录。

步骤：

1. 明确保留策略与界面提示，决定保留数量/时长的配置及迁移；优先不静默删除用户尚未了解的历史。
2. 将保留整理与保存的失败语义理清，避免“已插入但整理失败”被误报为完全未保存；用事务或明确状态覆盖数据库故障。
3. 后端按筛选条件分页，使用完成时间和 ID 的稳定复合排序，处理同一时刻完成及翻页时新记录进入，避免漏行/重复。
4. 页面搜索、分类、时间范围与总数统一走后端；保留清空/删除确认和“重置筛选”行为。
5. 用超过 500 条、相同时间戳、重启、筛选与删除场景验收，旧库升级不得改写错误原因。明确已经被旧版删除的记录无法凭空恢复。

## 2. 未保存结果跨重启恢复

任务执行结束但写历史失败时，持久保存待写队列；按任务 ID 幂等重试，落库确认后再清理。测试写入失败、退出重启与再次失败。恢复的是历史记录，不是自动重新解压或压缩。

## 3. 草稿与故障入口继续完善

在已有指引基础上再考虑按已验证路径定位文件、完整性检查预填和非敏感配置快照；设计具体入口时才添加，不从错误文本中猜路径。不保存明文密码，也不让一次点击自动执行旧任务。

## 发布纪律

每步真实代码与用户顺序审计、回归、文档、推送；本版 Windows N、原生选择器和完整媒体矩阵的验证边界继续保留。单测 CI workflow 权限欠项仍需补齐，不能把本地测试写成云端强制门禁。

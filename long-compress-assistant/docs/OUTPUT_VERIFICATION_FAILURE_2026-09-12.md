# 压缩产物校验失败分类

## 需求与实现

接续原规划的错误类别、阶段和最终原因补强，基线 `master@f3e4f80`。版本仍为 1.3.2，schema 仍为 8。

- 原生与外部引擎都经过 `verify_compression_output`；新增统一边界包装，非取消错误产生 `VerificationFailed`，同时保留 anyhow 原因链和原错误正文。
- 稳定标记为 `[archive-output:Verifying:verification-failed]`。历史记录明确类别“压缩产物校验未通过”和阶段 Verifying，不依赖最后收到的进度事件。
- 引擎缺失、文件读取失败、格式错误等均可能导致校验未通过；这个类别不是“已证明文件损坏”。更细原因继续看原始详情，不猜测。
- 已取消错误原样返回，不包装为失败；前端不因校验详情中的密码字样转入解压密码重试。
- 保持既有校验 → 发布 → 源文件清理顺序；没有新增校验次数，也未变更输出冲突和清理规则。历史详情、类别筛选及诊断导出接入新类别。

## 验证

- 前端 7 文件 98/98；类型检查、生产构建、严格 Clippy 和 diff 空白检查通过。
- Rust 历史 12/12：实际错误类型生成消息，SQLite 读回类别、阶段及原始详情；终态变为完成后清空失败结构。
- 服务校验失败回归 3/3：无效 ZIP 保留原目标与源文件、缺失输出保留 I/O 原因链、取消不被包装，以及既有分卷失败清理测试（后者依赖本机 7z）。
- 原生校验 4/4：真实 ZIP 内容读取/损坏、取消、加密 ZIP/7Z 创建密码验证及 AES 篡改检测。
- 未运行用户私有样本或桌面操作矩阵，不把临时样本测试写为用户实际任务已验收。CI 和合并证据完成后补录。

## 接续

下一步处理输出提交错误，区分发布失败、已发布后清理警告、待用户决定的文件冲突；不将三者混为任务失败。全格式细分错误、配置快照和跨重启未保存历史恢复仍未完成。

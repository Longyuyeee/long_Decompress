# v1.5.0 ZPAQ 读取实施审计

基线：v1.4.20，`a6fbd862`。2026-10-18 从已批准路线接续，当前尚在开发，未封板、未发布。

## 范围

接入作者 ZPAQ 7.15，覆盖流式与日志式归档的当前文件浏览、完整/所选提取、原生密码、完整性检查与转换输入。日志式归档只显示最新有效文件，不混入历史版本或已删除文件。创建留到 v1.5.1，不承诺原生多部分、自动备份或历史恢复。

## 代码审计与实现约束

- 现有 7-Zip CLI 不支持 ZPAQ，也没有本项目允许的非命令行密码通道，不能只添加后缀或向参数写密码。
- 作者 CLI 的目录扫描会跳过坏块及未完成事务，普通 `list` 未传播扫描错误；适配器必须拒绝把损坏后保留的旧视图作为完整结果。
- 使用官方算法与原生密码协议；增加机器目录输出和标准输入凭据通道，不修改压缩、解压或加密算法。保留原许可证及来源。
- 原生加密没有独立认证标签。解密头失败不能单独证明密码错误，最终提示保留“密码不匹配或文件损坏”的不确定性；已确认结构/内容错误则停止密码循环。
- 沿用事务暂存、冲突处理、取消、失败清理和历史记录；浏览检查路径，解压完成前不发布输出。

## 验证计划

第一步结果：5 项 Rust 测试通过，包含四类原包当前视图/提取/检查和密码、内容损坏、截断、取消及传输协议；格式工具 11 项前端测试通过。实际桌面四类完整解压、诊断及转换/独立 7-Zip 回解已经执行，浏览页常用/窄窗口的当前视图与帮助已查看；所选提取脚本的虚拟目录路径漏写尾斜线导致本轮中止，按导航实际代码修正脚本后需完整重跑，不计桌面验收完成。扩展前端检查发现设置页旧断言遗漏已交付 ZIPX，本版同时核对显示真实新增 ZPAQ 原生密码只读能力，未删除对应断言。

已观察到：流式头部属性/注释不受文件内容 SHA-1 覆盖，修改这部分可能仍是合法、可读的归档；格式也没有覆盖整个文件的认证标签。不能宣称能检测任意字节变化。内容损坏测试明确定位已知存储载荷，截断和事务异常另测，不以修改未认证注释来推断解码校验失败。

官方工具生成原始流式/日志式样本，覆盖中文路径、空文件、更新/删除、正确及错误密码、损坏与截断；按用户导入、浏览、所选提取、纠正密码、完整性检查、转换顺序验证并核对已知载荷。查看真实常用与窄窗口页面。每步更新事实，不提前填通过。

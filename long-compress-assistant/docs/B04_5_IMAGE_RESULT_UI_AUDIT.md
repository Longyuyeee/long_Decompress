## 1. 开发目标与边界

B-04.5 只负责把 B-04.1 至 B-04.4 已审计的事实、阶段、批量编排、统一 task store 和历史接入图片工作区。按钮只能在存在已完成真实检查且可执行的图片时开放；完成区只能显示实际任务的输出路径、输出字节、输出格式、应用方向后的尺寸和经授权的真实结果预览。

本节点不重新实现编码、目标规划、发布事务、任务队列或历史写入口，不增加删除源文件，不升版发布；100 张混合批量、超大图、安装版全矩阵仍属于 B-05。

## 3. 真实 Windows 桌面证据

使用 `VITE_DESKTOP_E2E=1` 前端和 `custom-protocol,desktop-e2e` 隔离 Release，在真实 Windows WebView2 中点击“开始图片压缩”。测试数据目录、WebView2 profile 和输出目录均为独立临时目录，不读取正式用户数据。

- 输入为固定真实 `exif-orientation.jpg`、`photo.webp`、`transparent.png`；GIF 与 PDF 继续在任务创建前拒绝；
- 第一轮实际结果：JPEG 15,788 B → 7,909 B、WebP 3,884 B → 3,814 B；PNG 实际失败并留下 `lossy mode is not valid for PNG` 历史，证明默认配置偏差；
- 修正后同一三图片场景全部完成；透明 PNG 1,546 B → 601 B，真实输出文件存在；
- 每项 `inputBytes` 与源文件 metadata 相同，`outputBytes` 与发布文件 metadata 相同；输出格式、可见宽高均来自后端验证事实；
- 三个 `compression/image` completed 历史在 UI 批量返回前已可读取，且都含真实 metrics；
- 结果预览使用最终输出路径授权并在 WebView2 实际显示；双尺寸 1100×720、760×560 无横向溢出，详情仍保持双栏；
- 工作负载切换后归档草稿保持隔离，真实系统文件选择仍接受 JPEG 并拒绝 GIF。

首次启动桌面测试时本机缺少 EdgeDriver，测试按设计在进入应用前失败；使用项目脚本安装与 WebView2 版本一致的驱动后重跑。该环境修复没有降低任何断言。

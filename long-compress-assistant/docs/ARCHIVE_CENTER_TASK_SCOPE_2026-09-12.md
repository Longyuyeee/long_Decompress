# 压缩中心批量操作范围纠偏

## 需求与实际代码

基线 `master@91e5e18`。产品负责人已批准图片、视频、PDF 移至“特殊压缩”，压缩中心只处理归档；共享 `compression` 顶层任务模型不代表每个页面都能批量操作所有工作负载。

审查发现 `CompressionView` 的 `compressionTasks` 仍取全部 `tasksFor('compression')`。由此派生的活动计数、“取消进行中”“清除已结束”跨越页面范围；清除还直接调用 `clearFinishedTasks('compression')`，即使只过滤显示也不能解决。

## 用户场景与复现

1. “我只清除归档任务，特殊压缩里的任务不能消失。”旧代码清除后队列为空，预期的 image/video/pdf 三项全部丢失。
2. “我取消的是归档压缩，后台视频还要继续。”旧代码实际发出五个取消命令，包含 image/video/pdf；预期仅旧式归档和显式 archive 两项。
3. “我只开了特殊压缩，空的归档页面为什么有取消和清除按钮？”旧代码显示了两个批量操作按钮。

新增三项测试均先在旧产品代码上失败，再修改产品逻辑；没有改变三个验收断言。

## 修复与范围

- 页面任务集合只包含 `type=compression` 且 `workloadKind` 缺省或为 archive 的任务；兼容旧任务。
- 批量清除仅遍历本页已结束任务的 ID，逐项通过任务仓库 `removeTask`；历史正在保存或保存失败的保护不变，再使用上轮逻辑同步文件行。
- 取消、计数、按钮显隐均使用同一本页集合；全局任务面板仍保持全局语义，特殊压缩和共享任务仓库不改。
- 本次清除指内存任务队列，不是删除持久化历史、归档文件或媒体输出。
- 版本 1.3.2、schema 8 不变，不发布 Release。

## 验证与接续

- 正式 `npm run test:unit` **58 文件 375/375**，包括上轮保存中/保存失败时保留工作项的测试；生产构建（含 vue-tsc）与 diff 检查通过。
- 以上为真实 Vue 组件按钮、共享任务仓库及模拟 Tauri 命令的场景验证；不是实际编码/取消进程测试，也不是原生桌面验收。
- 本轮未再次操作原生文件选择器，未重复宣称桌面工具失败有新进展。上轮真实桌面链仍暂停，见开发交接中的文件选择器记录。
- 后续在桌面操作可用时补充：让媒体任务运行，切到归档中心执行取消/清除，返回特殊压缩确认其任务继续；再完成原定完整包/截断包/重新下载后重试链。

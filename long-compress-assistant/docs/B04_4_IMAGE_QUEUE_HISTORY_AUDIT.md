# B-04.4 图片统一队列与历史审计

审计日期：2026-08-28（Asia/Hong_Kong）

开发分支：`codex/archive-media-roadmap`

公开基线：`v1.1.14`；本节点不升版、不生成 Release、不启用图片执行按钮。

## 1. 开发目标与边界

B-04.4 将 B-04.3 图片批量子任务接入现有 task store，并由同一个 `save_task_history` 写入口持久化完成、失败、取消三种终态。完成历史只能使用后端返回的已验证输入/输出事实；失败、取消和未执行 skip 不得生成虚假媒体指标。批量返回前必须等待每个终态的历史写入结果。

本节点不开放图片执行按钮，不把预计大小写成结果，不实现结果图预览；这些属于 B-04.5。

## 2. 预期、开发前实际与修正

| 检查项 | 预期 | 开发前实际 | 本节点修正与实际结果 |
| --- | --- | --- | --- |
| 统一队列 | 每张图片是现有 compression Task | 批量执行器不创建 task store 条目 | 每张图注册 `type=compression`、`workloadKind=image`、唯一 task id，并进入 preparing/compressing/终态状态机 |
| 完成事实 | 只使用后端已验证事实 | 结果尚未映射 Task 指标 | published 使用真实 input/output；候选不更小时以实际保留的源文件作为最终 output 事实，不把未发布 candidate 冒充输出 |
| 失败/取消 | 有终态历史但不发明指标 | 没有图片终态落库 | failed 保存真实错误，cancelled 保存取消终态；两者 `metrics=null` |
| skip | 保留结构化原因但不发明处理量 | 没有映射 | 作为已处理完成项写入原因日志，未编码所以不写媒体指标 |
| 持久化确认 | 批量返回前知道历史是否写入成功 | task store 对保存请求 fire-and-forget | task store 记录每个保存 Promise；图片批量等待全部写入，任一失败会明确报错 |
| 严格字段 | 图片事实嵌套只含历史契约字段 | 第一轮把含 `encodedBytes` 的运行时对象直接展开，Rust 会因未知字段拒绝 | 显式剥离 `encodedBytes`，字节只进入顶层 `inputBytes/outputBytes`；嵌套事实继续保持格式、矩阵、可见尺寸、方向、帧数和 Alpha |
| 状态机兼容 | 防止终态互相覆盖，同时允许失败任务重新进入 pending 重试 | 第一轮禁止终态后的所有转换，破坏加密归档密码重试 | 改为只禁止“终态直接覆盖另一个终态”；failed → pending → extracting 的既有重试链恢复，17 项解压视图测试通过 |
| 跨重启读取 | SQLite 关闭后重开仍有三种终态 | 只有序列化/净化单元测试 | 用真实 PNG 编码结果写入实际 SQLite 文件，关闭 pool，重新打开并读取 completed/failed/cancelled 三条记录 |
| 测试指标真实性 | 测试记录的节省比例也必须由真实输入/输出字节按 0–1 契约计算 | 收尾审计发现 SQLite 测试第一版把节省率写死为 `99.0`；第一次修正又按百分数乘以 100，被数据库重算后的真实断言立即识别 | 改为使用真实文件字节计算 0–1 比例并在重开数据库后复核，删除虚假的固定预期值和错误单位 |

## 3. 真实测试证据

- 输入 `transparent.png` 为 1,546 B、256 × 256、带 Alpha；Rust 实际规划目标并执行无损 PNG 编码；
- 完成记录的 `inputBytes` 与真实源文件 metadata 一致，`outputBytes` 与真实发布文件 metadata 一致；输出事实重新读取为 PNG；
- 同一实际 SQLite 数据库写入 completed、failed、cancelled 后主动关闭连接，再以新连接打开；实际读取顺序为 cancelled、failed、completed，数据库文件非空；
- 前端使用真实固定 PNG/WebP 文件大小驱动任务指标，验证 published 与真实失败分别进入 completed/failed 历史；
- 取消测试只取消活动后端 task id，活动项和未启动项均持久化为 cancelled，且均无媒体指标；
- 历史 JSON 实际不含非法嵌套 `encodedBytes`。

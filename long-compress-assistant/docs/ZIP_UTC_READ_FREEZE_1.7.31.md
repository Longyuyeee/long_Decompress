# v1.7.31 · ZIP / ZIPX UTC 修改时间读取与恢复封板

日期：2026-10-29。

## 实现和用户行为

新增共享 ZIP 日期解析入口。优先使用中央目录内唯一的 Info-ZIP UT（0x5455）修改时间；中央字段长度为 5，修改位已置位、无保留位。标志的其余低位引用本地头，故常见中央 flags=3/7、仅含修改秒值的记录有效。明确支持 Unix 秒 0..2147483647，即 1970-01-01 00:00:00 至 2038-01-19 03:14:07 UTC。高位值存在生产者有符号/无符号歧义，本期不推断为前 1970 或后 2038 年份，沿原 DOS 本地日期。

缺失、重复（包括相同副本）、冲突、保留位、无修改值及长度无效均回退。只依据中央目录；仅本地头的 UTC 不额外扫描，中央/本地不一致时使用已确认中央值。没有可用 UTC 时保留原本地两秒日期与原非法日历处理。浏览通过带时区字符串表达 UTC 时刻，资料对比仍按文件夹行的当地日历格式显示，页面结构不变。

顺序与实际并行文件写入、精确所选、平铺、明确目录的提交后时间、较新文件判断和冲突提示共用解析。冲突时间读取接入完整 ZIP / ZIPX 及标准/数字卷的原逻辑读入器；密码原生回退也使用相同文件日期。转换先把日期恢复到暂存文件/目录，TAR / 7Z 等目标按自身能力保留；本版没有修改创建器，输出 ZIP 的原 DOS 两秒策略保持。

依赖层把可选 UT 的声明边界与字段值解析分开：完整边界内的坏时间不阻止正常数据或后续 AES 元数据读取；整体容器截断、必要加密/大小字段错误仍由原解析器报错。严格时间字段解析器仍拒绝无效值，对应旧容器测试改为自包含空 UT 内容可读用例；本次实跑验证由独立 Python 控制归档覆盖，不声明依赖库整套测试已执行。内容 CRC、密码校验使用的原 DOS 字段、算法与原 UI/交互未改变。

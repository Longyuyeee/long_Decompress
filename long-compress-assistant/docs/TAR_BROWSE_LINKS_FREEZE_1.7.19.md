# v1.7.19 · 完整 TAR.LZO 硬链接目录与预览封板

日期：2026-10-28。

## 实现与用户行为

完整 TAR.LZO 的目录和预览使用独立的只读目标解析器。归档原始路径与 Windows 可见路径分开保存，原始目标区分大小写；只绑定前面已经过读取的唯一内容条目。普通头、局部 PAX linkpath 和 GNU L/K 组合衔接普通、空及旧 GNU / PAX 稀疏目标，目录显示目标的逻辑大小。歧义/重复可见路径、前向/未确认目标、链接链条、目录目标、带正文硬链接及符号链接等明确限制，避免把无法读取的内容展示成空文件。

严格元数据模式仅用于本期 TAR.LZO 只读入口，旧正常提取及其他 TAR 路由维持原入口。GNU K 独立校验完整载荷、NUL 结束符、零填充、单次应用和对应硬链接；与 PAX 同时出现时必须一致。LogicalEntry 保存原路径及目标元数据身份，不借用文件系统已有内容。

普通条目预览沿一遍读取，链接则先定位、再按目标条目身份重读。两遍共用 64 MiB 累计解码扫描预算，目标重读核对序号、原路径、头部和逻辑布局身份；保留原来源版本前后检查及取消控制。文字最多保留 1 MiB，图片完整内容最多 8 MiB；预览不能替代整包完整性检查。没有生成临时内容缓存、提取文件或系统链接。

双栏继续共用导航、列头、选择和列表，来源只在短标记/悬停和原详情出现。长来源占详情中的整行并换行。链接的提取和完整打开仍显示本期只读限制，普通文件原操作保留；单条展开、多选弹窗与等宽布局保留。

## 原件与检查

新增 `tar-browse-links-1719` 为项目自编文本、标准 PNG 与真实 Linux 硬链接的 GNU/PAX 原件。GNU 完整提取核对逐文件 SHA 和 inode，Python 独立读取完整/前缀内容，官方固定 SHA lzop 往返与原 TAR 一致。同时复用 v1.7.17 / v1.7.18 原件，独立生成其稀疏链接前缀摘要；不以构造样本冒充额外生产者兼容性。格式依据见 [GNU tar 文件头说明](https://www.gnu.org/software/tar/manual/tar.html#Standard)。

- 新原生 7 项首轮通过：旧 GNU/PAX/稀疏原件目录及独立前缀；新图文、空和长名称实际预览；无效/歧义/前向/链条目标；GNU 元数据完整边界、顺序及混合 PAX；两遍累计预算和图片上限；取消/来源变化无缓存输出；正常提取未被误开启。
- 相关旧原生 3 项通过：原 TAR.LZO 图文/诊断/所选提取、混合名称的浏览/预览/提取/转换及旧 GNU 稀疏完整流程。未受影响的其他格式矩阵复用。
- 前端 6 项通过（新增 4、相关旧 2）：共用列和提示、精确别名与来源版本、菜单限制/详情，以及普通文件提取保留。
- 后台真实 Vue/CSS 原生值回放 3 组通过：等宽双栏/搜索、图文预览与原栏保留、只读菜单/详情；1200×760、900×600 均无横向溢出。实看截图发现旧详情样式省略长来源，调整为整行换行后，只补查该详情场景，确认两行完整显示且无横向溢出。六张最终截图逐张查看，未接管用户桌面。
- 类型检查与 Vite 生产构建、Shell DLL、八个版本来源一致性通过；正式安装器和自动更新资产以对应提交 CI/Release 为准。

# 解压主流程收口审计（2026-08-22）

审计基线：`master@68cef47`，版本号仍为 `1.1.12`。只有本文门禁和正式发布构建完成后，才允许提升为 `1.1.13`。

## 结论

此前用户反馈的密码误判、进度跳变、正确 RAR 密码被判错、暂存目录短暂暴露、冲突处理重复解压、历史信息缺失和本机容量长期未知均已在唯一正式链路中修复，并以真实文件或真实 Windows 桌面程序复验。当前没有发现需要阻止 `1.1.13` 候选构建的代码问题。

## 问题与纠偏

| 问题 | 根因 | 当前结果 |
| --- | --- | --- |
| 未开始解压却显示 50%/100% | 密码候选序号与解压字节进度共用展示通道 | 候选阶段固定为 0；只有引擎开始产生实际输出字节后才进入解压进度 |
| 正确 RAR 密码被判错并转入字典 | RAR 首文件 CRC 校验存在固定 10 秒超时，且部分错误分类过宽 | 移除短超时；区分密码不匹配、损坏和验证器异常；正确密码不会因耗时被误判 |
| `.long-extract-*` 文件夹闪现、点击提示不存在 | 事务暂存目录位于目标父目录且 Explorer 缓存未及时刷新 | 暂存目录创建后立即设置隐藏属性，提交/清理后主动通知 Explorer 刷新；事务语义保持不变 |
| 文件冲突后重复解压 | 前端取消暂存事务，再用新策略从头执行归档 | 后端保留待处理暂存，前端逐项提交覆盖/跳过/重命名；取消会清理暂存，目标在确认前不变 |
| 本地历史格式为空 | 终态历史未保存后端实际识别格式 | 通过魔数与执行路线事件保存真实格式；伪装扩展名和复合 TAR 后缀均有回归 |
| 长密码字典淹没关键历史 | 历史简单截取最后 200 条 | 保留开始、阶段、警告、成功/失败等里程碑，并对高频候选日志均匀采样 |
| 本机任务持续显示容量未知 | 非 WMI 环境缺少可靠 Windows 卷查询后备 | 增加 Win32 卷、容量、文件系统和介质查询；不存在的目标路径回溯到最近已存在父目录 |

既有历史数据库不会被伪造或反向改写。旧记录中的空格式、容量未知和旧日志仍代表当时版本实际保存的数据；修复作用于新任务。

## 如实保留的发布边界

- 当前机器没有 WinRAR/Rar.exe，因此 RAR 创建仍按既有产品策略提示用户选择安装 WinRAR 或改为 7Z；RAR 解压和密码解压不依赖 WinRAR，并已使用官方真实样本通过。
- Windows 11 第一层菜单身份包需要商业 Authenticode 身份。当前公开无签名构建不分发该包；非管理员终端无法执行会临时写入 `LocalMachine\\TrustedPeople` 的开发 MSIX 部署测试。经典“显示更多选项”菜单的代码与安装器断言已通过。
- Microsoft Defender 在当前开发机上未处于可用验证状态，因此不能宣称 Defender 扫描通过；应在启用 Defender 的干净 Windows 环境做发布后补验。

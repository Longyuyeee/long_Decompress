# v1.7.35 规划 · ZIP 部分取回结果保留修改时间

状态：仅规划；接续流式 BZip2 / LZMA ZIP 取回，处理恢复结果中的日期传递问题。

目前恢复新包的写入选项没有传入来源条目的修改时间。内容取回后，用户按日期整理资料时可能看到写入器默认日期；正常创建与转换已有的 UTC 读写能力尚未完整接入这一入口。

1. 先核对完整中央目录、从本地头重建目录两类来源可确认的文件/目录时间。优先传递已确认且唯一的 UT 修改整数秒，沿既有 1970–2038 范围；同时保留有效 DOS 兼容日期。检查本地 UT 转为重建目录时的布局差异，不将中央独有、缺失或冲突时间补造为原日期。
2. 恢复新包的文件和明确目录分别使用自身日期；沿已支持的密码与完整数字/标准卷、部分结果和原件保留流程。不因此扩展密码流未知边界能力，不添加新的日期设置或页面。
3. 从最终新包经本软件和独立工具读回，核对内容、路径与可确认日期。时间缺失/歧义/超界沿已公布的回退规则，不以当前时间冒充原始时间；非法/可选元数据不能使坏内容被当作完整文件。

完成标准：声明范围内的真实来源或明确标记的元数据控制经恢复后，已确认文件/目录日期可从最终产物读回，原件不变，原部分取回计数、未知总数、取消及失败重试保持。仅检查新增及受影响流程，保留单条展开、多选弹窗和等宽双栏。

UTC 更宽范围、NTFS 亚秒、其他时间/权限元数据继续独立分期。之后继续算法/格式、密码/分卷与容错主线；其他流式方法、跨缺口扫描、恢复记录修复及 ALZ / EGG 外部原件和原生密码/块分段仍是未完成项。

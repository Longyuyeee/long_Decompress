# 十版本开发路线 v1.5.6 至 v1.5.15

从 v1.5.5 完成的[原十二版路线](ARCHIVE_ROADMAP_1.4.15_TO_1.5.5.md)接续，优先补齐真实格式、方法、密码和分卷组合，再改善解压压缩过程中的进度、错误原因和失败接续。v1.5.6 已于 2026-10-18 正式发布，见[封板记录](RAR_PROGRESS_FREEZE_1.5.6.md)；十版路线已交付一版，剩 v1.5.7～v1.5.15 九版未实施。不把已有 ZIP/7Z 密码分卷、ZPAQ 创建、ALZ/EGG 基础读取和转换重新计算为新增功能。

## 实际代码与使用痛点

v1.5.5 的真实 RAR 控制测试发现，UnRAR 可以先预分配完整文件长度。现有 `rar_support.rs` 与 `compression_service.rs` 的目录体积估算不能代表已解码字节，用户可能看到进度过早接近完成。暂停与取消已真实修复，进度准确性另列下一版，不能混称已经解决。

`sevenz-rust/src/decoders.rs` 已有 LZMA/LZMA2、部分 BCJ/Delta、AES 等分支，`reader.rs` 已有 BCJ2 路径；不能把这些全部规划成新算法。其默认编译配置与实际方法分支仍需逐项核对，PPMd/Deflate 等组合须用真实原包确认当前缺口。外置 7Z SFX 当前只识别固定 24.09 GUI 模块，不能外推所有模块版本。

`tools/egg-engine/src/complex.rs` 明确限制 LZMA 单块及固实压缩输入为 256 MiB；加密固实、LEA 中文密码等组合未作兼容承诺。`tools/alz-engine/src/main.rs` 只接 Store/Deflate/变体 Bzip2，未知方法仍拒绝。`native_extraction/tar.rs` 读取目录、普通文件并跳过链接/设备项，PAX/GNU 稀疏文件要单独核实库行为与最终内容，不能只看 `.tar` 后缀。

## 顺序与取舍

v1.5.6 已交付实际 RAR 进度及真实场景发现的总量、统计和取消问题，下一版先做 v1.5.7 的真实 7Z 方法兼容。每版开工先读当时主线代码，冻结具体方法、密码、卷型及损坏组合；原计划中的能力若已经支持，就补真实缺陷和证据，不为凑版本重写。相邻目标由同一实现完成时可合并交付，并同步调整后续版本号。

涉及新解码实现的版本先完成来源、可分发条件、原工具样本和完整内容核对。确实无法取得原包或实现时，公开记录未支持的具体组合，继续处理同版有依据的缺口；不能把拒绝提示换成成功或把普通分片伪装原生分卷。需要改变用户工作方式或明显扩大产品范围时再询问，其余技术取舍直接判断并记录。

每轮推至当前版封板并发布：定向回归、真实用户入口、UI 常用/窄窗实看、步骤提交推送、必需构建、受保护合入、两份 README/中文 Release/安装包及四资产回下载。已有未受影响的验收直接复用，不能为通过降低断言。智能目录与 ZIP 并行默认关闭，不恢复快速打包，Windows N 暂不保证支持。不新增云端处理、备份调度或未经批准的 ALZ/EGG/RAR 创建。

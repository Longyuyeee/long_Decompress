**C-05.3 已完成，C-05 尚未关闭。** Release WebView2 可见工作区已经用真实 109.52 MiB 视频在编码中触发取消，确认活动产品 FFmpeg 进程退出、取消历史落库、最终输出和视频暂存均不存在；随后两条成功视频的发布事实和完整实测指标在应用完全退出并重新启动后仍保持一致。发布结果也已由 Windows 默认应用接收。

## 实际代码审计与纠偏

开发前检查实际工作区发现“打开结果”按钮调用的是资源管理器定位，只会选择输出文件，偏离最初“输出默认应用播放”的要求。没有通过修改文档来迁就现状，而是完成以下纠正：

- 视频结果按钮改为“默认应用播放”，调用独立 `open_video_output_with_default_application` Tauri 命令；
- 后端只接受绝对路径、已存在的非符号链接普通文件和大小写不敏感的 `.mp4`，再复用既有系统默认应用打开服务；
- 相对路径、不存在路径、非普通文件、符号链接和非 MP4 均在原生边界拒绝，稳定错误码由架构门禁固定；
- 资源管理器定位能力仍保留给其他明确需要“定位文件”的入口，没有改变其语义。

这使“播放”和“定位”重新成为两个清楚的产品动作，也避免前端任意路径直接进入系统打开边界。

## 真实桌面证据

单命令 `npm run test:e2e:desktop:video-workspace` 会先重建并复验 C-05.2.2 的冻结长时长/大文件样本，再执行本节点 Release Tauri/WebView2 门禁。机器结果位于被忽略的 `test-results/desktop-e2e/video-workspace-execution-result.json`，不提交大体积输入或运行产物。

取消路径：

- 输入：`avi-100mib-1080p.avi`，114,842,332 B；
- 输入 SHA-256：`240682ed61e9b09dcbb461fd1e76f4dccc3184144aa759b676820d8ce02b8d26`；
- 可见 UI 进入编码后观察到对应 FFmpeg，再点击取消；
- 统一历史状态为 `cancelled`，`processExited=true`、`stagingCleaned=true`，最终输出不存在。

成功与重启路径：

- 30.536 秒多音轨输入发布为 700,693 B MP4；
- 1.200 秒 VFR/旋转/字幕输入发布为 23,060 B MP4；
- 两份输出均再次经过产品 ffprobe 验证；
- 原生应用完全退出、重新启动后，`completedRows=2`、`cancelledRows=1`，`exactMeasuredFactsPreserved=true`；
- 可见历史页同时显示三条视频源文件名。

## 预期—实际—修正记录

1. **产品偏差**：预期结果由默认应用播放；实际代码只在 Explorer 中定位。修正为受原生路径边界保护的默认应用命令，并补前端、composable、Rust 和架构门禁。
2. **首次桌面门禁偏差**：默认应用命令已经成功，实际 UI 也发出成功 Toast，但测试只查询 `[role="alert"]`；成功 Toast 的真实无障碍角色是 `status`，导致超时。修正测试查询为 `[role="status"], [role="alert"]` 并精确断言成功文案，从头复验后通过。没有弱化产品断言或把超时误报成播放失败。
3. **测试隔离偏差**：同一桌面会话从取消路径转入完成路径时，视频草稿仍可能残留。重置桥补充清理视频草稿，使每条路径从可证明的空状态开始；生产构建仍不包含该测试桥。

# v1.5.38 ZIP LZMA 创建实施

2026-10-21，接续已发布 v1.5.37（PR #232，标签 0f9d584bec5c1f6d98ff35a2c6a6f8eda6719d22）。按既定路线实施，本版功能封板，进入正式发布。

## 实现与用户流程

在已有本地 zip 8.6.0 写入器增加 ZIP 方法14，复用已锁定且启用编码的 lzma-rust2 0.16.2，不新增产品依赖或可执行引擎。写入 ZIP 专用版本/属性头与原始 LZMA1 流，完成时写 EOS，本地和中央目录标志一致；复用现有 AES/ZipCrypto 包装，原始复制保留来源 EOS 标志。默认编码、严格 CRC/密码读取与其他方法不改。

现有 ZIP 方法位置增加 LZMA，强度 1～9，旧0按1；字典从1 MiB到64 MiB，6级8 MiB。就近显示字典，不把它当总内存或保证压缩率/速度。真实写入与抽样共用同一 ZIP 写入器，含属性与结束；每批最多64 KiB检查暂停/停止。采样不套用 Deflate 或 LZMA-alone。

普通、AES-256、ZipCrypto 及单包/数字/标准卷接入原路径。新包浏览、预览、完整检查、所选/整包提取、补卷新任务、密码原包与新方法的双向内容转换、统一结果接续。配置组/模板、预设、草稿、历史与多选保留方法，ZIPX固定XZ。单条展开、多选弹窗、自然继承、50/50与窄窗滚动保持。

## 依据和收尾

最小方法14普通ZIP由 Python/liblzma 与独立7-Zip完整回解，覆盖普通/空文件、空目录、中文与同名层级。本版七项不同Rust、六项新增前端、三条公共原生和六条实际UI已通过，22张宽/窄布局与七张实看代表图见[封板记录](ZIP_LZMA_FREEZE_1.5.38.md)及[证据](evidence/zip-lzma-1.5.38/)；已通过的旧格式矩阵与真实盘满不重跑。检查发现AES外层未声明内层LZMA的EOS和最低版本，补齐后接续失败组合，其他已通过项保留。初次检查编译补齐模板枚举等接点后才运行，批量前端新案例补独立Pinia初始化，不作为产品缺陷计数。

格式与源码依据见本地 vendor/zip/LONG_COMPATIBILITY_PATCH.md 及随包 archive-engine/SOURCE.md。README、[中文Release](RELEASE_NOTES_1.5.38.md)与支持等级在封板同步。下一版[固实 WIM / ESD](ARCHIVE_ROADMAP_1.5.39.md)仅规划，尚未开发运行时。

# v1.5.46：密码 ZIP、编辑草稿与失败继续

2026-10-21，接续 v1.5.45，完成已批准编辑工作区第三阶段。

## 用户流程

在原 ZIP 浏览器继续添加、替换、删除、改名和移动。原包密码与密码编码沿原入口带入，可从保险箱选择；复核时明确选择保留原包加密、更换为 AES-256/ZipCrypto，或另存为无密码 ZIP。原加密条目保留其方案，新增内容显示使用的方案；新包密码编码明确可选，不静默改密或降级。

未保存的编辑自动保留为本地草稿，记录原包、修改清单、外部文件引用及输出配置，不保存密码。重启后在草稿入口恢复，先列出原包/外部来源缺失或变化，可重新定位/读取确认；密码重新填写，不自动另存。失败和停止继续保留修改，已保存结果不自动重复执行，原失败/原包/已有输出仍保留。

## 范围与界面

- 独立 Store/Deflate ZIP 的未加密、AES-128/192/256 与 ZipCrypto 读取和编辑；分卷、自解压、特殊路径/链接、嵌套临时来源及其他方法编辑仍后置。同包多密码仅支持一份用户凭据能够读全的情况。
- 保留原包加密时保留各原条目的加密方案/公开条目；新增条目沿统一原方案，混合方案时明确显示新条目 AES-256。新增/替换与仅改名内容按最终选定规则写出，时间、备注、方法和空目录保持。
- 密码条目需要重新写入，内容与压缩方法保留，压缩字节/体积不承诺不变；输出密码编码默认 UTF-8，在复核中可明确选择。
- 草稿只保存引用与配置；重新定位目录只映射原清单引用，不悄悄纳入新出现文件。恢复不自动启动任务或覆盖本次编辑。
- 保留原单条展开、多选弹窗、自然继承、压缩/解压等宽与滚动。复核中密码/来源信息就近显示，草稿入口紧凑，宽窄均可用。

# v1.5.2 ALZ 只读闭环

## 范围与接续

2026-10-18 从 v1.5.1 发布后主线 `3db0fd7` 接续，分支 `codex/v1.5.2-alz-read`。按批准路线补实际 ALZ 识别、普通/ZipCrypto 读取、原生卷组、浏览/所选提取、检查、转换和失败后接续；不提供 ALZ 创建。完成真实用户流程、常用/窄窗页面、独立工具载荷核对后才封板发布。

旧实现只有 `.alz` 扩展名，仍调用不提供 ALZ 解码器的随附 7-Zip；没有原生 `.alz/.a00/.a01` 归组。设置页静态 ALZ 文字不是验收证据，接入时同步纠正。

## 解码与原卷

候选 [unalz 0.2.1](https://docs.rs/unalz/0.2.1/unalz/) 声明 MIT，实际源码已读取。其默认多卷发现会吞掉打开错误，且允许截断索引保留完整条目；应用必须先验证真实卷头、卷号、后续卷标记和终卷，不将部分内容记为成功。传统密码短头只是候选，完整内容、大小和 CRC 通过才可记为密码有效；CP949 编码失败不能替换后试密码。

读取使用独立辅助进程，凭据经标准输入传递；沿用已有实际子进程暂停、恢复、取消与事务暂存。将指定的已校验卷组交给解码器，不盲扫同名文件或隐藏 I/O 原因。方法和压缩后数据边界在试密码前检查；明确缺卷、损坏或方法不支持时直接给最终原因。

原卷候选来自 [unalz 上游固定提交](https://github.com/alkegi/unalz/tree/30b4ad40c5452c686df69b3b45554de3073e57a1/tests/data)，标注真实工具产物，数据声明 CC0；保留原名原字节，通过独立 Bandizip 读取并固定载荷及 SHA 后再作为验收样本。另从 ALZip 官方下载页核实原工具，不执行输入归档里的程序。

已观察：Bandizip 7.38 Beta 可检查 Bzip2 和 ZipCrypto 原包；不能直接打开已取得的 `.a00` 成员，独立互通以原 `.alz` 入口为准。上游 `tests/data.rs` 使用带 Rust 模块 `::` 的临时目录名，Windows 下九项在建目录阶段失败，六项通过；不是应用验收，也不修改其断言来冒充全通过。

[Bandisoft 格式说明](https://en.bandisoft.com/bandizip/help/how-to-open-alz-and-egg-files/)另列 Obfuscated Deflate，不能由普通 Deflate 推断全部兼容。公开支持按实际方法、密码、卷型和真实样本分别列明。

## 实施与封板顺序

1. 固定解码来源、许可证、原卷及独立载荷，接卷组/严格结构检查和进程协议，覆盖缺首/中/末卷、混卷、I/O、大小/CRC 与取消清理。
2. 贯通目录、选择、密码校验、实际解压、检查报告和转换；原任务失败原因保留，补回原卷后新任务继续。导入任意成员归为一组，不重复解压。
3. 更新真实能力与目录名称，查看常用及窄窗口页面；不恢复快速打包，不改智能目录/ZIP 并行默认，不扩大 Windows N 承诺。
4. 按受影响范围回归，冻结提交，统一八处版本身份，完成普通生产、必需候选包、受保护 PR、固定标签、中文 Release/两份 README 和正式安装包；证据随文档推送，个人安装、设置和历史保持。

## 实施审计

已接入隔离读取进程、严格原卷结构、显式编码、完整载荷/大小/CRC、选择与筛选交集、解压事务、浏览、诊断和转换。八项后端测试通过，覆盖十组上游原包、两组原 ALZip 中文密码产物、任意成员、缺首/中/末卷、内部卷号混入、未知方法优先级及真实错误分类。93 项受影响前端测试与类型/构建检查通过；桌面验收仍在推进，不以单元测试代替。

审计纠偏：完整性检查命令原先仍走 7-Zip，已接 ALZ 实际读取器；诊断在请求密码前检查方法和结构。新 helper 尊重保留时间设置。ALZ 复用已有可持久化的来源编码参数，未选择时明确为 CP949；明确选择 CP936/CP932/CP950/UTF-8/当前 Windows 代码页时，不替换字符或轮流猜测。此参数在 ALZ 同时影响文件名与密码，不能沿用 ZIP“只影响密码”的提示。

真实 ALZip 原工具在本机 CP936 下将不可表示的韩文名称写成 `?`，保留该原始负向证据，不改名伪造恢复。另建可无损生成的中文名称/中文密码原包，与 Bandizip `-cp:936` 独立核对；普通包及五卷包完整内容、空目录和转换 ZIP 回解均需桌面确认。原工具及载荷/成员 SHA 见样本 provenance；256 MiB 进程控制原包留在忽略目录，最终证据记录 SHA，避免把大文件提交。

71 项不同 Rust 回归通过（ALZ 8、分卷 9、诊断 32、ZIP 密码相关 17、历史快照 5；另一个显式性能测量忽略，不记通过）。15 个前端文件 235 项通过。真实桌面已完成十二组原包整包解压/检查、两组中文原包转 ZIP 并独立回解、256 MiB 原包实际暂停/恢复/暂停中取消、文件管理器双击中间成员、所选提取、历史编码恢复及全包重做、缺中卷最终原因/补回后新任务、多成员导入去重、页面转换和诊断、三类批量参数与设置能力。22 张 1100×700/760×520 页面记录横向边界并逐张实看；说明保持问号弹出，不铺开大段说明。

桌面审计另修复：原局部提取历史会丢掉目录/来源编码；现在保存这两个可复用参数，密码和选择范围仍不持久化。历史明确说明新任务解压整个归档，不冒充原局部任务。任务格式采用实际浏览格式，不把 `.a01` 记为归档格式。诊断显式损坏标记优先于自由文本启发式，避免临时路径偶含 `eof` 被误归为截断；原断言保留，并加入确定性路径回归。

测试脚本按真实控件可交互后点击；滚动/尺寸改变会按设计关闭说明弹层，截图前重新点击打开。转换明确选择 ZIP 后才填写 `.zip` 名称，不能把旧默认格式当成 ZIP。没有放宽载荷、密码、最终失败原因或输出不残留断言。

支持证据边界：CP949 上游原包及 CP936 原 ALZip 中文密码已实测；其他可选代码页不由此宣称全部互通。ALZ 变体 Bzip2 的单条压缩输入由现有解码器限制为 256 MiB；应用原卷上限 1000、条目 25 万、声明展开体积 512 GiB，未实现 Obfuscated Deflate，不提供 ALZ 创建、损坏修复或缺卷部分救援。CRC 不构成来源认证。

功能验证完成；统一版本后的最终桌面、普通生产、必需候选包和受保护发布仍需完成后回填，当前不是正式发行完成。

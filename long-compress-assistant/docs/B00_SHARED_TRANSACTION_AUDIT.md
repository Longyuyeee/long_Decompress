# B-00.2 共享事务边界审计

日期：2026-08-27

公开版本基线：`1.1.14`

范围：只收敛归档与未来媒体任务必须复用的安全边界，不接入图片、视频或 PDF 页面及编码引擎。

## 开发目标与结论

B-00.2 已收口。单文件转换输出现在统一通过 `output_publish_transaction` 在最终目录旁生成唯一暂存名，调用方完成格式校验后才能请求发布；发布前再次检查取消、暂存文件类型和目标竞争，失败会清理本事务的暂存文件及旁车，成功使用同目录重命名提交。现有非分卷归档压缩已真实接入该边界，分卷压缩和目录型解压继续使用各自已验证的事务，行为没有被混合。

系统回收站调用也提取为 `source_recycle`。现有“完整解压后移入系统回收站”继续先解析整组分卷，再调用公共边界；部分解压、失败、取消和冲突跳过仍禁止处理源文件。未来媒体任务不得直接调用文件删除、回收站、历史写入或最终路径重命名。

## 可执行边界

| 能力 | 唯一复用点 | 媒体任务要求 |
| --- | --- | --- |
| 活动任务、进度、取消 | 现有 `task.ts`、任务队列与 Rust 取消标记 | 不新建媒体队列/store；引擎循环与子进程等待必须响应同一取消信号 |
| 容量保护 | `storage_preflight` 与运行时写入错误 | 编码前预检；未知容量只可警告，明确不足必须阻断 |
| 单文件暂存与发布 | `output_publish_transaction` | 最终文件同目录暂存；真实校验后发布；取消、缺失暂存、目标竞争和 I/O 失败不产生最终文件 |
| 目录型解压提交 | `extraction_transaction` | 媒体任务不得误用；归档选择性解压继续保留冲突、回滚和路径安全语义 |
| Mark-of-the-Web | `mark_of_web` | 来源策略成立时先写暂存输出，再随发布提交；不能在最终文件出现后补写 |
| 历史与指标 | 唯一 `save_task_history` 命令、`task.ts` 写入口及 B-00.1 版本化指标 | 不保存密码、完整命令行、临时路径或估算冒充的实测值 |
| 源文件清理 | `source_recycle` | 只能在校验和最终发布成功后调用 Windows 系统回收站；失败、取消时保留源文件 |

`npm.cmd run test:media-architecture` 已成为架构门禁：确认归档压缩真实使用公共发布事务、历史写入口仍唯一；未来出现名称含 `media` 的生产文件时，直接重命名最终输出、直接调用回收站、另写历史或新建媒体 store 会使门禁失败。

## 需求对齐与下一步

- 归档压缩、解压、密码、历史、浏览和右键入口没有被替换或削弱；本步骤只是把已工作的安全语义变成未来功能不可绕过的公共边界。
- 没有新增媒体 Tab、引擎、模拟进度、第二套队列、第二套历史或应用内回收站，未发生从“可靠归档工具”向堆功能的偏移。
- B-00 尚未整体完成，因此不升版本、不打包、不创建 Release。下一步为 B-00.3：固定图片、视频、PDF 候选依赖的精确版本、许可证、二进制来源、哈希、链接方式、平台、体积与安全更新责任，并实现缺项即失败的依赖门禁。

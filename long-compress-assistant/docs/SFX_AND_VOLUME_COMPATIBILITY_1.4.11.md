## 接续范围

v1.4.10 已于 2026-10-16 正式发布，合并与标签提交 `b1587d63b751fc37abf36ad9b38a2ce637a349e6`，见 [Release](https://github.com/Longyuyeee/long_Decompress/releases/tag/v1.4.10)。按 [多版本路线](ARCHIVE_FORMAT_AND_WORKFLOW_ROADMAP_2026-10-16.md)接续 v1.4.11，不重复发布 1.4.10。

本版优先处理用户收到自解压 EXE 后，无须运行程序即可查看、选择解压和转换内容；其次接入好压论坛分卷的正确分组和读取。保留原件、密码及独立任务设置，失败区分非归档程序、损坏、缺卷、密码和不支持的方法。不创建 SFX、不接管全部 EXE 默认打开方式，不把重命名的测试切片当作好压原始产物。

## 实施顺序

1. 核对 ZIP、7Z、RAR 的格式判断、密码、预检、浏览和解压实际代码，用外部工具生成真正的 SFX 样本，记录当前入口阻塞。
2. 统一 SFX 只读识别与原生读取；ZIP 的选择范围、7Z 的相对偏移、RAR 的加密头分别测试。普通 EXE 明确拒绝，绝不执行输入文件。
3. 查明特殊卷型的数据布局，才接分组与读入。任意成员统一为一个任务，缺卷显示实际文件名；设置不丢失。无真实样本则不宣称完成。
4. 使用隔离配置走实际桌面导入、浏览、错误密码、纠正、解压及转换链；涉及 UI 的页面在常用及窄窗口查看。每步审计、提交、推送。
5. 本版全部范围完成才冻结，统一版本、更新两份 README 与中文 Release，必需安装包检查通过后合入、打标签、发布并核对更新附件。

## 初始代码审计

- 公开导入后缀不包含 EXE；浏览及解压的头部判断只从偏移 0 读取。7Z 原生读取也要求逻辑偏移 0 为归档头，因此只把 EXE 加进后缀表不能实现 SFX。
- ZIP 的原生目录读取可处理前置模块，但路由、密码判断仍需统一识别。RAR 原生库可读取自解压包，部分辅助检查仍按 `.rar` 和起始签名判断，须检查实际调用。
- 标准 ZIP 与数字卷已有完整读取；`.haozipNN.zip` 不能套用 `.zNN` 名称规则。Bandizip 的[官方说明](https://www.bandisoft.com/bandizip/howto/open-haozip01.zip/)确认该命名来自好压论坛分卷，同时存在 7Z 变体，实际内部布局仍需样本确认。

## 阶段一 SFX 只读流程

ZIP、7Z、RAR SFX 的导入、浏览、原生密码、解压与转 ZIP 已实现；普通程序不会进入解压队列，也不会被执行。ZIP 保留原来的所选条目范围处理，7Z 使用只读偏移视图，不复制整个载荷；RAR 继续使用原生 UnRAR。完整性检查也统一到相同来源格式，避免解压成功却无法重新检查。

实际修正的问题：

- ZIP SFX 原先落入 UNKNOWN 路由；已先复现单元测试失败，再接入真实归档目录识别。
- RAR SFX 的版本检查仍读取 EXE 开头，实际解压报“不支持的 RAR 版本”；现从已核对的归档头读取。
- ZIP SFX 能列目录却无法预览文本；桌面点击复现后统一预览格式识别，没有删除预览断言。
- RAR 文件名加密包输入错误密码，浏览页误报损坏。`anyhow` 的外层上下文遮住底层 `Wrong password was specified`，现保留完整错误链；无依据的“无法读取元数据”不再被当作损坏证据。裸校验错误也不再自动断言密码错误，单独提示校验未通过。原来的裸校验测试预期据此改为校验分类，并新增真实密码、真实损坏和信息不足三种断言，并非放宽验收。
- 普通 EXE 被拒绝时，解压中心只显示用户可读原因，不把内部分类标记铺在提示中。

### 实际用户链与证据

真实包由外部 WinRAR、7-Zip、RAR 工具生成，内容为本轮合成的中文说明与二进制文件。ZIP 明文、ZipCrypto、AES 各 1 组；7Z 明文、内容加密、文件名加密各 1 组；RAR5 同样三组，共 **9 组**。每组均通过应用解压、只读完整性检查、转 ZIP，以及独立 7-Zip 回解；逐文件 SHA256 与原文件一致，输入 SFX 的 SHA256 不变。6 组加密包均拒绝错误密码。

文件选择复用项目已有的隔离对话框返回队列；其后的页面点击、原生命令、文件读写与结果核对真实执行。不是原生系统文件选择框/Explorer 菜单的人工验收。完整密码/转换矩阵通过真实应用命令执行，不声称每个矩阵项都手工点击了 UI；错误状态不是伪造完成状态。截图中的失败任务来自特意输入错误密码的用例，不是修复后遗留的未知失败。

本轮证据保存在 [结果 JSON](evidence/sfx-1.4.11/stage-one/sfx-1411-results.json)、[命令链结果](evidence/sfx-1.4.11/stage-one/sfx-1411-operations.json)及同目录 **11 张桌面截图**，包含测试程序 SHA256。单元测试中的 MZ 前缀小包仅验证偏移边界，不计作外部 SFX 兼容样本。

### 分组与失败处理

- 卷号、大小写和数字宽度按实际文件解析；拒绝 0 号或相同数字的重复成员。
- 以终卷的 EOCD 或 ZIP64 卷数声明核对总数，列出已知缺失首卷、中间卷的准确文件名。
- 只有连续的文件名、没有可读终卷目录时，说明“可能缺少后续卷或终卷损坏，总卷数无法确认”；不虚构某个终卷名称，不把它当普通 ZIP 继续尝试密码。
- 解压导入、失败重试、历史草稿和转换去重遵守同一卷组；来源检测失败不能降级为独立 ZIP。解压子目录和转换名称去除论坛卷号，独立任务设置不被全局选项重写。
- 浏览的早期密码解析错误也经过统一分类，缺卷的具体原因进入用户可见部分。页面复审发现长路径被提示框裁切，现优先显示所缺卷名，提示正文允许长文本换行；解压中心隐藏内部分类标记。

## 阶段三 好压跨卷 ZipCrypto 密码兼容

改走好压自带命令行生成器后发现了实际兼容缺陷：`HaoZipC.exe` 6.6.0.11316 生成的标准 ZIP 密码卷，独立 Bandizip 完整性检查成功，应用却拒绝正确密码。跨卷文件的通用标志为 `0x0809`，其中数据描述符位已设置，但解密头校验仍采用 CRC 高字节；原读取库在该标志下只检查 DOS 时间高字节。小文件不跨卷时没有这个差异，因此不能仅用小加密文件判断整组兼容。

### 修正与回归边界

- 将当前 `zip` 8.6.0 的同一版本源码纳入 `src-tauri/vendor/zip`，保留 MIT 许可、原始版本及来源。与 crates.io 原件逐文件比较，只有 5 个读取源文件有兼容补丁；锁文件只把同版本依赖改为本地来源，没有新增包。详情见 [本地补丁说明](../src-tauri/vendor/zip/LONG_COMPATIBILITY_PATCH.md)。
- 新增默认关闭的读取选项，显式允许数据描述符 ZipCrypto 的时间字节或 CRC 字节校验。应用只在共享密码读取入口启用；AES、编码候选、原文件、归档头、磁盘偏移和最终内容 CRC 不变，未使用忽略 CRC 选项。密码发现仍读完整条目后才能确认，短校验头匹配不等于密码正确。
- 默认执行的离线回归证明：依赖默认严格读取仍拒绝该非标准校验约定；应用兼容入口读出完整原文；错误密码不被接受；破坏密文后即使密码正确也不能通过内容校验。外部生成器测试默认忽略，已在本机显式执行，不将忽略算通过。
- 页面复审发现预览错误只显示原生英文 `provided password is incorrect`，现仅把这条明确错误翻译为“密码不正确，请修改密码后重试。”。CRC 损坏和方法不支持的错误保留原因，不扩大猜测成密码问题。

最初外部生成器用例在正确密码断言处失败；独立 Bandizip 对同一份生成物检查通过后才修读取器，没有改生成物或更换密码使其通过。离线回归的第一版误以为 Rust 写入器生成 CRC 式加密头，实际它自带时间式数据描述符，未能复现严格读取拒绝；已改成先令时间高字节等于已知内容 CRC 高字节，再只改变构造包的时间元数据，保持密文、内容 CRC 和真实描述符不变。严格模式必须拒绝、兼容模式必须完整读回的断言均保留；该构造用例不计作好压原生样本。

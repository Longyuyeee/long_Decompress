# Long解压 v1.1.10 发布审计

审计日期：2026-08-21

## 结论

分卷归档导入和任务详情响应式布局已达到补丁版本收口条件。当前没有发现需要阻止 v1.1.10 发布的新问题；无商业代码签名导致的 Windows 11 第一层菜单限制保持不变。

## 需求对齐

| 范围 | 实际结果 | 判定 |
| --- | --- | --- |
| 任意分卷拖入 | 解析同组分卷并归一到起始卷 | 已完成 |
| 多分卷重复导入 | 同组只创建一个解压任务 | 已完成 |
| 缺首卷/断档/混组 | 入队前显示明确诊断 | 已完成 |
| 解压详情左栏过窄 | 双栏接近等宽，左栏内容保持正常高度并纵向滚动 | 已完成 |
| 资源预检被压扁 | 禁止 Flex 子项收缩，窄栏自动使用可读单列 | 已完成 |
| 实时日志无限延伸 | 长路径限高，日志独立纵向滚动并强制换行 | 已完成 |
| 压缩中心同类问题 | 使用相同有界双栏，资源预检归入左侧配置 | 已完成 |
| 加密 7Z 密码门禁 | 使用真实 7-Zip 加密归档验证未输入、错误与正确密码三条路径 | 已完成 |

## 发布门禁

- 版本身份必须在 npm、Tauri、主程序、Shell Extension、Cargo lockfile、版本化 DLL 和 Git 标签间完全一致。
- GitHub Release 必须包含 NSIS 安装包、updater ZIP、更新签名和可解析的 `latest.json`。
- 发布前执行前端单测、类型检查、生产构建、响应式 Chromium E2E、Rust 与 Shell Extension 门禁。
- 加密 7Z 密码门禁已连续执行 3 次通过，避免由库自生成微型夹具造成跨环境误判。

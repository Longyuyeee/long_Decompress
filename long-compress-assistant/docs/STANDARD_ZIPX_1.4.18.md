# v1.4.18 ZIPX 标准多卷实施审计

基线 `a7ce1f9`，公开版 v1.4.17；分支 `codex/v1.4.18-standard-zipx`。本版按已批准路线补 `.zx01/…/.zipx` 标准多卷，不重复计算已有 ZIPX 数字卷，不扩张到未实现的 ZIPX 专有方法。

## 实际代码与范围

原有 `SplitArchiveDetector`、`StandardZipReader`、产物收集仅识别 `.zNN/.zip`；ZIPX 标准卷在后端主动拒绝，压缩/转换/配置组还会把用户选择静默改回数字卷。现复用标准 ZIP 的真实磁盘偏移读写、完整校验及事务发布，区分 ZIP 与 ZIPX 同名卷组，保持原数字卷默认值。补齐任意成员归组、浏览/预览/解压、输出目录名、密码编码、转换/改密/重新分卷及保存再执行。

## 独立原卷

本机已有 Bandizip `bz 7.38(Beta,x64)` 按原生命令直接生成无密码及 AES-256 两组三卷；原名原字节保存于[固定样本](../tests/fixtures/archives/standard-zipx-1418/README.md)。原工具完整检查通过。生成器脚本与工具/卷/载荷哈希一起保存，不使用改名数字卷。

[WinZip 官方说明](https://kb.winzip.com/en/130798)确认 `.zxNN/.zipx` 命名及磁盘布局；[Bandizip 官方 ZIPX 说明](https://www.bandisoft.com/bandizip/help/zipx/)说明其创建方法为 XZ，并支持 AES。产品创建预定覆盖 XZ × 无密码/AES-256/ZipCrypto；独立工具实际回解通过后才开放承诺。7-Zip 对 ZIPX 标准卷名的识别限制不通过改名绕过，不据此宣传所有软件兼容。

## 首轮实现与独立互通

原卷六种成员入口、浏览/说明预览/密码纠正/完整解压、缺卷补回和干净目录名通过。三种产品创建经普通验证及事务发布后，使用本机已有 WinRAR 7.23 原名完整回解，载荷 SHA-256、空文件和空目录一致。事务发布最初遗漏 ZIPX 分支，已经由实际失败定位并修复，取消、已有目标和处理中的目标碰撞不会覆盖用户文件。

本机 `bz 7.38 Beta` 能生成及读取自己的 ZIPX 标准卷，但对本产品输出读取目录成功、内容解码异常退出。保留失败目录 `.tmp7cVn3w`；删除 ZIP64 尾记录的实验仍失败，不采纳该猜测或修改产品尾记录。该卷原始 XZ 数据流另经 Bandizip 与 7-Zip 完整校验，原名多卷经 WinRAR 7.11、7.23 完整回解且 SHA-256 一致。因此本版独立输出互通明确以 WinRAR 7.23 为证据，不宣称 Bandizip Beta 或所有 ZIPX 软件兼容，也不关闭 XZ/ZIP 校验来绕过差异。

实际桌面原生命令矩阵已完成：两组原卷每个成员的整包/检查/转换及独立回解，24 次不同密码输入下的缺首/中/末卷与截断最终原因、补回后浏览，三种创建和 AES→改密 ZipCrypto 标准卷→合并取消密码。页面阶段初次因测试误写格式标签 `ZIPX` 而停止；产品可见标签是 `ZIPX（XZ）`，只纠正选择器并复用已完成矩阵。首轮 Rust 测试导入路径错误、并发测试占用可执行文件造成一次链接失败同样不计通过。

# RAR 密码匹配后误报失败修复审计（2026-09-05）

## 用户侧证据

- 生产应用近期文件记录指向同一数据盘上的一批 RAR；抽查最近 25 个文件时有 16 个为 0 字节，另有大文件在任务加入后继续写入。
- 密码保险箱当天产生了候选使用记录，但任务随后进入“输入密码重试”，证明候选预检与完整解压终态发生分歧。
- 审计过程未记录用户文件名、目录内容或密码正文。

## 根因

1. RAR 候选验证原先测试第一个非目录条目；混合归档的第一个条目若未加密，任意候选都可能被误报为匹配。
2. 正式解压只要携带密码，就把后续 `BadData` 统一映射为密码错误。文件仍在写入、截断、CRC 损坏、分卷缺失或后续条目使用不同密码都会错误进入手动密码重试。
3. 保险箱使用次数在候选匹配后立即增加，早于完整载荷解压成功，进一步放大了“密码已经找到”的错误信号。
4. 解压开始前没有锁定源文件大小与修改时间，下载或复制中的文件可能通过前部预检后在后部读取失败。

## 修复

- RAR 候选只允许由真正加密的条目证明；可见但未加密的条目会被跳过。
- 原生 RAR 解压跟踪密码是否已经由加密头或加密条目证明。证明前的 `BadPassword` / `MissingPassword` / `BadData(Process)` 仍返回密码错误；证明后的同类错误改为损坏、不完整或条目密码不一致，不再要求重复输入同一密码。
- 手动密码在显示“验证通过”前执行真实内容验证。
- 解压入口拒绝 0 字节压缩包；密码检测、预检及完整解压前后比较源文件大小和修改时间。源文件发生变化时清理暂存输出并提示等待下载或复制完成。
- 保险箱候选匹配不再立刻增加使用次数；只有完整载荷解压成功后才记录一次使用。

- RAR 错误分类聚焦回归：3/3 通过。
- 固定、独立来源的真实加密 RAR：错误密码拒绝、正确密码验证、双文件完整解压通过。
- 自动密码来源矩阵：保险箱、导入词表、内置字典、未加密归档拒绝假阳性及可见头加密 7Z 共 6/6 通过。

# v1.6.4 封板记录：ZPAQ 已校验文件部分取回

## 用户结果与进度

本版已封板，可进入正常合并与标签发布。用户在现有诊断详情选择检查通过文件，二级弹窗确认实际快照、所选数量、位置和不取回计数，再加入原解压队列。主页面保持紧凑，不增加常驻清单。每次创建独立结果目录，保留包内路径和原包；任务、批量、全局结果及历史提供按需查看的取回说明。

所选范围密码预检读取指定快照与精确文件，其他坏块不阻断正确凭据；所选内容或密码自身失败仍保留实际错误，不能跳过校验。正式执行重新逐块诊断并匹配原 revision，确认所选都通过，再完整提取和核对来源状态。失败或取消不发布私有暂存数据，沿现有提取事务提交；未复用普通整包的成功断言。revision 是诊断目录/状态身份，不是整包内容哈希。

取回说明包含实际快照、来源、文件路径及大小，分别记录已取回、受影响、未检查、未选择。说明文件与用户所选的根名称避让，和完整文件一起提交；不保存密码。详情弹窗筛选、搜索、分页，长清单不铺满主页面。

## 已完成依据

- 复用 v1.6.3 的四类明确标注受控损坏副本，不重新生成原件或重跑二十次官方诊断。普通/密码 × 单包/确认原生多部分，每种取回两个原校验通过文件，SHA-256 与官方原件预期一致；两个受影响、一个用户未选择文件不混入结果，原件 SHA 保持。
- 三项 Rust 分别覆盖四类实际取回/所选密码/事务提交、过期范围/受影响文件/真实取消/缺成员不发布，以及历史字段保留/不保存凭据。首次取回测试配置误用了默认平铺，修正测试为产品使用的保留路径后只接续该失败项；两个已过边界不重跑。
- 七项不同前端分别覆盖选择确认、范围复制、结果清单、过期诊断拒绝、草稿补密码、调用传递和历史重做；字节长度限制统一后只接续相应一项。
- 版本身份八处与 Shell DLL、类型/Vite 通过；本地候选应用 opt-level=1 缩短构建，正式 CI/Release 优化保持。没有新解码器、依赖、格式计数或数据库迁移。

## 范围与后续

仅完整日志式目录可诊断、原范围未变化且实际校验通过的文件；选择清单最多 2000 项且序列化不超过 60000 字节，较大清单可分批。超出诊断资源范围的文件保持未检查，本版不开放强行取回。受影响仍是共享块范围判断，不是每个文件损坏的证明。不完整目录、未知尾部、缺成员和未知密码不从此入口推断恢复。

沿用单条展开、多选弹窗、双栏等宽与窄窗交互；原普通提取保持既有规则。下一版 [v1.6.5](ARCHIVE_ROADMAP_1.6.5.md) 回到 ALZ 方法 3 的真实来源与跨流程兼容，之后继续 EGG 加密固实互通。新版本仅规划，尚未开始运行时开发。

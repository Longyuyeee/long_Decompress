# C-02.2 视频配置与估算模型审计

日期：2026-08-28

分支：`codex/video-c02-probe-model`

范围：在 C-02.1 可信探测事实之上建立三档配置、最大分辨率、派生输出尺寸、目标码率、估算区间和流变化摘要；不实现视频工作区、编码、进度、取消、输出验证或发布。

## 结论

C-02.2 已完成。后端是配置与估算的唯一真相源，前端只持有同构类型和 Tauri 调用封装。规划命令重新验证 C-01 产品运行时并探测当前文件，避免前端提交可伪造或已经过期的媒体事实。

“清晰、均衡、小体积”分别使用 0.120、0.075、0.045 bits/pixel/frame 的基础模型，并设置视频码率上下限与 192/128/96 kbps 音频目标。默认最大可见尺寸分别为 1920×1080、1280×720、854×480；竖屏输入自动交换默认边界。用户可同时提供最大宽高，但单边配置、任一边小于 2、任一边超过 3840 或总面积超过 3840×2160 均稳定拒绝。

输出尺寸按应用旋转后的可见方向计算，只缩小、不放大，并为首期 H.264 采用偶数尺寸舍入。大小区间按时长、派生像素、平均帧率和档位码率计算为名义值的 80%—125%；结果强制携带 `isEstimate=true`、计算依据和偏差说明，不会进入最终历史事实。

## 审计纠偏

- 估算不以输入文件大小乘固定比例，避免对不同编码复杂度给出虚假确定值。
- 配置不允许放大低分辨率输入，`willUpscale` 固定为 `false` 并由测试锁定。
- 旋转视频按 360×640 可见方向规划，而不是错误沿用 640×360 编码矩阵。
- 无音频输入的音频目标为 `null`，不会为估算虚构音轨。
- 有字幕等有损流变化时 `requiresExplicitConfirmation=true`；HDR 阻断会令 `canEncode=false`。
- 没有提前连接统一任务、编码器或发布事务，当前类型中的 `canEncode` 仅表达配置可行性，不是 UI 开放状态。

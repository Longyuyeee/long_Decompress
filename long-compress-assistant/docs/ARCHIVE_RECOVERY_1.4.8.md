## 实现范围

- `ZipInputReader::open_recovery` 对完整标准 ZIP 暴露原始卷组，不再要求先读取已经损坏的中央目录；正常浏览/解压保持原读取通道。诊断能够继续进入本地条目救援，跨卷内容、AES 与 ZipCrypto 复用原读取和密码逻辑。
- 本地重建支持声明体积且描述符一致的条目，以及未加密 Deflate 流的真实结束边界。读取压缩流并核对 CRC/体积与普通或 ZIP64 描述符，不扫描载荷中的魔数来猜文件边界；后续不明确的内容留下未恢复说明。
- RAR 创建可选恢复卷数量，设置贯通单条、多选、转换、草稿、历史、配置组和便携模板。`.rev` 与数据卷一并提交/取消清理、计入进度体积与产物清单，首个数据卷仍为解压入口。
- 已有完整 RAR 卷组可以单独生成恢复卷：核对完整内容后在暂存目录调用本机 RAR，数据卷优先使用 NTFS 硬链接只读输入，其他文件系统用可取消副本；只保存新恢复卷，拒绝混入或覆盖已有同组恢复卷。
- 检查页面增加批量列表，后端统一识别所选分卷组；单条展开，多选弹窗配置。检查/修复逐项进行，一项失败继续其他项，可停止当前处理；每组修复使用独立新目录，恢复结果保留其密码和各自解压目录，入队防止重复。

### 实际问题与修正

1. 第一轮在历史匹配处超时。SQLite 中记录正确指向已发布的 `.part1.rar`，脚本却等待分卷前的 `.rar` 名称；现按真实首卷匹配，保留恢复卷配置和最终体积断言，未改变产品历史行为。
2. 独立 ZIP 样本创建失败。7-Zip 26.04 的 [上游实现](https://github.com/ip7z/7zip/blob/26.04/CPP/7zip/Archive/Zip/ZipHandlerOut.cpp#L377-L395)明确拒绝非 ASCII 创建密码，本机以中文/ASCII 对照复现。ZIP 独立样本使用含空格和符号的 ASCII 密码，RAR 继续使用中文密码；批量配置后对 RAR 单独修改密码再检查，覆盖多包密码不同的真实操作。此项不扩大中文 ZIP 的独立兼容性承诺。
3. 实际截图发现 RAR 已完成但源数据为 `0 B`、压缩比仍为“计算中”。外部 RAR 路径原先只发送零字节完成事件；现以可取消、逐项遍历方式统计源文件体积，只在编码成功后上报最终总量，不生成假的中间字节进度，不为大文件树另存一份内存条目表。最后真实 UI 与历史均确认输入为 180000 字节，分卷和恢复卷体积共同计入结果。
4. 最小窗口复核改用软件 `uiScale` 实际采用的根字号（125%），与已有布局检查一致。CSS `zoom` 会把整个 `100vw/100vh` 画布放大，不能作为本项目设置缩放的等价验收。新增窗口和内容横向边界断言，保留最小窗口与弹窗滚动查看，不修改产品布局来迁就脚本。

## 实际发现与调整

1. 标准 ZIP 在正常读取器中依赖中央目录，旧救援在这一步提前退出；新增只用于救援的原始卷组通道，保留正常读取契约。
2. RAR 恢复卷若不进入产物提交列表，会遗漏或被当成异常数据卷；现分别验证数据卷和恢复卷编号，再共同提交、统计和展示。
3. 新增前端测试第一次把全局 `matchMedia` 的测试实现一起重置，造成测试夹具报错；改为仅重置本测试的模拟函数后 3 项批量流程通过，其余已通过文件未重跑。
4. 批量列表使用多根组件，显示/隐藏放在父容器，避免完整诊断与列表同时显示；已纳入最后前端构建。
5. 同名归档使用统一再次解压目录时，分别安排子目录，避免不同来源的恢复文件混在同一文件夹；新增批量流程检查通过。

## 边界

普通流式 Deflate 有压缩结束和描述符相互核对才恢复；密码条目仍要求本地声明的可靠体积。标准 ZIP 缺卷、未知边界、RAR4 恢复卷创建和未实测特性不扩大承诺。RAR 工具和 OEM 密码编码限制保持既有说明。

桌面脚本使用独立身份/数据目录，文件选择器使用已有测试响应队列，不能将其写成真实操作系统选择器点击证据。正式普通安装包不包含测试桥。用户已恢复本轮；封板和普通安装器的准确状态以最新交接及 PR 检查为准。

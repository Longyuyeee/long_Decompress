# v1.6.46 规划 · 7Z 压缩方法可选

仅规划，尚未开发。Bzip2 图文和大日志浏览补齐后，回到创建与转换流程，让用户创建 7Z 时也能按用途选择方法，先接通 LZMA2（默认）、LZMA 和 Bzip2；其他方法后续按实际需求继续增加。

1. **原配置区选择**：仅当目标为 7Z 时，在原行内配置和多选配置弹窗提供紧凑的方法选择，与现有 ZIP 方法字段同风格。默认 LZMA2，旧配置/草稿/历史没有新字段时行为不变；方法说明放问号，强度、密码和固实选项与所选方法一致，不新增独立页面或摊开介绍区。
2. **真正按方法创建**：本地引擎核对方法白名单并实际编码，接通普通/密码、内容/文件名加密、非固实/固实、完整数字分卷及取消/失败输出处理。Bzip2 编码必须明确完成真实尾部并正确结束后续 AES，不能依靠析构忽略写入失败。新方法沿现有发布事务、进度/日志/结果入口；默认 LZMA2 原流程保持。
3. **配置传递一致**：单条/全局/多选、配置组和用途模板、待处理草稿、历史再次执行、转换和工具工作流携带所选方法；源包解码方法与目标创建方法分开。体积分析使用实际选择的方法，不继续显示按 LZMA2 推算的误导结果；不支持的组合有明确处理建议，不静默换算法。
4. **交付一条完整用户流程**：从配置到生成，再回到原浏览/文本图片预览、解压和转换取回；新输出由独立 7-Zip 回解逐文件核对，检查普通/密码、固实/分卷及关键取消/失败场景。只补新增/受影响检查和必要默认方法连续性，实际宽窄窗口确认后同步 README/Release/能力表/交接，正常 PR/标签发布。

保留单条点击展开、编辑后自动独立、多选弹窗和左右等宽布局，保持主题/工具/快捷键与问号收纳。后续继续更多压缩算法、格式、密码/分卷与解压压缩容错主线；ALZ 方法 3、历史 ALZ Bzip2/原工具图片、EGG 加密固实仍需有效外部原件，不为空取材单独发版。

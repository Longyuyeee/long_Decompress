# 回滚不完整：保留恢复数据与禁止原暂存重试

## 需求与实现

基线 `master@c0175e5`。上轮修复成功回滚后的暂存完整性，本轮处理已知的回滚失败边界，继续对齐真实任务最终状态和数据一致性。

- 回滚失败返回独立 `RollbackIncomplete`，稳定标记 `archive-output:Publishing:rollback-incomplete`；错误包含恢复目录、提交错误和回滚详情，要求保留源文件与输出，人工核对后处理。
- 普通解压不再清理这种暂存；暂存所有者进入恢复保留状态，显式 cleanup 被拒绝，Drop 不再删除目录。
- 冲突恢复遇到此错误后不重新放回 pending 队列，防止同一任务再次提交不完整暂存；普通失败仍保留原来的 pending 重试行为。
- 前端重复确认同一回滚不完整任务时直接返回原原因，不调用后端，避免“无 pending”错误覆盖恢复目录信息。
- 历史类别显示“回滚不完整（需人工核对）”，阶段为 Publishing；详情和诊断导出保留恢复路径，不误判为密码错误。
- 这是终止原暂存自动重试并保留数据，不是自动恢复成功。保留目录可能隐藏，且可能包含旧目标备份；不得未经核对删除。新任务仍需用户主动选择，不能据此承诺新任务覆盖原输出安全。
- 版本仍为 1.3.2，schema 8；未增加后台扫描/自动恢复/清理入口。

# C-02.1 视频输入事实与首期流策略审计

日期：2026-08-28

分支：`codex/video-c02-probe-model`

范围：C-02 的第一段，只建立有界输入探测、结构化事实、首期流策略与前端调用契约；不实现预设、体积估算、视频工作区、转码、进度、取消或发布。

## 结论

C-02.1 已完成。正式 Tauri 命令会先复用 C-01 已准入的视频引擎校验，再以无 shell 参数数组调用产品 `ffprobe.exe`。探测最多运行 20 秒，子进程随超时终止，元数据输出限制为 8 MiB，错误详情限制为 2,048 字符；缺失、目录、空文件、损坏容器、无视频流、非法尺寸和非法时长都有稳定错误前缀。

探测结果区分编码矩阵和应用旋转后的可见尺寸，并报告时长、容器、总码率、主视频编码/档次/像素格式/帧率、VFR 分类、旋转、HDR、全部音频与字幕流、章节和封面数量。`constant-or-undetermined` 是刻意保守的分类：仅凭 ffprobe 汇总帧率相等不能证明恒定帧率。

## 审计纠偏

- 没有把 `r_frame_rate == avg_frame_rate` 冒充确定 CFR，而是返回 `constant-or-undetermined`。
- 没有用扩展名判断视频；损坏的 `.mp4` 必须由真实 ffprobe 拒绝。
- 没有在前端复制流规则；后端报告携带唯一的首期策略和稳定警告/阻断原因。
- 没有为了探测提前启用视频 UI 或创建统一任务；C-03/C-04 的执行与发布边界保持冻结。
- 架构门禁已扩展到视频引擎、探测服务、命令、类型和调用封装，禁止 shell 与共享边界旁路。

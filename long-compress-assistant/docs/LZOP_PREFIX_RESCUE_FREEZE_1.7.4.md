# v1.7.4 · LZOP 完整成员部分取回记录

状态：功能封板完成，接续正式合并与发布。版本 1.7.4，分支 `codex/lzop-prefix-rescue-174`，日期 2026-10-27。

## 实现

普通 LZOP 新增独立的恢复扫描与所选取回服务。沿现有 LZOP 读取器逐成员解码，确认文件头、数据块校验和零长度结束标记；首个坏头、坏块、截断或未提供内容校验的非空成员处停止。空文件仍需完整有效成员。复用名称和路径规则，重名编号稳定；不从任意字节搜索下一成员。

数字卷只取 .001 开始连续且非空的前缀。遇到缺中卷或空卷后，后续卷不拼接；缺首卷明确停止。结果带已确认成员清单、大小、内容 SHA、停止位置与原因（位置指完整前缀结束/后续成员起点），来源元数据和内容确认结果形成 revision。取回前重新核对来源，逐文件再次核对内容；暂存内只保留完整所选文件，成功后一次移入独立“部分取回”目录，取消或失败丢弃本次暂存，原件与旧结果保留。

失败任务沿原“检查并尝试救援”进入诊断，再用二级弹窗选择文件及保存目录。直接复用诊断中的已确认成员，不因打开弹窗再次扫描；停止原因默认折叠，范围说明放问号。文件列表筛选和分页，主要区域用于选择；显示真实检查/取回进度，支持停止。

新增 `archive-recovery` 执行记录，保存实际数量、停止原因和 revision。历史将成功的部分取回操作显示为“已部分取回”，与完整解压区分，提供结果位置及重新检查原包；失败/取消也保存状态。不会把恢复结果静默送入普通全量转换，原失败记录保留。正常解压和全量转换的成功条件没有降低。

## 已确认范围和边界

本版支持普通 `.lzo` / `.lzo.001` 数字切片的完整成员前缀。非空无内容校验成员不列为完好，缺中卷后不拼接或猜测。没有完整成员时不生成恢复结果。现有完整来源可以正常解压，补齐后重新沿原流程处理。

LZOP 没有总成员数/总卷数，不保证发现完整成员及后面内容整体丢失。普通 LZOP 不表达独立空目录；本版不提供 TAR.LZO 内部条目救援、原生密码、原生分段或恢复缺失数据。进程被强行终止后的暂存接续未在本期承诺。ALZ / EGG 外部原件缺口继续保留。

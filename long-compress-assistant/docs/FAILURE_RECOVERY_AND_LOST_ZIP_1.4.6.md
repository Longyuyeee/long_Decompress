# 失败任务处理与密码 ZIP 丢目录救援

2026-10-15 接续暂停提交 `6df5902`，目标版本 1.4.6。用户要求保留单条展开、多选弹窗，推进到可发版；本文件记录最后实现及其实际检查范围。

## 用户操作

- 单条失败任务点击后在原位置展开纠正表单；保留来源、输出目录、密码和子目录选项，创建的新任务与原失败记录关联。
- 已知缺卷直接显示名称，可打开原目录补齐后重新检查。损坏或原因不明的归档可从对应条目直接进入救援。
- 救回新包后可直接加入解压队列；原配置或在失败表单里新改的输出目录、子目录设置继续保留，密码在内存中交接。原失败任务与成功结果保留，待处理任务由用户启动。
- 多项纠正沿用弹窗，单条详情及配置不改成强制弹窗。本轮接续的等宽详情、滚动日志和小窗口修正见 [布局记录](TASK_DETAILS_LAYOUT_2026-10-14.md)。

## 目录丢失后的读取

`zip_recovery_reader.rs` 根据本地头声明的范围构建只读虚拟目录；原始载荷保持在原文件或完整数字卷中，目录元数据保留 AES、文件名及必要 ZIP64 信息，复用现有 ZIP 解密和内容校验。

诊断只做可恢复结构及密码头检查，完整读取和内容校验在实际救援时进行。新包只收录校验通过的完整文件，并沿用填写的密码使用 AES-256 / UTF-8。目录重建始终明确标为部分恢复，原包总数未知；明文条目不能代替完整加密条目证明密码可用。

本轮不覆盖本地尺寸未知的数据描述符、缺卷、标准磁盘 ZIP 卷丢目录或未知边界扫描；目录可读的普通标准卷救援沿用既有能力。RAR 恢复和新格式变体仍留后续。

## 定向检查进度

- 相关前端 4 文件 63 项及类型检查通过，包含单条纠正、多选原行为、补卷提示、救援交接、新包入队和配置保留。
- Rust 诊断/恢复 28 项通过，新增 AES/ZipCrypto 丢目录、完整数字卷、ZIP64 元数据和完整加密前缀后接未知/截断条目的检查。只有明文前缀时不发布加密救援结果。
- 暂停前 ZipCrypto 用例的夹具问题已收口：库的流式 ZipCrypto 写入使用未知尺寸描述符，新增声明尺寸夹具对应本轮支持范围。外部 7-Zip 样本及独立回解由本轮桌面检查补充，不能仅凭自建夹具声明完整通过。
- Windows WebView2 实测通过：外部 7-Zip 生成 AES/ZipCrypto 两种密码包，删除中央目录并损坏其中一个文件，对单包/完整数字卷共 4 个组合进行救援、错密码拒绝、独立回解与原件哈希比较。
- 真实桌面走通“损坏任务失败 → 单条纠正 → 救援 → 沿用本次修改的输出目录入队 → 成功解压”，以及“缺卷失败 → 显示缺卷 → 补齐 → 创建关联任务 → 成功解压”。查看常用和窄窗口的纠正表单、缺卷卡片与救援结果，均未横向溢出。
- 最终普通前端生产构建通过，不携带测试桥；npm/Tauri/Rust/右键 DLL 的版本统一为 1.4.6。最终 Windows 生产安装器由仓库必需的 `Windows package` CI 生成，状态以 PR #160 的最新检查为准。

# 源归档变化的失败分类

## 需求与实现

接续失败分类补强，不新增工作区、不改密码策略、版本仍为 1.3.2。

实际代码在预检/密码检测后，以及解压引擎结束后，均比较源文件大小与修改时间快照。之前能终止操作并给出原因，但历史只保存为未分类。

- 增加两个类型化错误：`SourceChangedDuringPrecheck`、`SourceChangedDuringExtraction`，分别发出受限的 `archive-source` 标记。
- 历史保存将这两个标记记录为 `source-changed`，阶段分别为 `Pre-checking` / `Extracting`，依据为 `recorded-marker`，优先于调用方的最后观测阶段。
- 历史详情、筛选、诊断导出显示“源文件已变化”；旧无标记记录不回填，未知阶段标记不猜测解析。
- 前端不会把这两类已确认的源变化故障再次当成密码错误，即使详情含密码错误字样。
- 保留现有输出丢弃与清理分支，不发布不稳定源的解压结果。不声称元数据快照能发现所有同长度、同修改时间的内容替换；也不能由变化推断一定还在下载，因此原因文本使用“发生变化”，建议等待下载或复制完成。

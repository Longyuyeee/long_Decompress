# 视频/PDF 切页控制：用户场景修复

## 需求与排序

用户正在处理视频/PDF，切到历史再回来，必须还能看到原任务并取消，不能重复执行。优先处理上版审计已有明确代码证据的跨页风险，再接失败处理动作；没有扩张媒体引擎或恢复引擎。

## 复现与修改

- 组合函数的新实例无法取消旧实例正在执行的任务；两个取消场景期望调用原任务取消，实际调用次数为 0。
- 输出路径规划阶段 `activeTaskId` 为空，第二批次未被拒绝，两个防重复场景在旧代码上超时。共四场景先红后绿。
- 视频/PDF 使用按 task store 和 workload 隔离的内存会话，规划、执行及历史保存全过程持有运行锁，外层 finally 释放。页面组件不再自行复位运行态。
- PDF 文件列表、配置和输出目录移至非持久化 Pinia store；重启不恢复未运行草稿，切页清空未提交的密码输入，不保存密码。
- 保留取消后等待后端清理及终态落库，不把用户切页当作取消，不自动重跑任务。

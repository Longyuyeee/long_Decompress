# v1.7.8 · TAR.LZO GNU 长名称部分取回

状态：功能封板与定向检查完成，进入打包发布。接续 v1.7.5 的完整条目部分取回，已完成 GNU `L` 长名称记录、长目录、UTF-8 名称与跨块/缺卷恢复，保持现有二级恢复弹窗。见 [实现与检查](TAR_LZO_GNU_NAME_FREEZE_1.7.8.md)。

2026-10-27 范围细分：全局 PAX 会改变后续普通条目的名称和大小，当前完整 TAR 读取与恢复读取的支持范围不同，不能只在恢复侧跳过全局头。原计划分为本版 GNU 长名称、[v1.7.9 全局 PAX 完整流程](ARCHIVE_ROADMAP_1.7.9.md)；后者尚未开发，不计入本版完成内容。

## 用户目标

让 GNU 格式中的长文件名和长目录在 TAR.LZO 后段损坏时也能保留此前已确认的资料，不再遇到 `L` 名称扩展就停止。恢复列表优先展示文件名，再展示目录，完整路径保留在悬停提示中；继续使用现有部分取回弹窗，不增加主页面。

## 拆分推进

1. 先取得独立 GNU tar / lzop 原件与明确的完整回读依据，覆盖长目录、同名文件、中文名称、跨块跨卷的扩展记录。先补 GNU `L` 长名称记录，记录头、数据和填充均完整且有外层校验后，才应用到紧随的普通文件或目录。
2. GNU 长名称必须在记录头、内容与填充完整并有外层校验后才应用到下一条普通文件/目录；只应用一次，不把元数据记录作为文件取回。遇到重复名称记录、局部 PAX 与 GNU 名称叠加、稀疏、链接、全局 PAX 或未知类型时明确停止，不猜后续条目。
3. 接通原选择、目录联选、独立结果、停止原因和历史；补齐后正常提取与转换仍走完整读取。使用实际坏尾、缺中卷、元数据截断和更换来源的定向检查，不重跑已通过旧矩阵。

## 保留边界

本期不顺带承诺硬链接、符号链接、稀疏文件或缺口后扫描。LZOP 原生块分段单独评估，原生密码不虚构；ALZ / EGG 有效外部原件缺口保留，不能以自造样本替代。完成后再按用户价值推进其他格式、算法与真实包兼容，性能优化按版本持续进行。

## 现场问题接续

v1.7.5 首次桌面结果发布曾报告一次 Windows 访问拒绝，同候选接续全部通过，根因未确认。若再次复现，先补齐发布阶段类型化错误与具体路径/占用定位，再决定是否需要针对性重试；不把系统写入失败标成数据损坏，也不凭一次错误猜原因。

# v1.4.0 开发计划：兼容、加密、分卷与简洁交互

更新时间：2026-10-11。状态：用户已确认方向，UI-01～06 已实现并完成浏览器专项；具体证据与未完成项见开发交接。当前已发布版本仍为 1.3.9，1.4.0 未封板或发布。

## 1. 决策与范围

用户确认以归档兼容性、密码与分卷完整体验为主线，加入压缩包转换、重新加密和重新分卷。用户随后提供九张界面截图，明确要求下列 UI 修正；这些修正排在引擎扩展前，属于本版必做项，不是可选美化。

- 保持现有行内展开方式与动效，不改成独立编辑页；默认窗口不能因过大间距、冗长文案或不合理断点把可并排的配置挤成上下长页。
- 普通解释按需阅读：统一使用标签旁可点击的小问号，不在主界面堆说明。错误、正在发生的冲突与必要操作反馈仍就地显示。
- **撤销此前保留快速打包的计划：用户明确不需要该功能，1.4.0 移除。** 不是只隐藏勾选后继续执行旧配置。
- 智能目录和 ZIP 并行解压仍保持用户主动开启、默认关闭；没有获准改变这些默认行为。
- 冷门格式、新后端和完整包内编辑器不自动纳入；Windows N 仍不保证支持。

## 2. 第一阶段：截图反馈的六项必做修正

### UI-01 解压配置布局与说明收纳

- 修复默认窗口展开后不合理上下堆叠；按真实内容宽度安排主要配置与选项区域，减少卡片内外空白，保留可读字号。
- “直接解压到此目录，不另建同名子目录。同名文件：询问如何处理。归档内的文件夹会保留。”及“新内容会放入已有目录；是否存在同名文件，将在解压时确认。”不再常驻正文，放入相关标签旁问号说明。
- 保留预计输出路径、复制、更换目录以及简短目录状态；目录已有内容不等于已确认同名冲突，不用误导文案代替实际检查。
- 极窄窗口可以合理降为单列，但默认窗口不能用“允许单列”的旧测试结论豁免此次问题。

### UI-02 目录快捷入口与菜单

- 将“书签 / 最近目录”入口改成更直观的“常用目录”；菜单内分为“收藏目录”和“最近使用”，保留收藏当前目录的操作及明确可访问名称。
- 替换截图中不协调的原生 select 下拉呈现，使用与应用一致的菜单风格；名称与路径分层显示，长路径截断但可查看完整内容。
- 菜单限制高度、适配上下可用空间，不越出窗口或被展开区域裁切；支持键盘、Esc、点击外部关闭及焦点返回。
- 保留目录不存在/无法访问时不修改原输出位置的行为；空列表须有简短空状态。

### UI-03 压缩配置布局、名称与格式菜单

- 修正默认窗口配置和按钮意外换行；名称、格式、密码及输出区域紧凑对齐，不靠缩小全部文字解决。
- 文件名输入和扩展名采用互不覆盖的布局：扩展名占独立固定空间，长名称只能在输入区域滚动，不能遮住 .zip、.7z 或复合后缀。
- 修正压缩包名称输入中不相关的密码名称占位提示。
- 目标格式改用统一样式菜单，合理分组、限制高度；保留格式限制的可理解反馈，不再显示巨大系统原生选项面板。

### UI-04 移除快速打包

- 移除勾选、相关帮助、配置组及历史恢复中的可执行选项，梳理前后端 fastPack/fast_pack 传递与执行路径。
- 旧设置、配置组和历史快照仍须可读取，但旧 true 值不能在新任务中悄悄启用快速打包；历史原记录不改写。
- 移除该功能特有的抽样直存策略，不误删正常 ZIP Store 模式、压缩等级或独立的预计体积分析功能。
- 更新当前说明和针对性测试；旧版本发布记录保留为历史事实。

### UI-05 高级选项直接可见与统一帮助

- 展开任务配置后，输出目录与高级选项直接显示，取消“输出与高级选项”的二次开关；配置组管理、保存操作独立紧凑排列。
- “保留源文件夹的层级关系”等选项说明全部迁入标签后的小问号；格式说明、抽样分析说明等采用相同原则。
- 问号点击或键盘激活显示解释，可关闭并返回焦点；不能只依赖悬停或原生 title。点击问号不能顺带改变复选框。
- “完成后删除源文件”等行为仍保留清楚的操作名称及原有授权/校验约束；仅精简说明，不改变执行含义。

### UI-06 历史页面精简与统计弹窗

- 精简顶部副标题及全库搜索、500 条显示窗口等长段说明，详细解释移至帮助入口；保留必要加载、筛选与结果状态。
- 将“查看当前结果统计与趋势”行内展开改为简短的“统计”按钮，点击打开弹窗，不挤占或推移任务列表。
- 弹窗明确统计口径是当前显示记录，不标成全部历史；保留已有真实计算，不借改版改变数据含义。
- 支持关闭按钮、Esc、焦点管理、内部滚动及小窗口；关闭后列表筛选、选择和滚动位置不应丢失。

### UI 验收场景

以用户截图为缺陷输入，而非把截图像素尺寸当成窗口逻辑尺寸。检查实际默认窗口、最小支持窗口、宽窗与可用的不同 DPI；默认窗口为首要验收条件。覆盖长中文名称、复合后缀、长目录、菜单靠近窗口上下边缘、多任务展开、问号与复选框相邻点击、空历史与大量历史、统计弹窗关闭恢复。保留前后对比截图及实际操作结果，不能仅靠 DOM 断言或放宽断点测试宣布修复；不为通过验收而改变用户要求。

## 3. 第二阶段：格式能力与密码/分卷组合

### ARCH-01 能力矩阵

建立格式 × 编码方法 × 加密方式 × 分卷形式 × 创建/读取的矩阵，区分实测、条件支持、不支持。当前 ZIP/7Z 密码压缩已存在，不算新增；ZIPX 后缀别名不证明所有 ZIPX 编码可解。当前实际执行拒绝加密分卷和目录分卷，7Z/RAR 的分卷能力标为关闭，是需要补齐的缺口。参考 [现有支持分级](FORMAT_SUPPORT_LEVELS.md)。

### ARCH-02 分卷完整支持

- 必做：ZIP、7Z 的目录、多文件、密码与分卷组合；分卷大小预设与自定义；整组结果展示、取消/失败残留处理。
- 明确 .zip.001 数字分割与 .z01/.zip 多卷 ZIP 的差异；支持何种生成/读取形式由矩阵及互操作证据决定，不能只改后缀冒充兼容。
- RAR 创建和分卷仍为可用且获授权的外部 WinRAR/Rar.exe 条件能力；无依赖时明确说明，不静默生成其他格式。
- 对分卷排序、从非首卷导入、重复导入、缺首/中/末卷、混入其他归档卷、加密文件头等逐项验证；无法可靠推断缺失末卷时不声称已确认完整。

### ARCH-03 密码兼容与最终原因

- ZIP 以 AES-256 为主；传统 ZipCrypto 兼容模式明确较弱，不静默降级。7Z 增加明确的文件名加密选项。
- 覆盖 ZIP、7Z、RAR 的单包、分卷、文件头加密及中文/特殊字符密码。
- 区分候选密码、密码已验证与任务完成。损坏、缺卷、不支持编码、空间不足和密码错误分别给出最终原因及下一步；未知不冒充密码错误。
- 不把历史密码明文保存作为便利功能，不把密码破解作为本版升级主线。

## 4. 第三阶段：转换与格式扩展

### ARCH-04 转换、重新加密、重新分卷

统一流程：选择已有包 → 目标格式/密码/分卷设置 → 显式执行 → 新包结果。只输出真实支持创建的格式，默认保留原包；提示临时空间需求，使用有界内存/临时文件。换密码通常需要解密后重打包，不能宣传瞬间修改；中途失败不覆盖原包。完整包内文件编辑器不随此项自动扩展。

### ARCH-05 有证据的格式扩展

优先明确常用 ZIP/ZIPX 编码兼容。LZ4、Brotli 和 TAR 组合为候选；ARJ、Z、UDF 等已有引擎能力需核对公开入口和真实样本后再决定开放。ALZ/EGG 等额外后端能力暂缓。候选不等于已承诺全部支持：实施前冻结具体格式清单，有不确定的依赖、分发或范围选择先询问用户。

## 5. 性能与封板

- 检查列目录、密码验证、校验和正式解压的重复读取，复用必须保证正确性；移除快速打包后也不能以降低必要校验换取速度。
- 大文件、小文件与混合场景分别记录端到端耗时、峰值内存、临时空间；物理磁盘和完整进程树未测的指标明确未测，不承诺倍数。
- 双向互操作：我们生成的包由竞品读取，竞品生成的包由我们读取；核对文件内容、目录、密码及所有分卷，不仅自己压自己解。
- 每一阶段完成后记录审计、测试与未完成项，按仓库规则提交、推送并通过 PR 检查，再继续下一阶段。正式发布需无测试桥安装包、升级及实际用户操作回归。
- 全部必做项完成且候选范围明确收口后，才同步 1.4.0 版本、README、Release、安装附件与更新清单。此计划批准不代表已封板。

- 旧设置、配置组和历史快照仍须可读取，但旧 true 值不能在新任务中悄悄启用快速打包；历史原记录不改写。
- 移除该功能特有的抽样直存策略，不误删正常 ZIP Store 模式、压缩等级或独立的预计体积分析功能。

## 3. 第二阶段：格式能力与密码/分卷组合

### ARCH-01 能力矩阵

建立格式 × 编码方法 × 加密方式 × 分卷形式 × 创建/读取的矩阵，区分实测、条件支持、不支持。当前 ZIP/7Z 密码压缩已存在，不算新增；ZIPX 后缀别名不证明所有 ZIPX 编码可解。当前实际执行拒绝加密分卷和目录分卷，7Z/RAR 的分卷能力标为关闭，是需要补齐的缺口。参考 [现有支持分级](FORMAT_SUPPORT_LEVELS.md)。

### ARCH-02 分卷完整支持

- 必做：ZIP、7Z 的目录、多文件、密码与分卷组合；分卷大小预设与自定义；整组结果展示、取消/失败残留处理。
- 明确 .zip.001 数字分割与 .z01/.zip 多卷 ZIP 的差异；支持何种生成/读取形式由矩阵及互操作证据决定，不能只改后缀冒充兼容。
- RAR 创建和分卷仍为可用且获授权的外部 WinRAR/Rar.exe 条件能力；无依赖时明确说明，不静默生成其他格式。
- 对分卷排序、从非首卷导入、重复导入、缺首/中/末卷、混入其他归档卷、加密文件头等逐项验证；无法可靠推断缺失末卷时不声称已确认完整。

### ARCH-03 密码兼容与最终原因

- ZIP 以 AES-256 为主；传统 ZipCrypto 兼容模式明确较弱，不静默降级。7Z 增加明确的文件名加密选项。
- 覆盖 ZIP、7Z、RAR 的单包、分卷、文件头加密及中文/特殊字符密码。
- 区分候选密码、密码已验证与任务完成。损坏、缺卷、不支持编码、空间不足和密码错误分别给出最终原因及下一步；未知不冒充密码错误。
- 不把历史密码明文保存作为便利功能，不把密码破解作为本版升级主线。

## 4. 第三阶段：转换与格式扩展

### ARCH-04 转换、重新加密、重新分卷

统一流程：选择已有包 → 目标格式/密码/分卷设置 → 显式执行 → 新包结果。只输出真实支持创建的格式，默认保留原包；提示临时空间需求，使用有界内存/临时文件。换密码通常需要解密后重打包，不能宣传瞬间修改；中途失败不覆盖原包。完整包内文件编辑器不随此项自动扩展。

### ARCH-05 有证据的格式扩展

优先明确常用 ZIP/ZIPX 编码兼容。LZ4、Brotli 和 TAR 组合为候选；ARJ、Z、UDF 等已有引擎能力需核对公开入口和真实样本后再决定开放。ALZ/EGG 等额外后端能力暂缓。候选不等于已承诺全部支持：实施前冻结具体格式清单，有不确定的依赖、分发或范围选择先询问用户。

## 5. 性能与封板

- 检查列目录、密码验证、校验和正式解压的重复读取，复用必须保证正确性；移除快速打包后也不能以降低必要校验换取速度。
- 大文件、小文件与混合场景分别记录端到端耗时、峰值内存、临时空间；物理磁盘和完整进程树未测的指标明确未测，不承诺倍数。
- 双向互操作：我们生成的包由竞品读取，竞品生成的包由我们读取；核对文件内容、目录、密码及所有分卷，不仅自己压自己解。
- 每一阶段完成后记录审计、测试与未完成项，按仓库规则提交、推送并通过 PR 检查，再继续下一阶段。正式发布需无测试桥安装包、升级及实际用户操作回归。
- 全部必做项完成且候选范围明确收口后，才同步 1.4.0 版本、README、Release、安装附件与更新清单。此计划批准不代表已封板。

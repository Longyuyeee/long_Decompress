# v1.7.13 规划 · TAR.LZO 旧 GNU 稀疏文件部分取回

状态：仅规划，尚未开发。文件与目录时间已分别在 v1.7.11～12 接通，接下来回到格式、容错与失败流程主线：正常完整读取已有 GNU/PAX 稀疏能力，部分取回仍会在稀疏条目处停止。

1. 先取得 GNU tar 生产者的旧 GNU `S` 稀疏原件及官方 lzop 完整回解依据，覆盖少量/多段数据、扩展块、空洞与结尾空洞；以独立工具的逻辑文件内容和大小为依据，不以应用写入器自证。
2. 首期只扩展旧 GNU 布局。稀疏图、扩展头、实际数据及填充均完整并位于已校验的 LZOP 前缀时，才列为完整可取回条目；核对段范围、存储大小与逻辑大小。未知/不完整布局明确停止，不扫描缺口后的条目。
3. 取回时区分逻辑文件大小与原包实际存储位置，流式确认空洞与数据的逻辑 SHA，避免把下一条目当作本文件内容。结合实际 Windows 稀疏落盘能力控制大空洞开销，容量/进度/取消与独立结果一致；若目标或规模暂不支持，明确说明，不宣称完整兼容。
4. 沿用原所选范围、目录联选、时间提示、结果和历史；只检查受影响的坏尾、稀疏图/扩展块截断、缺中卷、来源替换、实际输出和取消。补齐后正常完整读取继续使用既有引擎，不新增常驻界面，不接管桌面。

PAX sparse 0.0/0.1/1.0 的部分取回、链接救援、缺口后扫描及完整权限/所有者恢复不计入首期承诺。ALZ/EGG 加密分卷外部原件缺口及 LZOP 原生密码/块分段继续单独研究；若旧 GNU 原件或落盘链出现实质阻断，先记录依据并细化范围，不把推测列为已完成能力。

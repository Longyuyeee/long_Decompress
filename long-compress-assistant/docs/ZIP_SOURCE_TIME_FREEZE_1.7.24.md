# v1.7.24 · ZIP / ZIPX 源修改时间封板

日期：2026-10-28。

## 实现与用户行为

原生 ZIP 创建器原先给全部条目复用默认 `FileOptions` 日期。本期对每份文件从已打开的文件句柄读取修改时间，对目录从源元数据读取，分别设置 `last_modified_time`；空 ZIPX 成员继续采用原 Store 回退并保留日期与加密设置。所有现有 ZIP 方法、ZIPX XZ、密码及分卷均经过同一创建器，转换输入已暂存的源时间也可继续写入。没有新建界面或设置项。

日期采用 ZIP 标准 DOS 本地日历，秒数向下取到偶数，亚秒不编码；范围为 1980-01-01 00:00:00 至 2107-12-31 23:59:58，越界时夹到边界，并通过原任务日志汇总警告。保持当地时区语义，不承诺 UTC / 亚秒时间或跨时区、夏令时歧义无损恢复。源元数据读取错误保留路径和原错误，不以默认日期掩盖失败。原文件内容及修改时间不变。

本版只为实际写入的目录头保存日期。现有非空顶层目录可能仍是隐含父目录，软件原解压器的目录时间恢复也未在本版扩展；相关范围单独安排 v1.7.25。单条展开、多选弹窗、等宽双栏、最终结果与历史入口不变。

## 检查与证据

- 新原生 5 项通过：本地日期/闰日/两秒精度/年份边界；六种 ZIP 方法（Store、Deflate、Zstandard、Bzip2、LZMA、PPMd）及 ZIPX XZ；AES 标准 ZIP、ZipCrypto 数字卷、AES 标准 ZIPX；空文件/空目录、扁平重名与越界日期；顺序和实际工作线程并行解压；已确认 TAR.LZO 链接内容转换为校验后提交的密码 ZIP / ZIPX。相关旧日期回归 2 项通过（非法日期、闰秒处理）。
- 首次测试准备漏实现运行时 trait 方法，修正后执行。首轮 3 项通过，另 2 项暴露测试样本共用写入与分卷枚举参数问题；隔离样本、改用输出基名并观察实际工作线程后，只补查这两项。产品日期逻辑没有因此重改或重跑整套矩阵。
- 独立 Python 按原源文件/原 TAR 条目的日期与逻辑内容核对 13 份实际归档、71 个编码条目；直接解析本地头和中央目录（包含标准分卷 ZIP64 结尾），两处日期一致。由独立 7-Zip 提取后再核对文件内容与实际文件/显式目录日期；五份加密结果拒绝错误密码，原生顺序/并行输出再次按独立日期计算核对。
- ZIPX 标准卷沿原 `.zxNN/.zipx` 命名。外部 7-Zip 不自动识别此命名，本次独立读回使用字节不变的 `.zNN/.zip` 家族副本，实际归档头仍直接从原输出校对；未改分卷命名，也不据此增加外部工具兼容承诺。
- Shell DLL、八处版本身份与差异空白检查通过。UI 源码未改，沿用现有 UI/前端检查，不重做桌面控制、截图或无关格式矩阵。对应提交 CI/Release 负责正式前端/Windows 构建、安装器与签名更新附件。

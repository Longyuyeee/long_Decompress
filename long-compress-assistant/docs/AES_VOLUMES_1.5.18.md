# v1.5.18 自有 AES 容器数字分卷

2026-10-19，从已正式发布 v1.5.17 的 6f41d9e 接续。按现有三版路线进入第二项，分支 codex/v1.5.18-aes-volumes；v1.5.19 逐文件校验原因仍未开始，不重复规划。当前为开工审计，尚未封板或发布。

## 真实入口与交付范围

现有九种 .aes 输出已经使用 TARAES02/AESENC02，保留 V1 只读。普通 TAR/流数字卷的创建、整组 Seek/Read、暂存发布和失败纠正已经存在，本版复用。缺口是九格式前后端能力表禁分卷、路径校验再次拒绝加密分卷；AES 解密和魔数探测使用单文件 File::open/metadata，不能跨数字卷；外层 .001 还会影响内层文件名推导。自有 AES 浏览/预览和实际完整性入口需要接通原生路线，不能交给 7-Zip 猜读自有容器。

先以独立 Python cryptography 按既有容器布局生成原件，记录工具、原始内层与容器哈希，再固定旧版真实失败。加密字节不变，在完整容器外切数字卷，读取归一后以整组长度、连续数据和既有认证规则处理。整组认证和内层读取成功之后发布结果；缺首/中/尾卷、首段不能确认的密码或数据问题、后段已确认的认证失败各自说明，不把无法判断的错密/损坏冒称可以绝对区分。

接通压缩、浏览/有界预览、完整检查、所选/整包解压、转换与结果。只有认证完整的临时内层文件才交给已有格式读取器；保留单条展开、多选弹窗、自然继承、等宽详情与窄窗滚动。复用未受影响检查，只补相关容器/卷组及实际用户流程。

## 延续边界

这是 Long 自有容器数字切卷，不是通用 TAR 原生密码/分卷标准。V2 加密算法、Argon2 参数和默认开关不改；V1 有限只读兼容保持。数字卷未内嵌总卷数，缺尾需根据既有头部声明总长度发现，不猜未知卷数量。ALZ 方法 3、EGG 加密固实和真实 VHD 盘满补测仍未完成，不在本版顺带扩张。

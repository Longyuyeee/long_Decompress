# v1.7.37 规划 · 多帧 Zstandard ZIP 丢目录部分取回

状态：仅规划；接续 v1.7.36 单帧范围。普通 Zstandard ZIP 读写不等于已经具备多帧未知边界恢复，本期不增加格式数量。

已完成可行性探测：把 libarchive 原件中的两个实际非空 Zstandard 帧串为一个成员，按真实内容重算累计 CRC、压缩/展开尺寸和目录偏移，7-Zip 26.04 完整读回 208100 字节，SHA 与源内容拼接相同。另有非空帧后追加空帧的控制通过。两者都是明确标记的结构派生控制，不冒充独立生产者直接创建的多帧 ZIP；仅证明内容和结构可被独立工具读取，尚未接入恢复。见[探测证据](evidence/zip-zstd-rescue-1.7.36/next-nonempty-probe.json)。

1. 先固定来源、配方和独立读回，明确普通帧串联的成员边界。逐帧确认结束并累计实际消费量、展开量和 CRC，仅在准确位置匹配描述符；限制帧数与累计资源，不扫描正文签名猜测下一条。
2. 覆盖两个非空帧、空帧组合、普通/ZIP64 与有/无签名描述符、跨缓冲区和完整数字切片；后一帧损坏、截断或尺寸矛盾时，不把此前某一帧冒充该成员完整文件，只保留前面已确认的完整成员。
3. 可跳过帧先核对其独立来源、精确长度和累计范围，再决定是否同版交付；外部字典、历史 method 20 与密码未知边界继续另期。不跨缺卷缺口取回，不声称原清单已完整。
4. 继续复用新包验证、日期传递、结果/历史和失败重试。界面、单条展开、多选弹窗及等宽双栏保持；只检查新增和受影响流程。

完成标准：声明范围内的成员完整校验后可另存，前后成员边界、最终内容/路径及确认日期经独立读回；坏后帧不产生半个文件，原件不变，单帧和既有方法保持。

后续仍沿格式/算法、密码/分卷和流程容错主线；恢复记录修复、缺口后扫描、ALZ / EGG 外部原件与原生密码/块分段、更宽日期及 NTFS 亚秒等未完成项保留，不提前承诺支持。

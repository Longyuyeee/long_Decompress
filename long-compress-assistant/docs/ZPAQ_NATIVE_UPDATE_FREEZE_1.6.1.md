# v1.6.1 原生 ZPAQ 多部分另存更新

2026-10-22。本版已封板，进入正常 PR、Windows 打包检查与标签发布流程。

## 已实现

- 确认完整原生来源后，在原“ZPAQ 备份更新”入口另存完整原生新组，沿原单条展开、多选弹窗和自然继承。
- 私有目录内逐个复制旧部分，使用上游原生事务写入器追加一个真实新部分；沿用原密码、首部分盐和累计偏移，不把单包切片冒充事务。
- 检查完整新组和快照数量后发布全部部分；取消或发布失败回退本次移动的文件，清理私有暂存，不删除既有结果，不修改原组。
- 同路径内容更新、未选旧内容和全部历史保留；无变化时输出原部分的逐字节副本，不制造空事务。
- 草稿与历史恢复沿原确认来源，重新填写密码；失败后创建新任务，旧失败记录和成功结果保留。结果按实际顺序列出全部部分及快照变化。

## 定向依据

- 引擎研究：官方 7.15 与随附适配器，各自完成普通/密码三部分接第四事务，官方回解四个快照及哈希通过。四组合记录见 `engine-probe.json`；不重复生成旧原件。
- 新增 Rust 四项通过：普通/密码完整新组、四个快照独立官方回解、旧部分字节不变、无变化副本，以及错误密码、分卷误配、目标重名、晚出现的已有部分、复制取消、来源变化、纠正重试和超过 260 字符的来源记录路径。
- 因更新适配器入口有改动，定向接续一项原单包/数字卷回归，覆盖四种普通/密码输入输出组合，通过。
- 八项不同相关前端通过（四个文件）：原生来源输出与批量设置、紧凑配置/结果、原目录选择、既有增量配置，以及恢复时重识别原生模式和保留缺失更新来源提示。类型/Vite 构建通过，版本身份八处与版本化 Shell DLL 通过。
- 四条真实桌面流程通过：单条展开/多选弹窗、草稿恢复与重新填密码、普通新组与错误密码失败、补密码历史重试和完整产物。两种新组均由官方工具回解并比对全部文件哈希，原部分不变、旧失败保留、私有暂存清理。八条宽窄布局通过，八张界面均已实看。见 [本版证据目录](evidence/zpaq-native-1.6.1/)。

首次测试命令没有限制到 lib，导致编译无关旧集成测试并耗尽内存；改为 `cargo test --lib -j 1 ... zpaq161` 后通过。本轮未修无关旧集成测试，也未以其失败否定或宣称整个项目测试通过。

实机发现并修正两处：草稿恢复需在打开配置前重新识别来源；Windows 深目录下，来源记录的临时文件和发布目标均需使用规范化的扩展路径。独立小程序复现普通临时路径发布失败、规范化后成功，新增长路径 Rust 项通过。只接续受影响流程；本地最后实机候选使用应用包 `opt-level=1`，正式 CI 与 Release 保持默认发布优化。已通过的布局/恢复步骤保留原程序身份，未重跑；身份接续记录在桌面 JSON 中。

Release 流水线现从 `RELEASE_NOTES_<版本>.md` 读取中文正文，发布页面与更新清单沿同一正文生成，避免自动生成的提交列表覆盖说明。仅改变说明来源与生成方式，签名和安装包流程保持。配置依据见 [tauri-action 官方输入文档](https://github.com/tauri-apps/tauri-action/blob/v0/README.md#release-configuration)。

## 边界

新组以 `组名.part1.zpaq` 起连续编号，完整分享所有部分即可独立读取。原生部分按事务生成，不指定 MiB 大小；普通单包/数字卷更新保持原输出能力。发布是可回退的多文件提交，不声称文件系统原子多文件事务。

运行时核对当前快照内容与历史目录/数量；旧部分直接复制保留，不把逐个回解全部历史作为每次更新的额外成本。独立四快照回解用于本版新组合的互通依据。

仅完整日志式来源；不做流式更新、原地追加、改密、删除同步、远端索引或损坏事务抢救。现存文件名仍无法证明未知尾部是否丢失，来源成员由用户确认；已记录成员缺失或发生变化会拒绝。读取能力沿 v1.5.64，v1.6.0 全页面 UI、托盘、更新和主题检查沿用，未重跑旧格式、盘满和个人安装矩阵。

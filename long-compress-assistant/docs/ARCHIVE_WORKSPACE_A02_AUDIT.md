# 归档工作区 A-02 审计：归档内右键菜单

审计日期：2026-08-26

版本基线：Long解压 `1.1.13`

结论：A-02 的交互框架与当前可安全执行的动作已完成；大节点 A 未收口，不升版本、不打包、不发布 Release。

## 1. 目标与实现边界

本步骤让归档工作区具备符合 Windows 文件管理习惯的对象化右键操作，同时保持归档只读并复用已有安全解压事务。

| 对象 | 已提供动作 | 选择语义 |
| --- | --- | --- |
| 空白区 | 对当前已选文件解压、复制、详情、刷新 | 不改变选择 |
| 单文件 | 有界图片内部查看、当前/指定目录解压、复制名称/路径、详情、刷新 | 右键未选项只聚焦该项 |
| 多文件 | 批量解压、复制名称/路径、批量详情、刷新 | 右键已选项沿用既有多选 |
| 文件夹 | 打开、递归解压内容、复制文件夹名称/路径、详情、刷新 | 详情/复制针对文件夹本身，解压针对其内容 |

以下动作未伪装成已完成能力：

- 文件交给 Windows 默认应用打开：由 A-03 的规范化路径、会话缓存、Mark-of-the-Web、可执行文件确认和 TTL 清理完成后注册；
- “进入压缩包”：由 A-05 的嵌套预算、深度限制和归档链完成后注册；
- 新建、重命名、删除、剪切、粘贴和直接修改当前归档继续不支持。

## 3. 真实测试：预期、实际与修正

### 3.1 Windows 系统剪贴板

- 预期：复制中文八层长路径后，Windows 系统剪贴板与归档内路径逐字一致。
- 首次实际：测试在 WebView2 内调用 `navigator.clipboard.readText()` 时权限请求不返回，门禁等待。
- 修正：不扩大产品的剪贴板读取权限；测试进程改为读取 Windows 系统剪贴板。
- 第二次实际：路径已写入，但 PowerShell 传统输出代码页把中文显示为乱码，逐字比较失败。
- 修正：门禁固定 PowerShell 输出为 UTF-8。
- 最终实际：中文目录与文件名逐字一致，门禁通过。

### 3.2 右键选择性解压

- 预期：在搜索结果中只选择 `保留文件.txt`，从右键菜单启动解压；目标文件内容一致，`不应解压.txt` 不落盘。
- 实际：真实 Release Tauri/WebView2 调用正式解压 IPC，任务状态为 `completed`，`selectedEntries` 仅含目标中文长路径，实际产出 61 字节；目标内容一致，排除项不存在。
- 修正：无产品偏差。

### 3.3 加密格式回归

- 预期：新增右键交互不得破坏原有加密 7Z/RAR 浏览和精确解压。
- 实际：现场生成的文件名加密 7Z 使用手动密码完成单项解压；固定上游加密 RAR 完成 `foo.txt` 单项解压并保持固定 SHA-256，排除项均未落盘。
- 修正：无产品偏差。

### 3.4 视觉与响应式

- 预期：菜单在窗口边缘内定位，详情弹窗使用不透明表面，长中文路径换行且无横向滚动。
- 首次实际：可见截图显示菜单实际高度会受应用缩放影响，高于用于定位的固定估算值；靠近窗口底部时存在被裁切风险。
- 修正：菜单渲染后读取真实宽高，再将四边夹紧到当前视口；响应式门禁新增四边界坐标断言。键盘对文件夹的详情/复制最初也沿用了递归内容集合，与鼠标菜单语义不同，现已改为详情/复制文件夹本身，仅解压递归内容。
- 最终实际：Chromium 四档尺寸与真实 WebView2 均通过；可见截图为 `test-results/desktop-e2e/archive-browser-a02-context-menu.png` 和 `archive-browser-a02-entry-details.png`。

## 3. 当前阶段：原生 ZIP 真实字节遥测

### 开发目标

1. 普通 ZIP 和 AES-256 ZIP 在读取源文件时累计真实输入字节。
2. `task-progress` 使用真实 `processed_bytes/total_bytes`，由既有后端统一计算速度与 ETA。
3. 目录条目不计入载荷字节；空文件和总量为 0 时不展示伪造速度。
4. 取消、原子发布、校验、删除源文件和密码语义保持不变。

### 真实验收矩阵

| 场景 | 测试载荷 | 预期证据 | 当前基线（修复前） |
| --- | --- | --- | --- |
| 普通 ZIP | 至少 32 MiB 非空文件 | 中间事件 `0 < processed < total`；最终 `processed = total = 源文件字节数`；解压后 SHA-256 一致 | 进度事件存在，但字节字段为 0，速度/ETA 缺失 |
| AES ZIP | 至少 32 MiB 非空文件和固定测试密码 | 同上；空密码/错误密码失败，正确密码解出内容哈希一致 | 只有完成事件，字节字段为 0 |
| 多文件 ZIP | 大小不同的多个非空文件 | 字节单调递增，总量等于所有普通文件大小之和；当前文件名随输入切换 | 仅按文件数跳变，不能反映大文件内部进度 |
| Windows Release 可见桌面 | 从压缩中心真实创建 ZIP | UI 在任务执行期间出现非空速度和 ETA，最终归档经独立 7-Zip 测试与内容比对 | v1.1.6 桌面门禁只证明 7Z 路线的真实速度/ETA |

### 收口条件

- Rust 真实载荷测试、前端事件消费测试、Windows Release Tauri + WebView2 可见桌面测试全部通过。
- 记录修复前后差异，不能只报告“测试通过”。
- 完整单测、Clippy、生产构建通过；阶段结束后审计变更范围并推送独立提交。

### 2026-08-20 实施与真实结果

- 修复前代码路径的实际事件为：普通 ZIP 只在文件结束时按文件数推进，AES ZIP 只在完成时推进，两者 `processed_bytes/total_bytes` 均为 `0/0`，因此速度和 ETA 为空。
- 修复后普通 ZIP 与 AES ZIP 均在读取源文件时累计真实输入字节，以 4 MiB 为中间事件间隔，并在文件边界发出真实累计值；目录和空文件不伪造字节。
- 首轮 Windows Release 门禁实际发现：引擎的最终真实事件正确，但随后 `Finalizing` 阶段的 `0/0` 占位事件会覆盖前端已记录的总量和 ETA。前端现仅在事件提供非零真实总量或明确 ETA 时更新这些字段，并增加集成回归。
- 聚焦 Windows Release + WebView2 门禁最终通过：普通 ZIP 与 AES ZIP 各使用 64 MiB 随机非空载荷，均出现 `0 < processed < total` 的中间事件和 `67,108,864 / 67,108,864` 的最终真实字节，可见面板显示速度与 ETA；另以 24 MiB + 40 MiB 双文件验证累计字节单调且总量等于两文件之和。三份归档的独立 7-Zip 完整性测试通过，AES 错误密码被拒绝，所有解出文件的 SHA-256 与源文件一致。
- 验证命令：`npm.cmd run test:e2e:desktop:zip-telemetry`。综合归档门禁仍保留 ZIP 场景；本次在系统并行构建高负载下曾出现一次 WebView2 renderer 断开，因此新增聚焦门禁用于可靠复验本阶段，不把环境崩溃误写成产品通过或产品失败。
- 全量回归：前端 33 个测试文件、200 项测试通过；Rust 234 项通过、1 项固定机器性能基线按设计忽略；`cargo clippy --lib -- -D warnings`、普通生产构建和隔离桌面 Release 构建通过。

## 4. 后续顺序

1. TAR 系列使用有界计数读取器接入真实字节；先证明元数据、长路径和取消语义不回退。
2. 外部 CLI 路线研究实际落盘字节观测；如果只能得到百分比，继续只显示进度，不显示速度/ETA。
3. 在可证明 HDD 或网络位置补充固定规模矩阵，之后才设计任务级调度实验。
4. 为 HFSX 寻找可重复生成已知非空载荷的可信方案；未满足前维持未完成声明。

# Long解压开发审计（2026-08-20）

## 1. 基线与结论

- 审计基线：`master@0694fac`，公开版本 `v1.1.6`。
- `v1.1.6` 的 GitHub CI 与 Release 工作流均已通过；安装包、updater ZIP、签名和 `latest.json` 四项资产齐全。
- P0 主流程已经收口：密码候选由后端状态机统一执行；压缩/解压支持有界并发与同输出互斥；7Z 固实、ZIP 分卷能力声明、密码格式转换确认、取消和安装态恢复都有真实证据。
- 下一阶段不应继续扩充格式名称，而应补齐现有高频路径的可观测性、长期性能证据和仍未闭环的真实格式样本。

## 2. 预期效果与当前实际差距

| 优先级 | 现有能力 | 预期效果 | 当前实际效果 | 差距与处理原则 |
| --- | --- | --- | --- | --- |
| P1 | 任务进度、速度与 ETA | 高频压缩路线展示由真实处理字节计算的速度和剩余时间 | 原生 7Z、单流格式已有真实字节；普通 ZIP、AES ZIP、TAR 系列仍以文件完成数更新进度，字节字段为 0 | 先补普通/AES ZIP 的输入字节回调；不得用百分比乘总量伪造字节 |
| P1 | 压缩包浏览与图片预览 | 支持的预览必须内存有界、类型可信且不留临时文件 | ZIP/TAR 图片预览已闭环；7Z 固实块与当前 RAR 读取无法证明严格有界，按设计禁用 | 继续保持禁用，只有引擎提供可证明的单条目读取预算后再开放 |
| P1 | 自动更新与安装恢复 | 发布前验证升级、数据保持、菜单迁移、失败恢复 | v1.1.6 已有 43 项无签名安装态验证，但仍依赖本机/候选环境执行 | 后续接入可控 Windows self-hosted runner；不能用仅构建成功代替安装态证据 |

| P2 | 完整格式声明 | 每个公开格式都有非空已知载荷的真实解压与内容比对 | 常用归档和多类磁盘镜像已闭环；HFSX 仍缺可信已知载荷生成方案 | 保持“未完成”，禁止用空镜像或仅魔数识别冒充支持证明 |

## 3. 当前阶段：原生 ZIP 真实字节遥测

### 开发目标

1. 普通 ZIP 和 AES-256 ZIP 在读取源文件时累计真实输入字节。
2. `task-progress` 使用真实 `processed_bytes/total_bytes`，由既有后端统一计算速度与 ETA。
3. 目录条目不计入载荷字节；空文件和总量为 0 时不展示伪造速度。
4. 取消、原子发布、校验、删除源文件和密码语义保持不变。

### 真实验收矩阵

| 场景 | 测试载荷 | 预期证据 | 当前基线（修复前） |
| --- | --- | --- | --- |
| 普通 ZIP | 至少 32 MiB 非空文件 | 中间事件 `0 < processed < total`；最终 `processed = total = 源文件字节数`；解压后 SHA-256 一致 | 进度事件存在，但字节字段为 0，速度/ETA 缺失 |
| AES ZIP | 至少 32 MiB 非空文件和固定测试密码 | 同上；空密码/错误密码失败，正确密码解出内容哈希一致 | 只有完成事件，字节字段为 0 |
| 多文件 ZIP | 大小不同的多个非空文件 | 字节单调递增，总量等于所有普通文件大小之和；当前文件名随输入切换 | 仅按文件数跳变，不能反映大文件内部进度 |
| Windows Release 可见桌面 | 从压缩中心真实创建 ZIP | UI 在任务执行期间出现非空速度和 ETA，最终归档经独立 7-Zip 测试与内容比对 | v1.1.6 桌面门禁只证明 7Z 路线的真实速度/ETA |

### 收口条件

- Rust 真实载荷测试、前端事件消费测试、Windows Release Tauri + WebView2 可见桌面测试全部通过。
- 记录修复前后差异，不能只报告“测试通过”。
- 完整单测、Clippy、生产构建通过；阶段结束后审计变更范围并推送独立提交。

## 4. 后续顺序

1. 原生 ZIP/AES ZIP 真实字节遥测。
2. TAR 系列使用有界计数读取器接入真实字节；先证明元数据、长路径和取消语义不回退。
3. 外部 CLI 路线研究实际落盘字节观测；如果只能得到百分比，继续只显示进度，不显示速度/ETA。
4. 在可证明 HDD 或网络位置补充固定规模矩阵，之后才设计任务级调度实验。
5. 为 HFSX 寻找可重复生成已知非空载荷的可信方案；未满足前维持未完成声明。

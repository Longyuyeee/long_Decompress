# v1.7.2 · LZOP 多成员创建与转换记录

状态：功能封板完成，接续正式合并与发布。版本身份 1.7.2，分支 `codex/lzop-multimember-172`，日期 2026-10-27。

## 实现与用户流程

一个或多个普通文件可创建为独立 LZOP 成员序列。创建前完整规划成员，按大小写不敏感规则为重名编号；目录、空来源和多成员超长名称在输出创建前停止，提供 TAR.LZO 替代提示。单文件旧有超长名称回退策略保留；不截短多成员名、不丢文件夹。

每个成员使用独立有界 LZO1X 编码，统一累加进度，复用输出暂存、校验和失败清理。采样按文件重置编码器。原单条展开、多选弹窗、自然继承和左右等宽保留；对含目录任务禁用 LZOP，工作流原有目录打包边界不变。来源密码与输出配置分开，多顶层文件可以转换，含目录明确拒绝并保留原包。

## 独立互通依据与实际发现

[官方手册](https://www.lzop.org/lzop_man.php)定义多输入 `-o` / `-c` 为独立成员序列。已下载 [官方 1.04 源码](https://www.lzop.org/download/lzop-1.04.tar.gz)，SHA256 `7e72b62a8a60aff5200a047eea0773a8fb205caf7acbe1774d95147f305a2f41`，核对名称与成员标记。官方读取会拒绝名称中的单独点分量；旧写入的 `./文件名` 在逐文件回解时出错，本版新写入改为直接的相对文件名。

新产物带 multipart 提示、默认文件名及 UTF-8 标记。官方 Windows lzop 1.03 全量测试通过；官方 Linux lzop 1.03 在已有 Ubuntu WSL 中按独立文件完整恢复，核对名称、大小和 SHA256。Linux 可执行下载地址和身份见回执；不安装新运行时、不将外部工具加入发布包。

老 Windows lzop 的 ANSI 文件接口不按 UTF-8 标记转换磁盘名称，因此中文名会乱码；这项限制在原格式问号和 Release 说明中明确。Long解压自身及官方 Linux 名称核对通过，不把串联 stdout 的内容哈希充当逐成员名称验收。

## 已通过检查

- 新增 Rust 三项：九成员新建与 255 字节名称/重名/中文/空文件/图片/不可压缩数据，单文件改名和全空成员；列表、图文预览、全成员校验；有损请求预检、实际多成员采样；后续成员取消、暂存丢弃与重试。
- 前端八项：能力入口与来源密码转换四项、批量弹窗及普通文件组合/目录拒绝两项、配置面板来源限制两项。新面板测试初轮误查原生 disabled 属性，改为组件实际使用的 aria-disabled 后，两项单独通过；没有重跑其他成功项。
- Vue / TypeScript 与 Vite 构建通过。桌面测试桥扩展为多来源时，类型检查发现内部 Task 没有 sourcePaths 字段，移除该多余赋值后接续构建。Shell 扩展和版本身份核对通过。
- 六组全新原生/桌面产物经过官方 Windows 全流检查与 Linux 逐文件回解，全部名称和内容一致；初轮三组结果按产物及工具 SHA 复用，只接续三组桌面新产物；见 [独立回执](evidence/lzop-multi-create-1.7.2/official.json)。

- 真实 WebView2 四组流程通过：原界面合并多文件并创建/分析/批量配置/结果历史、原等宽双栏图文预览及选取空文件、密码 ZIP 多文件转入和转回 7Z/含目录明确停止与 TAR.LZO 重试、后续成员活动取消与再次创建。数据均走实际原生后端。1100×650 与 760×520 六张截图逐张实看，无横向溢出，双栏等宽、弹窗在窗口内。

## 保留边界与下一步

LZOP 不表达独立空目录，目录继续使用 TAR.LZO。未新增原生密码、创建分卷、原生块分段或缺卷救援；既有完整数字卷读取保留，格式数不变。多成员序列没有成员总数字段，不保证发现完整成员连同后续内容一起被删去的情况。ALZ / EGG 外部原件缺口保持开放。

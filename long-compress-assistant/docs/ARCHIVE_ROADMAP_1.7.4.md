# v1.7.4 规划 · LZOP 完整成员部分取回

状态：功能封板（2026-10-27），接续正式合并与发布。接续 v1.7.3 数字分卷创建，继续处理缺卷、截断等真实失败场景。

## 用户目标

多文件 LZOP 的后半段损坏或缺失时，让用户明确知道哪些文件仍能取回，并单独保存已完整解码且通过校验的成员。原有正常解压仍要求全量成功，不能把部分结果标成“解压完成”。

## 实施顺序

1. 先确认 LZOP 成员边界、结束标记和头/块校验的可证明范围。以完整前缀成员为首期，不扫描缺中间卷之后的任意字节来猜成员；优先覆盖未分卷截断及从 .001 连续存在的数字卷前缀。
2. 后续成员损坏或缺尾卷时，给出可取回成员、失败位置和原因。只有成员完整结束、所需头/数据校验通过后才进入结果；无校验来源不宣传为“验证完好”。截断成员不发布半文件，空文件仍需有效完整成员。
3. 沿原失败任务的救援入口打开二级确认，默认保存到独立目录，展示“部分取回”和实际数量；保留原包、已存在结果及重名处理。普通列表、预览和完整转换的成功标准不降低。
4. 接通所选救援、取消清理、结果位置与历史。补齐原卷后沿原流程重新完整解压；部分结果不能静默参与全包转换或覆盖已有文件。
5. 只检查新恢复链：坏头/坏数据/截断/缺尾卷、前一个成员跨卷、空文件、重名、取消及补卷重试；独立读取器核对成功成员的名称和内容，实际检查宽窄窗口和原交互。

## 本期边界

不同时扩展 TAR.LZO 的内部 TAR 条目救援，不新增原生密码、LZOP 原生块分段，也不承诺缺中间卷后的任意扫描恢复。序列没有成员总数或总卷数，无法从完整剩余内容证明后面是否原本还有完整成员。若没有完整且可验证的成员，明确说明没有可确认的恢复结果。

后续再分期评估 TAR.LZO 完整条目救援、更多编码算法和真实失败包兼容。ALZ / EGG 的外部原件缺口继续保留，不能由自造样本代替。交互继续遵循单条展开、多选弹窗、自然继承、左右等宽、次要信息收纳。

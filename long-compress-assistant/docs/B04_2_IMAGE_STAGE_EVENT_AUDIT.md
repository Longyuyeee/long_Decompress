# B-04.2 图片真实阶段事件审计

审计日期：2026-08-28（Asia/Shanghai）

开发分支：`codex/archive-media-roadmap`

公开基线：`v1.1.14`；本节点不升版、不生成 Release、不启用图片执行按钮。

## 1. 开发目标与边界

B-04.2 为图片后端建立可验证的解码、条件缩放、编码、验证和发布阶段，并将这些阶段映射到现有统一 `task-log` 事件。阶段必须对应真实执行边界；当前编码器没有可信字节回调，所以本节点不发送 `task-progress`，不生成百分比、速度或 ETA。

本节点不实现前端批量调用、目标冲突编排、完成/失败/取消历史和结果 UI。上述工作仍属于 B-04.3 至 B-04.5。

## 2. 预期、实际与修正

| 检查项 | 预期 | 修改前实际 | 本次修正与真实复核 |
| --- | --- | --- | --- |
| 阶段来源 | 阶段由实际 Rust 执行路径产生，可脱离窗口测试 | 图片服务没有阶段观察边界，命令也不发图片日志 | 新增纯 Rust `ImageCompressionStage` 与观察器；原单图入口保留并以空观察器兼容现有调用 |
| 统一日志 | 图片阶段进入现有任务日志，不复制日志 store | `compress_image_file` 不接收窗口且不发 `task-log` | Tauri 命令接收注入的 `Window`，在阻塞工作线程回调中发送现有 `TaskLog`/`Info` 事件 |
| 缩放真实性 | 只有可见尺寸确实变化才记录缩放 | 首稿设计需确认“方向归一/格式转换”是否应算缩放 | 真实方向 JPEG 转 PNG 的可见尺寸不变，实际序列不含 `resizing`；限制到 `180×320` 时才出现该阶段 |
| 发布真实性 | 未发布时不能记录发布 | 默认流程无法表达阶段，结果不更小与发布在日志上不可区分 | WebP“仅在更小时”真实候选不更小，序列停在 `validating`，目标不存在且无 `publishing` |
| 失败与取消 | 只记录已经真实进入的阶段 | 没有可审计序列 | 预取消不产生阶段；GIF/无效图片只产生 `decoding` 后失败；不会补齐未执行的后续阶段 |
| 进度诚实性 | 无可信字节回调时不发数值进度 | 若复用归档 `task-progress`，必须填写数值并可能被 UI 当成百分比 | 图片命令只发 `task-log`；架构门禁静态拒绝在该命令边界加入 `task-progress` |

## 3. 真实图片验证

本次继续使用 B-04.1 已锁定哈希的真实文件，而不是内存假对象：

- `exif-orientation.jpg`：同格式、转 PNG、真实方向 6 与按可见尺寸缩放；
- `transparent.png`：无损 PNG 与转 JPEG Alpha 边界；
- `photo.webp`：仅在更小时策略、预取消和不发布暂存清理；
- `animated.gif`：真实不支持格式在解码阶段失败。

实测阶段序列：

| 场景 | 实际序列 | 输出事实 |
| --- | --- | --- |
| 无缩放 PNG | `decoding → encoding → validating → publishing` | 发布成功 |
| 方向 JPEG 转 PNG、尺寸不变 | `decoding → encoding → validating → publishing` | 方向归一为 1，可见尺寸保持 `360×640` |
| 方向 JPEG 限制到 `180×320` | `decoding → resizing → encoding → validating → publishing` | 输出可见尺寸为 `180×320` |
| WebP 候选不更小 | `decoding → encoding → validating` | 不发布目标、不记录发布 |
| 预取消 | 无阶段 | 不创建目标或暂存 |
| GIF 拒绝 | `decoding` | 解码拒绝，不创建目标 |

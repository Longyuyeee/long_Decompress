# v1.6.5 ALZ Bzip2 压缩流完整性（已封板）

2026-10-22 从 v1.6.4 接续。原计划 ALZ 方法 3 已完成一轮来源调查，仍缺真实方法 3 原包，保留在 [来源记录](ALZ_METHOD3_SOURCE_1.6.5.md)，不宣称实现。按既定格式、密码、分卷与容错方向，本版改为修复已经复现的 ALZ Bzip2 完整性缺口，避免只反复取材和空发版本。

## 已复现的用户问题

复用 v1.5.2 固定的 CC0 原件 `bzip2.alz`，单独派生两种故障：条目压缩范围内追加 5 字节；保留完整载荷但移除结束标记。声明展开大小及 CRC 不变，旧 helper 两者均返回 verified=true。用户因此可能把不完整或混入额外数据的包当作检查、解压和转换成功。原件不修改，派生件不作为原工具互通依据。

## 实施与封板范围

1. Bzip2 解码必须读到合法结束标记，且声明压缩范围只能余下不足一个字节的对齐位；额外完整字节拒绝。遵守声明输入边界，短读和输出 I/O 原因保留。现有 256 MiB 单条压缩输入上限保持，方法 3 不开放。
2. 大小和 CRC 完整匹配后发现终止异常，给出确定损坏与重新获取原包的提示；仅短密码头或内容未匹配时保留不确定错误，不反复把确定损坏当作待试密码。
3. 沿原检查/诊断、所选/整包解压、转换及失败新任务/历史接通；不发布半成品，不覆盖旧结果。保留单条展开、多选弹窗、左右等宽及双栏浏览器结构，不新增常驻说明区。
4. 只补本次结束、尾随、输入边界、短读、密码状态和 I/O 的有意义回归，以及真实用户失败/重新获取后新任务和必要宽窄显示。已有方法 2、旧格式、安装/盘满矩阵不重跑。
5. helper、锁定哈希、许可修改记录、版本身份、两份 README、中文 Release 和交接同步后按正常 PR/标签正式发布。

五项 Rust（解码器四项、应用服务一项）、普通构建与版本身份通过；五项桌面记录与四张宽窄实看完成，见 [封板记录](ALZ_BZIP2_INTEGRITY_FREEZE_1.6.5.md)。只接正常 PR/标签发布，不重复已过检查。

# v1.6.37 已完成功能封板 · Deflate 固实大文本开头预览

已完成，见[封板记录](SEVENZ_SOLID_DEFLATE_PREFIX_FREEZE_1.6.37.md)；下一版[Deflate64 普通完整图文](ARCHIVE_ROADMAP_1.6.38.md)仅规划。接续非固实大文本，让共享 Deflate 数据块中的后续大日志也能先查看开头，继续格式、密码/分卷与容错主线。

1. **普通固实大文本**：新增独立部分共享读取入口，确认唯一所选普通条目、完整共享映射/顺序/条数/总量，流式跳过所选前置内容，只保留最多 1 MiB 开头。前置依赖与所选开头合计 ≤64 MiB，不分配整个共享块；发现开头前损坏、已知提前结束或声明不符时给提取下一步。
2. **密码与数字卷**：有序 AES → Deflate 载荷沿显式部分 AES；内容/文件名加密、手动密码/保险箱、完整数字卷与非首卷贯通。完整目录头等已创建的完整 AES 流仍须完成消费，手动错误不回退，预览不记整包密码成功。
3. **清楚表达范围**：沿原只读文本窗口、编码/滚动与提取全文，明确“仅开头、未校验整文件”；前置依赖、文件 CRC、未读尾部和整包密码都不能被称为完整校验。保留实际输入、参数、整体时间、取消/来源绑定，已完成的固实完整小图文读取不放宽。
4. **一次收尾**：原版工具样本由另一版本独立回解，确认首个/后续大文本、前置+开头精确边界、普通/密码与完整数字卷、取消/来源及原窗口宽窄显示。只补新接通和受影响连续性，完成后同步 README、Release、能力表与交接并发布。

随后分阶段接续 Deflate64（先普通非固实完整图文，再密码/分卷、共享与大文本），不将不同能力合成一个过大的版本。ALZ 方法 3、历史 Bzip2/原工具图片及 EGG 加密固实维持有效外部原件条件，不为空取材单独发版。保留单条展开、多选弹窗、50/50 双栏、主题/工具与问号收纳，不增加首页配置区。

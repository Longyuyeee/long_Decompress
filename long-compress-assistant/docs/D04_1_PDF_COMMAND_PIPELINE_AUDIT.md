# D-04.1 PDF 产品命令管线审计

审计日期：2026-08-31

开发基线：`master` / `2b7045e3bd892a776b2f707ccb21c5b9727d447f`

开发分支：`codex/pdf-d04-product-execution`

## 1. 节点结论

D-04.1 已把 D-03 的内部安全发布事务接成单一 Tauri 产品命令，但没有提前宣称 D-04 或 `v1.1.17` 完成。产品命令在每次执行时重新核验固定 qpdf 身份并重新分析源 PDF，复用现有压缩任务的进程级取消注册表，依次报告 `Transforming`、`Validating`、`Publishing` 三个可验证阶段，最终只返回校验并原子发布后的文件系统事实。

本节点仍不创建任务、不写历史，也没有把批量执行按钮接入 PDF 工作区。下一接续点严格为 D-04.2：使用现有统一任务/历史模型完成前端批量、取消、失败、结果事实和默认 PDF 阅读器闭环。D-04.3 还需完成真实内容矩阵与正式安装态矩阵；两步都关闭前不得提升 `1.1.17`。

## 2. 原始需求对齐

| 原始边界 | 实际实现 | 审计判断 |
| --- | --- | --- |
| 不建立媒体旁路任务系统 | PDF 命令复用 `compression.rs` 的共享取消注册表；任务创建仍留给统一前端任务层 | 对齐 |
| 默认新文件且不覆盖源文件 | 新增目标规划器，按模式生成后缀，并处理保留目标与冲突自动改名 | 对齐 |
| 执行前重新验证真实输入 | 命令重新核验打包 qpdf，并重新分析源文件，而非信任页面草稿 | 对齐 |
| 只有可验证阶段，不显示伪百分比/ETA | 只发送转换、验证、发布三个事实阶段 | 对齐 |
| 变大结果默认拒绝，但用户可明确保留 | 默认仍由验证层拒绝；只有产品请求显式设置 `allowLargerOutput` 才允许发布 | 修复了此前只实现“默认拒绝”而遗漏“显式保留”的需求偏差 |
| 签名默认只分析；加密不得泄露凭据 | 签名/加密执行仍由重新分析阻断；没有把密码放进产品执行请求或命令行 | 对齐；加密执行仍未获支持，不得由 UI 冒充可执行 |
| 成功必须代表已校验并安全发布 | 产品命令直接调用 D-03 已审计事务；转换、候选验证、源/候选复核、Mark-of-the-Web 和同目录原子发布不可拆开 | 对齐 |

## 3. 代码事实

- `commands/pdf_engine.rs` 新增 `plan_pdf_optimization_destination` 与 `compress_pdf_file`。请求只包含源、目标、白名单模式、有损确认、Mark-of-the-Web 策略和显式保留较大结果；不接受原始 qpdf 参数。
- `services/pdf_publish.rs` 增加阶段观察入口，同时保留原有默认拒绝较大输出的内部调用，避免测试或其他调用者静默改变策略。
- `services/pdf_output_validation.rs` 将显式保留较大结果限制在参数化验证入口；结构、页数、加密、表单、注释、书签和附件验证没有放宽。
- `commands/compression.rs` 只将既有取消注册能力收窄为 crate 内复用，没有复制第二份全局取消状态。
- 产品合同现标记 D-04.1：执行命令已开放，任务创建仍为 false；媒体架构门禁同步检查上述边界。

## 5. 开发中发现并处理的问题

1. 首轮编译暴露旧测试仅在测试配置下需要默认验证入口；已把导入限定到测试配置，生产代码保持无未用导入。
2. 严格 Clippy 报告阶段观察闭包冗余；已改为直接传递观察器，不屏蔽规则。
3. 仓库级 `cargo fmt --check` 暴露大量早于本节点的无关格式债务。本节点只格式化实际修改的 Rust 文件，避免把大范围机械变化混入功能提交；该历史债务不伪装为本节点新增失败。
4. 完整媒体夹具与图片专用夹具共用被忽略目录，并行运行会互相清理 PDF 文件。真实 PDF 门禁改为串行执行；不能把测试夹具竞争误判为产品失败。

## 6. 严格接续点

1. D-04.2 在 PDF 工作区接入统一任务：批量顺序执行、共享取消、失败状态、发布后输入/输出字节与页数、终态历史持久化。
2. 默认不保留变大结果；只允许用户通过清晰警告显式选择保留。签名和加密报告继续禁止执行。
3. 接入系统默认 PDF 阅读器打开已发布结果，并增加 Rust、前端和真实桌面门禁。
4. D-04.2 独立审计、提交、推送、CI 合入后，再执行 D-04.3 的文本/扫描/混合/中文字体/透明、结构边界、大页数/大图片和正式安装版批量矩阵。
5. 只有 D-04.3 关闭，才允许把三个版本源提升到 `1.1.17`，随后打包、安装态验收、更新 README/Release Notes、发布 GitHub Release 并回下载验证公开资产。

# v1.7.30 · TAR.LZO 前向链接内层包浏览封板

日期：2026-10-29。

## 用户行为与实现

完整 TAR.LZO 中链接目标在后方的内层压缩包副本，可以沿原双击、Enter 和右键“进入压缩包”继续打开。复用既有完整条目计划，移除嵌套物化阶段的前向引用限制，所选副本按独立文件放入原会话缓存；原目标不需要同时选中。普通头、GNU 长名称、局部 PAX 及完整数字分卷均按真实内容确认，不依据副本扩展名就认定成功。

浏览、图文预览、精确所选文件取回及内层独立密码沿原入口。三层、单文件 64 MiB、会话 256 MiB / 64 份限额保持。源版本和卷组状态检查、所选内容完整 SHA、层级/祖先身份、取消及失败清理继续使用既有路径；没有扩大部分抢救范围，也没有创建系统链接。

前端和 UI 源码没有改动。现有同栏导航、返回、选择、滚动位置与另一栏状态沿用 v1.7.23 已交付的交互；本期不重做同一套前端测试与截图，不把后台原生检查说成新一轮真实 UI 验收。单条展开、多选弹窗和等宽双栏保持。

## 原件与检查

- 新建三组 GNU tar 1.35 生产者原件：项目自编 ZIP（含文本、PNG 和第三层 ZIP）、官方 7-Zip 26.04 生成的文件名加密 LZMA2 7Z，以及伪 ZIP。真实 Linux 硬链接先经 GNU 创建，再删除内容记录、拼接 GNU 创建的后置目标，没有手写或改写归档头。固定 SHA 的 lzop 往返确认；两次有序 GNU 提取核对内容和 inode，Python 独立解析内容及各自日期。
- 新原生 4 项通过。成功流程取得 10 份第二层内层包，含 USTAR / GNU / PAX、GNU 长自身/目标名称、两组末卷进入的完整数字来源；内层 ZIP / 加密 7Z 浏览、文本及 32×24 PNG 预览、20 个精确所选文件取回正确，错误密码被拒绝。6 份 ZIP 可继续进入第三层并预览文字，第四层仍拒绝。
- 来源旧版本、复制期间变更/取消和注入错误 112 保留原包、清理本次缓存；伪 ZIP、坏尾、缺卷与深度不符不留下结果。普通非链接文件在含前向链接的外层包中仍走原提取回调，身份哈希可取消。错误 112 为受控注入，未重做真实盘满检查。
- 首轮 3 项通过，成功流程的测试直接在异步线程调用同步 ZIP 解压，触发运行时嵌套限制；测试改为与正式服务相同的后台阻塞线程调用，仅补跑这一项。产品物化流程没有为此另加分支。
- 相关旧 2 项通过：前向文本伪装为压缩包时到达真实格式检查并清理缓存；原普通/后向嵌套回退和哈希取消。旧“前向一律拒绝”的断言改为实际内容确认，没有重跑无关矩阵。
- 独立 Python TAR 读取与外部 7-Zip 核对 10 份物化内层包、6 份第三层包及 20 个原生所选文件，确认真实字节、预览 SHA、副本自身时间、原件保持和会话结束清理。数字源独立拼回原件，原始路径和结果见证据。
- 当前 Shell DLL、八处版本身份及差异空白通过。正式前端/Windows 构建、安装器和签名更新附件由本版 CI/Release 接续；没有控制桌面或修改系统时区/关联。

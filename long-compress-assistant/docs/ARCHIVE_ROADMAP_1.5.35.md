# v1.5.35 ZIP PPMd 创建与流程接续

2026-10-21，接续已发布v1.5.34。本版按下方顺序完成，功能封板进入发布；完成情况与外部工具差异见[实施](ZIP_PPMD_1.5.35.md)、[封板](ZIP_PPMD_FREEZE_1.5.35.md)和[证据](evidence/zip-ppmd-1.5.35/)。原计划保留，不把后续版本计入完成条件。

## 用户要解决的问题

在常用ZIP中为文本、资料归档提供PPMd这一可选方法，保留默认兼容Deflate、Zstandard、BZip2和既有ZIPX固定XZ。用户应清楚知道接收方需要支持PPMd，以及较高等级会增加内存，而不是根据文件类型被自动切换。

## 依据和顺序

1. 项目zip 8.6已启用ppmd；vendor/zip/src/compression.rs中方法号98，write.rs有Ppmd8Encoder编码分支。先核对真实方法号/参数、可压缩与混合内容、空文件/空目录、独立完整回解和资源占用。现有实现按1–9级选择阶数与内存，6级约32MiB、9级约256MiB字典；实现前确认编码/解码预算与进度/取消，不能仅因启用了特性就开放选项，不承诺固定压缩率。
2. 加入现有ZIP方法下拉框，明确等级、旧0级和内存提示，让显示、分析、实际参数一致。同步单条、多选、配置组/模板、预设、草稿与历史；默认与已有方法保持，非ZIP任务继续自然继承，ZIPX仍XZ。
3. 接通普通/AES-256/ZipCrypto、单包与数字/标准卷，独立核对方法98或AES扩展内的真实方法、正确/错误密码、任意成员浏览/有界预览/完整检查/所选及整包、密码原包双向转换、缺卷补回和统一结果。只核对新增PPMd影响链，旧算法/密码矩阵和真实盘满不重跑。
4. 保留单条展开、多选弹窗、50/50及窄窗滚动，确认实际显示和进度、结果后更新README、中文Release、范围与交接，收尾到可发版。

ZIP LZMA不能直接沿用本次策略：现有write.rs的LZMA编码分支明确返回不支持创建，仍需单独研究。WIM固实/ESD、SWM创建/部署、ZPAQ增量/原生追加多部分/损坏事务抢救、ALZ方法3及EGG加密固实保留独立研究；没有正面依据不作为已支持功能。

下一版仅规划[v1.5.36 ZPAQ增量更新](ARCHIVE_ROADMAP_1.5.36.md)，尚未开发。

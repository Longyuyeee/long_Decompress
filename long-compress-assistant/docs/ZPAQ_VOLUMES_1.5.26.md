# v1.5.26 ZPAQ 数字分卷实施

2026-10-20，从正式 v1.5.25 接续。按范围完成，进入封板发布；最终候选、合入和正式四资产身份由本版 PR/Release 接续。

## 范围与顺序

1. 普通和原生密码 ZPAQ 支持指定大小数字切卷，保留整组实际产物；从任意成员归组，不改密码算法，不把切片称为 ZPAQ 原生多卷或增量更新。
2. 贯通浏览、有界文本/图片预览、检查、所选/整包提取、密码 ZIP 互转、缺卷纠正新任务与结果生成校验清单。
3. 保留单条展开、多选弹窗、自然继承、左右等宽和窄窗滚动。只检查新增或受影响链，基础 ZPAQ、密码算法和旧格式矩阵不重复执行。

## 可行性依据与实现选择

固定随包的 ZPAQ 7.15 `InputArchive` 已有跨文件 seek 与按绝对流偏移解密。现有文件名通配方式不能可靠表达 `.001` 到 `.1000` 的编号变化，首个 32 字节密码盐也直接从首卷读取，不覆盖极小切片。

本版让适配器通过原有二进制 stdin 接收明确的成员列表，沿已有跨文件读取器处理；修正盐跨卷读取，保持普通单包协议。这样不必先拼接完整临时归档，也不新增一次全包复制。原始压缩/加密算法保持；实际能力须由独立原件和独立工具回解确认后开放。

预览沿现有文本/图片大小预算，增加对应 ZPAQ 读取/展开预算；超限明确提示先解压。未知大小或共享块不能当成有界成功，不通过完整落盘大文件来伪装预览。

## 已完成

普通/原生密码数字分卷创建、任意成员归组、浏览、有界文本/图片预览、完整检查、所选/整包提取、密码 ZIP 双向转换、补卷新任务与整组结果生成清单已接通。实际桌面发现外层 I/O 的旧密码分卷拦截，补一项回归并仅接续受影响链。未改密码或压缩算法。

能力异步加载前，配置使用完整静态元数据，打开配置不再清掉继承分卷；多选原弹窗补入 ZPAQ，只修改指定字段，密码/卷大小各自保留。切换 ZPAQ 清除不适用的文件名加密、固实和 RAR 恢复设置。原交互与等宽/窄窗布局保持。

## 预览与独立依据

预览先有界读目录，只接受已知大小单文件，再在独立临时目录解码所选内容，读取后清理，不把全包落盘来伪装预览。文本保留最多 1 MiB、条目最多 64 MiB，图片最多 8 MiB；每次原生预览累计读取和共享展开块最多 64 MiB，解码器内存最多 256 MiB，一个工作线程、30 秒超时。未知流式大小或超限提示先解压，正常完整提取不套预览预算。说明统一为“只读 · 不改原包”，取消读取按钮保持正常横排。

四个固定独立原件（日志式/流式、普通/原生密码）均按原件清单的 SHA256 核对当前视图；包含首卷 7 字节、第二卷 13 字节的不等长切片与超过 1000 卷。新普通/密码卷及转换结果在测试端按序合并后由未改动作者原版工具完整回解，文件与空目录一致；产品读取不合并。

[作者工具与源码](https://www.mattmahoney.net/dc/zpaq.html)的 `zpaq715.zip` SHA256 为 `e85ec2529eb0ba22ceaeabd461e55357ef099b80f61c14f377b429ea3d49d418`，原版 `zpaq64.exe` 为 `7a94b4f1d6323a758c7b0b6344036f166bff0fd44f1c3c86f05b3688023496cb`。适配器源码/程序由 `zpaq-engine.lock.json` 固定，许可和来源随包。密码 ZIP 沿现有独立 Python AES/PBKDF2/HMAC/Deflate 解码器，以明确 UTF-8 密码字节完整回读，不用 Windows CLI 本地代码页错密当判断依据。

数字切片需集齐全部成员，不是原生追加多部分；其他工具不能识别时先按序合并。不含增量更新、历史恢复、损坏修复或缺卷部分抢救。v1.5.27 WIM 数字卷、v1.5.28 资源管理器校验入口仍仅规划；ALZ 方法 3、EGG 加密固实和原生 SWM 保持独立研究边界。

定向检查、实际程序身份和界面证据见[封板记录](ZPAQ_VOLUMES_FREEZE_1.5.26.md)。
